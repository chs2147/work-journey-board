## 2. 업무노트 삭제 잠금 (시안 ①)
- **편집 화면 머리 막대**에 자물쇠 단추(저장 표시 바로 오른쪽): 풀림 `🔓 삭제 잠금 끔` / 잠김 `🔒 삭제 잠김`(채운 자물쇠 + 강조색). 누를 때마다 바뀌고 바로 저장된다.
- 잠그면:
  - 편집 화면 메뉴의 [노트 삭제]가 흐리게(눌리지 않음) + 안내 "삭제 잠금을 풀어야 지울 수 있습니다".
  - 업무노트 목록 줄의 🗑 자리에 작은 🔒(누르면 같은 안내, 지우지 않음). 목록에서 잠금을 풀 수는 없다 — **푸는 곳은 편집 화면 한 곳**(실수 방지).
  - **편집·제목 바꾸기·내보내기·다른 업무로 옮기기는 그대로**(잠금은 "삭제만" 막는다, D2).
  - 업무를 지우거나 공간을 정리하는 경로에서도 잠긴 노트는 지우지 않는다(업무는 노트가 있으면 지금도 지울 수 없음 — `ON DELETE RESTRICT`).
- 새 노트·복제한 노트는 **잠금 꺼짐**으로 시작(D3).
- 저장: `cabi_note.delete_locked INTEGER NOT NULL DEFAULT 0 CHECK(delete_locked IN (0,1))` — **구조 v19**(`0019_note_delete_lock.sql`, 전진 전용, 직전 자동 백업 `_pre-migration-v19`, D1). 저장소 `removeNote`가 **한 번 더 검사**(잠겼으면 `CABI_LOCKED` 오류) — 화면이 아니라 데이터 쪽에서 막는다. 노트 창은 지금처럼 메인 허용 RPC(`setNoteDeleteLock`)로만 바꾼다.

## 3. 업무노트 삭제 최종 확인 창 (시안 ②)
- `window.confirm` 두 곳을 앱 확인 창(`DeleteNoteDialog`, 보드 삭제 창과 같은 틀·`<dialog>` 모달)으로 바꾼다.
- 내용: 제목 "업무노트를 삭제할까요?" · 노트 제목(굵게)·업무·마지막 저장 시각 · 이미지 n개 · **이 노트를 가리키는 연결 n곳**(업무 보드 카드 등 — 지금 `referenceCount`) · "삭제하면 되돌릴 수 없습니다. 필요하면 먼저 [내보내기]로 저장하세요."
- 단추: [취소](**처음 초점**) · [삭제](빨강). `Enter`는 초점 단추(=취소), `Esc` 취소. 삭제 중에는 두 단추 잠김, 실패하면 창 안에 오류.
- 제목 입력까지 요구하지는 않는다(D4 — 보드 삭제는 여러 객체라 입력을 받지만, 노트는 잠금 + 확인 창 두 겹으로 충분).
- 지운 뒤: 편집 화면에서 지웠으면 창을 닫고, 목록에서 지웠으면 줄이 빠진다(지금과 같음).

## 4. 업무노트 복제 · 끌기 아이콘 (시안 ③)
- 목록 줄 단추 순서: `[⠿ 끌기] [⧉ 복제] [↗ 열기] [🗑 삭제 | 🔒]`.
  - **끌기 손잡이 아이콘을 6점 손잡이(⠿)로** 바꾸고 커서 `grab`/`grabbing`. 복사 모양(`IconCopyItem`)은 **복제에만** 쓴다(D5).
  - **적용 범위 — 같은 손잡이를 쓰는 모든 곳**(손잡이 그림은 `CabiDrag.tsx` `CabiDragGrip` 한 곳이라 함께 바뀐다):
    | 위치 | 동작 | 바뀐 뒤 |
    |---|---|---|
    | Cabi.NET 허브 목록 — 업무노트 줄 | 끌어 업무 보드·주간 메모에 원본 연결 | ⠿ |
    | Cabi.NET 허브 목록 — 폴더·링크 줄 | 끌어 원본 연결 | ⠿ |
    | 업무 보드 창 › 자료 서랍(노트·폴더·링크) | 끌어 보드에 원본 연결 | ⠿ |
    | 주간 메모 보드·업무 보드에서 **고른 객체의 끌기 단추** | 끌어 **다른 보드로 복제**(실제 복사) | ⠿ + 작은 `+` 표시(⠿⁺) — 끌면 "복사본"이 생긴다는 뜻을 남김 |
  - 그림은 주간 보드 항목 손잡이(⋮⋮, 점 6개 2×3 — `CellEditor` `Grip`)와 **같은 아이콘 하나**를 공용(`common/icons`)으로 옮겨 쓴다. 노트 블록 손잡이·표 손잡이도 같은 그림(5-1). 따라서 앱 안의 "끌어 옮기기" 손잡이는 모두 같은 모양, "복제"는 ⧉ 하나로 구분된다.
  - 툴팁: 끌기 "끌어서 업무 보드·주간 메모에 놓기" · 복제 "노트 복제".
- 복제하면:
  - 같은 업무에 `<제목> (사본)` 새 노트(이미 있으면 `(사본 2)`…). 본문·서식·표·목차 그대로.
  - **이미지는 새 자산으로 복사**(새 id, 소유자 = 새 노트 — Cabi.NET 규칙 "복제 시 이미지 소유 자산·객체 ID를 새로"). 원본을 지워도 사본 이미지는 남는다.
  - **연결은 옮기지 않는다** — 업무 보드에서 원본을 가리키던 카드는 계속 원본을 가리킨다. 삭제 잠금도 꺼진 채(D3).
  - 한 번의 `batch`(노트 1행 + 자산 n행), 실패하면 아무것도 남지 않음.
  - 목록 맨 위(최근 수정순)에 새 줄이 생기고 잠깐 강조 + 알림 "복제했습니다 [열기]"(바로 열지는 않음, D6).
- 편집 화면 메뉴에도 [노트 복제]를 함께 둔다(같은 동작 — 목록만 요청이지만 찾기 쉽게, D6).

## 5. 노트 표 (시안 ④)
### 5-1. 표 전체 끌어 옮기기(노션형)
- 손잡이를 셋으로 **자리·모양을 나눈다**:
  | 손잡이 | 자리 | 모양 | 동작 |
  |---|---|---|---|
  | **표 손잡이** | 표 바깥 왼쪽, **표 맨 위 줄 높이**(다른 블록 손잡이와 같은 열) | 6점 `⠿`(블록과 같음) | 끌면 **표 전체**를 다른 줄로 · 누르면 블록 메뉴(위/아래로·복제·삭제) |
  | 행 이끌이 | 그 행 **왼쪽 테두리 위**(표 안쪽에 반쯤 걸친 세로 알약) | 세로 점 3개 `⋮` | 끌면 행 이동 · 누르면 행 메뉴 |
  | 열 이끌이 | 그 열 **위 테두리 위**(가로 알약) | 가로 점 3개 `⋯` | 끌면 열 이동 · 누르면 열 메뉴 |
- 표 손잡이로 끌 때 다른 블록과 같은 **가로 놓기 선**(블록 사이, 강조색 2px)이 따라오고, 놓으면 표가 그 자리로 간다. 끄는 동안 원래 표는 반투명.
- 키보드: 표 안에서 블록 메뉴(`Shift+F10` 뒤 [위로]/[아래로])로도 표 전체를 옮긴다(지금 블록 메뉴 재사용).
- 실행 취소 한 번 = 표 이동 한 번(v1.23.3의 이력 경계 규칙 그대로 — 이동 전후 `closeHistory`).

### 5-2. 열 너비 조절 커서
- 열 경계(손잡이 폭 6px) 위에서 커서 **`col-resize`(↔)**, 끄는 동안 문서 전체에 같은 커서 유지, 경계에 강조색 세로선(지금 있는 `.column-resize-handle`).
- 고칠 곳: CSS 선택자 `.prose :global(.resize-cursor)` → `.prose:global(.resize-cursor)` (+ 끄는 동안 `body` 커서). 크롬·웹킷(맥) 둘 다 확인.

### 5-3. 행/열 이동 표시선
- 끄는 동안:
  - **원래 행/열**을 연한 강조 바탕으로 칠한다("이것을 옮기는 중").
  - **들어갈 경계**에 강조색 3px 선 — 행이면 표 너비만큼 가로선(대상 행의 위 또는 아래), 열이면 표 높이만큼 세로선(대상 열의 왼쪽 또는 오른쪽). 끝에 작은 동그라미.
  - 커서 `grabbing`, 표 밖으로 나가면 선을 숨기고 놓아도 움직이지 않는다. `Esc` = 취소.
- 판정: 지금처럼 포인터 아래 칸을 찾되, 칸의 **위/아래(왼/오른) 절반**으로 "앞/뒤"를 정해 선 위치와 실제 이동 결과가 같게 한다(지금은 칸 번호만 봐서 위로 끌 때와 아래로 끌 때 들어가는 자리가 직관과 다를 수 있음).
- 놓은 뒤 옮겨진 행/열을 0.6초 강조.

## 6. 새 판 확인 `403 Forbidden` 대응 (시안 ⑤)
### 6-1. 지금 규칙 안에서(승인 불필요 — 같은 주소·같은 시점)
- **조건부 요청**: 마지막으로 받은 판 목록의 `ETag`를 이 PC 앱 자료 폴더(`updates/releases-cache.json`)에 저장하고 다음 확인 때 `If-None-Match`로 묻는다. 바뀐 게 없으면 GitHub가 `304`를 돌려주고 **한도를 쓰지 않는다** → 저장해 둔 목록으로 판정. 같은 IP를 여럿이 써도 바닥나는 일이 크게 준다.
- **오류 구분**(Rust `update.rs`가 응답 머리를 읽어 종류를 넘김 → 화면 문구):
  | 판정 | 조건 | 안내 |
  |---|---|---|
  | 한도 초과 | 403/429 + `X-RateLimit-Remaining: 0`(또는 `Retry-After`) | "GitHub 확인 횟수 한도에 걸렸습니다(같은 인터넷 주소를 쓰는 PC가 많을 때). **약 N분 뒤**(HH:MM) 다시 확인합니다." |
  | 차단 | 403인데 한도 머리가 없음 · 연결 자체 실패 · 인증서 오류 | "회사망·보안 장비에서 GitHub 접속이 막힌 것 같습니다." |
  | 기타 | 그 밖 | 지금 문구 + 상태 코드 |
  - 셋 모두 [릴리스 페이지 열기] 단추 — 기본 브라우저로 넘김(링크 열기 규칙 4-1, 앱은 접속하지 않음). 한도 초과면 설정의 [업데이트 확인]을 다시 시각까지 흐리게.
  - 앱을 켤 때 확인이 실패하면 알림 없이 조용히 넘어가고(지금과 같음) 설정 › 업데이트에 "마지막 확인 실패: …"를 `SettingsCard.CardMessage`로 표시.
- `cargo test`: 응답 머리 판정(403+한도 0, 429+Retry-After, 403 머리 없음, 304 → 캐시), 캐시 파일 깨짐 → 무시하고 새로 받기.

### 6-2. 대체 경로(**사용자 승인 필요** — CLAUDE.md 4-1 "주소·시점을 넓히려면 사용자 승인", D8)
- 판 목록(`api.github.com`)이 한도 초과로 실패했을 때만 **같은 저장소의 `https://github.com/chs2147/work-journey-board/releases/latest`** 를 리디렉션 따라가지 않고 한 번 물어 `Location` 머리의 태그(`/releases/tag/v1.23.3`)에서 **판 번호만** 읽는다.
- 설치 파일·`SHA256SUMS.txt` 주소는 지금 허용된 `…/releases/download/v<판>/…`로 만들어 받고, **SHA256 확인을 반드시 통과**해야 설치(지금 규칙 그대로). 이 경로에서는 릴리스 노트 글이 없으므로 "변경 내용은 릴리스 페이지에서" 링크로 대신한다.
- `releases/latest`는 정식(Latest) 판만 가리킨다 — 정식 판 사용자에게는 충분하고 rc 판은 대상이 아니다.
- 허용 목록(`ALLOWED_PREFIXES`)에 `https://github.com/chs2147/work-journey-board/releases/latest` **정확히 한 주소**만 더한다. 웹 화면 CSP는 그대로.
