# 요구사항 — 업무 기록에서 재사용 지식으로

## 1. 제품 정의

**작업명: Universe / 사용자 표시 제안: 지식 지도.** 현재 일지에 쌓인 업무 기록·메모·자료를 근거로 맥락을 되찾고, 해결법·판단·배운 점을 지식 카드로 정리해 다음 업무에 재사용한다.

문제는 자료 수집 부족보다 주가 바뀌거나 업무가 달라질 때 기록의 연결과 결론을 다시 찾기 어렵다는 점이다. 통합 검색·업무별 타임라인은 이미 있으므로 새 기능의 가치는 **주를 넘는 연결, 근거 있는 지식 정리, 다음 업무에 필요한 문맥 전달**이다. 실제 시간 손실·사용 빈도에 대한 정량 조사는 아직 없으므로 아래 수치는 가설 목표다.

## 2. 설계 전제와 용어

- **업무**: 기존 `category`. 진행 중/종료 상태는 기존 구간 규칙을 따른다.
- **기록**: `entry_item`의 본 항목·세부 항목. 모든 기록이 할 일인 것은 아니다. `flag_done_at`은 중요 항목의 처리 기록이며 모든 항목의 완료 상태로 확장하지 않는다.
- **메모**: 주간 `NoteDoc` 안의 글·이미지·링크 상자.
- **자료**: Cabinet에 등록된 폴더·링크. 파일의 실제 본문은 현재 접근 범위 밖이다.
- **지식 카드**: 원본을 참조해 사용자가 정리한 해결법·판단·배운 점·업무 길잡이.
- **관계**: 업무 소속, 기존 메모/자료 연결, 새로 만든 주간 횡단 연결을 출처별로 구분.
- **근거 묶음**: 질문·범위·선택 원문·출처·주의를 담은 내보내기 텍스트.
- **작업 공간**: 검토 중인 멀티 보드 개념. 현재 MVP는 열린 일지 하나를 대상으로 한다.

본 명세의 기능·치수·한도·일정은 신규 제안이며 기존 사용자 승인을 대신하지 않는다.

## 3. 목표와 측정

| 목표 | 측정 | 초기 목표 |
| --- | --- | --- |
| 과거 해결법 빨리 찾기 | 같은 10개 가상 업무 질문에서 기존 검색/타임라인과 신규 흐름의 중앙 시간 비교 | 40% 감소 |
| 출처 유지 | 지식 카드의 출처와 내보내기 인용을 검사 | 모든 인용에서 원본 위치·변경 상태 확인 가능 |
| 기록 부담 유지 | 기존 기록 입력 흐름을 새 기능 켜기 전후 비교 | 새 필수 입력 0개, 입력·저장 성능 회귀 없음 |
| 실제 재사용 | 2주간 사용자 확인으로 과거 기록을 새 업무에 참고한 사례 기록 | 주 3회 이상, 기능 수요 검증용 가설 |
| 상태 오해 방지 | 끊긴 출처·미검토 카드·필터 밖 자료·수정된 기록 사례 | 최신 원문/확정 결론으로 오표시 0건 |

측정은 가상 테스트와 사용자가 선택한 로컬 집계로 한다. 원문·검색어·클립보드·성과 정보를 외부 분석 도구에 보내지 않는다.

## 4. 사용자 스토리

- U1. 지난달 같은 오류를 해결한 기록을 찾아 당시 조건과 해결 방법을 다시 사용하고 싶다.
- U2. 주가 달라져도 이어진 문제·회의·의사결정 기록을 연결하고 싶다.
- U3. 지나간 활동을 다음에도 쓸 지식으로 정리하되 근거 날짜와 원문은 남기고 싶다.
- U4. 기록·메모·등록 자료를 함께 보며 왜 관련 있는지 알고 원래 위치로 돌아가고 싶다.
- U5. 필요한 자료만 골라 사내 AI에 전달할 질문과 근거를 만들고 싶다.
- U6. 회사/개인 공간을 함께 다룰 때 어떤 공간의 자료인지 명확히 확인하고 싶다. 이는 멀티 작업 공간 이후 범위다.

## 5. 범위

| 단계 | 포함 |
| --- | --- |
| **P0 · 첫 출시** | 현재 일지의 검색·원본 이동·관계 투영·주간 횡단 수동 연결·지식 카드·근거 묶음·갱신/삭제 안전 |
| **P1 · 후속** | 멀티 공간 읽기 전용 통합 탐색, 로컬 추천 관계, 지식 검토·재사용 보조 |
| **P2 · 별도 결정** | 공간 간 영속 관계, 직접 AI 연동·임베딩·외부 파일 본문 읽기 |

첫 출시는 지식 카드 작성이나 태그를 매일 기록의 필수 단계로 만들지 않는다. 자동 성과 평가·직원 비교·생산성 점수·외부 전송·자동 원문 수정은 포함하지 않는다.

## 6. 상세 기능과 수용 기준

### U-01 · 기존 데이터 투영 — P0

현재 일지의 업무, 본/세부 기록, 메모 상자, Cabinet 항목을 공통 탐색 모델로 만든다. 메모 이미지 자체는 노드 미리보기가 열릴 때만 읽고 검색 대상은 설명이다. 과거 `day_memo`만 있는 주도 기존 `docFromDayMemos`에 준한 읽기 전용 표현으로 누락 없이 보인다.

**수용 기준**: 같은 기록이 보드와 지도에서 같은 ID를 가리킨다. 원문·이미지·순서를 복제 저장하지 않는다. 레거시 메모를 조회한 것만으로 새 `week_note`를 쓰지 않는다. 잘못된 메모 JSON은 진단하고 나머지는 탐색 가능하다.

### U-02 · 기존 관계의 의미 보존 — P0

다음은 별도 관계다: 업무 소속, 메모↔항목(`refs`), 같은 주 메모↔메모(`edges`), Cabinet↔업무/항목(`cabinet_link`). 데이터에서 확인한 연결과 사용자가 새로 만든 연결을 구분한다.

**수용 기준**: 관계를 고르면 ‘연결 이유·만든 기능·출발·대상’을 볼 수 있다. 같은 카테고리에 속한다는 이유로 두 기록 사이에 ‘해결했다’ 선을 만들지 않는다. 기존 메모 선의 방향·점선·레이블을 보존한다. 기존 `refs`의 같은 주·20개 제한을 임의 확장하지 않는다.

### U-03 · 검색과 필터 — P0

현재 낱말 AND·부분 일치 규칙을 유지하면서 업무, 기간, 종류, 직접 연결/지식 카드, 진행 중/종료 업무 포함 여부로 좁힌다. 기존 `Ctrl+Shift+F`는 보존하고 ‘지식 지도에서 보기’를 추가한다.

**수용 기준**: 2글자 미만 입력은 기존 규칙대로 안내한다. 필터 사이 AND, 같은 필터 안 OR. 기록·메모·Cabinet·지식 카드의 건수를 분리하고 일부 결과는 상한을 표시한다. 기존 300건 반환을 전체 조회로 간주하지 않는다. 지식 지도 조회는 커서 페이지를 사용한다.

### U-04 · 업무 중심 지도와 목록 — P0

기본 진입은 현재 업무·최근 12주와 주변 1단계다. 전체 보기에서는 업무 군집을 먼저 표시하고 펼칠 수 있다. 그래프와 목록은 같은 선택·필터를 공유한다.

**수용 기준**: 기본 최대 150노드·300선, 초과는 생략 수와 확장/좁히기를 안내한다. 지도 위치는 데이터의 의미가 아니다. 목록만으로도 모든 원본 열기·연결·담기가 가능하다. 마지막 선택은 일지별로 기억한다.

### U-05 · 원본으로 정확히 돌아가기 — P0

기록은 항목 ID로 찾은 현재 날짜/업무 칸, 메모는 주차+상자, 관계선은 주차+선, Cabinet은 항목을 선택한다. 지식 지도 복귀 시 필터·줌·선택을 복원한다.

**수용 기준**: 항목을 다른 날·업무로 옮긴 뒤에도 같은 ID로 최신 위치에 이동한다. 삭제/복원 중인 원본은 안내한다. 단순히 해당 주만 열고 대상이 선택되지 않는 상태를 성공으로 보지 않는다. 편집 미저장 상태에서는 기존 저장 완료를 먼저 기다리고 실패 시 화면 이동을 중단한다.

### U-06 · 주를 넘는 직접 연결 — P0

선택한 기록·메모·Cabinet·지식 카드에서 ‘연결하기’로 다른 주 자료를 찾고 연결한다. 관계는 관련/후속/근거/반대 근거/대체 중 하나다. 관련은 무방향, 나머지는 출발→대상. 관계 설명은 선택 200자다.

**수용 기준**: 기존 `NoteDoc.edges`를 고치지 않고 독립 관계로 저장한다. 같은 끝점·종류·방향의 중복을 막고 기존 연결을 보여 준다. 자기 연결은 금지한다. 새 관계 생성/편집/해제는 실행 취소가 가능하다. ‘A가 B를 대체’여도 원문·다른 관계를 삭제하지 않는다.

### U-07 · 지식 카드 만들기 — P0

한 개 이상의 원본을 선택해 해결법/의사결정/배운 점/업무 길잡이를 정리한다. 필드는 제목(1~120자), 요약(선택 300자), 본문(1~10,000자), 적용 조건(선택 1,000자), 관련 업무, 출처(1~50개)다. 저장은 명시 버튼, 작성 중 로컬 임시본은 복구 가능하게 한다.

**수용 기준**: 원문은 그대로이고 카드만 저장된다. 단일 세부 항목에서 만들면 부모 본 항목을 함께 확인한다. 저장 실패 시 작성 내용이 남고 성공처럼 닫히지 않는다. 실제 영속 테이블·백업에 포함된다. 이미지/OCR·AI 자동 생성은 필수로 넣지 않는다.

### U-08 · 카드 상태와 출처 — P0

카드 상태는 초안/검토함/보관이다. ‘검토함’은 사용자가 적용 조건과 출처를 확인한 상태이며 진실 보증이 아니다. 출처마다 원문 위치, 선택 당시 발췌, 내용 지문, 현재 상태를 보존한다.

**수용 기준**: 원문이 바뀌면 ‘근거 변경’, 삭제되면 ‘원문 없음’, 복원 후 일치하면 정상으로 표시한다. 날짜 이동은 위치 갱신으로 구분할 수 있다. 변경된 출처가 있는 검토함 카드에는 재확인 배지를 추가한다. 원문 없이 카드만 최신 사실로 표시하지 않는다.

### U-09 · 지식 카드 찾기·수정·보관 — P0

업무·유형·카드 상태·원문 상태·검색어로 찾고 수정할 수 있다. 카드를 보관하면 기본 추천에서 제외하되 검색 필터로 볼 수 있다. 보관/해제는 실행 취소를 지원한다.

**수용 기준**: 원본 삭제가 카드를 연쇄 삭제하지 않는다. 직접 만든 관계·출처를 보존한다. 카드 삭제는 휴지통/소프트 삭제+복구로 구현하며 초기에는 영구 삭제 UI를 제공하지 않는다. 동일 카드 편집 기준 revision이 달라지면 덮어쓰기 대신 재확인을 요구한다.

### U-10 · 질문별 근거 바구니 — P0

원본과 지식 카드에서 ‘근거에 담기’로 바구니에 추가한다. 업무 목적·질문, 기간, 선택 목록, 미검토·변경·끊김 경고, 제외할 자료를 확인한다. 같은 원본 중복은 합친다.

**수용 기준**: 출처 없는 요약만으로 원본을 대체하지 않는다. 카드의 본문과 그 근거를 선택적으로 함께 넣되 중복 출처는 한 번만 싣는다. 목록이 최신 데이터와 다르면 복사 전 다시 검증한다. 선택을 바꿔도 기록 입력 포커스와 자동 저장은 방해하지 않는다.

### U-11 · 사내 AI용 근거 묶음 — P0

클립보드 복사와 Markdown 저장을 제공한다. 구성은 질문·범위·업무 길잡이(선택)·원문/카드·출처 번호·원본 위치·미확인 사항·‘추측 금지/인용 번호 사용’ 지시문이다. 앱은 외부 AI에 자동 전송하지 않는다.

**수용 기준**: 복사 전 미리보기 필수, 포함된 내용이 무엇인지 사용자가 확인한다. 원문 12,000자/최대 20개 원본, 질문·지시·메타데이터 별도 최대 4,000자. 초과 시 원본 단위로 제외하고 제외 목록을 표시한다. 클립보드 실패 시 다운로드/수동 선택 대안을 제공한다. 모델 미지정 시 토큰 수를 확정 표시하지 않는다.

### U-12 · 갱신·저장·복원 일관성 — P0

현재 일지 저장 성공 후 탐색 모델을 갱신한다. 대량 가져오기·되돌리기·DB 복원·일지 전환은 파생 인덱스를 폐기하고 다시 만든다. 실패 시 기존 성공 스냅샷과 오래됨 표시를 유지한다.

**수용 기준**: 복원 전과 후에 같은 ID의 내용이 달라도 과거 인덱스로 결과를 내보내지 않는다. 비동기 검색 응답이 뒤늦게 도착해도 현재 일지/질의 결과만 반영한다. 생성된 카드 임시본을 다른 일지에 저장하지 않는다.

### U-13 · 삭제·실행 취소·데이터 안전 — P0

원본과 연결을 읽는 것만으로 기존 기록을 변경하지 않는다. 파생 연결은 삭제된 원본을 숨기고, 카드의 출처와 새 직접 관계는 ‘원본 없음’ 상태로 보존한다. 원본 되돌리기로 동일 ID가 복원되면 다시 연결한다.

**수용 기준**: 기록 삭제→되돌리기, 메모 상자 삭제→되돌리기, Cabinet 제거→되돌리기를 검증한다. 실행 취소는 열린 일지에만 적용한다. DB 마이그레이션은 기존 자동 백업·batch·전진 전용 규칙을 따른다. 노드 정리 작업이 실제 사용자 파일을 삭제하지 않는다.

### U-14 · 키보드·접근성·테마 — P0

Windows/macOS의 기존 단축키·시그니처/라이트/다크를 따른다. 새 기능은 레일과 메뉴에 ‘지식 지도’로 진입하고 현재 점유 단축키를 바꾸지 않는다. 신규 단축키는 프로젝트 전체 표 대조 후 확정한다.

**수용 기준**: 키보드만으로 검색→원본 읽기→카드 작성→근거 복사 가능. Escape는 현재 팝업부터 닫고 복귀 포커스를 보존한다. 색 외에 노드 모양·관계 문구·상태 배지를 제공한다. 한글 조합 중 Enter로 저장/이동이 발생하지 않는다.

### U-15 · 업무별 길잡이 — P1

업무 목적·용어·절차·주요 카드/자료·주의를 업무 길잡이 카드 한 곳에 정리하고 관련 업무의 지도·근거 묶음에서 접근한다.

**수용 기준**: 원본을 복사한 별도 진실 저장소로 취급하지 않는다. 같은 업무의 기본 길잡이를 명시적으로 지정하고 삭제/보관 시 연결 해제·대체 안내를 제공한다. 길잡이 선택이 다른 작업 목적에 자동 강제되지 않는다.

### U-16 · 멀티 공간 통합 탐색 — P1

멀티 작업 공간 승인·구현 뒤 사용자가 포함한 공간만 읽기 전용으로 함께 탐색한다. 쓰기는 현재 공간에만 가능하다. 노드 ID는 공간 ID+유형+원본 ID로 식별한다.

**수용 기준**: 회사/개인 같은 원문도 공간별로 구분한다. 읽을 수 없는 공간은 현재 일지를 닫지 않고 누락 이유를 알린다. 다른 공간에서 온 기록은 직접 수정하지 않고 공간 전환 후 연다. 현재 공간을 제외한 자료의 외부 내보내기는 기본 꺼짐이다.

### U-17 · 로컬 관련 후보 — P1

같은 업무·공유 Cabinet·공통 태그·텍스트 겹침을 근거로 관련 기록 후보를 보여 준다. 초기 추천은 오프라인 규칙 기반이며 의미 이해·원인 분석을 보장하지 않는다.

**수용 기준**: ‘같은 자료에 연결됨’처럼 추천 이유를 설명한다. 사용자가 채택하기 전 직접 관계로 저장하지 않는다. 거절한 후보는 숨길 수 있다. 동일 카테고리·단어만으로 ‘후속/해결/대체’를 자동 부여하지 않는다.

### U-18 · 카드 검토·재사용 보조 — P1

최근 참고한 카드, 근거가 바뀐 카드, 검토가 필요한 카드를 로컬에서 모아 보여 준다. 사용자가 선택하면 새 업무 기록에 기존 카드 참조를 추가한다.

**수용 기준**: 횟수는 개인의 재사용 편의를 위한 값이다. 직원 성과·생산성 지표로 해석하지 않는다. 읽었다는 이유만으로 ‘검토함’이 되지 않는다. 표시 이력을 삭제해도 원본·카드는 유지된다.

### U-19 · 수동 AI 결과 반영 — P1

사내 AI에서 가져온 결과를 붙여넣어 지식 카드 초안으로 검토할 수 있다. 인용 번호가 현재 근거 묶음과 일치하는지 검사한다.

**수용 기준**: 잘못된 인용·없는 출처를 표시하고 사용자가 선택한 본문만 저장한다. 붙여넣은 텍스트의 도구 실행·파일 변경·외부 전송 명령을 실행하지 않는다. 자동 원본 수정·자동 검토 완료는 없다.

### U-20 · 범위 확장 — P2·별도 결정

공간 간 영속 관계, 앱 내부 AI API·로컬 모델·임베딩, Cabinet 파일 본문 읽기/OCR은 별도 설계로 검토한다.

**수용 기준**: 현재 코드에 숨은 호출 경로·외부 권한을 미리 추가하지 않는다. 업무 데이터 전송 대상·범위·비용과 읽기 권한을 구체화한 뒤에만 구현한다. 현재 기능의 오프라인 사용은 독립적으로 유지한다.

## 7. 핵심 시나리오와 예외

### S1. 반복 문제를 찾아 해결법으로 정리

가상 업무 ‘데이터 연계 개선’의 지난달 기록에서 ‘재시도’를 검색한다. 관련 메모와 연결 자료를 확인하고, 서로 다른 주의 3개 기록을 직접 잇는다. ‘배치 재시도 조건’ 해결법 카드를 만들고 적용 조건·출처를 저장한다. 다음 달 같은 문제에서 이 카드를 찾아 원문을 확인한 뒤 새 업무에 참고한다.

### S2. 근거 원문이 수정됨

Given 카드에 출처가 저장되어 있을 때, When 원본 내용이 수정되면, Then 카드를 자동 재작성하지 않고 변경 배지를 표시한다. 사용자가 과거 발췌와 현재 원문을 비교하고 재확인하면 새 지문과 검토 시점을 저장한다.

### S3. 기록이 다른 날짜로 이동

Given 지도에서 선택한 기록을 보드에서 다른 날짜로 옮겼을 때, When ‘원본 열기’를 누르면, Then 오래된 날짜가 아니라 동일 ID의 현재 위치로 이동한다. 날짜별 의미가 달라진 카드에는 위치 변경 안내를 남긴다.

### S4. 삭제·복원·뒤늦은 응답

Given 검색 중 복원 또는 일지 전환이 발생하면, When 이전 조회 결과가 도착해도, Then 세션 키가 달라 적용하지 않는다. 삭제된 원본을 포함한 묶음 복사는 막거나 사용자가 삭제 사실을 포함해 명시적으로 제외 후 진행하게 한다.
