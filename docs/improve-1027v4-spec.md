## 1. 새 판 확인·자동 설치 (#1, 시안 ①)

### 1-1. 규칙과의 관계
- CLAUDE.md 4-1: "외부 통신 0(제품의 존재 이유)", "자동 업데이트(updater) 금지". 요청을 그대로 "앱이 인터넷에서 새 판을 확인·설치"로 하면 이 두 규칙을 바꿔야 한다.
- 그래서 두 안을 둔다. **A는 규칙 안에서**, B는 규칙 변경(사용자 승인)이 필요하다.

| | A. 폴더 확인 (추천) | B. 인터넷 확인·내려받기 |
|---|---|---|
| 새 판 알기 | 정해 둔 폴더(기본 `내려받기`, 공유 폴더 가능)에 놓인 `WorkJourneyBoard_<판>_setup.exe` | 앱이 GitHub API(`releases/latest`)에 하루 1번 물어봄 |
| 사용자 손 | 브라우저에서 내려받기 1번([릴리스 페이지 열기]가 열어 줌) | 없음(설치 확인만) |
| 외부 통신 | **0 그대로** | `api.github.com`·`github.com`·`objects.githubusercontent.com` — CSP `connect-src` 추가, 4-1 개정 |
| 회사 PC | 폴더만 보면 됨 | 회사망·프록시가 GitHub를 막으면 동작 안 함, 보안 검토 대상 |
| 공통 | 판 번호·SHA256 검사, 설치 전 자동 백업, 설치 후 다시 시작. 설치 파일은 코드 서명이 없어 백신·SmartScreen이 막을 수 있음(회사 PC 확인) | |

### 1-2. A안 화면
- **설정 › 업데이트**(새 절): 지금 판 · 새 판 찾는 곳(폴더, [바꾸기…]) · ☑ 앱을 켤 때 이 폴더 확인(기본 켬) · [지금 확인] · [릴리스 페이지 열기 ↗] · "마지막 확인 10/27 09:12 — 최신 판입니다".
  - [릴리스 페이지 열기]는 링크 규칙(4-1)과 같게 `Platform.openUrl`로 **기본 브라우저에 넘길 뿐** — 주소는 앱에 박힌 `https://github.com/chs2147/work-journey-board/releases/latest` 하나.
- **찾았을 때**: 보드 위 파란 띠 "새 판 0.2.18이 있습니다 (내려받기 폴더) [설치하고 다시 시작] [나중에]" + 왼쪽 레일 설정 아이콘에 파란 점. [나중에] = 그 판은 다음 실행 때까지 띠를 다시 띄우지 않음(점은 남음).
- **설치 확인 창**: ✓ 파일 이름·판 번호(0.2.17 → 0.2.18) · ✓ SHA256(같은 폴더의 `SHA256SUMS.txt`와 일치) · ✓ 설치 전 일지 자동 백업(`…_pre-update`) → [설치하고 다시 시작].
  - `SHA256SUMS.txt`가 없으면 "무결성 파일이 없어 확인하지 못했습니다" 경고 + [그래도 설치](기본 아님).

### 1-3. A안 동작
1. 확인 시점: 앱을 켤 때(설정 켬) · [지금 확인] · 앱이 열려 있는 동안 1분마다(폴더 목록만, 가볍게).
2. 고르기: 폴더의 파일 중 이름이 정확히 `WorkJourneyBoard_<x.y.z>_setup.exe`(오프라인판 `_setup_offline.exe`도)이고 `<x.y.z>` > 지금 판인 것 중 가장 높은 판.
3. 설치: 입력 중인 글 저장(`flushAll`) → 자동 백업(`_pre-update`, 가져오기 전 백업과 같은 길) → 새 Rust 명령 `run_installer(path)`가 **다시 검사**(폴더 = 설정의 찾는 곳, 이름 패턴, 판 > 지금, SHA256 일치) 후 설치 파일을 현재 사용자 권한으로 조용히(passive) 실행 → 앱 종료 → 설치가 끝나면 새 판을 연다(설치 파일의 "끝나면 실행" 옵션 — 회사 PC에서 확인, 안 되면 "설치가 끝나면 앱을 다시 열어 주세요" 안내로).
4. 설치 파일은 지우지 않는다(사용자 폴더 파일 삭제 규칙 4-3 그대로).

### 1-4. B안(선택 시)
- A의 화면·설치 그대로 + 하루 1번 `releases/latest`를 읽어 판·릴리스 노트를 보여 주고 [내려받고 설치] — 내려받기는 앱 자료 폴더 안(`updates\`)으로. CSP·4-1·`.github`·확인표를 함께 바꾸고, "외부 통신" 문구(README·릴리스 노트)도 고친다.

## 2. 중요 업무 완료 뱃지 (#2, 시안 ②)

### 2-1. 보드 항목
- 완료 = `flagged = 0` 이고 `flagDoneAt`이 있는 항목. ☆/★ 자리에 **완료 뱃지**를 늘 보인다: 18px 초록 원 + 흰 체크(인라인 SVG).
- 색: 새 토큰 `--done`(라이트 `#0f6e56`, 다크 `#4fc29a` — 기존 `--ok`와 같은 값, 이름만 따로), 체크는 라이트 흰색 / 다크 검정. 업무 색·★(주황)·형광펜(노랑)과 겹치지 않고 바탕 대비 3:1 이상, 색만이 아니라 체크 모양으로 구분.
- 글은 그대로(취소선·흐림 없음 — 기록이므로). 처리 전 노란 강조는 처리하면 없어지므로 "노랑 ★ = 할 일, 초록 ✓ = 끝남".
- 뱃지를 누르거나 그 항목에서 `Alt+I` → 작은 창 "중요 업무 처리 완료 · 10/24 (토) 14:20에 처리 · [되돌리기 — 다시 중요 업무로]". (`Alt+I`가 완료 항목에서 다시 중요로 바꾸는 것은 지금 동작과 같음 — 이제 작은 창으로 한 번 확인.)
- 화면 낭독기: `aria-label="중요 업무 처리 완료, 10/24"`.

### 2-2. 연결된 메모 상자
- 띠 줄: 그 항목이 완료면 줄 앞에 14px ✓(마우스 올리면 "10/24 처리 완료").
- 상자: 연결된 항목 가운데 **중요 표시였던 항목(처리 전 + 완료)이 1개 이상이고 그것이 모두 완료**면 상자 오른쪽 위에 22px ✓(흰 테두리). 중요 표시가 아닌 항목은 셈에서 뺀다.
- 스냅샷 그림(v0.2.17)·경과 타임라인 항목에도 같은 ✓.

## 3. 완료 기록 영구 보관 (#3)
- 지금: 처리 완료 시 `flag_done_at`에 시각을 쓰고 지우지 않는다. 패널 "최근 완료"만 `RECENT_DONE_DAYS = 7`로 걸렀다.
- 바꾼 뒤: 7일 거르기·문구("7일간 보관", "7일 동안 남습니다")를 없앤다. **데이터·스키마 변경 없음.**
- 완료 기록이 지워지는 때: ① [되돌리기](패널·뱃지 창·`Alt+I`) = 다시 중요 업무 ② 보드에서 그 항목 자체를 지움(`Ctrl+Z`로 되살리면 완료 기록도 함께).

## 4. 보고 있는 주의 완료만 (#4)
- 패널 아래 접는 절 "▾ 이 주 완료 · 2026-W43 (10/19~10/25) N": 보드에서 **보고 있는 주에 처리한** 항목(처리한 날 = `flag_done_at`의 내 PC 날짜 기준), 처리한 날로 묶고(최근 위), 줄 끝에 항목 날짜·[되돌리기]. 줄을 누르면 보드의 그 칸으로.
- 주를 바꾸면(`Alt+←/→`·연간 보기) 따라 바뀜. 오늘 뷰에서는 오늘이 든 주. 0개면 "이 주에 처리한 중요 업무가 없습니다." 펼침 상태는 기억.
- "모두 챙겼습니다" 빈 화면의 문구 "'최근 완료'에 7일 동안 남습니다" → "아래 '이 주 완료'에 남습니다".
- 저장소: `listRecentDone(days)` → `listDoneInWeek(weekId)` — `flag_done_at`이 그 주 앞뒤 하루 범위인 행을 읽어(UTC 저장) 내 PC 날짜로 다시 걸러 정확히 그 주만.
