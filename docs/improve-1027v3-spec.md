## 1. 메모 보드 스냅샷 (#1, 시안 ①)

### 1-1. "별도 저장"의 뜻
- 추천: **그림 파일(PNG)로 따로 저장**한다(그 시점 메모 보드의 모습 그대로). 메일·보고서에 붙이거나 보관할 때 쓴다.
- 다른 뜻으로 받을 수 있는 안 — "앱 안에 시점 사본을 여러 개 보관(스냅샷 목록에서 다시 보기)" — 은 이번에 하지 않는다(8절 #1-1). 일지 파일이 커지고, 메모 보드는 주마다 따로 있어서 "그 주의 메모" 자체가 이미 시점 기록이다.

### 1-2. 들어가는 곳
- 메모 머리(도크·오늘 뷰 왼쪽 메모 공통) 아이콘 단추 줄 끝에 **[스냅샷]**(카메라 아이콘, 툴팁 "메모 보드 스냅샷"). 누르면 메뉴:
  - **PNG 그림으로 저장…** — 저장 대화상자(기본 이름 `메모보드_2026-W43.png`, 기본 폴더 = 마지막 내보내기 폴더).
  - **그림으로 복사** — 클립보드에 PNG(메일·문서에 바로 붙여넣기). 성공하면 알림 "메모 보드 그림을 복사했습니다".
- 상자가 하나도 없으면 단추 흐림(툴팁 "메모가 비어 있습니다").
- 단축키는 두지 않는다(드물게 쓰는 동작, `Ctrl+Shift+S`는 편집기 취소선 기본 키와 겹침).

### 1-3. 그림 내용
- **판 전체**: 모든 상자를 감싸는 사각형 + 여백 24px(보이는 부분·줌과 무관).
- 위에 제목 띠 한 줄: `이번 주 메모 · 2026-W43 (10/19~10/25)` + 작은 글씨 `Work Journey Board · 2026-10-27 저장`.
- 그리는 것: 글 상자(배경색·4-3 서식 전부 — 제목·크기·굵게/기울임/밑줄/취소선·글자색·형광펜·글머리/번호/체크 목록·구분선), 이미지 상자(원본 이미지 + 설명), 링크 카드(제목·주소·메모), 업무 연결 띠(여러 줄, 5개 이상이면 화면처럼 4줄 + "연결 N개 더"), 관계선(꺾은선·화살표·점선·이름표, [관계선 보기]가 꺼져 있어도 **그림에는 그린다** — 8절 #1-4).
- 그리지 않는 것: 손잡이·연결점·⋯·선택 테두리·미니맵·대기(빈 새) 상자·점 격자 배경(바탕은 단색).
- **항상 라이트 테마**(인쇄·문서용), 해상도 2배. 긴 변이 8192px를 넘으면 그 안에 들어가게 비율을 줄인다(브라우저 캔버스 한계).

### 1-4. 그리는 방법
- 화면을 캡처하지 않고, **메모 문서 JSON(`week_note.doc`) + 이미지(`note_asset`)를 Canvas 2D로 직접 그린다** — `src/export/noteSnapshot.ts`.
  - 이유: ① 엑셀에 여러 주를 넣으려면 화면에 없는 주도 그려야 한다 ② DOM→SVG(foreignObject) 방식은 글꼴을 data URL로 넣어야 하는데 CSP(`default-src 'self'`)와 부딪힌다 ③ 같은 문서 → 같은 그림이라 테스트가 쉽다.
  - 글꼴은 이미 불러온 Pretendard(`document.fonts`)를 그대로 쓴다. 글 줄바꿈은 상자 너비 기준 단어 단위(한글은 글자 단위), 줄 높이·여백은 Note.module.css 값과 맞춘다.
  - 상자 높이: 화면에서 잰 높이가 있으면(`h`) 그것을, 없으면 그리기 엔진이 잰 높이.
  - 관계선 경로는 `domain/noteEdge.ts` `routeEdge`를 그대로 재사용(화면과 같은 선).
- 저장: `Platform.writeExport`(엑셀·메모 이미지 저장과 같은 길) — `.png`만, 일지 파일·`backups\` 거부, Rust `export_write`가 한 번 더 검사(이미 `.png` 허용, 새 Rust 명령 없음).
- 복사: `navigator.clipboard.write([new ClipboardItem({"image/png": blob})])`(WebView2 지원, 네트워크 없음). 실패하면 "복사하지 못했습니다 — [PNG 그림으로 저장…]을 써 주세요".

### 1-5. 엑셀 내보내기에 포함 (시안 ① C·D)
- 내보내기 대화상자 [포함]에 세 번째 체크 **메모 보드 스냅샷** — 기본 **꺼짐**(파일이 커지므로), 마지막 선택을 기억. 옆에 "(메모 있는 주 N개 · 시트 1개 추가)", 아래 안내 "스냅샷은 그림이라 파일이 커질 수 있습니다(주당 약 0.2~1MB)".
- 새 시트 **"메모 보드"**(시트 순서 = 주간보고 · 원장 · 메모 보드). 범위 안의 **메모가 있는 주마다** 위에서부터:
  - 제목 행 `2026-W43 (10/19~10/25) 메모 보드`(굵게) → 그 아래 셀 위에 떠 있는 그림(너비 1000px에 맞춤, 아래 행은 그림 높이만큼 비움) → 빈 행 2개.
  - 최신 주가 위(주간보고 시트와 같은 순서). 메모가 없는 주는 맨 끝 한 줄 "메모가 없는 주: 2026-W40, …".
- 엑셀용 그림은 1.5배 해상도(파일 크기와 선명도 절충), PNG.
- ExcelJS `workbook.addImage({ buffer, extension: "png" })` + `worksheet.addImage(id, { tl, ext })`. 인쇄 영역은 그림 너비에 맞춤(가로 1쪽).
- `ExportOptions`에 `noteSnapshots: boolean` 추가, 그림은 내보내기 전에 만들어 `buildWorkbook`에 넘긴다(엑셀 모듈은 캔버스를 모르게).
- 범위가 길어 메모 주가 많으면(20주 초과) 대화상자에 경고 "메모 그림 N장 — 파일이 커지고 시간이 걸릴 수 있습니다"(막지는 않음). 만드는 동안 진행 표시 "메모 그림 만드는 중 3/12".

## 2. 메모 상자를 업무 항목으로 끌 때 — 상자는 제자리 (#2, 시안 ② 위)

### 2-1. 지금(0.2.15)
- 상자 위 막대를 끌면 상자가 **커서를 따라 움직이고**(`moveBoxLive`), 보드 항목 위에 있으면 "+ 여기에 연결 추가". 놓으면 상자는 원래 자리로 돌아가고 연결만 더한다.
- 문제: 큰 상자가 보드를 가려 놓을 항목이 안 보이고, 메모 판이 따라 흔들린다.

### 2-2. 바꾼 뒤
- 끌기 시작은 지금과 같다(막대 끌기 = 옮기기).
- 포인터가 **메모 판(`[data-note-drop]`) 밖으로 나가는 순간** "연결 모드"로 바뀐다:
  - 상자는 **끌기 시작 자리로 돌아가** 파란 점선 테두리 + 옅은 바탕("연결 중")으로만 표시한다(내용은 가리지 않음 — 시안의 안내 글은 설명용). 안내는 꼬리표 툴팁·화면 낭독기용 `aria-live` "연결할 항목에 놓으세요, Esc 취소".
  - 커서 옆에 **작은 꼬리표** `⛓ 상자 이름`(`boxName`, 24자 자르기, 어두운 바탕)만 따라간다. 보드 행 끌기의 꼬리표와 같은 모양.
  - 보드 항목 위 강조·"+ 여기에 연결 추가"/"연결됨"은 지금과 같다(`useLinkDrop`).
- 다시 판 안으로 들어오면 연결 모드가 풀리고 상자가 커서 위치로 이어서 옮겨진다(되돌리기 한 번 = 끌기 전체).
- 놓기: 항목 위 = 연결 더하기(`linkBox`), 판 밖 다른 곳 = 아무것도 안 함(상자 제자리), `Esc` = 취소.
- 오늘 뷰 왼쪽 메모도 같다. 이미지·링크 상자도 같다.

## 3. 업무 항목을 메모 판에 놓기 — 빈 곳 / 기존 상자 (#3, 시안 ② 아래)

- **이미 0.2.15에 있는 동작**이다:
  - 보드 행 ⋮⋮을 메모 판 **빈 곳**에 놓기 → 그 항목에 연결된 새 글 상자(improve-1026v2-spec 5-2, `addLinkedBox`).
  - **기존 상자**(띠·본문·이미지 어디든) 위에 놓기 → 그 상자에 연결 더하기(multi-link-spec 2-2, `linkBox`). 이미 연결된 상자는 회색 "연결됨", 놓아도 그대로.
- 회사 PC에서 이렇게 동작하지 않았다면 그 상황(어느 화면·어떤 상자·어디에 놓았는지)을 알려 주시면 원인을 찾는다.
- 이번 다듬기:
  - 상자 바깥 **16px 이내**는 빈 곳으로 보지 않고 그 상자로 본다(경계에서 새 상자가 잘못 생기지 않게).
  - 빈 곳 위에서는 놓일 자리에 **점선 미리보기**("여기에 놓으면 이 항목과 연결된 새 메모")를 보이고, 다른 상자와 겹치면 아래로 비켜 표시(놓으면 그 자리에 생김).

## 4. 배경색 컬러칩 버그 (#4, 시안 ③ 왼쪽 위)

- 증상: 글 상자 ⋯ 메뉴의 배경색 칩(없음·노랑·파랑·초록·분홍 5개)이 모두 흰색. 고르면 상자 색은 제대로 바뀐다.
- 원인: `src/ui/note/Note.module.css`에서 색 클래스 `.bg_yellow{background:var(--note-bg-yellow)}` 등(353행 부근)보다 `.swatch{…background:var(--surface-card)}`(474행 부근)가 **뒤에 있고 우선순위가 같아** 흰 배경이 이긴다.
- 고침: 칩 색을 `.swatch.bg_yellow` 같은 **두 클래스 결합 선택자**로 따로 정의(파일 순서에 기대지 않음). "없음" 칩은 흰 바탕 + 사선. 고른 칩은 파란 고리, 툴팁에 색 이름(없음·노랑·파랑·초록·분홍).
- 테스트: E2E — 메뉴를 열어 칩들의 계산된 `background-color`가 서로 다른지, 라이트·다크 모두.

## 5. 릴리스 노트 공통 규칙 (#5, 시안 ④)

### 5-1. 지금
- `build-windows.yml`의 "Publish pre-release"가 **고정 본문**(설치 파일 표 + "앱은 실행 중 인터넷으로 아무것도 보내지 않습니다.")만 쓴다 → 릴리스 화면에서 무엇이 바뀌었는지 알 수 없다.

### 5-2. 바꾼 뒤

  ```markdown

  ## 새 기능
  - 사용자가 보는 화면 이름 + 바뀐 점, 한 줄에 하나

  ## 고친 점
  - 증상으로 적기("~하던 문제")

  ## 주의
  ```

### 10-1. 설계와 달라진 점·구현에서 정한 것
- **위 연결점 자리(7절)**: 막대(grip) 가운데에 겹치면 막대 가운데를 잡을 때 옮기기 대신 잇기가 시작돼, 위 막대가 있는 상자(글·이미지)는 **막대 바로 위**(상자 위 26px)에 둔다. 막대가 없는 링크 카드는 위 가장자리 가운데.
- **"오늘 뷰 왼쪽 중요 목록"(6절)**: 오늘 뷰에는 중요 목록이 따로 없다(왼쪽 레일의 중요 업무 패널 하나뿐) — 패널에만 적용.
- **"없음" 칩(4절)**: 이미 "흰색" 칩(흰 바탕)이 그 역할 — 사선 표시는 넣지 않았다.
- **띠 구조(6절)**: 실제 패널은 날짜 묶음 › 업무 순서(시안은 업무 › 날짜로 그렸음). 띠는 날짜 묶음 머리에 붙는다.
