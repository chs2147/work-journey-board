# 개선 v16 — 상세 설계 A안·구현 기록

브랜치 `improve-v16`, main `20a99c8` 기준. **A안 승인, 구현 진행.** 최종 수정: 기록 일수 제목·표시 열을 제거하며, 활동 이름 열을 조절하면 날짜 격자가 유동적으로 늘고 줄어 가로 스크롤을 만들지 않는다.

## 1. 항목을 지정 날짜로 복제

주간/데일리 항목의 기존 ⋯(손잡이 클릭·우클릭) 메뉴에서 **날짜로 복제…**를 ‘다른 날로 이동…’ 다음에 둔다. 겹친 사각형 모노그램과 텍스트를 함께 표시한다.

팝업 A: 원본 업무·날짜·항목 → 대상 날짜(내일/다음 주 같은 요일/달력 직접 입력) → 복제 범위·연결 안내 → [복제]. 복제 후 토스트에 [그 날짜로 이동]·[되돌리기]. 기본은 현재 화면 유지. 같은 날짜도 명시적 복제로 허용하고 기존 칸 끝에 추가한다. 원본 업무는 유지하며 다른 업무/공간 복제는 이번 범위 밖이다.

| 정보 | 추천 기본 규칙 |
|---|---|
| 본 항목 선택 | 딸린 하위 항목까지 함께 복제. 팝업에 개수 표시 |
| 하위 항목 선택 | 선택한 항목만 복제. 대상 부모가 모호하므로 독립 본 항목으로 생성하고 미리 안내 |
| 본문·링크 텍스트·중요 표시 | 보존. 완료 항목의 원래 중요 표시는 저장된 원래 상태를 참고 |
| 완료 상태 | 새 항목은 미완료. 완료 시각·취소 이력은 복제하지 않음 |
| 시작 시각 | 같은 시각 유지 |
| 마감일 | 원래 절대 날짜 유지, 팝업에 표시. 대상일보다 이른 경우 경고 안내하되 선택 가능. 날짜 차이만큼 자동 이동하지 않음 |
| 매주 반복 | 반복 규칙·recurrence ID는 복제하지 않음. 별도 일회성 항목 |
| 메모·Cabinet | 원본 객체 재사용, 새 항목 ID에 대한 연결만 추가. 원본 연결 유지 |
| 대상일이 휴일·업무 비활성 기간 | 휴일임을 표시. 업무가 대상 주에 표시될 수 없는 경우 원인과 업무 재활성 필요를 안내하고 실행 차단. 종료 이력을 묵시적으로 바꾸지 않음 |

복제 실행은 중복 클릭을 막는다. 선택한 원본이 삭제/변경되면 실행 전에 다시 읽고 변경된 범위를 보여 재검토한다. 수동 복제는 의도적 반복이므로 같은 문구라는 이유로 생략하지 않는다.

## 2. 같은 메모·Cabinet을 공유하는 연결

현재 확인: `NoteBox.refs`는 같은 주 entry ID를 담는 구조이며 `LINK_MAX=20`이다. `CabinetLink`는 원본 Cabinet item ID와 entry ID를 잇는다. `pullPrevious`의 `appendCopies`는 새 항목을 만든 뒤 셀을 저장하며 연결 재생성은 없다.

### 메모 추천 구조

다른 주의 대상 항목을 기존 `refs`에 단순 추가하면 기존 같은 주 검사/정리와 충돌할 수 있다. **주를 넘는 메모-항목 연결을 정규 관계로 관리하는 DB 구조 v15를 적용**했다(`0015_note_entry_link.sql`).

- `note_entry_link(note_week_id, box_id, entry_id, created_at)` 복합 고유 키, 양방향 조회 인덱스. 원본 객체 정체성은 `(공간 일지, 메모 소유 주차, box_id)`이다.
- 기존 refs를 마이그레이션해 관계 테이블을 정본으로 전환한다. 화면 어댑터로 기존 연결 띠/배지 API를 제공하며 JSON refs와 DB를 각각 쓰는 이중 정본은 금지한다.
- 텍스트·이미지·링크 메모 및 여러 객체 연결을 같은 규칙으로 지원한다. 원본 주간 메모 내용·이미지 asset·객체 위치·관계선은 복제하지 않는다.
- 대상 항목의 메모 배지에 **원본 주차**를 표시한다. 누르면 원본 주의 원본 객체를 연다. 대상 주 판에 같은 모양의 새 상자를 만들지 않는다.
- 원본 메모의 연결 띠에는 대상 날짜·업무·항목을 추가한다. 다른 주 항목으로도 이동 가능하며, 기존 많은 연결 접기 규칙을 적용한다.
- 같은 객체를 공유하므로 내용 수정은 모든 연결에서 같은 원문을 가리킨다. 연결 해제는 해당 관계만, 객체 삭제는 모든 관계를 정리한다. 항목 삭제는 그 항목 관계만 제거한다.
- 연결 20개 제한은 사전 계산한다. 초과가 있으면 해당 객체와 예상 연결 수를 안내하고 **전체 실행을 차단**한다. 일부 연결을 생략해 성공으로 보고하지 않는다. 제한 확대는 별도 검토 사항이다.
- 주간 요약·엑셀·검색·Universe·메모 내보내기·이미지 정리·원본 열기의 참조 조회를 모두 점검한다. 원본 주의 이미지가 참조되지 않는다고 오판해 삭제하지 않게 한다.

### Cabinet

기존 `cabinet_item`은 그대로 두고 원본에 직접 연결된 `cabinet_link`의 entry 관계만 새 entry ID로 추가한다. 동일 원본의 다중 링크는 한 번만 추가한다. 업무 전체에 연결된 Cabinet은 이미 같은 업무에서 보이므로 항목 전용 연결로 중복 생성하지 않는다. 폴더·URL·썸네일/파일 내용은 복사하지 않는다.

## 3. 이전 내역 가져오기에도 연결 유지

칸 하나·해당 요일 모든 업무·주간/데일리 진입 경로에 같은 복사 서비스를 사용한다.

- 기존 완료 제외 규칙 유지: 완료 부모와 하위 전체 제외, 완료 하위 제외.
- 실제로 새로 추가되는 항목에 대해 원본→새 ID 매핑을 만들고 메모·Cabinet 관계를 함께 생성한다.
- 기존 중복 건너뛰기 유지. 건너뛴 대상 항목의 연결을 임의로 덧붙이지 않으며 추가/건너뜀 수를 안내한다. 생성이 0건이면 연결도 변경하지 않는다.
- 기록·관계 생성은 한 트랜잭션으로 처리한다. 관계 실패/연결 한도 초과 시 항목도 남기지 않는다. 일괄 가져오기는 전체 단위를 한 번에 되돌린다.
- 원본/대상 주의 예약 저장을 먼저 정리하고 최신 관계만 패치한다. 화면에 남은 오래된 메모 문서가 DB 관계를 덮어쓰지 않도록 저장 경로를 통합한다.
- 되돌리기는 이번에 만든 항목과 관계만 제거한다. 다른 항목·공유 객체와 이후 편집을 전체 스냅샷으로 덮어쓰지 않는다. 이후 연결 변경과 충돌 시 범위를 재확인한다.
- 공간 전환·주 전환 중 지연 응답은 일지/문서 세대로 차단한다. 실패 시 원본·대상 모두 그대로 유지한다.

## 4. 업무 타임라인 업무 목록 너비

기존 목록은 272px 고정이다. **업무 목록 오른쪽 경계 드래그** A안을 제안한다. 기존 제목·검색·태그·업무 선택은 그대로 둔다.

기본272px, 최소200px, 최대480px를 기준으로 본문 최소440px를 남기도록 실제 창 크기에 따라 상한을 제한한다. 넓은/좁은 창 변경 시 저장값을 지우지 않고 적용 폭만 제한한다. 기존 좁은 창의 업무 선택 상자 전환은 유지한다.

손잡이는 8px 조작 영역과 가는 시각선, hover/focus 강조. 더블클릭은 기본 폭 복원. 키보드 separator의 좌우키 16px, Shift+좌우 32px, Home 기본 폭. `aria-valuemin/max/now`와 이름 제공. 공간별 UI 설정에 저장한다.

## 5. 활동 ‘모든 업무’ 열과 기록 일수

‘모든 업무 영역’은 **업무 이름 열 전체**로 해석한다. 모든 업무 합계 행과 각 업무 이름 행, 월/주 헤더가 공유하는 이름 열의 오른쪽 경계를 끌어 조절한다.

기본196px, 최소160px, 최대420px. 모든 행을 같은 CSS 열 정의로 갱신하며 날짜 칸은 남은 폭을 사용한다. 주말 비율은 유지하고 날짜 칸의 최소 폭을 0으로 두어 남은 폭에 유동적으로 맞춘다. 이름 열 조절로 가로 스크롤을 만들지 않는다. 창이 좁아지면 이름 열의 실제 적용 상한을 낮추어 격자 공간을 남기되 저장한 선호 폭은 유지한다. 타임라인 목록과 별도의 폭 설정을 저장하며 같은 키보드·초기화 규칙을 적용한다.

기록 일수 표시 최종안: 사용자 추가 요청으로 **기록 일수 제목과 모든 행의 일수 박스/열을 표시하지 않는다.** 해당 열의 예약 폭도 없애 이름 열을 제외한 가용 폭 전체를 날짜 격자에 사용한다. 활동 셀의 툴팁·표 보기에서 사용하는 기존 지표 계산은 유지한다.

## 6. 구현·검증 범위

1. DB v15 관계 모델·기존 refs 이전·버전 호환/이전 직전 백업·삭제/저장/조회 경로부터 확정한다. 예전 앱이 새 구조를 여는 경우 차단/복구 정책도 점검한다.
2. 단일 복사 서비스와 원본→대상 ID 매핑, 트랜잭션·되돌리기·연결 한도·중복·완료·반복 정책을 구현한다.
3. 주간/데일리 메뉴·날짜 팝업·피드백, 두 종류 폭 조절과 기록 일수 표시 열을 제거한다.
4. 같은 주/다른 주·연도 경계, 본/하위·완료·중복·기존 데이터/20개 한도·실패 롤백을 검증한다. 메모 수·asset 수·Cabinet item 수는 그대로, 관계 수만 늘어나는지 저장소에서 확인한다.
5. 공간3회 왕복·저장/취소/삭제/복원·메모 편집·원본 주 이동·검색/Universe/내보내기 회귀를 확인한다. 폭 조절은 세 테마·좁은/넓은 창·키보드·재실행 저장을 확인한다.
6. Feature List·버전 스냅샷·Excel·가이드·릴리스 노트 갱신. 버전은 구현/빌드 단계에서 확정하고 Windows 기본판+macOS를 함께 검증한다.

검토 포인트: 본/하위 복제 범위·상태/시각/마감일 정책, 원본 메모 공유와 다른 주로 이동하는 동작, 연결 한도 초과 전체 차단, 이름 열 너비와 기록 일수 표시 제거.

## 구현 기록 — 1.19.0-rc.1 / improve-v16

- 날짜 복제 팝업, 원본→신규 ID 매핑, 항목·관계 batch, 연결 제한 트리거와 실패 롤백, 새 항목만 되돌리기/다시 실행을 구현했다. 기존 대상 행의 내용·표시·마감일을 덮어쓰거나 지우지 않는다. 직전 기록 복제도 같은 서비스를 사용한다.
- 정규 연결을 마이그레이션하고 저장 기준과의 관계 차이만 패치한다. 현재 메모·실행 취소 문서에 외부 공유 관계만 병합한다. 객체/항목 삭제·가져오기 덮어쓰기·복원, Universe·인사이트·Markdown·PNG·엑셀 스냅샷의 조회를 갱신했다.
- 대상 배지의 W주차와 원본 전체 주차 툴팁, 원본 주 객체 열기, 원본 띠의 다른 날짜 항목 표시를 제공한다.
- 타임라인·활동 이름 열 경계 드래그/키보드/복원·공간별 설정을 구현했다. 활동의 이름 열 변화는 날짜 칸 폭으로 흡수한다. 기록 일수 제목과 표시 열은 최종 사용자 요청에 따라 제거했다.

- Feature List/Excel·스냅샷, 가이드 화면·HTML·PDF, 릴리스 노트 검사 통과. Windows/macOS 설치판 실기·WebKit은 이번 로컬 검증 범위 밖이며 설치 파일 빌드는 후속 요청 단계다.

### 추가 요청 — 기록 일수 표시 제거

기록 일수 제목·각 행 표시·예약 열 폭·관련 스타일과 표시 문구를 제거했다. 날짜 격자가 가용 폭을 채우며 기존 이름 열 조절/스크롤 없는 유동 배치를 유지한다. 활동/v16 Chromium E2E 14건, 정적 검사·웹 빌드·Feature List/Excel·가이드/릴리스 문서 검사를 확인했다.

## RC2 — CI 회귀 보완

RC1 웹 CI에서 구형 DB 번호를 고정한 백업 검사와 빈 refs 배열을 연결 유무로 오판하는 화면 회귀가 확인됐다. 연결 없음은 refs 필드 없음으로 정규화하며 세 종류 메모 화면 모두 실제 연결 수를 확인해 띠를 그린다. 항목 삭제 전에 메모 저장을 마쳐 실행 취소의 관계 스냅샷을 보존한다. 삭제 시 관계 정리·본문 유지라는 v16 설계에 맞춰 기존 회귀 검증을 갱신했다. 키보드만으로 메모에 진입하는 시나리오는 편집기 포커스를 확인한 후 입력한다.

백업·메모·5주 사용 흐름 Chromium E2E 19건, v16 단위 12건 통과. 이전 RC와 설치 파일을 구분하기 위해 1.19.0-rc.2로 갱신하며 일지 구조는 v15 그대로다.

RC2 로컬 최종 검증: 단위 498건·관련 Chromium E2E 37건·프로덕션 CSP 6건 통과. 포맷·lint·typecheck·웹 빌드·기능 목록/Excel·가이드·릴리스 문서 검사 통과.
