## F1. 검색

**목표**: 요일별 업무 기록과 메모 보드 내용을 한 번에 찾고, 결과로 바로 가며, [검색 초기화] 전까지 결과를 따라 이동한다.

- **여는 곳**: 상단 2줄 오른쪽 검색 칸(태그 필터 왼쪽) · `Ctrl+Shift+F`(어디서나) · 결과는 오른쪽 **검색 패널**(주간 요약 패널 자리, 폭 조절 가능 — improve-1101 #2와 같은 손잡이). 주간 요약과 동시에는 하나만.
- **대상**:
  | 영역 | 찾는 곳 | 표시 꼬리표 |
  |---|---|---|
  | 업무 기록 | `entry_item.text`(본 항목·세부) | `업무 기록` / `업무 기록 · 세부` |
  | 메모 · 글 상자 | 글 상자 본문(서식 뺀 글), 연결 띠는 제외 | `메모 · 글 상자` |
  | 메모 · 이미지 설명 | 이미지 상자 한 줄 설명 | `메모 · 이미지 설명` |
  | 메모 · 링크 카드 | 제목·메모·주소 | `메모 · 링크 카드` |
  | 메모 · 관계선 이름표 | 관계선 이름표 | `메모 · 관계선` |
  - 업무 이름·태그는 대상이 아님(태그 필터가 맡음) — 정할 것 #3.
- **찾는 규칙**: 띄어쓰기로 나눈 낱말이 **모두** 들어간 것(AND), 대소문자 무시, 한글은 그대로 부분 일치(형태소 분석 없음). 2글자 이상부터 찾기 시작(0.25초 쉬면 자동). 기간 필터: 전체·올해·최근 12주·직접 지정.
- **결과 목록**: 주(최근 주 먼저)로 묶고, 줄마다 꼬리표 + `업무명 · 날짜(요일)` 또는 `이번 주 메모 · 연결: …` + 찾은 낱말 형광 표시. 위쪽 칩으로 **전체 / 업무 기록 / 메모 보드** 거르기(개수 표시). 200건 넘으면 "더 보기".
- **바로가기**: 결과를 누르면 그 주로 이동 →
  - 업무 기록: 그 칸·그 항목에 커서 + 노란 테두리(데일리 뷰면 그 날 카드)
  - 메모: 메모 도크를 펼치고 그 상자로 화면을 옮겨 선택 + 테두리(접혀 있으면 펼침)
- **검색 결과 기준 보기(초기화 전까지 유지)**: 보드 위에 노란 띠 `🔍 '배치' 검색 결과 기준으로 보는 중 · ▲ 이전 3/10 ▼ 다음 · ✕ 검색 초기화`.
  - `F3`·`Enter`(검색 칸) = 다음, `Shift+F3` = 이전 — 주를 넘어 이동, 지금 결과는 패널에서도 강조.
  - 띠가 있는 동안 보드의 일치 칸에 옅은 노란 바탕(지금 결과는 진한 테두리).
  - 패널을 닫아도(`Esc`·✕) 띠는 남고, **[검색 초기화]**로만 끝난다. 앱을 다시 켜면 초기화.
- **구현**: `JournalRepository.search(query, range)` — 업무 기록은 SQL `LIKE`(낱말마다 AND, `ESCAPE` 처리), 메모는 `week_note.doc` JSON을 읽어 `domain/search.ts`(순수 함수)에서 글을 뽑아 일치. 1년치(항목 약 4,400개·52주 메모)에서 0.3초 안 목표(`perf:mem` 샘플로 측정). 새 표·인덱스 없음.
- **정할 것**
  | # | 정할 것 | 추천 |
  |---|---|---|
  | 1 | 결과 위치 | 오른쪽 패널(보드를 보며 이동) |
  | 2 | 단축키 | `Ctrl+Shift+F` 열기 · `F3`/`Shift+F3` 이동(인사이트 안의 `Ctrl+F`는 그대로) |
  | 3 | 업무 이름도 찾기 | 넣지 않음(태그 필터와 겹침) |
  | 4 | 일치 규칙 | 낱말 AND · 부분 일치 |
- **구현 기록(2026-11-01, 추천안 4건 승인)**
  - `domain/search.ts`(낱말·일치·형광 위치·줄임·메모 글 뽑기·정렬, 단위 테스트) · `JournalRepository.search(query, from?)`(업무 기록 SQL `LIKE … ESCAPE`, 메모 `week_note` JSON) — 결과 최대 300건(넘으면 안내).
  - `ui/search/` — 상단 검색 칸, 오른쪽 결과 패널(주간 요약과 자리 하나·폭 손잡이 공유·좁으면 겹쳐 뜸), 보드 위 노란 띠(`▲ n/N ▼`·[결과 목록]·[검색 초기화]), 강조는 `data-search-hit`·`data-search-current` 속성(보드 항목·메모 상자).
  - 기간 고르기: 전체·올해·최근 12주(직접 지정은 다음 단계).
  - 바로가기: 업무 기록 = `revealItem`(태그 필터로 숨은 업무면 필터 해제), 메모 = 그 주로 이동 후 `revealBox`. 인사이트·설정이 열려 있으면 닫고 보드로.
  - 예전 요일 메모(주간 메모로 아직 저장 안 된 주)는 찾지 않는다(상자 id가 없어 이동 불가).
  - E2E `search.spec.ts` 3건.

## F2. 휴일 설정(공휴일·기타 휴가)

**목표**: 지금의 "근무 상태(근무·연차·반차)"에 **공휴일**과 **기타 휴가(사유: 공가·야유회 등)**를 더한다.

- **고르는 곳**: 요일 머리 ⋯ 메뉴 · 데일리 뷰 [근무 ▾] — `근무 / 연차(종일) / 오전 반차 / 오후 반차 / ─ / 공휴일(이름) / 기타 휴가(사유)`.
  - 기타 휴가를 고르면 아래에 사유 칩(설정의 사유 목록) + [직접 입력]. 공휴일은 이름 입력(비우면 "공휴일").
- **보드 표시**: 요일 머리 배지 — 공휴일 = 붉은 계열 + 이름(`한글날`, `대체공휴일`), 기타 휴가 = 청록 계열 + 사유(`야유회`), 연차·반차 = 지금 그대로. 휴일 칸에도 기록은 쓸 수 있다.
- **다른 기능에 미치는 영향**: 무기록 알림·직전 기록 찾기·히트맵 "근무일"에서 휴일은 연차처럼 뺀다. 주간 요약·엑셀의 날짜 줄에 `(공휴일: 한글날)`·`(야유회)` 표기.
- **데이터(구조 변경 v8)**: 새 마이그레이션 `0008_day_mark_ext.sql` — `day_mark` 표를 새로 만들어 옮김(CHECK 조건 확장: `holiday`·`other` 추가) + `label TEXT`(공휴일 이름·휴가 사유). 직전 자동 백업 `_pre-migration-v8`, fixture 왕복 테스트. 사유 목록은 일지 설정 `holiday.reasons`(기본: 공가·야유회·경조사·교육·대체휴무).
- **정할 것**
  | # | 정할 것 | 추천 |
  |---|---|---|
  | 1 | 사유 기본 목록 | 공가·야유회·경조사·교육·대체휴무(설정에서 고침) |
  | 2 | 휴일 칸 기록 | 허용(막지 않음) |
  | 3 | 색 | 공휴일 붉은 계열 · 기타 휴가 청록 계열(세 테마 토큰) |

## F4. 메모 보드 → 마크다운 내보내기

**목표**: 주간 메모 보드를 다른 곳(위키·노트 앱·메일)에 옮길 수 있는 `.md` 문서로 내보낸다.

- **여는 곳**: 메모 머리 ⋯ › [마크다운으로 내보내기…] · 내보내기 창(엑셀)에도 "형식: 엑셀 / 마크다운" 고르기.
- **창**: 범위(이번 주 / 최근 4주 / 기간 지정) · 포함(연결된 업무 항목 `> 연결: …`, 관계선 목록, 체크 목록 `[x]`, 빈 주 제목) · 이미지(파일로 함께 저장 / 넣지 않음 — 설명만) · 파일 이름 · **미리보기** · [클립보드로 복사] [저장…].
- **변환 규칙**(`src/export/noteMarkdown.ts`, 순수 함수 + 골든 테스트):
  - 주 = `# 2026-W43 이번 주 메모 (10/19~10/25)`, 상자 = `##` + 첫 줄(글 상자)·`이미지 — 설명`·`링크 — 제목`. 상자 순서 = 보드 위→아래, 왼→오른쪽.
  - 서식: 굵게 `**`·기울임 `*`·취소선 `~~`·목록 `-`·번호 `1.`·체크 `- [ ]`·제목 `###`·링크 `[글](주소)` · 글자 크기·색·형광펜은 버림.

## F5. Cabinet — 자주 쓰는 작업 폴더·링크

> **2026-11-01 보완(사용자 아이디어)** — 시안 [f5b-cabinet.png](mockups/1102/f5b-cabinet.png)
> - 업무별로 **폴더 외에 관련 링크**도 끌어 놓기로 등록. 업무 안에서 **[전체 · 📁 폴더 · 🔗 링크]**로 나눠 보거나 함께 보기, 제목 앞 아이콘으로 구분(📁 폴더 / 🔗 링크).
> - 링크를 놓으면 **링크 등록** 창: 제목(기본 = 브라우저가 끌어 놓을 때 함께 주는 페이지 제목) · 주소 · 업무/항목 연결 → `Enter` 등록. 제목은 등록할 때, 또는 나중에 ⋯ › 제목 고치기(`F2`)로 언제든 바꾼다.
> - 링크를 누르면 OS 기본 브라우저(지금의 링크 열기 규칙 — 앱은 접속하지 않음). 검색(F1) 대상에도 Cabinet 제목·주소를 더할 수 있음(정할 것 #7).
> - **기본 제목과 외부 통신 0**: 앱이 그 주소에 접속해 제목을 읽어 오면 외부 통신이 생긴다(규칙 4-1, 링크 카드 B안을 하지 않은 것과 같은 이유). 그래서 **끌어 놓을 때 브라우저가 넘겨주는 정보만** 쓴다 — 주소창·탭·페이지 안 링크를 끌면 대개 제목(또는 링크 글자)이 함께 온다. 없으면 주소에서 만든 이름(`wiki.example.com › batch-ops`)으로 채우고, 창에서 바로 고친다. Edge의 [링크 복사](친숙한 형식)를 [+ 링크…]에 붙여 넣어도 제목이 함께 들어온다.
> - **끌어 놓기 기술 제약**: 윈도우 웹뷰(WebView2)는 창 하나에서 "탐색기 폴더 경로를 받는 방식"(Tauri 끌어 놓기)과 "브라우저 링크를 받는 방식"(웹 표준 끌어 놓기)을 **동시에 켤 수 없다**. 
>   - A안(추천): Cabinet 창은 웹 표준 끌어 놓기로 둘 다 받고, 폴더는 WebView2의 "놓은 파일을 앱에 넘기기"(`postMessageWithAdditionalObjects` → 경로) 기능으로 경로를 얻는다 — 놓는 자리 하나로 폴더·링크 모두. Rust 쪽 WebView2 연동 코드가 필요하고 회사 PC에서만 확인 가능 → 먼저 작은 시험판으로 확인.
>   - B안(대비책): A안이 안 되면 폴더는 Cabinet 창 끌어 놓기(Tauri), 링크는 [+ 링크…] 붙여넣기와 메인 창(보드 업무 머리)으로 끌어 놓기.


**목표**: 업무별로 자주 여는 폴더를 등록해 두고, 앱 안에서 **여러 폴더를 동시에(모달리스)** 열어 파일을 찾고 기본 앱으로 연다.

- **위치**: 소개 사이트 `site/guide/index.html`(사이트 머리 메뉴 [이용 가이드] + 내려받기 아래 링크), PDF = `site/guide/work-journey-board-guide.pdf`(같은 HTML을 Playwright 인쇄로 생성 — 인쇄용 CSS로 쪽 나눔·목차 쪽번호). 앱 설정 › 업데이트·정보에 [이용 가이드 ↗](OS 브라우저).
- **원본·생성**: 원본 = `docs/guide/*.md`(장면별 1파일) → `scripts/guide/build.mjs`가 HTML·PDF 생성, 스크린샷 = 브라우저 모드 `?sample=showcase`로 자동 촬영(`scripts/guide/shots.mjs`). 가이드 머리에 "vX.Y 기준 · 갱신일".
- **갱신 규칙(운영)**:
  1. `docs/guide/map.md` = **기능 ↔ 장면** 대응표(예: 데일리 뷰 → 2·3장, 검색 → 9장).
  2. 화면·동작이 바뀌는 작업은 같은 작업 안에서 해당 장면 글·스크린샷을 고친다(CLAUDE.md 6절 "문서 동반 갱신"에 가이드 추가).
  3. 판올림 때 릴리스 노트에 `## 가이드` 줄(바뀐 장면 또는 "변경 없음") — `release-notes.mjs check`가 누락을 막고, main 배포 때 사이트(HTML·PDF)를 함께 다시 만든다.
  4. CI: 가이드 링크·스크린샷 파일이 있는지 검사(`guide.mjs check`).
