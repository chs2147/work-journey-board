## 1. 관문(Gate) 정의

### ◆G1 — 설치 검증 판정 (I-M0 직후)
| 결과 | 판정 | 후속 |
|---|---|---|
| per-user 설치 성공 + 실행됨 + WebView2 있음 | **GO (Tauri 확정)** | D2는 SQLite 파일 저장으로 진행 |
| SmartScreen/백신 차단, IT 허용 목록 등록 가능 | **조건부 GO** | IT 요청 병행, 등록 전까지 개발은 진행 |
| 설치·실행 불가, 허용 목록 등록도 불가 | **대안 전환** | 브라우저 전용(Chrome + IndexedDB + File System Access) 구조로 D2 재작성 |

### ◆G2 — 실사용 검증 (I-M1 직후 2주)
- 실제 업무에 **2주(10영업일) 연속** 사용.
- 판정 기준: ① 하루 기록에 **2분 이내** ② 이월·카테고리 관리에 불편 없음 ③ 기록을 거르게 만드는 마찰 지점 목록화.
- 마찰이 크면 M2로 가기 전에 입력 UX를 먼저 고친다. **입력이 귀찮으면 산출물은 의미가 없다.**

## 2. 설계 트랙 (본 논의 공간)

### D1. 화면 구성·와이어프레임
**목표**: 매일 쓰는 화면을 "열자마자 오늘 칸에 바로 적는" 수준으로 구체화.

**결정할 것**
1. **주간 보드 기본 배치** — 후보 비교 후 택1
   - (a) 격자: 행=업무 카테고리, 열=월~일 (한 주 전체가 한눈에, 셀이 좁음)
   - (b) 오늘 집중: 오늘 요일을 넓게 펼치고 나머지 요일은 접힘 (입력은 편함, 주 전체 조망은 약함)
   - (c) 혼합: 격자 + 선택한 셀을 넓은 편집 패널로 엶
2. **이동(네비게이션)** — 이전/다음 주, "오늘로" 버튼, 연간 보기(52~53주 미니맵)에서 주 선택
3. **개조식 입력 방식** — Enter=새 항목, 들여쓰기 깊이(1단 고정 vs 2단 허용), 항목 순서 바꾸기, 붙여넣기 시 줄 단위 분해 여부
4. **카테고리 관리** — 추가·이름 변경·색·순서·종료·재활성 위치, **3주 무기록 종료 제안**을 보여주는 방식(배너 / 카테고리 옆 표시)
5. **일일 메모 위치** — 요일 열 하단 / 별도 영역
6. **주말 표시** — 토·일 좁은 열, 기록이 있으면 자동으로 넓힘 여부
7. **주간 요약 패널** — 보드 옆 패널 / 별도 탭, 자동 집계본·AI본·수정본 전환
8. **첫 실행 흐름** — 저장 폴더 선택(OneDrive 경고 포함) → 첫 카테고리 만들기

**산출물**: `docs/wireframe-weekly-board.svg`(주간 보드), 필요 시 `wireframe-*.svg` 추가, README에 "화면 구성" 절 추가.
**완료 기준**: 위 8개 결정 모두 확정 + 주간 보드 와이어프레임 1장 이상.

**시작 프롬프트**
```
my-discussions 저장소 10번 주제(업무 일지 보드)의 D1 작업을 진행하자.
docs/README.md 와 project-plan.md 의 D1 항목을 먼저 읽고,
주간 보드 배치 후보 (a)격자 (b)오늘 집중 (c)혼합을 비교해 추천해줘.
이후 D1의 8개 결정 항목을 순서대로 확정하고, 확정되면 와이어프레임 SVG를
같은 디렉토리에 만들고 README에 "화면 구성" 절로 반영해줘.
```

### D2. 데이터 상세 스펙
**목표**: 구현자가 그대로 테이블을 만들 수 있는 수준의 스키마와 규칙.

**결정할 것**
1. **주차 규칙** — ISO 8601(월요일 시작, 1월 4일이 포함된 주가 1주차) 채택 여부, 연말·연초 경계 주(53주차) 처리, 보드 제목 표기(예 `2026-W43 (10/19~10/25)`)
2. **개조식 항목 저장 형식** — 항목 1개 = 1행(순서 번호 보유) vs 하루치 텍스트 블록
   - 1행 방식이 엑셀 원장·경과 타임라인에 유리(잠정 추천)
3. **테이블 정의** — 컬럼·타입·제약·인덱스
   - `category`(id, name, color, sort_order, created_at, archived_at)
   - `entry_item`(id, date, category_id, seq, depth, text, created_at, updated_at)
   - `day_memo`(date, text, updated_at)
   - `weekly_summary`(week_id, auto_text, ai_text, edited_text, generated_at, updated_at)
   - `app_meta`(schema_version, settings JSON)
4. **카테고리 활성 계산** — 주 W에 보일 카테고리 = `created_at ≤ W 종료일` 그리고 (`archived_at` 없음 또는 `archived_at ≥ W 시작일`) — 경계 조건 확정
5. **3주 무기록 판정** — "무기록 주"의 정의(그 주에 해당 카테고리 항목 0개), 생성 직후 카테고리 유예, 무시하기 선택 시 재제안 주기
6. **삭제 정책** — 카테고리는 아카이브만, 항목은 실삭제 허용 여부(되돌리기 범위)
7. **백업·이전** — 롤링 백업 개수(예 최근 14일+월 1개), 백업 파일명 규칙, `schema_version` 기반 마이그레이션 원칙
8. **G1 대안 전환 시** — IndexedDB + 파일 저장 매핑(같은 논리 모델 유지)

**산출물**: `docs/data-spec.md`
**완료 기준**: 스키마 SQL 초안 + 위 8개 규칙 확정.

**시작 프롬프트**
```
my-discussions 저장소 10번 주제(업무 일지 보드)의 D2 작업을 진행하자.
README.md(특히 5-2·7-3절)와 project-plan.md의 D2 항목을 읽고,
주차 규칙·항목 저장 형식·테이블 정의·카테고리 활성 계산·3주 무기록 판정·
삭제 정책·백업 규칙을 하나씩 확정해줘. (I-M0 결과가 있으면 반영)
결과는 같은 디렉토리 data-spec.md로 작성하고 README에 링크해줘.
```

### D3. 산출물 스펙 (주간 자동 집계·엑셀·AI 지시문)
**목표**: 손으로 쓴 기록이 어떤 모양의 결과물로 나오는지 고정.

**결정할 것**
1. **주간 자동 집계 포맷** — 업무별 묶음 → 요일순 항목 나열, 무기록 업무 표시 여부, 일일 메모 포함 여부, 텍스트 형식(개조식 그대로 / 요일 태그 부착)
2. **엑셀 양식 상세**
   - 주간보고 시트: 주차 블록 머리글, 열 구성(업무 | 월~금 | (토·일: 기록 있을 때만) | 주간 요약), 셀 안 개조식 줄바꿈, 열 너비·글꼴·테두리
   - 원장 시트: `날짜 | 주차 | 요일 | 업무 | 순번 | 내용`, 필터 설정
   - 주간 요약 열에 넣을 본(수정본 > AI본 > 자동 집계본 우선순위)
3. **내보내기 UX** — 범위 선택(이번 주 / 지정 기간 / 전체), 파일명 규칙(예 `업무일지_2026-W40~W43.xlsx`), 저장 위치
4. **AI 클립보드 지시문 템플릿** — 역할·톤(보고서체)·분량·형식 지시, 기록 삽입 위치, 결과 붙여넣기 화면

**산출물**: `docs/output-spec.md` + 엑셀 양식 예시(표 또는 샘플 파일)
**완료 기준**: 샘플 주 1개를 기준으로 집계본·엑셀 2시트·AI 지시문 예시가 모두 완성.

**시작 프롬프트**
```
my-discussions 저장소 10번 주제(업무 일지 보드)의 D3 작업을 진행하자.

### D4. 시각화 스펙
**목표**: 정성적 관리에 맞는 4개 시각화를 데이터→화면 매핑까지 고정.

**결정할 것**
1. **업무별 경과 타임라인**⭐ — 세로 시간축(주차) × 항목 텍스트, 업무 선택 방식, 긴 기간 접기
2. **활동 히트맵** — 행=업무, 열=날짜, 칸 밀도=그날 항목 수, 기간 단위(최근 12주 / 연간)
3. **업무 기간 막대** — 생성~종료(진행 중이면 오늘까지), 실제 기록 구간 강조
4. **주별 업무 비중** — 주마다 업무별 "기록한 날 수" 누적 막대(시간 투입이 아니라 기록 일수임을 명시)
5. **공통** — 기간·업무 필터, 화면 배치(대시보드 1장 / 탭), 아카이브 업무 포함 토글
6. **차트 구현 방식** — 라이브러리 후보(구현 단계 확정용 메모)

**산출물**: `docs/viz-spec.md` + `wireframe-insights.svg`
**완료 기준**: 4개 차트 각각 입력 데이터·축·인터랙션 정의 + 대시보드 와이어프레임.

**시작 프롬프트**
```

경과 타임라인·활동 히트맵·기간 막대·주별 비중 4개 시각화의 데이터 매핑과

### D5. 이관 패키지
**목표**: 구현 저장소가 첫날부터 일할 수 있게 넘길 것을 묶고, 본 주제를 종결.

3. **구현 저장소 CLAUDE.md 초안** — 8번 주제 공통 규칙(`topics/8 common-vibe-coding-rules/common-claude-rules.md`) 반영 + 이 프로젝트 고유 규칙(외부 통신 0 원칙, 데이터 파일 안전 등)
