## 3. 승인된 A안의 수정 시안

사용자 피드백: 위치 A안 채택. 세 버튼 앞 모노그램 아이콘, 별도 업무명/태그 온보딩 팝업, 하단 추가 행 제거 후 보드·메모의 경계 밀착.

### 3-1. 상단 세 버튼

- 태그 필터 옆에 `[사각형 안 +] 업무 추가` → `[문서·목록] 주간 요약` → `[아래 화살표·받침] 내보내기`.
- 모노그램은 기존 앱과 맞는 단색 선형 SVG 아이콘으로 제안한다. 크기 16~18px, 동일한 선 굵기, 글자 앞 6~8px 간격. 이모지·글자만의 약자는 사용하지 않는다.
- 버튼명은 유지하며 아이콘은 보조 표식이다. 좁은 화면에서 글자가 사라지거나 잘리지 않도록 기존 반응형 배치를 확인한다.
- 주간/데일리의 같은 위치에서 사용한다. 새 단축키는 추가하지 않는다.

### 3-2. 한 화면에서 끝나는 온보딩 팝업

- 중앙 모달 460px 기준(좁은 창에서는 여백을 둔 전체 폭), 제목 `업무 추가`, 보조 정보 `현재 워크스페이스 · 현재 주에 추가합니다`.
- `01 업무 이름`: 필수, 처음 열면 자동 포커스, 현재 규칙(최대 40자·공백·중복 검사) 재사용.
- `02 태그`: 선택, 기존 태그 칩을 여러 개 선택/해제. 태그 없이도 만들 수 있다. 많으면 태그 영역 스크롤과 검색을 제공한다.
- `새 태그 이름` 입력 + `+ 태그 추가`: 새 태그를 임시 선택 칩으로 쌓고 ×로 제거. 이미 있는 이름은 중복 생성하지 않고 기존 태그를 선택한다. 태그 이름 검증은 기존 규칙 재사용.
- 하단 `취소` · `추가하고 계속` · 주 버튼 `업무 추가`.
- `업무 추가`: 저장 성공 후 닫고 새 업무를 보여 준다. `추가하고 계속`: 이름만 비우고 태그를 유지해 연속 생성한다. 저장 후 새 태그는 기존 태그로 승격한다.
- 새 태그는 입력 단계에서 DB에 저장하지 않는다. 업무 생성 + 신규 태그 + 연결은 한 트랜잭션으로 확정한다. 취소/실패 시 업무나 태그 일부만 남지 않도록 한다. `JournalRepository.createCategory`의 선택 옵션으로 트랜잭션을 확장하고 UI에서는 원래 주·저장소와 취소 신호를 확인한다.
- 업무명에서 Enter는 제출, 새 태그 입력의 Enter는 태그 준비만 한다. 한글 조합 중 Enter 오작동 방지. 포커스 트랩·Esc 취소·닫은 뒤 원래 버튼으로 포커스 복원. 입력 중 바깥 클릭은 닫지 않는다.
- 현재 태그 필터가 있으면 대응 태그를 초기 선택한다. 사용자가 빼서 새 업무가 필터 밖에 생기면 저장 후 필터를 해제해 새 업무를 보여 주고 안내한다(수정 시안 제안).
- 저장 중 중복 제출 금지, 오류 시 입력 보존. 주/워크스페이스 전환 시 팝업을 닫고 늦은 결과가 다른 일지에 쓰이지 않게 기존 전환 대기/트랜잭션 경로와 연결한다.

### 3-3. 보드와 메모의 경계

- 기존 하단 `+ 업무 추가` 행과 그 행 전용 패딩/최소 높이를 제거한다.
- 자동 높이에서는 마지막 업무 행 아래와 메모 상단 경계가 공백 없이 맞닿는다. 이중 테두리는 1px로 합친다.
- 보드·메모 높이 조절 기능은 유지한다. 별도 8px 장식 행 대신 경계선 위에 투명한 8px 잡기 영역과 포커스 표시를 두는 안을 제안한다. 메모 툴바·카드 입력을 가리지 않게 한다.
- 수동 높이 모드에서는 사용자가 지정한 비율을 보존하며, 추가 행 제거 때문에 빈 장식 공간이 생기지 않게 확인한다. 보드 내용이 넘치면 기존 스크롤을 유지한다.
- 빈 보드 안내의 ‘아래 업무 추가’ 문구도 상단 버튼 기준으로 수정한다.

## 4. 마감일 목록

- 날짜 머리줄: `[D-day 칩] 11/7 (토)`; 오른쪽 개수는 삭제한다.
- 지남: 연한 빨강 + 진한 빨강 글씨, `2일 지남`.
- 오늘: 진한 주황 + 밝은 글씨, `오늘 마감`.
- 1~7일: 연한 황토 + 짙은 글씨, `D-3`.
- 8일 이상: 중립색 배경 + 본문 대비 글씨, `D-14`.
- 테마 토큰을 사용해 다크에서도 읽히게 한다. 기존 날짜 정렬·날짜별 묶음·날짜 표기·항목명·완료 동작은 유지한다.
- 실제 날짜는 칩 옆에 항상 표시한다. 색만으로 구분하지 않는다. 목록 항목마다 중복 D-day 칩을 추가하지 않는다.
- 날짜별 개수와 ‘마감일이 있는 업무’ 제목 총개수를 제거한다. 다른 묶음과 레일 배지는 유지한다(추천안 승인).

## 5. 메모 글자색

- 기존 글자색 select를 `A + 현재 색 밑줄 + 글자색` 버튼으로 교체하고 6색 팔레트 표시.
- 기존 `TextColor` mark, `TEXT_COLORS`, 테마별 CSS 클래스를 그대로 사용한다. 새 라이브러리·DB 마이그레이션은 필요하지 않을 것으로 예상한다.
- 텍스트 선택이 있으면 선택 범위만 변경한다. 커서만 있으면 이후 입력의 색을 바꾼다. 비편집 상태에서는 편집 진입 안내를 표시하고 전체 메모의 색을 임의로 바꾸지 않는다.
- 기본색은 mark 제거. 현재 색 체크, 혼합 선택은 ‘여러 색’ 표시, 닫은 후 편집기 선택 범위·포커스 복원.
- 툴팁에 색 이름, 방향키·Enter·Esc, 명확한 포커스 표시를 제공한다.
- 현재 메모 편집 도구는 편집 시 나타나므로 실제 구현 때 선택/편집 상태에서 버튼 발견성을 함께 확인한다.
- CSP는 기존 클래스 방식으로 유지(인라인 스타일 추가 없음). 저장·다시 열기·되돌리기·스냅샷/PNG의 색 보존 확인.
- Markdown 내보내기는 순수 Markdown의 색 미지원 정책을 유지한다. 임의 HEX는 별도 승인 대상이다.

## 6. Markdown 드롭 → 새 텍스트 메모

### 사용자 흐름

1. 메모 보드에 `.md`/`.markdown` 파일을 드롭한다. 편집 중인 메모 위에 놓아도 새 텍스트 메모로 만든다.
2. 드롭 위치(배율·스크롤 좌표 반영)에 파일당 1개의 메모를 배치한다. 여러 파일은 약간씩 어긋나게 배치한다.
3. 파일 내용을 읽고 서식을 제거해 텍스트를 추출하되, http/https URL은 기존 메모의 링크 텍스트로 제공한다. 파일 경로나 이름을 본문에 자동 삽입하지 않는다.
4. `텍스트 메모 N개를 만들었습니다 · 이미지/첨부 데이터 제외` 및 되돌리기 제공. 실제 제외가 없으면 제외 문구를 생략한다.

### 추출 기준 제안

| 원본 | 텍스트 메모 |
|---|---|
| 제목·강조·목록·인용 | 기호를 정리하고 글/문단/줄바꿈 보존 |
| 코드 블록 | 코드 텍스트 보존, 코드 실행·서식 없음 |
| `[제목](https://주소)` | 제목을 표시하고 URL을 기존 TipTap link mark로 연결. 주소를 괄호로 중복 표기하지 않음 |
| URL 단독·자동 링크·참조형 링크 | http/https 주소를 해석해 기존 링크 mark 제공. 단독 URL은 주소 자체를 링크 텍스트로 표시 |
| 이미지 Markdown·HTML img | 이미지/첨부 데이터 제외; 사람이 쓴 대체 텍스트는 있으면 보존 |
| data URI, base64 첨부 블록·연속 페이로드 | 본문에서 제외. 디코딩·저장하지 않음 |
| 참조형 이미지와 정의 | 이미지 데이터/경로 제외; 필요한 대체 텍스트만 보존 |
| HTML | script/style 등 비본문 요소 제외; 보이는 본문은 글로 추출. HTML 실행·렌더링 없음 |
| YAML front matter | 메타데이터는 제외 |
| 표 | 행·열 텍스트를 줄/탭으로 보존 |

- 짧은 영문/숫자·일반 식별자·URL을 ‘base64처럼 보인다’는 이유로 삭제하지 않는다. 명확한 data URI·첨부 구조와 충분히 긴 연속 인코딩 블록을 구분하고 회귀 사례로 검증한다. 정확한 길이/판정 기준은 파서 설계에서 명시한다.
- 모든 내용을 제거한 파일은 빈 상자를 만들지 않고 `가져올 텍스트가 없습니다` 안내.
- 잘못된 인코딩·너무 큰 파일·미지원 파일은 파일별 건너뛰기와 사유 안내. 나머지는 계속 처리한다.
- ‘순수 텍스트’는 제목·강조·목록 등 Markdown 서식을 적용하지 않는 뜻이다. URL 링크 mark는 사용자 요청에 따른 예외이며 기존 Ctrl+클릭·↗ 열기 방식을 유지한다. 위험 스킴은 링크로 만들지 않고 기존 http/https 검증을 재사용한다.
- Markdown 내용에서 외부 파일, 상대 경로 이미지, 링크·스크립트·플러그인·네트워크 요청을 가져오는 동안 실행하지 않는다. 링크는 사용자가 기존 방식으로 열 때만 OS 브라우저로 넘긴다. 원본 파일은 변경하지 않는다.
- 이미지 파일/링크/업무 항목 드롭은 기존 경로 유지. 확장자에 따라 정확히 분기하고 드롭 중복 처리 방지.
- 브라우저 `File.text()`/`arrayBuffer()`를 우선 검증하고 Windows WebView2·macOS 실제 파일 드롭에서도 동작 확인. 네이티브 읽기가 필요하면 사용자가 드롭한 파일만 읽는 최소 플랫폼 경로를 설계한다(임의 경로 읽기 추가 금지).
- 비동기 읽기 중 주/워크스페이스 전환 시 원래 대상 일지·주를 확인하고 결과를 취소한다. 바뀐 일지에 쓰거나 이전 일지 메모를 연결하지 않는다.

## 7. 승인 후 구현 순서

1. D1 위치 및 D2~D7은 승인됨. 업무 추가 팝업·아이콘·보드/메모 경계 수정 시안 승인에 따라 구현. 기존 디자인 v2 직선 규칙 유지.
2. 마감일 개수/칩 정리 → A안으로 업무 추가 이동 및 업무/태그 팝업(원자적 저장·취소 보장).
3. 글자색 선택기를 팔레트로 개선(선택·키보드·CSP·기존 색 보존).

5. 기능별 테스트 및 가이드 장면 02·04·05·07 갱신, 화면 이미지·HTML·PDF 재생성.
6. 검증 결과 보고. 판올림/커밋/푸시/병합은 해당 단계에서 요청에 따라 진행.

## 9. 구현 기록

- 업무·신규 태그·연결을 단일 `SqlDriver.batch`로 처리한다. `flushAll`은 진행 중인 업무 생성을 기다리고, 팝업은 주/공간 전환 시 취소된다.
- `AddCategoryDialog`는 별도 상태 저장소를 만들지 않고 기존 보드의 `addOpen`을 사용한다. 새 태그는 확정 전까지 컴포넌트 안에서만 보관한다.
- `mdast-util-from-markdown` + GFM 확장과 `htmlparser2`를 버전 고정해 사용한다. 문자열을 구문 분석하는 라이브러리로 런타임 외부 통신·스크립트 실행 없음. 메모 드롭 시에만 지연 로드한다. 이미지/링크의 기존 드롭 경로는 유지한다.
- 명시적 data URI를 제거하고, 표시가 없는 연속 base64는 혼합 대소문자·숫자/기호 조건 및 한 줄 256자 이상 또는 3줄 이상(각 40자 이상, 총 128자 이상)일 때 첨부로 판단한다. 짧은 식별자는 보존한다.
- Markdown 읽기 전의 저장소·주·세대 번호를 함께 기억해 같은 주로 돌아온 경우에도 오래된 결과를 버린다. Ctrl+Z는 한 드롭을 한 단계로 취소하며 토스트의 되돌리기는 그때 생성한 상자만 제거한다.
- 태그/업무 저장 실패의 전체 롤백, 링크/서식/첨부/HTML 추출 단위 테스트를 추가했다. 공간 3회 왕복 및 파일 읽기 지연 중 전환 시나리오를 기존 무결성 E2E에 추가했다.
- 버전은 1.13.1로 유지한다. main 병합/판올림/배포는 별도 단계이며 이 작업은 기능 브랜치 커밋·푸시까지다.
