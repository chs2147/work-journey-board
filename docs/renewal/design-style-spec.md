**적용 범위:** 색상, 서체, 간격, 외형, 컴포넌트 상태, 아이콘, 모션

## 1. 목적과 적용 원칙

마지막 베이지 톤 시안의 ‘정돈된 워크스페이스’를 기준으로 한다. 따뜻한 종이색, 짙은 웜그레이 글자, 절제된 브라운 포인트, 고운돋움의 부드러운 인상을 하나의 스타일 체계로 사용한다.

이 문서는 화면 구조를 정하지 않는다. 메뉴 위치, 영역 순서, 패널 배치, 열 개수와 폭, 화면 분할 비율, 화면별 구성, 반응형 전환 방식은 별도 설계에서 결정한다. 아래 규칙은 어떤 구성에도 적용할 수 있는 시각 스타일 명세다.

### 핵심 원칙

1. **본문이 먼저 읽힌다.** 실제 기록은 짙은 색으로 표시하고, 테두리와 장식의 대비는 낮춘다.
2. **여백과 면으로 구분한다.** 영역을 나눌 때 간격 → 미세한 배경 차이 → 필요한 구분선 순으로 적용한다.
3. **아웃라인은 얇고 조용하게 둔다.** 모든 요소에 테두리와 그림자를 함께 적용하지 않는다.
4. **베이지의 농도로 위계를 만든다.** 크림색 기록면, 옅은 베이지 보조 면, 샌드색 선택 면을 구분한다.
5. **색에는 역할이 있다.** 브라운은 상호작용, 구리색은 브랜드 포인트, 의미색은 상태 전달에 사용한다.
6. **편집과 키보드 포커스는 분명하게 보여준다.** 평상시 테두리를 줄이는 원칙과 조작 중 포커스 표시는 구분한다.

### 수치의 기준

- 주요 색상과 서체는 마지막 시안에서 가져왔다.
- 간격·서체 크기·모서리는 재사용을 위해 제한된 단계로 정규화했다. 시안의 모든 개별 수치를 그대로 복제하는 문서는 아니다.
- 시안에 충분히 드러나지 않은 경고·오류·비활성 등의 상태는 같은 색감으로 보완했다.
- 보조 글자의 대비가 낮아지는 배경에는 더 짙은 보조색을 사용한다. 색 조합은 9절에 명시한다.

**사용 규칙**

- 본문을 순수 검정으로 바꾸지 않는다. `--text-primary`를 기본으로 한다.
- 기본 화면에서 순수 흰색과 차가운 청회색을 새로 섞지 않는다.
- `--brand-copper`와 `--warm-marker`는 작은 일반 본문에 사용하지 않는다. 장식과 의미 표식에 제한한다.
- 보조 글자가 선택 배경이나 베이지 면 위에 놓이면 `--text-secondary-strong`을 사용한다.
- 업무별 구분색은 기존 카테고리 팔레트를 유지할 수 있다. 브라운으로 모두 통일하지 않는다. 이름 옆 점·작은 표시 등 제한된 면적에서 사용한다.
- 색만으로 중요·선택·오류를 전달하지 않는다. 이름, 아이콘, 모양 중 하나를 함께 사용한다.

### 2.3 구분선

| 토큰 | 색상 | 용도 |
|---|---|---|
| `--border-subtle` | `#F1EBE1` | 반복되는 내부 구분선 |
| `--border-default` | `#E9E1D5` | 필요한 구조 경계 |
| `--border-chrome` | `#EEE5D8` | 보조 면 사이의 옅은 경계 |
| `--border-frame` | `#E8DFD1` | 독립 표면의 외곽선이 필요한 경우 |
| `--border-selected` | `#D6C3AA` | 선택된 항목의 얇은 보조선 |

선은 기본 `1px solid`다. 구분선이 먼저 보일 정도로 진하게 만들지 않는다. 반복되는 셀마다 강한 외곽선을 두르거나 이중 테두리를 만들지 않는다. 접근 가능한 입력 경계나 포커스가 필요한 곳에 장식용 옅은 선을 대신 사용하지 않는다.

### 2.4 의미색 — 보완 규칙

| 상태 | 글자·아이콘 | 옅은 배경 | 사용 |
|---|---|---|---|
| 성공 | `#526847` | `#EEF1E7` | 저장 성공·처리 완료 |
| 주의 | `#806031` | `#F6EEDC` | 확인이 필요한 상황 |
| 오류·삭제 | `#A94F42` | `#F8ECE6` | 저장 실패·파괴적 동작 |

평상시 모든 상태를 컬러 배지로 표시하지 않는다. 성공 상태는 보조 글자와 작은 아이콘으로 충분할 수 있다. 오류는 짧은 문구로 원인 또는 다음 행동이 읽혀야 한다.

## 3. 타이포그래피

### 3.1 기본 서체

**고운돋움 / Gowun Dodum Regular, weight 400**을 한글 본문, 입력, 메뉴, 버튼, 보조 레이블에 공통 적용한다.

```css
font-family: "Gowun Dodum", "Malgun Gothic", "맑은 고딕", sans-serif;
font-weight: 400;
font-synthesis: none;
```

- 고운돋움의 기본 굵기를 사용한다. 임의로 600·700을 지정해 가짜 볼드를 만들지 않는다.
- 위계는 글자 크기, 색, 간격으로 만든다.
- 제목을 강조하려고 외곽선, 텍스트 그림자, 과한 자간을 추가하지 않는다.
- 버튼·입력 요소가 OS 기본 글꼴로 돌아가지 않도록 서체를 상속한다.

### 3.2 크기와 줄 높이

| 역할 | 크기 | 줄 높이 | 굵기 |
|---|---:|---:|---:|
| 대표 제목 | 20px | 1.5 | 400 |
| 섹션 제목 | 16px | 1.6 | 400 |
| 기본 UI·버튼 | 14px | 1.6 | 400 |
| 기록·편집 본문 | 14px | 1.75 | 400 |
| 메모·부연 본문 | 13px | 1.8 | 400 |
| 태그·날짜·보조 레이블 | 12px | 1.7 | 400 |
| 짧은 비핵심 메타데이터 | 11px | 1.6 | 400 |

11px는 비핵심 메타데이터에만 제한한다. 실제 기록·버튼 이름·중요 안내를 11px로 줄이지 않는다. 큰 글자 설정에서는 본문을 15px 이상으로 확대할 수 있고, 간격과 컨트롤도 함께 늘린다. 작은 화면에 맞추려고 본문 크기를 축소하지 않는다.

### 3.3 한글과 숫자

- 본문 자간은 `0`을 기본으로 한다. 제목에만 `-0.02em` 이내의 미세한 조정을 허용한다.
- 한글은 `word-break: keep-all`을 기본으로 하고 긴 URL·끊어지지 않는 문자열에는 `overflow-wrap: anywhere`를 적용한다.
- 입력과 읽기 상태의 글꼴, 크기, 줄 높이, 안쪽 여백을 같게 유지한다.
- 날짜·주차·개수처럼 자릿수 정렬이 필요한 경우에만 `font-variant-numeric: tabular-nums`를 사용한다.
- 숫자 정렬을 위해 본문 전체를 별도의 모노스페이스로 바꾸지 않는다.

### 3.4 로고와 영문

브랜드 로고는 별도 자산으로 취급한다. 기존 손글씨 Journey의 인상은 유지할 수 있다. 일반 한글 UI 전체에 로고용 서체를 확장하지 않는다.

시안의 영문 브랜드 표현은 Georgia와 따뜻한 구리색을 사용했지만 이를 새로운 로고 제작 명세로 확정하지 않는다. 실제 적용 시 기존 SVG 로고를 유지할 수 있으며, 로고용 글꼴 설치를 본문 표시의 의존성으로 만들지 않는다.

### 3.5 라이선스와 포함 방식

- 고운돋움은 SIL Open Font License 1.1로 배포된다.
- 앱에 서체 파일을 포함할 때 저작권 고지와 라이선스 전문을 함께 배포한다.
- 회사 PC의 오프라인 환경을 위해 실제 앱은 서체를 로컬 자산으로 포함한다. 외부 웹폰트 호출을 필수로 만들지 않는다.
- 시안의 제한된 글자만 포함한 미리보기용 파일을 실제 업무 입력용 서체로 사용하지 않는다. 실제 앱에는 필요한 한글·영문·기호를 포함한 배포본을 사용한다.

## 4. 간격과 크기 체계

### 4.1 간격 토큰

기본 단위는 4px다. 시안의 개별 미세값을 아래 단계로 정리해 반복 사용한다.

| 토큰 | 값 | 일반적인 용도 |
|---|---:|---|
| `--space-1` | 4px | 아이콘과 짧은 레이블, 밀접한 요소 |
| `--space-2` | 8px | 항목 내부, 작은 컨트롤 간격 |
| `--space-3` | 12px | 입력 안쪽, 관련 항목 사이 |
| `--space-4` | 16px | 일반적인 독립 컴포넌트 안쪽 |
| `--space-5` | 24px | 서로 다른 내용 묶음의 구분 |
| `--space-6` | 32px | 큰 내용 구분이 필요한 경우 |

- 가까운 관련 요소에는 작은 간격, 다른 목적의 내용에는 큰 간격을 사용한다.
- 모든 컴포넌트에 동일한 큰 패딩을 넣지 않는다.
- 텍스트 줄 높이와 패딩이 함께 과도하게 커지지 않도록 확인한다.
- 내부 패딩은 콘텐츠가 많은 경우에도 일관된 토큰을 사용한다. 고정 높이를 강제하여 여러 줄 기록을 자르지 않는다.

### 4.2 컨트롤 밀도

| 요소 | 기본 기준 |
|---|---|
| 일반 버튼 | 높이 32px 이상, 좌우 패딩 12px |
| 작은 보조 버튼 | 높이 28px 이상, 좌우 패딩 8px |
| 아이콘 버튼 | 시각 크기 28~32px, 아이콘 16px |
| 한 줄 입력 | 높이 34px 이상, 좌우 패딩 12px |
| 여러 줄 입력 | 패딩 8~12px, 줄 높이는 본문과 동일 |
| 터치 중심 환경 | 조작 영역 약 44px 확보 |

큰 글자 설정이나 번역된 긴 레이블에서 최소 높이는 커질 수 있다. 고정 높이보다 최소 높이로 구현한다. 아이콘이 작더라도 실제 클릭 영역까지 작게 만들지 않는다.

## 5. 표면·테두리·모서리·그림자

### 5.1 표면

- 기본 내용은 크림색 표면에 놓는다.
- 부연 내용은 옅은 베이지 면으로 구분할 수 있다.
- 모든 내용 묶음을 흰 카드 안에 다시 넣지 않는다.
- 같은 성격의 표면에는 동일한 색·모서리·패딩 규칙을 적용한다.
- 중첩된 표면에 테두리와 그림자를 반복하지 않는다.

### 5.2 모서리

| 토큰 | 값 | 용도 |
|---|---:|---|
| `--radius-none` | 0 | 연속되는 내용·구분선 |
| `--radius-sm` | 4px | 작은 배지·미세한 상태 표식 |
| `--radius-md` | 6px | 버튼·입력·약한 보조 면 |
| `--radius-lg` | 8px | 팝오버·메뉴·독립 표면 |
| `--radius-xl` | 10px | 외곽 프레임이 필요한 경우 |

알약 모양의 모서리를 기본값으로 사용하지 않는다. 독립된 콘텐츠 표면의 모서리를 둥글게 할 수 있지만 반복되는 데이터 항목 하나하나를 카드로 만들지는 않는다.

### 5.3 그림자

기본 표면과 일반 카드에는 그림자를 적용하지 않는다. 메뉴·팝오버·대화상자처럼 위에 떠 있다는 정보가 필요한 요소에만 허용한다.

```css
--shadow-floating: 0 6px 20px rgb(66 60 52 / 8%);
```

검고 진한 그림자, 이중 그림자, 색이 번지는 광원 효과는 사용하지 않는다.

### 5.4 포커스

```css
outline: 2px solid var(--accent);
outline-offset: 2px;
```

`focus-visible`을 우선 적용한다. 평상시의 옅은 테두리만으로 포커스를 대신하지 않는다. 테두리를 없애기 위해 키보드 포커스까지 제거하지 않는다.

## 6. 컴포넌트 외형

### 6.1 버튼

| 종류 | 기본 스타일 | 호버·활성 |
|---|---|---|
| 주요 동작 | `--surface-action` + `--text-action`, 테두리 없음 | 배경을 한 단계 진하게 |
| 일반 동작 | 투명 또는 `--surface-muted`, 본문색 | 옅은 베이지 배경 |
| 텍스트 동작 | 투명, `--accent`, 간결한 레이블 | 약한 배경 또는 밑줄 |
| 아이콘 동작 | 투명, 보조색 | 아이콘 색과 옅은 배경으로 반응 |
| 파괴적 동작 | 오류색 글자·아이콘 | 오류의 옅은 배경 |

- 밝은 베이지 버튼에 흰 글자를 올리지 않는다.
- 강한 채움·테두리·그림자를 한 버튼에 동시에 적용하지 않는다.
- 같은 맥락에서 시각적으로 가장 강한 버튼은 제한적으로 사용한다.
- 누르는 동작과 상태 표시가 같은 외형으로 보이지 않게 한다.

### 6.2 입력과 편집기

- 기본 상태는 투명하거나 `--surface-content` 배경으로 둔다.
- 별도 입력 경계를 보여야 하는 경우 얇은 경계를 사용하되, 입력 영역으로 알아볼 수 있는 레이블·배경·상태 표시를 함께 제공한다.
- 편집 중에는 포커스를 명확하게 표시한다.
- 내용과 입력값의 글자색은 `--text-primary`다.
- 플레이스홀더는 보조색을 사용하며, 입력 방법의 유일한 설명으로 사용하지 않는다.
- 읽기 → 편집 전환 시 글자의 시작 위치와 줄바꿈이 바뀌지 않게 한다.

### 6.3 선택 컨트롤과 활성 항목

- 바탕은 `--surface-control`, 선택된 면은 `--surface-content`를 기본으로 한다.
- 더 분명한 선택이 필요하면 `--surface-active`와 `--text-active` 조합을 사용한다.
- 각 옵션에 별도 테두리를 반복하지 않는다.
- 선택 표시는 배경·문구·얇은 선 중 필요한 조합으로 표현한다.
- 선택 상태와 키보드 포커스는 서로 독립적으로 표시한다.

### 6.4 태그·배지

- 태그는 보조 정보로 취급한다. 기본 12px, 패딩 2px 6~8px, 모서리 4px를 사용한다.
- 기본 태그는 베이지 바탕에 짙은 보조 글자로 표현한다.
- 모든 태그에 카테고리 색을 강하게 채우지 않는다.
- 누를 수 있는 태그는 호버·포커스 상태를 제공하고, 표시 전용 배지와 구분한다.
- 상태 배지는 문구나 아이콘으로 의미를 함께 전달한다.

### 6.5 반복 데이터·구분선

- 본문 간격과 정렬을 먼저 맞추고, 구분선은 필요한 곳에만 남긴다.
- 반복 항목의 내부 경계는 `--border-subtle`, 구조 경계는 `--border-default`를 사용한다.
- 바깥 테두리·내부 선·선택선이 한꺼번에 진해지지 않게 한다.
- 선택된 내용은 `--surface-selected`로 표현하고, 필요하면 `--border-selected` 1px 선을 더한다.
- 포인터가 올라온 항목에만 진한 외곽선을 두르는 효과를 기본으로 사용하지 않는다.

### 6.6 메모·부연 내용

- 필요한 경우 `--surface-note`의 옅은 면을 사용한다.
- 내부 내용은 투명 표면으로 이어질 수 있으며, 상자마다 별도의 테두리·그림자를 적용하지 않는다.
- 제목 14px, 본문 13px, 줄 높이 1.8을 기본으로 한다.
- 관계·출처 레이블은 보조색을 사용하되 배경에 따른 대비 규칙을 따른다.
- 선택된 메모는 약한 배경 변화로 표시할 수 있고, 편집 포커스는 별도로 분명하게 표시한다.

### 6.7 링크

- 기본 링크는 `--accent`를 사용한다.
- 본문 안 링크는 밑줄로 구분한다. 색만으로 구분하지 않는다.
- 필요하면 작은 외부 이동 아이콘을 함께 사용한다.
- 긴 주소 때문에 본문 영역이 넘치지 않게 한다.

## 7. 상태 표현

| 상태 | 스타일 규칙 |
|---|---|
| 기본 | 크림색 면, 본문색, 최소한의 구분선 |
| 호버 | 옅은 베이지 배경 변화, 레이아웃 변화 없음 |
| 선택 | 샌드색 면 + 짙은 글자, 필요하면 1px 보조선 |
| 현재 항목 | `--surface-current` + `--text-current`의 작은 표식 |
| 편집·키보드 포커스 | 2px 브라운 포커스 링 |
| 중요 | 별·작은 구리색 선·짧은 레이블, 필요한 강조만 적용 |
| 예정·반복 | 작은 반복 아이콘과 상태 문구, 본문보다 약한 위계 |
| 비활성 | 글자·아이콘의 강조 감소, 선택·호버와 구분 |
| 오류 | 오류색 문구·아이콘 + 옅은 오류 배경 |

비활성 요소에 낮은 불투명도를 사용할 수 있으나 중요한 설명까지 함께 흐리지 않는다. 선택·현재·중요·편집 상태는 같은 의미가 아니므로 서로를 덮어쓰지 않는다.

## 8. 아이콘과 모션

### 아이콘

- 같은 계열의 라인 아이콘을 일관되게 사용한다.
- 기본 크기는 16px, 보조 14px, 큰 단독 조작은 18px를 기준으로 한다.
- 선 두께는 1.5~1.75px 범위에서 통일한다.
- 아이콘 색은 글자색을 상속한다. 브랜드·업무 구분·상태 외에는 아이콘마다 색을 다르게 주지 않는다.
- 아이콘만 있는 버튼에는 접근 가능한 이름과 툴팁을 제공한다.
- 마우스 호버 없이도 키보드 포커스로 보조 동작을 찾을 수 있어야 한다.

### 모션

- 호버·배경·색 변화: 100~140ms.
- 메뉴·팝오버의 등장: 140~180ms.
- 기본 완화 곡선: `ease-out`.
- 입력 중 반복 애니메이션, 큰 이동, 튀는 스프링 효과는 사용하지 않는다.
- `prefers-reduced-motion`을 존중한다.

## 9. 가독성 확인과 적용 범위

### 9.1 확인한 색 대비

불투명한 단색 sRGB 조합을 기준으로 계산한 값이다. 전체 화면이나 앱의 접근성 준수 판정은 아니다.

| 글자 / 배경 | 대비 비율 | 사용 판단 |
|---|---:|---|
| `#423C34` / `#FCF9F3` | 10.37:1 | 본문 기본 |
| `#786F63` / `#FCF9F3` | 4.70:1 | 기본 면의 보조 글자 |
| `#856748` / `#FCF9F3` | 4.96:1 | 기본 면의 링크·강조 |
| `#5F4B36` / `#E9DDCC` | 6.16:1 | 주요 버튼 |
| `#68523D` / `#E8DDCD` | 5.47:1 | 활성 항목 |
| `#71583E` / `#E8D9C3` | 4.78:1 | 현재 표식 |

`#786F63`는 `#EDE6DC` 위에서 약 3.99:1, `#F4EBDD` 위에서 약 4.18:1이다. 이 조합을 작은 일반 보조 글자에 그대로 사용하지 않고 `--text-secondary-strong`으로 바꾼다. 구리색 포인트도 작은 본문의 글자색으로 사용하지 않는다.

실제 적용에서는 투명도·배경 이미지·입력 상태·브라우저 배율·폰트 렌더링을 포함해 다시 확인한다.

### 9.2 테마 범위

이 명세는 **밝은 베이지 테마**를 정의한다. 다크 테마는 포함하지 않는다. 어두운 테마를 추가할 때는 이 색을 단순 반전하지 않고 별도의 토큰으로 검토한다.

### 9.3 적용 확인 항목

- [ ] 기본 본문과 입력에 고운돋움이 실제 로드되는가?
- [ ] 오프라인에서도 기본 서체와 아이콘이 표시되는가?
- [ ] 가짜 볼드 없이 제목·본문의 위계가 구분되는가?
- [ ] 테두리보다 본문이 먼저 읽히는가?
- [ ] 채워진 베이지 면 위에서 보조 글자의 대비가 유지되는가?
- [ ] 일반 상태와 선택·호버·키보드 포커스가 구분되는가?
- [ ] 텍스트가 길거나 글자 크기가 커져도 내용이 잘리지 않는가?
- [ ] 입력 전후 글자 위치와 줄바꿈이 유지되는가?
- [ ] 색을 구분하기 어려워도 중요한 상태를 알아볼 수 있는가?
- [ ] 폰트 저작권 고지와 OFL 전문이 포함되어 있는가?
