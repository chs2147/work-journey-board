# Work Journey Board 디자인 개편 컨셉 설계

작성: 2026-10-26 · 단계: 컨셉 제안 · 범위: 현재 업무 스타일을 유지하는 UI 개편

## 1. 설계 방향

**추천 컨셉은 ‘차분한 업무 장부 — Quiet Ledger’다.** 기록이 주인공이고 날짜와 업무가 자연스럽게 정돈되는 화면을 지향한다. 기존 손글씨 Journey 로고의 개성은 유지하고, 그 아래 작업 화면은 차분하고 정밀하게 만든다.

경쟁 서비스의 작업 방식이나 새로운 생산성 루틴을 가져오는 단계가 아니다. 현재의 주간 격자, 셀 안 개조식 입력, 오늘 보기, 자유 메모, 중요 업무, 요약·엑셀 동선에 디자인 체계를 입힌다. 새로운 기능 추가는 이번 개편의 전제로 삼지 않는다.

이번 검토는 현재 저장소의 디자인 토큰, Board·TopBar 스타일, 브랜드 규칙, 기존 설계와 이전 리서치에 근거한다. 실제 설치 앱을 실행한 사용성 평가가 아니라 소스와 설계 기준의 컨셉 제안이다. 비교 화면에는 가상 업무와 가상 기준일 2026-10-28을 사용했다.

## 2. 현재 디자인에서 정리할 기회

현재는 Pretendard 14px, 따뜻한 회백색 바탕, 파란 강조색, 손글씨 워드마크라는 기반이 있다. 전면 교체할 필요는 없다. 기록 도구에 맞는 체계가 이미 있으므로 시각적 우선순위를 다듬는 것이 효과적이다.

- **격자:** 모든 칸에 비슷한 강도의 선이 있어 경계가 본문과 함께 눈에 들어올 수 있다. 행 구분은 유지하고 세로선의 무게를 줄이는 방향을 검토한다.
- **강조:** 오늘 머리, 선택 열, 중요 형광펜, 업무 색, 태그·링크·반복 표시가 함께 있다. 각각의 역할을 고정하여 같은 색이 여러 의미를 떠맡지 않게 한다.
- **조작 요소:** 외곽선 버튼·배지·아이콘이 많아졌으므로 주요 동작, 보조 동작, 상태 표시의 외형을 구분한다.
- **편집기:** 읽는 상태와 편집 상태를 구분하되 편집을 시작할 때 높이·패딩·문자 위치가 바뀌지 않아야 한다.
- **브랜드:** 손글씨 워드마크는 개성으로 남기고, 기록 본문과 조작 요소는 일관된 산세리프를 사용한다.

위 항목은 관찰된 사용자 실패를 뜻하지 않는다. 실제 화면에서 개선 효과를 확인할 디자인 가설이다.

## 3. 세 가지 컨셉

### 차분한 업무 장부 — Quiet Ledger · 추천

**인상:** 정밀함, 차분함, 오래 써도 편한 업무 도구.

차가운 회백색 작업 배경 위에 밝은 기록면을 놓는다. 슬림한 왼쪽 메뉴, 얇은 격자, 선명한 업무명, 옅은 선택 열이 중심이다. 메모는 보드 아래 별도 작업면으로 구분하되 강한 그림자나 장식은 줄인다.

- 기존 격자와 직접 입력을 가장 충실하게 유지한다.
- 파란색은 선택·포커스·주요 동작에 제한한다.
- 업무 색은 이름 옆 작은 점으로, 중요 표시는 별과 작은 황토색 표식으로 표현한다.
- 날짜 머리는 큰 파란 면 대신 오늘 숫자 표식과 선택 밑줄로 구분한다.
- 로고는 작은 크기로 유지하고 본문 영역에는 손글씨를 확장하지 않는다.

**장점:** 학습 부담이 작고 작은 화면에서도 밀도 조절이 쉽다. 현재 CSS·토큰을 기준으로 점진적으로 바꿀 수 있다.

**주의:** 선을 지나치게 옅게 하면 칸의 소속이 약해진다. 업무 행과 날짜 열의 기준선은 남긴다. 본문을 회색으로 연하게 만드는 방식으로 정리하지 않는다.

### 따뜻한 기록장 — Warm Journal

**인상:** 개인적인 기록, 여유, 종이 노트의 차분함.

아이보리 바탕과 짙은 잉크색, 작은 구리색 포인트를 사용한다. 주간 제목을 여유 있게 두고, 세로선보다 행 간격과 가로선으로 업무를 구분한다. 주간 메모는 같은 종이 위에 이어지는 기록처럼 표현한다. 주요 메뉴는 상단에서 텍스트로 보여준다.

**장점:** 현재 손글씨 브랜드와 가장 자연스럽게 어울리고 자유 메모와의 연결감이 좋다.

**주의:** 여백을 늘리면 한 화면의 기록량이 줄어든다. 베이지·갈색을 모든 상태에 쓰면 연차·중요·선택 구분이 흐려진다. 전체 방향보다 브랜드·메모 영역의 온도감을 참고하는 용도로도 적합하다.

### 정돈된 워크스페이스 — Structured Workspace

**인상:** 명확한 구역, 안정적인 앱, 익숙한 업무 환경.

텍스트가 있는 왼쪽 메뉴와 중립적인 상단 바를 두고 기록 영역을 독립된 작업면으로 구분한다. 메모와 요약은 각각 경계가 있는 작업 영역으로 표현한다. 세 컨셉 중 메뉴 이름과 작업 구역의 발견성을 가장 중시한다.

**장점:** 아이콘만으로 기능을 찾기 어려운 경우 유리하고 패널의 역할이 분명하다.

**주의:** 넓은 사이드바와 패널이 함께 열리면 요일 칸이 좁아진다. 1366px에서는 접힌 메뉴를 기본으로 삼는 편이 적절하다. 지금의 개인 기록 도구에는 다소 무거운 인상을 줄 수 있다.

| 판단 항목 | 차분한 업무 장부 | 따뜻한 기록장 | 정돈된 워크스페이스 |
|---|---|---|---|
| 현재 기록 습관과의 연속성 | 가장 높음 | 높음 | 높음 |
| 기록 밀도 | 균형적 | 여백 때문에 낮아질 수 있음 | 메뉴 폭에 영향 |
| 브랜드 개성 | 손글씨를 작은 포인트로 | 가장 적극적으로 표현 | 중립적인 앱 분위기 |
| 작은 화면 | 슬림 메뉴로 대응 | 여백 축소 필요 | 메뉴 접기 필요 |
| 권장 활용 | 전체 개편의 기본 | 로고·메모의 온도감 | 메뉴·패널 구획 참고 |

이 표는 설계 판단이며 사용자 조사 점수나 정량 평가가 아니다.

## 4. 추천안의 디자인 규칙

### 색의 역할

다음 값은 라이트 모드의 출발점이다. 다크 모드는 단순 반전 대신 별도 표면·본문·포커스 값을 사용한다. 표의 기본값은 최종 접근성 검증 전 제안이다.

| 역할 | 시작값 | 사용 위치 |
|---|---|---|
| 작업 배경 | #F6F7F9 | 앱 작업 공간 |
| 기록면 | #FFFFFF | 보드·메모·패널 |
| 본문 | #253044 | 실제 기록과 업무명 |
| 보조 문자 | #626E7E | 날짜 보조 정보·태그·저장 상태 |
| 구조선 | #E6E9EE | 행·패널 경계, 세로선은 더 약하게 |
| 상호작용 파랑 | #315F9E | 선택·편집 포커스·주요 동작 |
| 선택 배경 | #EEF4FC | 선택한 날짜의 칸 |
| 브랜드 포인트 | #B55C3D | Journey·작은 장식 |

기존 업무별 팔레트는 유지한다. 브랜드 색과 카테고리 색을 통합하지 않는다. 배경색이 상태 의미를 모두 대신하지 않도록 문구·아이콘·선 모양을 함께 쓴다.

### 글꼴과 간격

- 본문은 기존 Pretendard를 유지한다. 기본 14px를 출발점으로 15px 모드와 비교한다.
- 개조식 본문 줄 높이는 1.55~1.65를 검토한다. 여러 줄 기록의 읽기 편의와 셀 높이를 함께 본다.
- 업무명은 14px·600, 보조 정보는 12px·400, 주차 제목은 18~20px·600 정도로 위계를 만든다.
- 4px 간격 단위를 사용하고 셀 안쪽은 8~12px, 패널 안쪽은 16px를 출발점으로 삼는다.
- 보드 모서리 6~8px, 버튼 6px, 메뉴·팝오버 8px. 모든 요소를 둥근 카드나 알약 모양으로 만들지 않는다.
- 숫자는 날짜·주차·정렬이 필요한 위치에만 고정폭 숫자를 사용한다.

### 상단 바와 메뉴

브랜드·앱 동작과 날짜·보기 조작을 두 묶음으로 정리한다. 주간/오늘은 텍스트가 있는 작은 전환 버튼으로 비교하고, 연간 보기는 주 이동 근처, 태그는 보드 가까이에 둔다. 저장 상태는 클릭할 수 있는 버튼과 다른 외형으로 표현한다.

기본 상태에서 가장 강한 채움 버튼은 하나로 제한한다. 시안에서는 내보내기를 사용했지만 실사용에서 호출 빈도가 낮다면 중립 버튼으로 내려도 된다. ‘주간 요약’과 ‘내보내기’의 이름을 유지하여 목적이 바로 읽히게 한다.

보기 전환은 현재 아이콘만 있는 방식과 비교하는 제안이다. 기존 아이콘 선호가 확정되어 있다면 이름을 항상 붙이는 대신 선택 시 이름 표시나 명확한 툴팁으로 조정할 수 있다.

### 주간 보드

업무별 행 × 월~일 열과 선택 날짜 확장 원칙은 유지한다. 본문 위치는 읽기·편집 상태에서 동일하게 하고, 포커스 테두리만 추가한다. 기록량이 많아졌을 때 고정 높이로 잘라 숨기지 않는다.

행 구분선은 남기고 세로선은 더 옅게 한다. 실제 편집 칸에는 분명한 포커스 링을 사용한다. 마우스를 올렸을 때만 나타나는 보조 동작은 키보드 포커스에서도 나타나야 한다. 삭제 버튼이 본문을 덮거나 등장할 때 문장을 밀지 않도록 동작 영역을 확보한다.

### 오늘·선택·중요·연차

| 상태 | 표현 제안 | 다른 상태와 공존할 때 |
|---|---|---|
| 오늘 | 날짜 숫자의 작은 채움 표식 + ‘오늘’ | 선택을 다른 날로 옮겨도 유지 |
| 선택 날짜 | 머리 밑줄 + 열의 옅은 배경 | 오늘 표식과 독립 |
| 편집 칸 | 입력 영역의 1~2px 포커스 링 | 선택 열보다 명확한 경계 |
| 중요 항목 | 별 + 작은 황토색 선·절제된 배경 | 업무 색·선택 파랑과 독립 |
| 반복 | 작은 반복 아이콘 + ‘예정’ 문구 | 수행 기록처럼 진하게 보이지 않음 |
| 연차·반차 | 이름 있는 배지 + 미세한 따뜻한 음영 | 오늘·선택 표식의 형태를 보존 |
| 저장 실패 | 빨간 상태 문구 + 재시도 | 정상 저장 상태보다 분명하게 |

현재의 ‘오늘 머리 전체 파랑’과 ‘중요 형광펜 띠’를 바꾸는 안이므로 실사용 비교가 필요한 지점이다. 단지 화면을 차분하게 만들기 위해 필요한 강조를 없애면 안 된다.

### 자유 메모와 패널

자유 메모의 위치·크기 조절·이미지·링크·업무 연결을 유지한다. 캔버스 바탕의 점은 낮은 대비로, 선택 상자는 명확한 테두리로 구분한다. 모든 메모를 자동으로 같은 카드 크기에 맞추지 않는다. 시안의 두 메모 배치는 비교를 위한 예시다.

연결된 메모는 상단의 업무명·날짜 띠가 기록과의 관계를 보여준다. 요약 패널도 같은 표면색·제목·버튼·입력 스타일을 공유한다. 그림자는 메뉴·팝오버 등 떠 있는 요소에 제한한다.

### 오늘 보기

기존의 메모 + 날짜별 업무 카드 구조를 사용한다. 주간 보드와 동일한 글자 크기·편집기·태그·중요 표시를 사용하고, 카드 장식만 따로 키우지 않는다. 개편 때문에 보기마다 입력 감각이 달라지지 않는 것이 중요하다.

## 5. 반응형·상태 검토

실제 앱의 주요 기준은 1366×768과 넓은 데스크톱이다. 웹 시안은 대화 안에서 비교하기 위해 작은 폭에서는 선택한 날짜만 보여준다. 이는 모바일 제품 제공이나 실제 앱의 새 반응형 정책을 결정한 것이 아니다.

- 1366×768, 업무 8개, 여러 줄 기록에서 보드와 메모 도크가 사용 가능한지 확인.
- Windows 배율 100%·125%·150%, 글자 크기 변경을 함께 확인.
- 오늘과 선택 날짜가 다름, 연차+오늘, 중요+연결 메모, 긴 업무명, 태그 다수, 저장 실패를 확인.
- 빈 주·종료 업무·장기간 기록도 같은 스타일 체계로 표현.
- 일반 본문 대비 4.5:1, 주요 조작·포커스의 비문자 대비를 검사. 제안 색상 표만으로 준수 판정을 내리지 않음.
- 다크 모드에서 회색 선·중요색·메모 배경이 과하게 빛나거나 묻히지 않는지 확인.

## 6. 적용 단계

1. **토큰과 대표 화면:** 배경·본문·선·강조·간격·모서리를 바꾸고 주간 보드 한 화면에서 방향을 검토한다.
2. **공통 조작 요소:** 버튼·보기 전환·태그·메뉴·포커스·저장 상태를 통일한다.
3. **입력과 메모:** 글자 위치·행 높이·강조·메모 선택·업무 연결 표시를 정돈한다.
4. **관련 화면:** 오늘 보기·중요 업무·요약·내보내기·설정에 같은 규칙을 적용한다.

본문 편집, 한글 조합, 키보드 이동, 실행 취소, 드래그, 메모 연결, 좁은 화면 패널 동작은 개편 전후로 확인한다. 기능이나 데이터 구조를 바꿀 필요 없이 디자인부터 진행할 수 있다.

## 7. 컨셉 결정 시 핵심 질문

- 가장 오래 보기 편한 화면은 어느 쪽인가?
- 현재보다 오늘·선택 칸·중요 항목을 더 빨리 구분할 수 있는가?
- 메모와 보드의 시각적 구분이 충분한가?
- 글자 크기를 유지했을 때 한 화면의 기록량이 적절한가?
- 손글씨 브랜드가 포인트로 남는 정도가 적절한가?

추천 조합은 **차분한 업무 장부를 기본으로, 따뜻한 기록장의 브랜드 온도감만 일부 더하는 방향**이다. 메뉴 구획은 정돈된 워크스페이스에서 필요한 만큼 참고한다.
