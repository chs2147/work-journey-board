# Work Journey Board 유사 서비스 심층 리서치

조사 기준일: 2026-10-26 · 목적: 시험판의 제품 방향과 개선 순서 결정

## 1. 결론

우선 볼 서비스는 **NotePlan, Sunsama, Agenda**다. NotePlan에서는 날짜와 업무 문맥을 연결하는 구조, Sunsama에서는 일주일의 기록을 돌아보는 흐름, Agenda에서는 한 업무의 과거와 현재를 시간순으로 읽는 경험을 참고할 가치가 크다.

메모 영역은 Heptabase·Amplenote, 로컬 데이터와 업무 이력은 Obsidian·Super Productivity, 주간 화면의 단순함은 WeekToDo를 보조 레퍼런스로 삼는 것이 좋다.

다음 시험판은 **업무별 이력 → 기록·메모 검색 → 보고서 마무리 → 연결 메모 미리보기 → 활동 차트** 순서를 권한다. 이미 갖춘 주간 입력·오늘 보기·메모·엑셀 기능을 연결해, 기록을 다시 찾고 보고에 쓰는 가치를 검증하는 순서다. 이는 조사에 근거한 제품 판단이며 사용자 검증 결과는 아니다.

## 2. 프로젝트 이해와 조사 범위

README, overview, output-spec, viz-spec, project-plan, 소스 트리와 App.tsx를 확인했다. README 상단 상태에는 과거 버전 설명이 남아 있어 최신 변경 이력 v0.2.11과 현재 화면 구성을 함께 기준으로 삼았다.

현재 핵심은 회사 Windows PC에서 사용하는 개인 업무 일지다. 업무별 행 × 요일별 열의 주간 보드, 오늘 보기, 개조식 입력, 중요 표시, 반복, 직전 기록 가져오기, 자유 메모, 이미지·링크, 기록과 메모 연결, 자동 집계·수정본·복사·엑셀, SQLite·백업·외부 통신 0이 중심이다. 업무별 경과와 활동 시각화는 설계가 있으나 확인한 현재 UI에는 연결되어 있지 않다.

따라서 유사성의 기준은 단순한 일정 관리가 아니라 **‘짧게 쓴 기록이 업무 문맥과 보고 자료로 얼마나 잘 돌아오는가’**다.

근거: [README](https://github.com/chs2147/work-journey-board/blob/main/README.md), [요구사항·화면 설계](https://github.com/chs2147/work-journey-board/blob/main/docs/overview.md), [현재 화면 구성](https://github.com/chs2147/work-journey-board/blob/main/src/ui/App.tsx), [산출물 설계](https://github.com/chs2147/work-journey-board/blob/main/docs/output-spec.md), [시각화 설계](https://github.com/chs2147/work-journey-board/blob/main/docs/viz-spec.md).

공식 제품 페이지·가이드·개인정보 안내·공개 저장소 문서를 읽은 데스크 리서치다. 유료 로그인 후 실사용, 속도 측정, 네트워크 검증은 수행하지 않았다. 사용성 평가는 설명된 구조에 대한 분석이다. 기능 미확인은 기능 부재를 뜻하지 않는다. 가격 비교보다 설계 참고에 집중했다.

## 3. 후보 비교

판정 기준은 입력 부담, 날짜와 업무의 연결, 회고·보고, 근거 자료의 재발견, Windows·로컬 적합성이다. 아래 우선도는 전체 제품 순위가 아니라 이 프로젝트의 참고 가치다.

| 서비스 | 참고 우선도 | 가장 볼 부분 | 프로젝트와의 거리 |
|---|---|---|---|
| NotePlan | 최우선 | 일간·주간·프로젝트 노트 연결 | 네이티브 Apple 중심, PC는 웹 |
| Sunsama | 최우선 | 날짜별 보드·주간 회고 | 계획·시간 배분 중심 |
| Agenda | 최우선 | 업무별 시간순 기록 | Apple 앱, Windows 직접 대체에 부적합 |
| Super Productivity | 높음 | 로컬 업무 이력·기간별 내보내기 | 태스크·시간 추적 중심 |
| Heptabase | 높음 | 카드·화이트보드·연결 문맥 | 지식 정리·연구 중심 |
| Amplenote | 높음 | 빠른 기록·상세 근거의 분리 | 범용 노트·태스크 흐름 |
| Obsidian | 높음 | 로컬 파일·일일 노트·Canvas | 사용자가 업무 흐름을 구성해야 함 |
| WeekToDo | 보조 | 단순한 주간 화면 | 계획·할 일 중심 |

기능 근거는 아래 서비스별 공식 링크에 붙였다. 참고 우선도와 거리는 프로젝트 요구사항에 대한 해석이다.

## 4. 서비스별 심층 분석

### 4-1. NotePlan — 날짜와 업무를 연결하는 구조

**확인한 특징:** 일일·주간·프로젝트 노트를 함께 제공한다. 프로젝트 노트의 태스크에 날짜를 붙이면 해당 날짜의 일일 노트에 나타나며 백링크·검색·필터를 지원한다. 네이티브 Apple 앱은 오프라인으로 동작하며 PC에는 웹 버전을 안내한다. [기능·화면](https://noteplan.co/features), [플랫폼 안내](https://noteplan.co/).

**참고 가치:** 사람은 오늘은 날짜 기준으로 생각하지만 몇 주 뒤에는 ‘그 업무가 어떻게 됐지?’라고 묻는다. 두 관점을 연결하는 것이 핵심이다. Work Journey Board의 업무별 행은 사용자가 직접 링크를 만들지 않아도 이 연결을 확보한다는 장점이 있다.

**적용 제안:** 업무명을 누르면 ‘이번 주 기록 / 전체 경과 / 연결 메모’로 이동하게 한다. 오늘 보기의 직전 기록은 이미 있으므로 날짜와 원문 이동 경로를 더 명확하게 만들고, 전체 경과를 붙여 장기간 이력으로 확장한다. 태그는 업무를 가로지르는 보조 분류로 쓰고 업무 ID를 대신하지 않는다.

**옮기지 않을 것:** 날짜 문법·노트 링크 규칙을 배워야만 이력을 읽을 수 있는 구조. 이미 업무 카테고리로 자동 연결되는 장점을 유지한다.

**볼 장면:** 공식 기능 페이지의 Daily & Weekly Notes → Project Notes → Scheduling → Backlinking. 같은 일이 다른 화면에 보일 때 원문과 날짜를 어떻게 알아보는지 관찰한다.

### 4-2. Sunsama — 주간보고를 마무리하는 흐름

**확인한 특징:** 날짜마다 열이 있는 보드와 날짜 집중 보기를 제공한다. 미완료 태스크 이월, 여러 날에 걸친 작업의 흔적을 남기는 completion credit이 있다. 주간 회고는 목표 확인 → 수행한 일·시간 배분 확인 → 회고 작성으로 이어진다. [보드](https://help.sunsama.com/docs/getting-started/basics/kanban-task-view/), [주간 회고](https://help.sunsama.com/docs/usage-guides/weekly-objectives/weekly-review/).

**참고 가치:** 회고를 빈 문서에서 시작하지 않는다. 쌓인 일을 먼저 보여준 뒤 의미를 정리한다. 현재의 자동 집계 → 수정본 → 최종본 복사와 방향이 잘 맞는다.

**적용 제안:** 기존 요약 패널에 선택적인 ‘보고서 마무리’를 얹는다. 이번 주 기록을 확인하고 대표 성과·다음 주 확인할 일에 필요한 문장만 보완한 뒤 복사·내보내기로 끝낸다. 매일 새 필드를 입력하게 하기보다 주말에 기존 기록을 활용한다. 필요한 사람은 지금처럼 바로 복사할 수 있어야 한다.

**옮기지 않을 것:** 실제 수행 기록까지 미완료 태스크처럼 다음 날로 이동시키는 규칙. 진행 중 업무의 계속 표시, 반복 예정 항목 생성, 지난 기록 가져오기, 과거 수행 기록 보존은 서로 다르다. 기록 원문은 해당 날짜에 남아야 한다.

**환경:** 회사 사용의 IT·보안 승인 절차를 공식 안내한다. 외부 통신 0 제품의 직접 대체보다 UX 참고용으로 적합하다. [보안·회사 승인](https://help.sunsama.com/docs/security/overview/).

### 4-3. Agenda — 업무가 흘러온 과정을 읽는 화면

**확인한 특징:** 프로젝트 안의 노트를 날짜 순으로 묶고 On the Agenda로 현재 집중할 노트를 모은다. 과거·현재·미래 노트를 함께 다루며 목록 정렬 방향도 바꿀 수 있다. 공식 플랫폼은 macOS·iOS·iPadOS다. [제품·화면](https://www.agenda.com/), [기본 사용법](https://agenda.com/manual/en/the-basics/).

**참고 가치:** 업무 기록은 ‘언제 몇 건 썼는가’보다 ‘왜 이 결정에 이르렀는가’를 읽을 때 강해진다. Agenda는 프로젝트 문맥을 날짜순 노트 자체로 전달한다.

**적용 제안:** 기존 viz-spec의 경과 타임라인을 다음 시험판의 중심으로 삼는다. 업무 선택 → 주차별 기록 → 연결 자료 → 원래 보드로 이동의 왕복을 완성한다. 기본 정렬은 현재 설계대로 과거→최근을 유지하되 최신 위치를 먼저 보여준다. 최근→과거 전환이 필요한지는 실제 회상 과제로 검증한다.

**옮기지 않을 것:** 활성·중요·집중·진행 중처럼 비슷한 상태를 계속 추가하는 방식. 현재의 업무 종료·재개와 항목 중요 표시를 먼저 명확히 사용한다.

**볼 장면:** 프로젝트 선택, 시간순 목록, 집중 노트 모음, 오래된 노트에서 현재 업무로 돌아오는 동선. 색·아이콘보다 정보 순서가 핵심 참고 대상이다.

### 4-4. Super Productivity — 로컬 이력과 내보내기

**확인한 특징:** Windows를 지원하고 업무·시간 추적을 로컬에서 사용할 수 있다. History는 활성·보관 태스크의 날짜별 시간을 연·월·주·일로 묶고 프로젝트·기간별 내보내기를 제공한다. 개인정보 안내에는 데스크톱 기본 업데이트 확인과 선택적 동기화·연동도 설명되어 있다. [플랫폼](https://super-productivity.com/download/), [History 공식 문서](https://github.com/super-productivity/super-productivity/blob/master/docs/wiki/4.21-Worklog.md), [데이터·통신 정책](https://super-productivity.com/privacy/).

**참고 가치:** 원본과 보관된 업무를 함께 이력으로 읽고 필요한 범위를 산출물로 꺼내는 흐름. 종료된 업무도 과거 검색·보고에서 계속 살아 있어야 한다.

**적용 제안:** 새 내보내기 형식을 늘리기 전에 화면에서 확인한 범위와 실제 산출물 범위를 쉽게 비교하게 한다. 현재는 태그 필터 중에도 요약·엑셀이 전체 업무 대상이므로 내보내기 직전에 ‘전체 업무 기준’을 명확히 보여주는 것이 유용하다. 필터별 보고의 실제 수요가 확인되면 선택지를 추가한다.

**옮기지 않을 것:** 기록을 위해 타이머·예상 시간·완료 처리를 필수화하는 방식. 하루 2분이라는 현재 목표와 입력 비용이 다르다.

### 4-5. Heptabase — 자유 메모의 재발견

**확인한 특징:** 카드·화이트보드·양방향 링크·일일 저널을 제공하고 노트·파일의 오프라인 접근을 안내한다. 다만 공식 가이드상 버전 복원에는 온라인 연결이 필요하고 보드 배치와 카드 내용의 복원 범위도 다르다. [제품 화면](https://heptabase.com/), [복원 조건](https://support.heptabase.com/en/articles/10448124-restore-from-version-history).

**참고 가치:** 공간 배치는 이해와 비교에 유리하지만 나중에 원하는 자료를 다시 찾는 경로가 필요하다. 현재 제품은 줌·패닝·미니맵·이미지·링크·업무 연결이 이미 있으므로 기본 캔버스 기능을 계속 늘리기보다 연결을 활용하는 것이 중요하다.

**적용 제안:** 업무 경과에서 해당 업무의 메모만 열고 돌아오게 한다. 전체 메모판으로 이동하면 해당 상자를 중앙에 맞추고 잠깐 강조한다. 업무별 자료 목록이나 임시 강조는 기존 공간 배치를 건드리지 않고 제공할 수 있다.

**옮기지 않을 것:** 보고 일지를 쓰려고 카드 위치부터 정리해야 하는 구조. 섹션·연결선·자동 정렬은 실제 찾기 실패가 관찰된 뒤 검토한다.

### 4-6. Amplenote — 짧은 본문과 상세 근거의 공존

**확인한 특징:** Jots는 빠른 기록을 위한 모드이고 일반 노트와 별개 데이터 종류가 아니다. Rich Footnotes는 단어나 문장에 텍스트·이미지·링크·다른 노트 미리보기 등 문맥을 붙인다. [Jots](https://www.amplenote.com/help/jots), [Rich Footnotes·예시](https://www.amplenote.com/help/rich_footnotes_content_preview).

**참고 가치:** 목록에는 핵심 한 줄을 남기고 필요할 때 상세 자료를 펼친다. 근거 자료가 늘어나도 주간 보드를 짧게 유지하는 설계다.

**적용 제안:** v0.2.11의 연결 메모 배지를 누르면 제목·첫 문장·이미지 썸네일·전체 메모 열기를 작은 미리보기로 제공한다. 키보드로도 열 수 있어야 하며 닫으면 원래 기록의 편집 위치로 돌아온다. 메모 내용을 복사하여 별도로 중복 저장할 필요는 없다.

**옮기지 않을 것:** 외부 URL에 자동 접속하여 임베드·썸네일을 가져오는 기능. 로컬 이미지와 직접 입력한 제목으로 핵심 경험을 구현한다.

### 4-7. Obsidian — 데이터 소유권과 연결의 기준점

**확인한 특징:** 노트는 로컬 폴더의 파일로 저장된다. Daily notes는 오늘 날짜의 노트를 열거나 만들고 템플릿을 지원한다. Canvas에는 노트·첨부·웹 카드 등을 배치하고 연결한다. 파일 없는 텍스트 카드는 백링크에 나타나지 않는 제한도 명시한다. [로컬 저장](https://help.obsidian.md/Getting+started/Sync+your+notes+across+devices), [Daily notes](https://help.obsidian.md/plugins/daily-notes), [Canvas](https://help.obsidian.md/plugins/canvas).

**참고 가치:** 기록을 계속 꺼내 쓸 수 있다는 신뢰. 또 화면상 가깝게 놓인 카드와 실제 참조 관계는 다르다는 점이다.

**적용 제안:** SQLite를 유지하면서 ‘앱 없이 읽는 산출물’과 ‘완전 복원용 백업’의 의미를 명확히 설명한다. 엑셀은 유용한 읽기 경로지만 메모 이미지·공간 배치·연결까지 복원하는 백업과 같지 않다. 메모가 주요 정보 저장소가 될수록 이 차이가 중요해진다.

**환경:** Obsidian도 업데이트 확인, 플러그인·테마 설치, 웹 임베드 등에서 통신할 수 있다고 안내한다. 로컬 저장과 외부 통신 0은 별도 판단이다. [개인정보 안내](https://obsidian.md/privacy).

### 4-8. WeekToDo — 단순한 주간 화면의 비교 기준

**확인한 특징:** 달력과 할 일 목록을 결합한 주간 플래너다. Windows·macOS·Linux·웹, 로컬 저장, 드래그·반복·하위 항목을 안내한다. 개인정보 문서는 후원 정보·업데이트·오류 보고 연결과 설정에서 끄는 방법을 설명한다. 해당 문서의 갱신일은 2020년으로 오래되었다. [제품](https://weektodo.me/), [저장소](https://github.com/manuelernestog/weektodo), [개인정보 안내](https://weektodo.me/privacy-statement/).

**참고 가치:** 주간 도구가 복잡한 데이터베이스 화면일 필요는 없다는 비교 기준. 날짜 탐색·직접 입력·드래그를 단순하게 유지하는 장면을 살펴보기 좋다.

**적용 제안:** 항상 보일 정보는 업무명·날짜·기록·저장 상태를 중심으로 삼는다. 자주 쓰는 행동은 찾기 쉽게 두되 가끔 쓰는 설정 때문에 기록 칸이 좁아지지 않게 한다. 현재 보기 아이콘은 공간 절약과 이름 발견성 사이의 비용을 비교한다.

**한계:** 조사한 공식 자료에서는 이 프로젝트와 같은 업무별 개조식 주간보고·엑셀 흐름을 확인하지 않았다. 단순한 입력 경험의 보조 참고 대상이다.

## 5. 기존 대안 OneNote와의 비교

프로젝트는 이미 OneNote 주간 페이지를 옮기는 가져오기 흐름을 갖췄다. ‘OneNote에 계속 적는 것보다 왜 편한가’도 검증해야 한다. Microsoft는 줄·문단 단위 태그, 태그 검색·요약을 안내하므로 중요 표시·자유 메모의 존재만으로 차별화를 설명하기는 어렵다. [Microsoft 공식 안내](https://support.microsoft.com/en-us/onenote/onenote-help-and-learning/apply-a-tag-to-a-note-in-onenote).

동일한 가상 데이터로 다음을 비교한다.

1. 오늘 업무 3개를 기록한다.
2. 지난 4주 동안 특정 업무의 변경 과정을 찾는다.
3. 이번 주 기록을 보고용으로 정리하고 엑셀로 가져간다.

차별화 가설은 특히 두 번째와 세 번째 과제에서 나온다. 업무별 자동 연결과 보고 재작성 부담 감소를 검증한다. 숙련도·입력량이 달라지면 도구 효과를 오해하기 쉬우므로 과제 조건을 맞춘다.

## 6. 차별화 가설과 환경 해석

이번 후보 조사에서는 다음 네 조건을 같은 기본 흐름으로 제공하는 조합을 확인하지 못했다. 시장 전체에 없다는 뜻은 아니다.

- 업무 × 요일의 주간 일지.
- 완료·시간·진척률을 필수 입력하지 않는 정성적 이력.
- 로컬 주간보고·엑셀 산출물.
- 회사 PC 단독 사용·외부 통신 0.

권장 제품 설명: **회사 PC에서 짧게 남긴 업무 기록이 주간보고와 업무 이력으로 이어지는 로컬 업무 일지.**

기능 수보다 ‘금요일에 다시 쓰는 시간을 줄인다’, ‘몇 주 전 업무 맥락을 찾는다’를 앞세운다. 아직 검증해야 할 가치 제안이며, 성능·시장 우위가 입증되었다는 의미는 아니다.

오프라인 편집, 로컬 저장, 동기화 선택, 외부 통신 0은 서로 다르다. Obsidian·Super Productivity·WeekToDo의 공식 안내에도 비핵심 기능의 연결이 설명되어 있다. NotePlan의 Apple 네이티브 오프라인 설명을 Windows 웹에 그대로 적용해서도 안 된다. Heptabase의 오프라인 접근 역시 온라인 복원 조건과 구분해야 한다. 따라서 UX 참고 적합성과 회사 PC의 직접 대체 적합성을 별도로 본다.

## 7. 다음 시험판 권장 순서

| 순서 | 개선 | 현재 기반 | 완료 판단 |
|---|---|---|---|
| P0-1 | 업무별 경과 타임라인 | viz-spec에 설계됨 | 여러 주의 업무 문맥을 한 화면에서 읽고 원문으로 이동 |
| P0-2 | 기록·메모 검색 | 주간 이동·태그를 보완 | 과거 문구·자료를 찾아 해당 위치로 이동 |
| P1-1 | 보고서 마무리 | 집계·수정본·복사·엑셀 구현됨 | 기존 기록으로 보고를 끝내는 시간 감소 |
| P1-2 | 연결 메모 미리보기 | v0.2.11 연결 구현됨 | 메모를 열고 원래 편집 위치로 복귀 |
| P2 | 활동 차트·정보 배치 정리 | viz-spec에 설계됨 | 패턴 발견 후 원문 확인 가능 |

### 업무별 경과 타임라인

최소 범위는 업무 선택, 주차별 기록, 기간 필터, 종료 업무 포함, 원문 이동, 경과 복사다. 새 입력 필드가 필요 없다. 차트는 패턴을 보여주지만 결정의 이유를 설명하지 않는다. 텍스트 이력을 먼저 완성하는 편이 정성적 관리 목표에 가깝다. 기존 설계의 무기록 구간 접기·장기간 월별 접기를 활용한다.

### 검색

처음에는 단어 검색, 업무·기간 좁히기, 날짜·업무명·본문 일부, 원문 이동으로 충분하다. 메모 본문·제목·링크 제목도 검토한다. 이미지 문자 인식은 첫 범위에서 제외한다. 타임라인 검색은 이미 설계되어 있으므로 결과 표현과 원문 이동을 공유하면 일관성이 좋아진다.

### 보고서 마무리

이번 주 전체 확인 → 필요한 문장만 보완 → 복사·엑셀로 끝낸다. 대표 성과·다음 주 확인할 일은 선택적으로 제안하고 매일 작성 의무로 만들지 않는다. 로컬 자동 집계와 문장형 요약을 혼동하지 않는다. 사내 AI 클립보드 경로를 선택적으로 연결할 수 있지만 AI 완성을 기다릴 필요는 없다.

### 연결 메모 미리보기

배지 → 미리보기 → 필요하면 전체 메모 → 원래 기록 복귀를 완성한다. 캔버스를 열 때 읽던 문맥을 잃지 않는지가 중요하다. 공간 배치 자체를 바꾸기보다 선택 상자 강조와 관련 자료 목록을 우선 검토한다.

### 차트·배치

차트는 원문으로 들어가는 입구로 쓴다. 기록 건수·일수는 실제 시간·성과가 아니라는 현재 명시를 유지한다. 자동 반복·가져온 문구가 밀도에 어떻게 반영될지 실사용에서 검증한다. 1366×768과 넓은 모니터에서 열 폭 변화, 오늘/선택 날짜 구분, 아이콘 이름 발견, 패널을 닫은 뒤 커서 복귀를 관찰한다. 이는 현재 구조에 대한 검증 질문이며 측정된 결함은 아니다.

## 8. 시험판 검증 계획

기존 ‘하루 2분·10영업일’ 목표에 회상·보고 과제를 더한다. 아래 수치는 초기 제안이지 측정 결과가 아니다.

| 과제 | 관찰 | 제안 기준 |
|---|---|---|
| 매일 기록 | 3개 업무 기록 저장 | 하루 2분 이내 |
| 과거 찾기 | 4주 전 결정의 원문 찾기 | 30초 이내 |
| 근거 확인 | 이미지·메모 확인 후 복귀 | 위치를 잃지 않음 |
| 주간보고 | 초안 확인·수정·내보내기 | 기존 방식보다 시간 감소 |
| 업무 종료 | 종료 업무의 과거 찾기 | 누락·혼동 없음 |
| 데이터 이전 | 백업 사본에서 열기 | 메모·관계 보존 |

기록 누락의 이유도 남긴다. 바빠서 잊음, 입력 위치 발견 실패, 중복 정리 부담, 메모를 찾다 포기함, 보고 문구 재작성 등으로 구분하면 다음 개선이 구체화된다. 외부 분석 서비스 없이 로컬 사용 기록표로 시작할 수 있다.

사용자를 넓힐 때는 가상 데이터로 같은 과제를 수행한 뒤 자기 업무에 2주 적용한다. 기능 선호 설문보다 실제로 기록을 계속 남겼는지, 보고에 재사용했는지에 큰 비중을 둔다.

## 9. 레퍼런스 관찰 순서

1. NotePlan: 일일·주간·프로젝트 노트의 연결.
2. Sunsama: 날짜 보드 다음 주간 회고 설명과 공식 walkthrough 링크.
3. Agenda: 프로젝트 선택·시간순 목록·집중 노트 모음.
4. Amplenote: 짧은 본문에서 상세 근거를 여는 장면.
5. Heptabase: 카드·화이트보드·연결·저널을 현재 메모와 비교.
6. Super Productivity·Obsidian: 보존·이력·내보내기·통신 조건.
7. WeekToDo: 주간 화면의 정보량과 행동 수.

공통 질문은 ‘몇 번 클릭하는가’와 함께 **‘이동한 뒤 원래 문맥을 얼마나 쉽게 회복하는가’**다. 같은 기록이 보드·요약·업무 이력·메모에 나타날 때 날짜와 업무명이 일관되게 보여야 한다.

권장 방향은 이미 쓴 기록을 다시 찾고, 읽고, 보고에 쓰는 연결의 완성이다.
