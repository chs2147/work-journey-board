## 1. 목적과 추천안

업무 보드는 업무의 현재 상태를 확인하는 공간으로, 업무 노트는 문서 가까이에서 편집하는 공간으로 정리한다. 기존 자유 보드·자료 카드·본문 블록 엔진을 재사용한다.

**추천 A: 기존 보드에 위젯을 놓는 방식 + 문서 집중형 노트.** 상단 `+`에서 Live Widget을 추가하고, 다른 객체와 같이 이동/크기 조절/다중 선택/화살표 연결한다. 노트에서는 전체 폭의 고정 서식 툴바를 정리하고 블록 이끌이 메뉴·선택 텍스트 옆 서식 팝오버를 사용한다.

| 대안 | 구조 | 장점·검토점 |
|---|---|---|
| **A · 자유 배치형 (추천)** | 위젯도 기존 캔버스 객체. 노트는 롤오버 이끌이+선택 서식 | 기존 사용법·공간 구성 유지, 자료 카드와 연결 가능 |
| B · 상단 상태 스트립형 | 경과일·중요 업무·최근 타임라인을 상단 고정 | 빠른 확인. 상단 공간을 계속 사용하며 위젯의 자유 배치 효과가 작음 |
| C · 대시보드 구역형 | 위젯 격자와 자료 보드를 두 구역으로 구성 | 상태/자료 구분이 쉬움. 현재 자유 보드와 구조 변화가 큼 |

시안의 `A/B/C` 선택은 위젯 배치 차이를 비교한다. 노트 편집과 안전 절차는 공통이다.

## 2. 요구사항 대응표

| 요구 | 상세 결정·시안 |
|---|---|
| 업무 진행 경과일 | 업무 최초 시작일 기준 경과 달력일을 기본 제안. 마지막 기록일 기준도 선택 가능, 시안의 날짜 이동으로 갱신 확인 |
| 업무 타임라인 | 같은 공간·업무의 주간 기록에서 년월→주차→업무 내역 요약. 원문 이동 |
| 미완료 중요 업무 | 같은 업무의 중요·미완료 항목만 표시. 완료 버튼은 메인과 동일 원본 항목을 변경 |
| 모든 본문 행의 이끌이 | 문서 블록·목록 항목별 롤오버/키보드 포커스 버튼. 클릭=메뉴, 드래그=순서 이동 |
| 블록 종류·텍스트 근처 서식 | 블록 종류는 이끌이 메뉴로, 텍스트 스타일·링크·글자색은 선택 근처 팝오버로 이동 |
| 동일 색상 세트 | `TEXT_COLORS`: 기본(색 제거) + gray/orange/blue/green/red, 주간 메모와 같은 토큰 |
| 저장 상태 디자인 | 메인 TopBar의 녹색 체크 알약/저장 중/실패 컴포넌트를 공용화 |
| 중복 설명 제거 | 보드 제목 아래와 도크 상단의 `업무당 하나의 자유 메모보드`를 모두 제거 |
| 자료 객체 네 방향 연결 | 자료·노트·폴더·링크·주간 원본 카드 및 위젯에 같은 네 방향 핸들 제공 |
| 내보내기 버튼 | 일반 내보내기 모노그램 아이콘 + `내보내기`, 기존 Markdown/이미지 기능으로 연결 |
| 업무 보드 삭제 확인 | 영향 범위 안내 + `삭제`를 직접 입력해야 활성화되는 최종 확인 |
| 주간 메모 목록 정렬 | 연결됨 라벨은 왼쪽, 원본 열기 아이콘은 오른쪽 체크박스와 같은 세로 축 |
| 노트 줄 간격 | 본문 line-height 1.9→1.65, 문단 상하 여백 12→6px 기준 제안 |
| 삭제한 노트 창 종료 | 삭제 성공 후 해당 noteId 창만 자동 종료. 저장 실패 시 삭제·창 종료 모두 중단 |

## 3. Live Widget 공통 규칙

### 3.1 소유와 표시

- 위젯은 **현재 workspace의 category.id에 종속되는 업무 전용 보드 객체**다. 날짜별 entry_item.id는 위젯 소유자가 아니다.
- 추가 메뉴에 `Live Widget › 경과일 / 업무 타임라인 / 중요 업무`를 제공한다. 세 종류를 모두 하나씩 추가할 수 있고, 동일 종류의 추가 배치도 허용한다(설정·표시 범위를 다르게 둘 수 있음). 동일 category 질의는 재사용한다.
- 제목, 타입 아이콘, 업데이트 상태, `⋯` 설정 메뉴를 공통 제공한다. `Live`는 원본을 다시 읽는 동작을 의미하며 외부 서버 통신이 아니다.
- 다른 객체와 동일한 좌표·줌·선택·다중 이동·크기 조절·관계선·배치 삭제·Undo를 지원한다. 위젯 본문 클릭은 이동을 시작하지 않고, 머리 또는 선택 프레임을 잡아 이동한다. 내부 완료·스크롤·원문 버튼은 캔버스 제스처와 분리한다.
- 위젯 배치/설정 변경만 보드 저장 대상이다. 오늘 날짜나 원본 업무가 갱신되어 표시 값이 바뀌는 것은 보드 문서 수정으로 저장하지 않는다.
- 위젯 제거는 보드 배치만 지운다. 원본 업무항목·중요 표시·완료 상태·주간 기록은 바뀌지 않는다.
- 최소 크기 제안: 경과일 240×160, 타임라인 340×280, 중요 업무 340×240px. 좁히면 내부 세로 스크롤과 짧은 요약을 사용하며 내용 때문에 객체를 자동으로 무한 확대하지 않는다.

### 3.2 갱신·오류·성능

1. 창 열기/복귀/업무 변경 후 최신 snapshot 조회.
2. 메인에서 업무 입력·중요 표시·완료·취소·삭제·가져오기·복제가 성공하면 범위가 명확한 데이터 변경 이벤트를 발행.
3. 같은 category의 구독을 묶어 약 150ms debounce로 새 snapshot을 읽고, 영향을 받는 위젯만 다시 그림.
4. 경과일은 기기 로컬 달력 날짜를 사용한다. 다음 자정 예약 + 창 focus/visibility 복귀 시 날짜 비교로 절전·시간 변경·자정 넘김을 보완한다. 날짜 차이는 달력 날짜 ordinal로 계산하며 밀리초/24시간 나눗셈에 의존하지 않는다.
5. 숨겨진 창은 반복 질의를 멈춘다. 이미지 base64나 전체 업무 기록을 매번 전송하지 않는다. 타임라인은 집계/요약·페이지 단위, 중요 업무는 초기 20개와 더 보기.
6. 데이터 변경 요청 중에는 해당 항목 버튼만 잠근다. 실패 시 체크 상태를 복구하고 재시도 안내를 표시한다. 로딩/빈 목록/원본 삭제/데이터 읽기 실패를 구분한다.
7. workspace epoch가 바뀌면 구독과 날짜 타이머를 해제한다. 이전 공간의 결과는 무시하고 현재 공간 위젯에 섞지 않는다.

### 3.3 복제와 내보내기

- 같은 업무 보드 내 복제는 같은 원본을 보는 새 배치이며 설정만 독립이다.
- 다른 업무 보드로 복제 시 **목적지 업무에 연결**한다는 확인 미리보기를 제공한다. 출처 업무를 조용히 바꾸지 않는다. 승인 후 새 위젯은 목적지 category를 사용한다.
- 주간 보드로 옮길 때는 그 시점의 **일반 텍스트/표현용 객체 사본**으로 변환하고 `기준일`과 출처를 남기는 안을 추천한다. 날짜별 보드에 새 라이브 소유 규칙을 추가하지 않는다. 이 정책은 최종 검토 대상이다.
- Markdown 내보내기는 경과일·타임라인 목록·중요 업무 체크 목록을 읽을 수 있는 텍스트로, PNG는 보이는 상태로 출력한다. 위젯 ID나 실행 코드를 파일에 넣지 않는다.
- 내보내기 시작 시 하나의 snapshot/기준 시각을 고정해 문서 중간에 완료·날짜 상태가 바뀌지 않게 한다. 원본을 변경하는 완료 컨트롤은 내보낸 파일에는 없다.

## 4. 위젯별 설계

### 4.1 경과일

**원문 해석 제안:** ‘업무 진행일로부터 n일’은 기본적으로 최초 업무 시작일부터 오늘까지의 경과일로 본다. 이 기준이 사용자의 의도와 같은지 최종 검토 때 확인한다.

| 기준 | 데이터·계산 | 표시 |
|---|---|---|
| **업무 시작일 (기본)** | category_period의 가장 이른 start_date → 오늘 | `37일 경과` / `2026.10.01 시작 · 2026.11.07 기준` |
| 마지막 기록일 | 같은 category에서 오늘 이하의 가장 최근 entry_item.date → 오늘 | `마지막 기록 후 1일` / 기준 원본 날짜 |

- 시작 당일은 `0일 경과`. `1일차`와 섞지 않는다.
- 시작일이 미래면 `시작까지 n일`, 데이터가 없으면 `기준일 없음`을 보여 준다. 결측 값을 0으로 만들지 않는다.
- 업무 중단/재개 기간이 여러 번이어도 기본은 최초 시작일부터의 달력 경과일이다. 활성 업무일 합산은 별도의 계산이므로 이번 기본값에 포함하지 않는다.
- 종료 업무도 원래 시작일과 종료 상태를 표시하며, 요청대로 오늘 기준 경과일은 갱신한다.
- 위젯 값은 읽기 전용. 설정에서는 기준 선택·제목·기준일 표시 여부를 조정한다.

### 4.2 업무 타임라인

- 인사이트 `업무 타임라인`과 같은 기록 선택·년월/ISO 주차 분류를 재사용한다. 기록이 없는 날을 활동일로 만들지 않는다.
- 기본 최근 8주, `전체 기간 / 최근 4·8·12주` 설정. 최초 20개 요약 행과 더 보기. 소속 업무가 종료되어도 기록을 조회할 수 있다.
- 년월(16px) → 주차(14px) → 상세 내역(13px) 위계와 구분선을 제공한다. 같은 위젯 크기에서 한눈에 보이도록 본문은 2줄 요약, 펼치기 아이콘으로 확장한다.
- 항목/주차의 원문 열기는 메인 창의 해당 주·업무·항목으로 이동한다. 위젯에서 본문을 별도로 수정하지 않는다.
- 범위 밖 기록, 원본 삭제, 빈 기간을 각각 안내한다. 위젯 내 펼침 상태는 UI 상태이며 원본 기록의 변경이 아니다.

### 4.2.1 타임라인 표현 유형 — 추가 요청 반영

한 타임라인 위젯의 `variant`를 선택하는 방식이다. 같은 보드에 서로 다른 유형을 여러 개 배치할 수 있다. 기존 기록 목록형을 유지하고, 새로 선택할 수 있는 **가로 마일스톤형**과 **가로 주차 요약형**을 추가 제안한다. 보드 전체의 A/B/C 배치안과 위젯의 T1/T2/T3 표현 유형은 별도 설정이다.

| 유형 | 표시 내용 | 추천 용도 |
|---|---|---|
| T1 · 기록 목록형 | 년월→주차→업무 내역 | 상세 기록 확인, 기존 기본형 |
| **T2 · 가로 마일스톤형 (추천)** | 주요 기록의 날짜·점·짧은 제목, 한 줄 축 | 중요한 전환점을 심플하게 요약 |
| T3 · 가로 주차 요약형 | 기록이 있는 ISO 주차·기록 수·대표 기록 | 직접 고르지 않고 주간 흐름을 자동 확인 |

**T2 표시 제안:** `10.01 업무 착수 ─ 10.12 범위 확정 ─ 10.28 설계 검토 ─ 11.06 검증 완료`. 아래 날짜/제목은 모두 시안의 가상 원본 기록이다.

- `마일스톤 관리`에서 같은 업무의 주간 기록을 직접 선택한다. 최초에는 ‘주요’의 의미를 앱이 임의 판정하지 않고 선택 안내를 보여 준다. 원본 목록은 기간/검색/페이지 조회를 지원한다. 4~6개 선택을 권장한다.
- **중요 업무 별표·완료와 독립**이다. 마일스톤으로 골라도 원본의 중요/완료 상태는 변경하지 않는다. 위젯에서 점을 누르는 동작은 원본 열기이며 완료 명령이 아니다.
- 선택한 entry ID를 위젯별 config에 저장하고 원본 날짜순으로 표시한다. 원본의 날짜·제목이 바뀌면 갱신한다. 새로운 업무 기록은 선택 목록에 추가되지만 기존 마일스톤에 자동 추가하지 않는다.
- 기본 제목은 원본 첫 줄의 짧은 표시이고 길면 두 줄 이내 줄임·전체 제목 tooltip을 제공한다. 별도 사용자 표시 제목을 도입할 경우 위젯 설정만 변경하고 원본 텍스트는 유지한다(초기 시안은 원본 짧은 제목 사용).
- 점 간격은 **균등 배치**한다. 긴 기간이 긴 선으로 표현되는 시간 비례 도표가 아니다. 날짜를 함께 표시하고 위젯 footer/설정에 ‘날짜순·균등 배치’를 안내한다.
- 마지막 점의 약한 강조는 ‘가장 최근 선택 기록’이다. 완료율·전체 업무 완료 상태를 추정하지 않는다. 별도 완료 퍼센트는 표시하지 않는다.
- 원본이 삭제되면 관리 목록에 `원본 없음`을 표시하고 제거/대체를 선택할 수 있게 한다. 위젯에는 날짜를 지어내지 않는 끊긴 참조 안내를 표시하며, 유효한 기록과 구분해 뒤에 배치한다. 마일스톤 배치 삭제는 원본을 삭제하지 않는다.
- 가로형 권장 크기는 **640~960 × 180~240px**. 좁혀도 세로 목록으로 조용히 바뀌지 않고 위젯 내부 가로 탐색을 제공한다. 키보드로 각 점에 접근할 수 있고 날짜/제목/원본 열기 이름을 읽을 수 있다.

**T3 집계 규칙:** 같은 기간의 원본 업무항목을 `ISO year-week`로 묶어 실제 기록 수와 가장 최근 항목을 대표로 표시한다. 같은 날의 동률은 기존 seq/id 순서로 고정한다. 빈 주는 점을 생성하지 않으며 ‘빈 주 생략’을 표시한다. 대표 기록을 주요 마일스톤으로 판정하거나 AI로 요약하지 않는다. 연도를 넘으면 연도도 표시한다. 점 선택 시 해당 주의 업무 기록으로 이동한다.

**공통 데이터/레이아웃:** `config.variant = records | milestones | weeks`, `config.milestoneEntryIds`는 선택한 원본의 안정적 ID다. 유형을 바꿔도 객체 ID·좌표·크기·관계선과 마일스톤 선택은 보존한다. 크기 조정은 사용자가 수행한다. 데이터 변경 갱신은 기존 위젯 snapshot 구독을 사용하고 유형 변경만 보드 저장 대상이다. 복제·백업·복원에 설정을 포함하며, Markdown/PNG는 선택한 유형의 기준 시각 내용을 내보낸다.

**추가 인수 조건:** 유형 전환 시 원본 상태/객체 ID/선 보존, 위젯별 독립 유형·선택, 마일스톤 추가/제거/취소/0개 상태, 원본 제목·날짜 변경/삭제, 같은 날짜·연도 경계 정렬, T3 집계 수 일치, 좁은 위젯의 내부 가로 탐색·키보드 접근, 내보내기 기준 시각 일치.

### 4.3 중요 업무

- 조회 조건: **같은 workspace/category + flagged=1 + flag_done_at IS NULL**. 메인 중요 업무와 동일한 원본 선택/정렬 함수를 사용한다. 마감일 임박순→그 외 기존 목록 순서, 날짜·마감일 컬러칩 표시도 재사용한다.
- 완료는 기존 `boardStore.completeImportant` → `JournalRepository.completeFlag` 경로에 합류한다. 별도 ‘위젯 완료’ 필드는 만들지 않는다.
- 현재 `completeImportant`는 UI 오류 안내 후 void로 반환하는 경로가 있으므로, 성공/실패를 RPC가 구분하도록 공용 mutation을 추출해 typed result/예외를 반환하게 한다. 메인과 위젯의 UI wrapper는 이 공용 경로를 사용한다.
- 클릭 시 메인 편집 중 내용을 먼저 flush하고, 해당 entry가 여전히 같은 category의 중요·미완료 항목인지 재검증한다. RPC는 workspace epoch와 category 소유를 검증한다.
- 저장 성공 뒤 위젯에서 사라지고, 메인 중요 업무의 미완료 개수와 완료 목록·주간/데일리 줄의 취소선이 함께 갱신된다. `완료 처리됨 · 되돌리기` 토스트를 위젯 창에도 보여 준다.
- 원본에서 이미 완료된 항목을 다시 누른 요청은 중복 완료·중복 Undo를 만들지 않는다. 두 창의 경쟁 요청은 같은 결과를 반환한다.
- Undo는 같은 원본 entry의 해당 완료 시각/token을 확인하여 되돌린다. 다른 창의 이후 변경을 덮어쓰지 않는다. 중요 표시 복원은 기존 completion_was_flagged 규칙을 따른다.
- 읽기 전용/공간 연결 해제/업무항목 삭제 시 완료 버튼을 비활성화하고 이유를 표시한다.

## 5. 노트 편집기

### 5.1 블록 이끌이

- 문서 제목은 제목 필드, 본문의 문단·제목·목록 항목·체크 항목·인용·코드·이미지·표는 각각 유효한 구조 단위로 이동한다. 자동 줄바꿈된 시각적 한 줄은 원래 문단에 속한다. 표는 전체 표를 하나의 블록으로 이동하고 표 내부 행 편집은 표 명령으로 처리한다.
- 본문 왼쪽 고정 gutter에 메인 업무항목과 같은 6점 모노그램 이끌이를 둔다. 롤오버·현재 블록의 키보드 포커스·메뉴 열림·드래그 중에만 보이며 본문 가로 위치는 흔들리지 않는다. 터치에서는 활성 블록에 노출한다.
- 이끌이 클릭: `블록 종류 › 본문/H1/H2/H3/글머리/번호/체크/인용/코드`, 위/아래 이동, 복제, 삭제. 상단 `블록 종류` 버튼은 제거한다. 기존 `/` 입력도 같은 명령 목록을 사용한다.
- 이끌이 드래그: 임계 이동 후 시작, 삽입선·소형 드래그 미리보기 표시, 가장자리 자동 스크롤, Esc/취소 시 원복. 문서 흐름의 앞/뒤/유효한 목록 위치에 삽입한다. 하나의 ProseMirror transaction/Undo로 처리한다.
- 목록 항목을 움직일 때 중첩된 자식도 함께 이동한다. 코드·표 내부 구조가 깨지는 위치는 드롭 대상으로 허용하지 않는다. 한글 조합 중에는 편집 명령을 실행하지 않는다.
- 클릭/드래그 판정은 5px 내외 임계값과 drag 완료 후 click 억제로 분리한다. 키보드 메뉴/위·아래 이동을 제공해 드래그에만 의존하지 않는다.

### 5.2 텍스트 선택 팝오버

- 선택 텍스트 바로 위(공간 부족 시 아래)에 `B / I / S / 코드 / 링크 / A(글자색)` 모노그램 버튼을 제공한다. 클릭·키보드 조작 중 selection bookmark를 유지한다.
- 링크 입력은 선택 위치에 연결된 작은 입력창으로 열며 URL 입력/적용/해제와 검증 오류를 표시한다. 기존 앱의 http/https 링크 검증·열기 규칙을 재사용한다.
- 색상은 주간 메모의 **기본 + 회색·주황·파랑·초록·빨강**으로 고정한다. 동일 `TEXT_COLORS`·CSS 토큰·tooltip/aria-label을 사용한다. 칩 하단 색상 띠는 직각이다. 선택된 색상은 체크/테두리로도 구분한다.
- 선택이 없을 때는 현재 커서의 스타일을 표시하는 키보드 진입 명령을 제공하고, 문단 자체의 종류 변경은 이끌이 메뉴에서 수행한다.
- 팝오버는 노트 창의 스크롤/확대/크기 변경을 따라가고 화면 밖으로 나가지 않는다. Esc는 팝오버만 닫으며 본문 selection은 유지한다.

### 5.3 읽기 밀도

현재 본문 line-height 1.9·문단 margin 12px를 **1.65·6px**로 줄이는 안을 추천한다. 제목 계층은 유지하되 H2/H3 전후 여백을 본문보다 크게 둔다. 체크박스/목록 줄은 같은 baseline에 맞추고 중첩 구조가 구분될 정도의 들여쓰기를 유지한다. 시안에서 기존 간격 보기와 비교할 수 있다.

## 6. 보드·주변 UI

### 6.1 공통 저장 상태

메인 `TopBar`의 표시를 공용 `SaveStatus`로 추출해 메인·노트·업무 보드에 사용한다. 녹색 체크/테두리 알약, 회색 저장 중·스피너, 빨간 실패/재시도와 tooltip을 그대로 맞춘다. 400ms 이내 저장은 깜빡임을 억제한다. 위젯 원본을 읽는 중인 상태를 문서가 저장 중인 것으로 표시하지 않는다.

### 6.2 네 방향 연결점

`ResourceCard`는 이미 `EdgeKnobs`를 렌더링한다. 표시 조건은 `showEdges` 및 다중 선택/편집 상태에 영향을 받는다. 추가로 `Note.module.css`의 핸들 노출 규칙은 `.box:hover .knob`·`.selected .knob`인데, 자료 카드는 `Cabi.module.css`의 `.reference`·`.selected`를 사용한다. CSS Module 클래스가 서로 달라 노출 규칙이 적용되지 않는 것이 유력한 원인이다. 구현 때 이 상태와 overflow·hit-test·pointer 전파를 실제로 재현해 확인한다. 아직 실기에서 원인 전부를 재현한 것으로 단정하지 않는다.

추천: 객체 선택 또는 롤오버 시 동/서/남/북 중앙 핸들을 노출하고 드래그해 연결. 기존 선 잇기 도구/메뉴도 유지한다. 자료 카드·위젯 모두 같은 컴포넌트, 줌 좌표 보정·포인터 캡처·Esc 취소·내부 버튼과 드래그 충돌 방지 규칙을 적용한다. 노드/선/화살표의 저장 ID를 바꾸지 않는다.

### 6.3 헤더와 내보내기

- 보드 헤더는 `업무명 / 저장 상태 / + Live Widget / 자료함 / 주간 메모 / 내보내기 / 삭제`로 정리한다.
- 헤더 아래와 도크의 중복 설명 두 곳을 제거한다. 설명 공간을 빈 행으로 남기지 않고 캔버스를 위로 올린다.
- `Markdown으로 내보내기`는 일반 내보내기 아이콘 + `내보내기`로 변경. 메뉴는 기존 Markdown(.md+이미지)과 PNG 스냅샷으로 연결한다. 새 PDF 보드 내보내기를 구현 범위에 암묵적으로 추가하지 않는다.

### 6.4 삭제 확인

1. 삭제 아이콘 → 객체/위젯 수와 업무명을 표시한 확인 모달.
2. 보드에만 있는 메모·이미지·배치·관계선·위젯이 삭제된다고 안내. 원본 업무항목·등록 폴더/링크·업무 노트·주간 보드의 원본은 유지.
3. **`삭제`를 직접 입력**해야 최종 버튼 활성화. 입력 전에는 disabled, Enter도 실행되지 않는다. Esc/취소 시 변경 없음.
4. 최종 확인 후 strict flush와 revision 검증. 실패 또는 중간 변경이면 삭제하지 않고 사유 안내/재확인.
5. 성공 시 보드 store/timer를 detach한 후 창을 닫는다. 닫기 flush가 삭제된 보드를 다시 저장하지 않는다.

### 6.5 주간 메모 목록

각 항목 header 오른쪽에 체크박스, footer 왼쪽에 `연결됨`, footer 오른쪽에 `원본 열기` 모노그램 아이콘. 체크박스와 아이콘 중심은 같은 x축, 카드 오른쪽 16px gutter를 공유한다. 라벨/버튼 사이 최소 12px. 버튼은 독립 요소로 두어 클릭이 카드 체크 선택까지 토글하지 않는다. 원본 열기는 tooltip·aria-label·키보드 포커스를 제공한다.

## 7. 노트 삭제 시 열린 창 종료

### 코드 관찰과 수정 경로

현재 메인은 삭제 뒤 일반 `changed`만 발행하고, 노트 창은 초기 noteId 로드 중심으로 구독한다. 삭제한 noteId를 지정하는 종료 경로가 부족한 것이 원인 후보다. 구현 착수 시 허브 삭제/노트 내부 삭제/다른 창 삭제 각각 재현한다.

- 메인 조정기는 해당 노트 편집창을 잠그고, pending autosave·이미지 작업·draft의 저장 승인을 확인한다. 실패하면 원본 삭제도 창 종료도 하지 않는다.
- revision 비교 삭제 성공 후 `{type:'documentRemoved',kind:'note',id,epoch}`를 발행하고 소속 허브/참조 카드를 갱신한다.
- 일치하는 노트 창만 타이머/비동기 generation/flush 구독을 해제하고 저장 종료 처리 후 닫는다. 삭제된 문서에 대해 close handler가 다시 저장하지 않게 한다. 다른 노트·업무 보드 창은 유지한다.
- 이벤트 중복·늦은 저장 응답을 안전하게 무시한다. 주기적인 404만으로 다른 문서를 닫지 않는다. 공간 변경은 기존 detach/epoch 경로를 유지한다.
- 창 종료가 OS에서 실패하면 `삭제된 노트` 읽기 전용 상태와 닫기 버튼을 표시한다. 저장되지 않은 내용이 있어 삭제가 중단된 상황과 구분한다.

## 8. 데이터·이벤트 구조 제안

- 목표 DB **v17**은 신규 migration에서만 올린다. v16 파일을 수정하지 않는다. JSON의 새 객체 종류를 이해하지 못하는 이전 앱이 보드를 열어 저장하는 것을 구조 버전 검사로 차단한다. 실제 번호는 구현 착수 때 최신 main과 재확인한다.
- 업무 보드 DB 레코드 `format_version=2`: 기존 보드를 읽고 다음 저장 때 갱신한다. 모든 문서를 시작 시 일괄 다시 쓰지 않는다. 공유 보드 JSON의 `v:1` 좌표 엔진은 유지하며 DB v17 검사로 구 앱의 재저장을 차단한다.
- 구현 시 공유 보드의 복제·관계선·실행 취소 경로를 재사용하도록 `TextBox(kind:'text')`에 선택적 `widget:{type,basis,variant,weeks,milestoneEntryIds}` 설정을 추가했다. 공통 id/x/y/w/h/z를 그대로 사용하며 본문은 비운다. 소속 업무는 BoardOwner에서 결정하고 표시값·원본 텍스트·완료 상태는 보드 JSON에 저장하지 않는다. 주간 보드에는 widget 설정 저장을 거부하고 현재값의 일반 텍스트 사본으로 변환한다.
- 메인 허용 명령: `widgetSnapshot(categoryId,scope)`, `widgetComplete(categoryId,entryId,requestId)`, `widgetUndoCompletion(token)`. 자식 창이 SQL이나 임의 repo 메서드를 실행하지 않는다.
- 기존 `changed` 이벤트와 단조 증가하는 구독 버전을 재사용하고, 삭제 알림 `documentRemoved`에는 kind/id/epoch를 담는다. 위젯 조회는 변경 이벤트와 저장을 만들지 않는다. 업무/설정/날짜 키별 조회 결과를 공유하고 숨긴 창은 조회를 멈춘다.
- category별 snapshot 요청 중복 제거, 오래된 요청 취소·epoch 확인, 날짜 timer 정리를 공통으로 둔다. 관계선 레이아웃은 위젯의 프레임 높이를 기준으로 하며 내부 스크롤로 선이 튀지 않게 한다.
- 신규 업무 위젯은 같은 SQLite 백업/복원에 포함한다. 복제/가져오기/백업 구조 검사/검색/Markdown/PNG/Undo의 새 객체 분기 누락을 구현 체크리스트에 포함한다.

## 10. 승인된 결정 (설계 검토 기록)

1. **A 자유 배치형** + 문서 집중형 노트로 진행. 타임라인 위젯은 T1 기록 목록 / **T2 가로 마일스톤 추천** / T3 가로 주차 요약 중 선택.
2. 경과일 기본 기준은 **최초 업무 시작일**(시안에서 마지막 기록일과 비교 가능).
3. 다른 업무 보드에 복제하면 목적지 업무에 연결하고, 주간 보드로는 기준 시각의 일반 객체 사본을 만드는 정책.
4. 보드 삭제는 **`삭제` 직접 입력**으로 확인하는 절차.
5. 노트 간격 **1.65 / 문단 6px**와 블록의 논리적 구조 단위 이동.

설계 검토 단계에는 제품 기능 목록을 변경하지 않았다. 구현 승인 후 검증판 `1.21.0-rc.1`의 기능 목록·이용 가이드를 동반 갱신한다. 정식 버전은 main 반영 시 확정한다.

### 12-1. 최종 원격 CI 회귀 수정

첫 원격 CI `42340857016`은 단위 519개·타입/린트/포맷·Rust 검사와 578개 E2E를 통과했지만, Chromium/WebKit의 8개 시나리오(총16건)가 실패했다. 공통 저장 표시의 새 `role=status`가 토스트의 같은 역할과 충돌한 선택자 7개와, 최초 저장 시각이 없을 때 기본 title을 생략한 저장 표시 1개가 원인이다.

토스트 검사를 기존 알림 live region으로 한정해 메시지·실행 취소 검증을 유지했고, 저장 상태는 시각이 없어도 기존 기본 도움말을 제공하도록 복원했다. 앱의 저장/가져오기/삭제 데이터 동작을 우회하지 않는다. 같은 RC 버전에서 수정 후 재검증하며 설치판도 최신 소스로 다시 빌드한다.

로컬 Chromium 관련 영역 38개 검사와 타입/린트 검사를 통과했다. 원격 전체 Chromium/WebKit 검증과 두 플랫폼 설치판 빌드를 새 커밋으로 다시 진행한다.


### 12-2. 1.21.0 정식 main 반영

사용자가 최종 CI 성공을 확인한 뒤 main 반영과 정식 1.21.0을 승인했다. 기존 main 1.20.0 (`58c19d0`)은 원격 `release/v1.20.0`에 보존했다. 최종 검증 커밋은 `9a138a7`, CI `42351204067`의 단위 519개/E2E 594개(1개 건너뜀)·macOS Rust 검사와 설치 파일 빌드 `42351204076`의 Windows 기본판/macOS 유니버설 DMG가 모두 성공했다. RC 이력/스냅샷을 유지하면서 정식 Feature List 도입 버전·가이드 HTML/PDF·릴리스 문서를 갱신하고 main에서 두 플랫폼 정식 산출물을 생성한다. Windows 오프라인판은 포함하지 않는다.
