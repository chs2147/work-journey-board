## 2. 세션별 상세

### M2-S1. 자동 집계 + 주간 요약 패널

**domain (순수 함수)**
- `aggregate.ts`
  - `buildWeeklySummary(input, { includeMemo }) → string` — 입력은 저장소에서 꺼낸 한 주 자료(보드 제목, 보이는 업무 목록(보드 순서), 칸별 항목, 날짜별 메모). output-spec 2-1의 9규칙 그대로:
    - 업무 순서 = 보드 순서, 항목 0개 업무는 본문에서 빼고 맨 끝 `※ 이번 주 기록 없음: …` 한 줄
    - 본 항목 `- (요일) 내용`, 세부 항목 `  · 내용`, 항목 안 줄바꿈은 같은 들여쓰기로 이어 쓰기
    - 메모는 `[메모]` 블록(끄면 빠짐), 기호는 `■`·`-`·`·`만
  - `finalVersion({ edited, ai }) → "edited" | "ai" | "auto"` — 최종본 고르기(수정본 > AI본 > 자동 집계본). 패널·엑셀이 같은 함수를 쓴다.
  - `basisHash(text) → Promise<string>` — SHA-256(Web Crypto `crypto.subtle`, 외부 통신 없음). 해시 대상은 **메모 포함 여부와 무관하게 메모를 포함한** 자동 집계본(설정만 바꿨을 때 "기록이 변경됨"이 뜨지 않게).
- 매주 반복으로 들어와 손대지 않은 항목도 **일반 기록처럼 집계**한다(important-repeat-spec 6절 — 무기록 판정 예외와 다름).
- 종료된 업무: 그 주에 보이는 업무(이 주 중 종료·기록만 있음 포함)는 집계, 보이지 않는 업무는 제외 — `categories.ts`의 표시 규칙을 그대로 재사용.

**data**
- `JournalRepository`
  - `getSummaryInput(weekId)` — `getWeek`와 같은 표시 규칙으로 집계 입력을 만든다(새 SQL은 `weekly_summary` 읽기만).
  - `getWeeklySummary(weekId)` → `{ editedText, editedBasisHash, editedAt, aiText, aiBasisHash, aiSavedAt } | null`
  - `saveEdited(weekId, text, basisHash)` / `deleteEdited(weekId)` — 다른 열(`ai_*`)은 건드리지 않는 upsert(`SqlDriver.batch` 1회).
- 스키마 변경 **없음**(0001의 `weekly_summary` 그대로). 설정은 기존 `summary.includeMemo`·`ui.summaryPanelOpen` 사용.

**화면**
- 상단 2줄 오른쪽에 **[주간 요약]** 버튼(열림 상태면 눌린 모양). 단축키 **`Alt+S`**(6절 결정 3). 열림 상태는 `ui.summaryPanelOpen`에 기억.
- **패널**(보드 오른쪽, 폭 360px, 머리줄 `주간 요약 · 2026-W43` + [닫기]) — **보드에서 보고 있는 주**를 따라간다(주 이동 시 함께 바뀜).
  - 탭: **자동 집계 | 수정본**(저장된 수정본이 있으면 ●). 머리에 `최종본: 수정본`/`최종본: 자동 집계`.
  - 자동 집계 탭: 읽기 전용 글 상자(고정폭 아님, 줄바꿈 유지) + `[✓] 메모 포함` + [수정본 만들기]. 보드에서 기록을 고치면 **저장 직후 다시 계산**해 바로 반영.
  - 수정본 탭: 편집 상자(자동 저장 0.5초 — 보드와 같은 저장 상태 표시) + [자동 집계로 다시 만들기](확인 창) + [수정본 삭제](토스트 [되돌리기]).
  - 근거가 달라지면 수정본 탭 위에 `작성 후 기록이 변경되었습니다 · [자동 집계본과 비교]` — 비교는 지금 자동 집계본을 수정본 아래에 접힌 상자로 펼쳐 보여 준다(자동으로 덮어쓰지 않음).
  - 맨 아래 **[최종본 복사]** — 실앱은 clipboard-manager, 브라우저 모드는 `navigator.clipboard`. 복사 후 토스트 `최종본(수정본)을 복사했습니다`.
- **자리 규칙**(6절 결정 2): 레일(52) + 중요 업무 패널(264, 열렸을 때) + 요약 패널(360)을 빼고도 보드 폭이 **900px 이상** 남으면 보드를 밀어내고, 아니면 요약 패널을 보드 위에 **겹쳐** 띄운다(그림자, 보드 칸을 누르면 닫힘 — 중요 업무 패널의 1180px 규칙과 같은 방식).
- 키보드: `Alt+S`로 열면 패널 첫 탭에 포커스, `Esc`는 보드의 이전 칸으로. 탭 전환은 `←`/`→`.

**구현하며 정한 점 (M2-S1)**
- 자동 집계는 DB가 아니라 **보드 화면 상태**에서 계산한다 → 저장 전 입력 중인 글까지 바로 반영. 엑셀(M2-S2)은 같은 함수를 저장소 자료(`getSummaryInput`)로 부른다.
- **근거 해시는 만들 때·다시 만들 때·[확인함]을 누를 때만** 정한다. 수정본 글을 고쳐도 그대로라, "기록이 변경되었습니다" 안내는 사용자가 확인할 때까지 남는다(글을 고치다가 안내가 저절로 사라지지 않게).
- 수정본 저장은 상단 "저장 중…/저장됨 ✓" 표시를 같이 쓰고, 창 닫기·저장 위치 전환 전에 대기 중인 수정본도 저장한다.
- [최종본 복사]는 플랫폼 `writeClipboard`(실앱 clipboard-manager, 브라우저 모드 `navigator.clipboard`) — 사용자가 누를 때만 쓴다.
- 패널 단추는 상단 2줄 오른쪽 저장 표시 앞 [주간 요약](켜지면 강조), 단축키 `Alt+S`.

### M2-S2. 엑셀 내보내기

**export (순수 + ExcelJS)**
- `textWidth.ts`: 표시폭(한글·전각 2, 그 외 1)과 행 높이 계산 `max(15, 줄 수 × 13.5 + 3)` — output-spec 3-1 공식. 병합된 요약 행은 병합 너비 합계로.
- `filename.ts`: 4규칙 + 로컬 날짜(overview 13-3 #3).
- `excel.ts`: `buildWorkbook(range, data, { sheets, appVersion, exportedAt }) → Uint8Array`
  - **주간보고**: 오래된 주부터 블록(제목행 병합·머리행·업무 행(왼쪽 굵은 테두리 = 업무 색)·메모 행·요약 행(최종본 = 수정본 > AI본, 없으면 `—`, 첫 줄 `[수정본]`/`[AI본]`)·빈 행). 블록에 넣는 업무 = 자동 집계와 **같은 함수**로 고른다. 토·일 열은 범위 안 어느 주라도 기록이 있을 때만 시트에 존재하고, 블록별로 그 요일 기록이 있을 때만 머리·칸·테두리를 만든다.
  - **원장**: `날짜 | 주차 | 요일 | 업무 | 순번 | 세부 | 내용` (+ 6절 결정 4의 `중요` 열), 날짜는 엑셀 날짜 값 `yyyy-mm-dd`, 메모는 `(메모)`, 틀 고정 A2, 자동 필터, 종료된 업무의 과거 항목 포함.
  - 글꼴 **맑은 고딕** 10pt(회사 PC 엑셀 기준 — 앱 화면 글꼴 Pretendard와 다름, 6절 결정 9), A4 가로·너비 1페이지·바닥글, 문서 속성(제목·작성 프로그램 `Work Journey Board <버전>`·만든 날짜), 주간보고 시트 활성.
  - 업무 색: 팔레트 키 → **라이트 테마 색값**(viz-spec 6절)으로 고정(인쇄용).
- **ExcelJS는 동적 import** — 내보내기를 처음 열 때만 불러와 앱 시작(스플래시 2.5초·바로 타이핑)에 영향이 없게. 런타임 네트워크 호출 없음을 확인하고 커밋 설명에 적는다(CLAUDE.md 4-1).

**data**
- `getExportData(fromWeek, toWeek)` — 주별 집계 입력 + 원장 행 + 주별 최종본. 주 목록은 `domain/week.ts`로 만들고 SQL에서 주차 계산 금지(`strftime('%W')` 금지, CLAUDE.md 4-4).
- `firstRecordWeek()` — "전체" 범위의 시작(첫 기록 주 ~ 이번 주).

**platform**
- `Platform.saveExport(suggestedName, defaultDir, bytes) → { path } | null`
  - 실앱: dialog 플러그인 **저장 대화상자**(덮어쓰기 확인은 윈도우 대화상자 그대로) → Rust 명령 `export_write(path, bytes)` 1개 추가. Rust에서 **확장자 `.xlsx`만 허용**, 저장 폴더의 `work-journey.db`·`backups\` 안은 거부(이중 가드). 6절 결정 5의 규칙 보완과 함께.

**구현하며 정한 점 (M2-S2)**
- ExcelJS는 **별도 조각(약 930 kB, gzip 256 kB)으로 내보내기를 처음 할 때만** 불러온다 — 앱 시작 번들은 그대로. 의존성은 런타임 네트워크 호출 없음. `npm audit`의 uuid 경고(moderate)는 uuid v3/v5/v6에 버퍼를 넘길 때만 해당하며 ExcelJS는 v4만 써서 이 앱과 무관.
- 내보내기 전에 **입력 중인 칸·수정본을 먼저 저장**하고 읽는다(0.5초 자동 저장을 기다리지 않음).
- 저장 폴더 기억: 마지막으로 저장한 폴더(`ui.lastExportDir`)가 없어졌으면 `저장 폴더\exports`로 돌아간다(없으면 만든다).
- 파일 쓰기는 임시 파일(`*.xlsx.tmp`)에 다 쓴 뒤 바꿔치기 — 엑셀에서 같은 파일이 열려 있으면 "닫고 다시 시도" 안내.
- 엑셀 업무 색은 인쇄를 고려해 **라이트 팔레트** 값으로 고정. 원장 날짜는 시간대와 무관한 엑셀 날짜 값.
- 토스트에 단추를 여러 개 둘 수 있게 했다([폴더 열기] [파일 열기]).
- 브라우저 모드의 저장은 경로 입력 + 내려받기로 대신한다(E2E는 내려받은 파일을 ExcelJS로 다시 읽어 검사).

## 3. 데이터 안전·보안
- **외부 통신 0 그대로**: 엑셀은 앱 안에서 만들고, 파일은 사용자가 고른 위치에만 쓴다. 클립보드 쓰기는 사용자가 [최종본 복사]를 누를 때만.
- 덮어쓰기 범위가 넓어지는 유일한 변경 = 내보내기 파일 쓰기. 6절 결정 5로 규칙을 명시하고 Rust에서 다시 검사한다. 일지 파일·백업은 여전히 덮어쓰지 않는다.
- 테스트·샘플·스크린샷은 가상 데이터만. 실제 기록으로 만든 엑셀은 저장소·세션에 올리지 않는다(확인은 회사 PC에서 사용자가).
- 스키마 변경 없음 → 마이그레이션·직전 백업 불필요.
