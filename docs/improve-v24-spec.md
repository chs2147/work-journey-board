## 1. 온라인 워크스페이스

### O1. 신규 공간 아이콘·색상

- 확인한 경로는 `CreateOnlineDialog` → `prepareEmpty` → `app_meta.settings.workspace` → 게시 → `workspace_list` → `onlineSpaceStore`입니다. `025-workspace-list-label.sql`의 `workspace_label`은 아이콘 ID를 소문자로만 제한합니다. 앱 아이콘 `chartUp`, `chartBar`, `cardIndex`, `moneyBag`, `creditCard`는 저장할 수 있지만 서버 목록에서 외형 전체가 `null`이 됩니다. 따라서 유효한 색상까지 목록에서 빠집니다. 동기화 설정 행은 있으나 외형을 읽을 수 없을 때 게시 사본으로 넘어가지 않는 경로도 확인했습니다.
- 서버 목록 검증을 앱의 28개 아이콘 ID와 일치시키고, 동기화된 설정과 게시 사본 중 유효한 최신 설정을 표시합니다. 색상·아이콘에 대해서는 앱의 허용 목록과 서버의 허용 목록을 시험에서 대조합니다. 기존 게시·동기화 행에 들어 있는 유효한 값은 목록을 다시 읽을 때 복원할 수 있어야 합니다. 기존 설치 SQL은 보존하고 함수 수정이 필요하면 신규 전진 마이그레이션으로 개발 환경에서 먼저 검증합니다.
- 게시 완료 시 확인한 공간 ID와 외형을 함께 넘겨 완료 카드·열린 공간 레일에 표시합니다. 서버 목록을 갱신해 확인된 값을 반영하되, 같은 계정·공간의 오래된 요청이나 외형이 빠진 중간 응답이 방금 게시한 외형을 기본값으로 바꾸지 않게 합니다. 계정이 바뀌거나 게시가 실패하면 임시 표시를 정리합니다.
- 완료 기준은 게시 직후·재실행·다른 기기 로그인에서 완성 화면·서버 목록·열어 둔 일지의 외형이 일치하는 것입니다. 대문자 혼합 아이콘과 기본 아이콘, 다른 색, 복제 공간, 게시 뒤 외형 수정, 외형이 누락된 기존 공간을 각각 시험합니다.

### O2. 공간 전환 문구

- 온라인 공간의 첫 동기화 상태를 **`서버와 동기화 중…`**으로 표시합니다. 한국어 띄어쓰기와 기존 말줄임표 표기를 적용했습니다.
- 첫 동기화 대기 상한 10초와 기존 온라인 사본 열기 흐름을 따릅니다. 오프라인 사본으로 열면 보드의 동기화 상태에서 그 결과를 표시합니다. 오류로 전환이 중단되면 잠금을 풀고 원래 공간에서 오류를 확인할 수 있게 합니다.

### O3. Cabinet 등록 폴더 열기

- 확인한 차이는 로컬 플랫폼이 `cabinet_set_roots`로 현재 일지의 등록 폴더 목록을 Rust에 전달하는 데 있습니다. 온라인 플랫폼은 폴더·Cabinet 별도 창을 네이티브로 열면서 `cabinetSetRoots`를 빈 동작으로 두고 있습니다. 별도 창의 경로 요청은 기존 Rust 검사를 거치므로, 이 기기에서 지정한 온라인 폴더도 허용 목록이 없으면 열리지 않습니다.
- 온라인 메인 창도 **현재 공간에서 이 기기에 지정한 폴더만** 기존 허용 목록으로 전달합니다. 이 기기에서 폴더를 다시 지정할 때는 네이티브 폴더 선택기를 사용하고, 선택한 경로에 대한 확인만 허용합니다. 복제·동기화의 폴더 경로 자리표시자는 그대로 유지합니다. 아직 지정되지 않은 행은 `[이 기기에서 경로 지정…]`으로 연결하고, 등록된 행은 `[탐색기에서 열기]`를 제공합니다(macOS `[Finder에서 보기]`).
- 공간 전환·로그아웃·등록 삭제 시 이전 폴더 창과 허용 범위를 정리합니다. 전환 중 늦게 돌아온 조회가 이전 공간의 목록을 재등록할 수 없게 합니다. Rust의 절대 경로·정규화·등록 폴더 및 하위 경로 검사를 재사용합니다. 탐색기 열기는 기존처럼 등록 폴더 안으로 들어갑니다.
- Windows·macOS에서 폴더를 다시 지정해 열기, 존재하지 않는 경로, 다른 기기에서 미지정, 로컬↔온라인·온라인↔온라인 전환 직후 옛 경로 거절, 권한 밖 링크·접두어가 비슷한 경로 거절을 확인합니다.

## 2. 공통 전체화면 로딩

| 안                       | 화면                                                               | 검토 포인트                                            |
| ------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------ |
| **A 중앙 카드형 · 추천** | 얕은 배경 가림 위 중앙 카드, 작은 진행 표시와 작업 문구 한 줄      | 어느 화면에서 전환해도 상태를 빨리 찾기 쉬움           |
| **B 상단 상태형**        | 앱 상단에서 직각 진행선과 중앙 정렬 상태 줄, 화면 전체에 옅은 가림 | 작업 맥락이 더 많이 보이고 보드 가운데가 가려지지 않음 |

- 적용 대상은 기존 전체 잠금 흐름인 온라인 공간 열기·로컬로 돌아가기·변경을 저장하고 목록으로 이동·로그아웃·앱 종료입니다. 장면마다 기존 작업 문구를 사용합니다. 백그라운드 동기화는 기존 상단 상태로 표시합니다.
- 종료 이벤트에서도 즉시 띄울 수 있는 현재 공통 DOM 진입점을 사용합니다. 잠금 동안 본문을 `inert`로 두고 키보드·포인터·스크롤과 앱 단축키를 차단합니다. 시작 때 설명을 한 번 읽고, 상태 변화가 있으면 필요한 문구만 알립니다. 종료 실패 등으로 화면이 남으면 잠금과 임시 초점을 해제하고 유효한 이전 초점으로 돌아갑니다.
- 실제 남은 시간을 모르는 작업에는 퍼센트나 예상 시간을 표시하지 않습니다. 동작 줄이기 설정에서는 정적 진행 표시를 사용합니다. 두 안 모두 좁은 창과 시그니처·라이트·다크 테마에서 문구와 배경을 구분할 수 있어야 합니다.

## 3. 칸반 보드

### K1. 섹션별 기간

| 섹션        | 기본과 설정                                                                                                              | 날짜 기준                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| TODO        | 상단 기간만 적용                                                                                                         | 기록일                       |
| 사용자 섹션 | 기본 `상단 기간 따르기`. 섹션 ⋯ › `[기간 설정…]`에서 `전체 기간` 또는 상단과 같은 기간 값·사용자 지정 범위를 별도로 고정 | 기록일                       |
| DONE        | 상단 기간만 적용                                                                                                         | 실제 완료일, 내 PC 날짜 기준 |

- 고정한 섹션에만 작은 기간 칩을 표시합니다. 예를 들어 상단 `이번 주` 중에도 `모니터링`을 `전체 기간`으로 고정하면 이전 주의 미완료 카드가 같은 상태로 남아 보입니다. 고정은 기간 조건에만 적용하고 업무·태그·검색·종료된 업무 설정은 보드와 같은 기준을 적용합니다.
- `listOpen`의 전역 기간 조건을 보완해 TODO·상단을 따르는 열린 섹션, 고정한 섹션 각각에 해당 기간을 적용합니다. DB에서 기간과 섹션을 함께 거릅니다. 전체 기간의 오래된 공간에서도 모든 세부·메모 정보를 한꺼번에 만들지 않도록 결과를 나눠 읽고, 목록의 끝까지 접근할 수 있게 합니다. 동일 기간에서 섹션 이동 시 같은 카드 ID가 두 열에 나타나지 않는지 확인합니다.

### K2. 카드 목록과 직접 순서

- 같은 열에서 카드를 원하는 위치로 끌어 놓으면 가로 삽입선 위치에 순서를 저장합니다. 카드에 초점을 둔 상태의 `Alt+Shift+↑`/`↓`도 지원합니다. 열 사이 드래그로 카드의 상태를 바꿉니다. 열 머리의 `[직접 순서 ↺]`를 누르면 기본 정렬로 돌아갑니다.
- 기본 정렬은 지금처럼 상단 정렬을 따릅니다. 직접 순서를 저장하면 해당 열만 `직접 순서`가 적용되고, `[기본 정렬로]`로 돌아갈 수 있습니다. DONE의 자동 모드에는 완료일 묶음을 유지하고, 직접 순서 모드에는 완료일을 각 행에 표시해 묶음을 넘나들며 배치할 수 있게 합니다. 날짜·완료 여부는 카드의 정렬과 독립입니다.
- 저장 값은 **공간별·기기별 보기 설정**을 추천합니다. 기존 `app_meta.settings.ui`의 독립 키에 섹션별 기간과 카드 ID 순서를 넣습니다. 예전 일지는 상단 기간·자동 정렬 기본값으로 열고, 온라인 공간의 설정은 해당 기기의 일지에만 보관하는 안입니다. 현행 온라인 매퍼가 공용으로 보내는 `ui.kanbanColumns`의 순서·아이콘과 새 보기 설정은 별도입니다. 설정 전파는 결정 D2에서 선택합니다.
- 현재 필터에 보이는 카드끼리의 위치만 다시 배치하며, 보이지 않는 카드 자리와 기존 순서는 보존합니다. 새 순서는 저장 직전의 섹션·카드와 대조합니다. 동기화 중 삭제되거나 이동된 카드는 건너뛰고, 새 카드나 저장 순서에 없는 카드는 그 열 끝에 기존 정렬 기준으로 붙입니다. 되돌리기·초기화 시 이전 설정 또는 자동 정렬을 복원합니다. 순서만 고칠 때 기록 날짜·요일 칸 순서·완료 시각·상태 이력에 쓰지 않습니다.
- 시험은 TODO/DONE에 섹션 기간 설정이 없는지, 과거 카드 겹침이 없는지, 필터를 바꿔도 숨은 카드의 순서가 남는지, 페이지를 넘긴 DONE과 저장·재실행·삭제·이동을 검증합니다.

### K3. 마감 경고

| 조건                  | 카드 배지               | 강조   |
| --------------------- | ----------------------- | ------ |
| 마감까지 2일 또는 1일 | `마감 D-2` / `마감 D-1` | 황색   |
| 당일                  | `오늘 마감`             | 주황색 |
| 기한 초과             | `마감 초과 N일`         | 적색   |

- 미완료 카드의 기존 마감 표시 자리를 사용합니다. D-3 이상은 날짜 표시, 마감 없음은 표시 없음으로 두고 DONE에는 경고 대신 기존 완료 표기를 유지합니다. 완료 취소 후에는 현재 날짜로 다시 계산합니다. 기존 `daysLeft`와 기기의 날짜 갱신을 사용하고 칸반의 2일 경고 기준만 둡니다. 날짜는 툴팁과 접근 가능한 이름에 포함합니다.

## 4. Universe

### U1. 동일한 본 항목 묶기

- 사용자 표현 `depth-1`은 첫 번째 들여쓰기 단계인 **본 항목**으로 해석했습니다. 현행 저장 구조는 본 항목 `depth = 0`, 세부 항목 `depth = 1`입니다.
- 기본 묶음 기준은 **같은 워크스페이스, 같은 업무 ID, 같은 본문 이름**입니다. 본 항목의 전체 이름을 NFC로 맞추고 앞뒤와 연속 공백을 정리해 비교합니다. 표시용으로 잘린 제목, 부분 일치, 다른 업무의 동명 항목은 묶음 키로 쓰지 않습니다. 날짜가 달라도 같은 묶음은 지도에 노드 하나로 표시합니다.
- 날별 원본 ID·기록일·세부 순서·마감은 보존합니다. 각 회차의 세부 항목은 날짜 및 순서를 유지한 채 해당 본 항목 아래로 연결합니다. 상세 패널 `[기록]`에서 날짜별 원본과 해당 세부를 펼치고 원래 기록으로 이동합니다. 기간·업무 필터는 먼저 원본을 좁히고 보이는 회차를 묶으므로 기간 밖 기록이 같이 나타나지 않습니다.
- 기존 원본 그래프와 직접 연결·메모·Cabinet·지식 카드의 저장 참조를 유지합니다. 화면 투영 때만 선의 끝을 묶음으로 연결하고 동일 표시선은 합치되, 상세에는 원본 양쪽·관계 방향·출처를 남깁니다. 같은 묶음 안의 직접 연결도 상세에서 확인합니다. 묶음에서 새 직접 연결을 만들 때는 날짜별 원본을 한 번 고릅니다. 검색 결과나 저장된 탐색 위치가 원본 ID를 가리키면 그 묶음과 회차를 열어 줍니다.

### U2. 표시할 노드의 우선순위

| 보기           | 기본 표시                                                                                 | 더 따라가기                                                      |
| -------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 전체 지도      | 공간·업무·본 항목 묶음. 태그와 직접 연결은 현재 필터와 표시 선택에 따라 보임              | 묶음을 선택해 상세·초점으로 이동                                 |
| 초점 탐색      | 선택한 묶음의 상위 업무, 바로 연결된 묶음·직접 연결, 그 기록에 연결된 메모·자료·지식 카드 | `[세부 펼치기]`로 원본 하위 항목, 연결을 선택해 다음 노드로 이동 |
| 상세 목록·검색 | 원본 회차·세부·첨부와 연결의 종류·날짜                                                    | 지도에서 감춘 대상도 검색 결과에서 바로 열기                     |

- 업무 소속과 날짜처럼 이미 상위 노드에서 알 수 있는 경로를 세부마다 반복 그리지 않습니다. 직접 연결 및 사용자가 찾아 들어간 기록은 우선 표시합니다. 보이지 않는 연결이 있으면 연결 목록에서 접근할 수 있게 합니다. 필터와 접힌 상태로 숨은 연결을 없는 연결처럼 처리하지 않습니다.
- 3D·2D·목록 화면이 같은 묶음과 탐색 위치를 사용합니다. 기존 1천·5천 노드 가상 데이터에 반복 본 항목을 넣고 지도에 그려지는 노드·선 수, 첫 표시 시간, 선택 후 탐색 가능 여부를 비교합니다. 성능 목표는 기준 측정 뒤 확정합니다.

## 5. 주간·데일리 엑셀 내보내기

- 공통 `[내보내기]` 창의 포함 항목에 `[ ] 주간 요약 시트`를 추가합니다. 기존 `주간보고 시트`, `원장 시트`, `메모 보드`와 독립 선택하고 요약만으로도 저장할 수 있습니다. 처음에는 해제 상태를 추천합니다. 데일리 뷰에서 들어와도 해당 날짜가 속한 주가 기본 범위이며 기간 선택은 기존과 같습니다.
- 새 시트명은 `주간 요약`. `주차 | 기간 | 요약 종류 | 요약 내용`으로 주차당 한 행을 둡니다. 주차 오름차순, 셀 줄바꿈, 머리행 고정을 적용합니다. 긴 요약은 Excel의 셀 글자·행 높이 한계를 넘기기 전에 같은 주 안에서 이어지는 행으로 나눠 내용과 순서를 보존합니다. 셀 내용은 글자로 저장합니다.
- 출력 우선순위는 화면의 최종본 규칙을 재사용해 **수정본 → AI본 → 자동 집계**로 합니다. 저장된 두 본이 모두 없으면 `buildWeeklySummary`와 현재 일지의 메모 포함 설정을 적용합니다. 내보내기 전에 편집 중인 요약을 저장하며, 기존 주간보고 시트의 요약 행 규칙은 별도 유지합니다. 기록과 메모가 없는 주는 선택한 기간에 포함된 경우 `—`로 표시합니다.
- 기존 엑셀 저장 경로 검사와 원장 형식을 유지합니다. 현행 온라인 플랫폼의 파일 저장 범위는 이 설계에서 확장하지 않습니다. 시험은 두 진입점, 단독·조합 선택, 여러 주, 수정본·AI본·자동 집계, 주간 메모 포함/제외, 긴 한글 요약과 기존 시트 셀 비교입니다.
