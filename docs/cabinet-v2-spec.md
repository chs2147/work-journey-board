# Cabi.NET — Cabinet V2 상세 설계·시안 검토안

작성: 2026-11-06 (한국 시간) · 기준: main `8c2ce2e`, 앱 1.19.0 / DB v15  
작업 브랜치: **`cabinet-v2`** · 상태: **추천안 H-A / N-A / B-A / W-A / D-A 구현 · 1.20.0-rc.1 브라우저 검증 · 네이티브 실기 검증 대기**

사용자가 추천안대로 구현을 승인했다. 업무 소유 단위, 원본 연결/독립 사본 규칙을 포함한 A 조합으로 구현한다. 아래 구현 검증 기록에 완료 범위와 실기 확인 대기 항목을 구분한다. 정식 버전·배포는 별도 요청 시 진행한다.

## 1. 목적과 범위

일정에 따라 흩어진 기록과 자료를 하나의 업무 관점으로 모은다. **Cabi.NET = 업무별 자료함 + 여러 노트 + 업무당 하나의 자유 메모보드**이다. Cabi.NET 허브, 노트, 업무 보드는 모두 메인 주간 화면과 함께 사용할 수 있는 별도 모달리스 창이다.

이 설계에서 '업무'는 기존 Cabinet 왼쪽 업무 목록의 **업무 분류(category.id)**, '업무항목'은 특정 날짜에 작성한 줄(entry_item.id)이다. 따라서 같은 업무의 월요일·금요일 기록은 하나의 Cabi.NET에 모인다. 개별 날짜의 업무항목마다 독립 노트함/보드를 만들지 않는다. 이 해석도 승인 대상이다.

| 사용자 요구 | 설계 대응 |
|---|---|
| Cabinet → Cabi.NET | 메뉴·버튼·창 제목·도움말·가이드·검색 표시명을 일괄 변경. 기존 DB 테이블명과 파일 경로는 표시명 변경 때문에 바꾸지 않음 |
| 업무당 여러 노트 | 노트는 한 업무에 소속, 생성 개수 고정 제한 없음. 독립 페이지 및 독립 모달리스 편집창 |
| 업무당 보드 1개 | 업무 선택 시 하나의 보드만 생성/재사용. 열려 있으면 기존 창으로 이동 |
| 폴더·링크·노트를 보드에 드롭 | 원본을 가리키는 자료 카드 생성. 카드끼리 관계선 연결 |
| 주간 ↔ 업무 보드 양방향 복제 | 선택된 객체/그룹을 다른 창에 드롭하면 독립 사본 생성. 원본은 유지 |
| 누적된 주간 메모 빠른 연동 | 업무항목 연결을 역조회하는 '주간 메모 모아보기'. 원본 연결 / 사본 만들기 구분 |
| 블록 Markdown 에디터 | 문단·제목·목록·체크·인용·코드·구분선·표·이미지·링크. 파일 가져오기 및 Markdown/PDF 내보내기 |
| 다양한 허브 뷰 | 목록·카드·보드 미리보기 제공. 업무/종류/검색 필터 유지 |

## 2. 현 구조 확인과 보존 원칙

- `src/domain/cabinet.ts`, `0009_cabinet.sql`: 폴더·링크 원본은 공유 자료이고, 업무 또는 날짜별 업무항목과 다대다 연결된다. **기존 원본·연결·정렬·경로·폴더 탐색 동작을 보존**한다. 업무 소속 노트를 추가한다고 기존 자료를 업무별로 중복 복사하지 않는다.
- `src/platform/tauri.ts:102` 이후: Cabinet 별도 창은 DB를 직접 열지 않고 메인 창의 RPC/동기화를 사용한다. 새 창도 이 **단일 쓰기 주체** 원칙을 확장한다.
- `src/domain/note.ts`, `0003_week_note.sql`: 주간 보드는 `week_id` 소유 문서와 이미지다. 업무 보드를 가짜 주차 ID로 저장하지 않는다. 공통 보드 엔진에 소유자 구분을 도입한다.
- `0015_note_entry_link.sql`: 주간 메모 ↔ 업무항목 연결이 별도 테이블에 있다. 누적 메모 조회는 이 연결을 기준으로 한다. 현재 객체당 업무항목 연결 한도 20개는 유지한다.
- 메모 다중 선택/일괄 이동·글자색·링크 텍스트·이미지·관계선·줌·실행 취소 등 기존 기능을 공통 엔진으로 재사용한다. 업무 보드용으로 기능이 빠진 별도 편집기를 만들지 않는다.
- 워크스페이스별 DB 1개, 외부 통신 없는 저장 원칙을 유지한다. 여기서 창 간 복제는 **같은 워크스페이스 안**의 동작이다.

## 3. 검토할 시안 — 요소별 3안

[요소별 비교 갤러리](mockups/cabinet-v2/review.html)와 [인터랙티브 시안](mockups/cabinet-v2/index.html)에서 요소 5개 × A/B/C, 총 **15개 화면**을 확인할 수 있다. 합성 예시 데이터이며 실제 앱 구현이 아니다. 선택·모드 전환·접기·드롭 등 일부 동작은 화면 검토용으로만 흉내 낸다. 네이티브 창 간 드래그 성공을 입증하는 데모가 아니다.

### H. Cabi.NET 허브

| 안 | 배치 | 장점 / 고려점 |
|---|---|---|
| **H-A 업무 허브형 — 추천** | 왼쪽 업무 목록 / 가운데 자료 목록 / 오른쪽 접이식 미리보기. 업무 제목 아래 노트·보드 진입 | 기존 Cabinet과 가장 유사. 빠른 탐색, 날짜와 무관한 업무 맥락. 미리보기 기본 닫힘 |
| H-B 자료 갤러리형 | 업무 선택 사이드바 + 자료 종류별 카드 격자. 보드 카드도 함께 표시 | 시각적으로 자료 찾기 쉬움. 자료가 많으면 목록보다 밀도 낮음 |
| H-C 노트 중심형 | 업무 목록 + 노트 목록을 중심으로 표시, 폴더·링크는 자료 탭 | 글 기록이 주 목적일 때 유리. 기존 폴더 관리 접근은 한 단계 늘어남 |

공통: 어느 안을 고르든 **목록/카드/보드 보기 전환** 제공. 보드 보기는 현재 보드의 읽기 전용 미리보기와 '별도 창에서 열기'이며 두 번째 보드를 만들지 않는다. 전체 업무에서 보드 보기는 업무별 보드 미리보기 목록이다. 필터는 전체/노트/폴더/링크, 보드는 업무 단위 고정 진입이다. 종료 업무도 숨기지 않고 별도 묶음에서 조회한다. 검색은 제목·노트 본문·폴더 경로·링크 주소이며 파일 내용은 검색하지 않는다.

### N. 노트 모달리스 창

| 안 | 배치 | 장점 / 고려점 |
|---|---|---|
| **N-A 문서 집중형 — 추천** | 상단 업무 경로·저장 상태 / 문서 중심 편집 / 접이식 목차 | Notion 페이지와 유사. 업무가 다른 창과 혼동되지 않음 |
| N-B 노트 탐색형 | 같은 업무의 노트 목록을 왼쪽에 유지 + 본문 | 여러 노트 전환이 빠름. 창 폭을 더 사용함 |
| N-C 편집·미리보기형 | 왼쪽 블록 편집 / 오른쪽 내보내기 미리보기 | Markdown/PDF 결과 확인에 유리. 좁은 창에서 탭으로 접어야 함 |

공통: 외부 독립 창, 본문은 블록 편집, Markdown 소스 입력을 강요하지 않는다. 새 창을 열어도 주간 화면 조작 가능. 다른 노트를 동시에 열 수 있고 동일 노트는 기존 창에 초점 이동한다. 가져오기/내보내기는 아이콘+텍스트, 목차·서식 보조 버튼은 접근성 이름이 있는 모노그램 아이콘이다.

### B. 업무 전용 메모보드

| 안 | 배치 | 장점 / 고려점 |
|---|---|---|
| **B-A 캔버스 집중형 — 추천** | 전체 자유 캔버스 + 왼쪽 접이식 자료함 + 오른쪽 선택 객체 속성 | 기존 주간 메모와 조작 일치. 양쪽 패널 기본 닫힘으로 작업 면적 확보 |
| B-B 자료 선반형 | 캔버스 아래에 폴더·링크·노트 선반 | 좌우 폭 확보. 세로 작업 면적이 줄어듦 |
| B-C 업무 스튜디오형 | 왼쪽 자료/노트 상시 목록 + 중앙 보드 + 오른쪽 누적 메모 | 자료가 많은 업무에 적합. 작은 창에서는 두 패널을 접어야 함 |

공통: 업무당 보드 하나, 무한한 날짜 기록판과 구분. 기존 자유 배치·다중 선택·정렬/이동·이미지·텍스트·링크·관계선·색·줌·스냅샷/기존 내보내기를 계승한다. 노트/폴더/링크 카드는 보드 위의 참조이며 더블클릭하면 해당 원본을 연다. 관계선에는 사각 색상 레일을 붙이지 않는다. 패널 폭 조절·접기·사용자별 마지막 상태 기억을 제공한다.

### W. 해당 업무의 누적 주간 메모 연동

| 안 | 배치 | 장점 / 고려점 |
|---|---|---|
| **W-A 오른쪽 모아보기 — 추천** | 보드에서 '주간 메모' 열기 → 검색·주차 필터·미리보기·체크 선택 → 하단 일괄 연결 | 캔버스를 보면서 연동. 기본 '원본 연결', 필요 시 사본 만들기 |
| W-B 넓은 선택 대화상자 | 여러 주차의 썸네일을 넓게 비교한 후 선택 | 많은 자료를 한 번에 고르기 좋음. 선택 중 보드가 가려짐 |
| W-C 업무별 기록 브라우저 | 주차 묶음 목록 + 메모 미리보기, 선택 항목 보드로 끌기 | 출처 흐름 파악이 쉬움. 화면 영역을 많이 사용함 |

공통: 링크된 날짜를 조건으로 찾되 **전체 기간이 기본**이다. 동일 상자가 같은 업무의 여러 항목과 연결되어도 `(workspace, weekId, boxId)` 기준 1개만 표시하고 관련 업무항목들을 함께 보여준다. 이미 연결된 객체는 '연결됨' 표시. 종료·재개 업무도 같은 category.id로 누적 조회한다. 업무항목 연결이 없는 메모나 연결 항목이 삭제된 메모는 자동 추정해 끌어오지 않는다. '전체 주간 메모에서 직접 찾기' 보조 진입을 제공한다.

### D. 창 간 드래그·복제 피드백

| 안 | 표시 | 장점 / 고려점 |
|---|---|---|
| **D-A 위치 직접 드롭 — 추천** | 목적 보드의 실제 위치에 반투명 객체 묶음·'3개 복제' 표시 → 놓기 → 원본 유지 토스트 | 기존 드래그와 자연스럽고 빠름. 그룹의 상대 위치 유지 |
| D-B 화면 가장자리 받기 | 목적 창 진입 시 상단 받기 영역 표시 → 놓은 뒤 위치 지정 | 수신 가능 여부 명확. 배치가 두 단계임 |
| D-C 복제 내용 확인형 | 목적 보드에 놓으면 객체 수·포함 관계·출처 확인 후 확정 | 큰 그룹 복제에 유리. 반복 동작은 느려짐 |

공통: **원본은 이동하지 않음**. 주간→업무, 업무→주간 모두 지원. 수정 동기화는 하지 않는다. 복제 후 취소는 목적지의 생성 묶음만 되돌린다. 마우스 외에 '다른 보드에 복제…' 메뉴/키보드 경로도 함께 제공하지만, 이것으로 실제 창 간 드래그 요구를 대체하지 않는다.

### 추천 조합 및 검토 포인트

기본 추천은 **H-A / N-A / B-A / W-A / D-A**이다. 기존 Cabinet 탐색을 유지하고 새 기능은 필요할 때 열어 사용한다. 다른 조합도 가능하다(예: H-A + N-B). 최종안 승인 전 아래 의미도 확인한다.

1. 업무의 기준 = 업무 분류(category), 개별 날짜의 한 줄이 아님.
2. 누적 메모를 모아볼 때 기본은 **원본 연결**, 직접 보드 간 드래그는 **독립 사본**.
3. 업무 보드는 처음부터 빈 보드이며 누적 메모를 자동 복사하지 않음.
4. 노트는 하나의 업무에 소속. 다른 업무 보드에 참조 카드를 올릴 수 있지만 소유 업무가 바뀌지는 않음.
5. 현재 따뜻한 테마와 직각 색상 띠 규칙 유지. Universe 전용 어두운 우주 스타일은 가져오지 않음.

## 4. 추천안의 화면·상호작용 명세

### 4.1 허브

- 제목 'Cabi.NET' + 선택 업무명 + 업무색을 작은 사각 마커로 표시. 모든 강조 띠는 **직각**, 띠와 아이콘/글자 사이 최소 12px 확보.
- 왼쪽: 전체 / 진행 업무 / 종료 업무 / 연결 없는 기존 자료. 업무 목록 200~360px 조절, 기본 224px. 업무 선택은 주간 날짜를 바꾸지 않는다.
- 상단: 검색, `+ 새 노트`, `업무 보드 열기`, `+ 자료 등록`, 목록/카드/보드 아이콘. 자료 등록 = 기존 폴더/링크 등록 흐름. 전체 업무에서 새 노트/보드 열기는 업무를 먼저 고르는 간단한 선택을 제공한다.
- 기본 목록 열: 아이콘·제목 / 종류 / 소속·연결 / 수정. 열 너비 조절, 제목 먼저 늘어나며 우측 중요 동작이 가려지지 않게 한다. 더블클릭은 원본 열기, 단일 선택은 선택 상태만 변경. 미리보기는 버튼으로 열기.
- 노트는 생성 즉시 업무에 소속. 폴더·링크는 기존처럼 여러 업무/업무항목에 연결 가능. '업무에서 연결 해제'와 '등록 자료 삭제' 구분, 실제 파일은 삭제하지 않는다.
- 보드가 없는 업무는 '업무 보드 만들기', 이후 '업무 보드 열기'. 전체 화면에서 과도한 빈 보드를 일괄 생성하지 않는다.
- 상태: 자료 없음(새 노트/자료 등록/주간 메모 찾기), 검색 결과 없음, 자료 경로 없음(다시 지정), 저장 실패(재시도·사본 내보내기). 모든 상태 메시지 시작선을 내용 영역과 정렬한다.

### 4.2 노트 편집

- 제목, 소속 업무, 갱신 시각, `저장 중 / 저장됨 / 저장 실패` 표시. 업무 변경은 명시적인 '소속 업무 변경…' 메뉴에서만 하고 보드 참조는 note.id를 유지한다.
- 본문 폭 기본 760px, 창을 넓히면 '넓게 보기' 옵션으로 확장. 문서 밖 빈 공간 클릭은 마지막 문단 편집. IME 한글 조합 중 Enter가 블록 생성을 중복 처리하지 않아야 한다.
- 지원 블록: 문단, 제목 1~3, 글머리/번호 목록, 체크 목록, 인용, 코드(언어 표기), 구분선, 표, 이미지. 기본 서식: 굵게·기울임·취소선·인라인 코드·글자색·링크. `/` 메뉴, 블록 추가·드래그 정렬·복제·삭제, 선택 여러 블록 이동/실행 취소.
- URL은 링크 텍스트로 편집/열기. 문서 내 코드·HTML·링크는 실행하지 않는다. 외부 이미지·미리보기는 자동 다운로드하지 않는다.
- 지원하지 않는 Notion 데이터베이스·실시간 공동 편집·임베드 실행은 이번 범위에 넣지 않는다. 단순 페이지 링크는 지원 가능하나 문서 트리/하위 페이지는 후속으로 분리한다.
- Markdown 가져오기: 파일 선택 또는 본문에 드롭 → **새 노트 생성 / 현재 위치에 삽입** 선택. 기본 새 노트. 제목은 첫 H1 또는 파일명, 사전 미리보기와 제외 항목 건수 제공. 기존 주간 보드의 'Markdown을 순수 텍스트 메모로' 동작과 구분하여 노트에서는 구조를 유지한다.
- GFM 기본 블록·표·체크·링크를 변환한다. 임의 HTML은 텍스트로 정리, 스크립트 제거. base64/data URI 콘텐츠와 실행 가능한 링크 제외. 상대 경로 이미지는 사용자가 선택한 자산을 함께 가져오는 경우만 DB 자산으로 복사하고, 못 찾은 이미지는 대체 텍스트·경로·누락 안내를 남긴다. 인터넷 이미지는 링크로 남긴다.
- Markdown 내보내기는 `.md` + 필요한 이미지 묶음(사용자 선택 위치). 일반 Markdown에서 보존되지 않는 글자색 등은 내보내기 안내에 명시. PDF는 텍스트 선택 가능·한글 글꼴·페이지 나눔·표/코드 잘림을 검증한다. OS별 프린트 창만 제공하는 것을 PDF 저장 완료로 취급하지 않는다.
- 자동 저장은 입력 후 짧은 지연(제안 600ms), 포커스 이동/창 닫기 때 flush. 실패 시 닫기를 막고 재시도/내용 내보내기 제공. 창 강제 종료에도 최근 승인된 저장본은 DB에 남아야 한다.

### 4.3 업무 보드와 자료 카드

- 상단 업무명·보드 저장 상태·자료함·주간 메모·줌·기존 도구. 자료함과 속성 패널은 처음에는 닫고, 열 때만 영역을 사용한다. 패널 조절값은 창 설정에 저장한다.
- 자유 메모는 원본 콘텐츠를 보드가 소유. 자료 카드는 `folder/link/note`의 ID 참조로 제목·연결 상태를 최신 표시한다. 폴더 경로를 통째로 복제하거나 웹 페이지를 수집하지 않는다.
- 원본 연결 카드에서 '원본 열기'는 노트 창 또는 기존 폴더/링크 열기, '사본으로 전환'은 주간 메모에만 제공하며 내용을 독립 객체로 만든다.
- 원본 주간 메모 참조는 읽기 전용 내용 미리보기, 편집은 원본 보드에서 수행. 원본 변경 이벤트로 카드 갱신. 원본이 지워졌으면 '원본 없음'과 마지막 제목/출처를 표시하며 참조 카드를 조용히 삭제하지 않는다.
- 보드 위 카드를 삭제하면 배치/관계선만 삭제. 노트/폴더/링크 원본과 주간 메모는 유지. 노트 원본 삭제 시 영향받는 참조 수를 안내하고 명시적으로 확인. 업무를 '종료'해도 노트·보드와 자료 연결은 유지하고 열람/편집 가능. 업무 영구 삭제는 새 노트·보드가 존재할 경우 기본 거부하고 이전/내보내기/명시적 삭제 안내를 제공한다.
- 노트의 수정과 보드 카드 이동은 서로 다른 문서 작업이다. 한 카드의 이동 때문에 노트 본문 전체를 저장하지 않는다.

### 4.4 누적 메모 연결과 복제의 의미

| 동작 | 생성물 | 이후 원본 수정 | 날짜별 업무항목 연결 |
|---|---|---|---|
| 자료함에서 폴더/링크/노트 드롭 | 해당 자료 ID의 참조 카드 | 최신 제목/경로/내용 반영 | 기존 연결 변경 없음 |
| 누적 메모 '원본 연결' | 원본 `(weekId,boxId)` 참조 카드 | 최신 표시, 원본에서 편집 | 원본 연결 그대로, 새 entry 링크 생성 안 함 |
| 누적 메모 '사본 만들기' | 독립 보드 객체 | 동기화하지 않음 | 출처 정보와 분리. 날짜별 entry 연결 자동 복사 안 함 |
| 주간 ↔ 업무 보드 객체 드롭 | 독립 목적지 객체/묶음 | 동기화하지 않음 | 자동 복사 안 함. 필요하면 목적지에서 기존 연결 UI로 명시적 추가 |
| 업무항목 행을 보드에 드롭 | 기존과 같은 업무항목 연결 메모 | 현재 항목 표시 | 사용자가 명시적으로 선택한 entry 연결 생성 |

업무 보드에 있는 것만으로 소속 업무와 연결된다. 날짜별 완료 여부를 복사하거나 주간업무에 새 업무항목을 만들지 않는다. 사본에 표시하는 '출처: 11월 1주'는 추적용 메타데이터이며 살아 있는 entry 연결과 다르다.

- 여러 객체 복제 시 새 box ID·edge ID 발급, 선택 객체 사이의 관계선만 새 ID로 매핑하여 보존. 선택 밖 관계선은 제외 개수 안내. 좌표는 원점 대비 상대 위치 유지, 겹침 적은 위치로 배치.
- 이미지/썸네일은 먼저 목적지 소유 자산으로 준비하고 문서·업무항목 연결·관계선은 문서 저장 batch에서 반영한다. 이미지 복제 batch는 SQLite 내부에서 처리해 원본 base64를 창 간 전송하지 않는다. 문서 저장 실패는 성공으로 표시하지 않고 임시 편집 내용을 보존한다. 미사용 준비 자산이 남을 수 있으나 부분 문서나 다른 소유자의 이미지 참조를 저장하지 않는다. 원본 삭제/자산 정리가 사본 이미지를 지우지 않아야 한다.
- 폴더/링크/노트 자료 카드를 다른 보드로 복제해도 같은 원본을 참조한다. '배치 객체의 복제'와 '노트 문서 자체 복제'는 다르며 토스트에 표시한다.
- 객체 복제 실패 시 부분 생성 없이 재시도. 동일 drag token 중복 드롭은 멱등 처리. Undo는 이 작업이 생성한 목적지 객체·관계선·독점 자산 연결만 제거하고 다른 창의 이후 작업을 지우지 않는다.

## 5. 데이터·멀티윈도 구조 초안

### 5.1 개념 모델 (물리 스키마는 최종 승인 후 확정)

| 개념 | 핵심 필드·제약 |
|---|---|
| 기존 CabinetItem / CabinetLink | 현 데이터 그대로 유지. 신규 노트 때문에 기존 kind CHECK를 무리하게 확장하지 않고 통합 조회 모델에서 합성 |
| TaskNote | id, categoryId FK, title, blockDoc, docFormatVersion, revision, createdAt, updatedAt. categoryId별 여러 개 |
| TaskBoard | id, categoryId UNIQUE, boardDoc, docFormatVersion, revision, createdAt, updatedAt. 경쟁 생성도 DB 유일성으로 1개 보장 |
| BoardOwner | `{kind: 'week', weekId}` 또는 `{kind: 'task', categoryId, boardId}`. 기존 주간 API에 새 소유자를 단계적으로 연결 |
| ResourceReference | 참조 카드 id, sourceKind, sourceId 또는 sourceWeekId+boxId, 표시용 최소 스냅샷. 출처 삭제 시 깨진 참조 표시 |
| Asset + AssetUse | 노트/주간/업무 보드가 같은 바이너리를 써도 참조 소유자 구분. GC는 전체 소유자 참조를 확인한 뒤 수행 |
| BoardEntryLink | 보드 소유자·boxId·entryId 연결. 주간 v15 연결을 보존/통합할 전진 마이그레이션. 기존 SQL trigger와 한도 유지 |

문서 버전·앱 버전·DB 스키마 버전을 구분한다. 목표 DB 번호는 구현 시 최신 main 기준으로 정한다. 기존 `0003`, `0009`, `0015` 마이그레이션은 수정하지 않는다. 새 migration 직전 백업, 빈 DB/현재 v15/과거 fixture의 왕복 데이터 검증을 수행한다.

### 5.2 쓰기와 동기화

```text
메인 주간 창 ─┐
Cabi.NET 허브 ├─ 명령(requestId, workspaceId, sessionEpoch, docId, baseRevision)
노트 별도 창 ─┤        ↓
업무 보드 창 ─┘   메인 창의 저장 조정기 → JournalRepository → SqlDriver.batch
                       ↓ 승인(revision) / 변경 이벤트(문서별 증분)
                 각 창의 구독·저장 상태·참조 미리보기
```

- 자식 창은 DB 직접 연결 금지. RPC는 명시적 허용 명령만, 전송 문서 형식·크기·소유자 검증. 현재 Cabinet의 고정 목적창 RPC를 다중 windowId/문서 구독 구조로 확장한다.
- 문서별 순차 명령, baseRevision 비교, requestId 중복 방지. 오래된 전체 문서 저장을 받지 않는다. 충돌 시 조용한 덮어쓰기 없이 최신 본과 내 임시 내용 복구 경로를 제공한다. 한 노트/보드는 하나의 편집창을 재사용하여 기본 경쟁을 줄인다.
- 메인 종료/워크스페이스 전환/백업 복원 전 모든 자식 창 저장 요청 승인까지 기다린다. 저장 실패면 전환을 멈춘다. 기존 `flushPending → finishNote → detachAll → close → activate` 경로에 합류한다. 활성 workspaceId+epoch가 달라진 메시지는 거부하며 이전 창을 닫거나 전환 안내 상태로 바꾼다.
- 자식 창의 비동기 결과·자동 저장·Undo도 읽어 온 저장소/세션에 묶는다. 메인 프로세스가 사라지면 자식 편집을 읽기 전용 복구 상태로 바꾸고 내보내기를 제공한다.

### 5.3 실제 창 간 드래그

- 브라우저 `DataTransfer`의 사용자 정의 MIME이 WKWebView/WebView2 창 사이에서 그대로 유지된다고 가정하지 않는다. 기존 네이티브 폴더 드롭 다리와 내부 객체 드래그가 충돌하지 않는지도 확인한다.
- 제안: 실제 데이터는 메인 메모리에 보관하고, 짧은 수명의 **opaque drag token**으로 목적 창이 payload를 조회하는 플랫폼 브리지를 설계한다. source/target 창·workspace·session·원본 revision·만료·중복 수신을 검증한다. token 외부에 DB 경로나 이미지 base64를 실어 나르지 않는다.
- Windows와 macOS의 실제 WebView 간 pointer/OS drag 경계를 먼저 실험한다. 네이티브 이벤트가 필요하면 얇은 Rust 계층에 제한한다. 브라우저 모드는 동일 인터페이스로 미리보기만 제공한다.
- 필수 검증: 양방향/선택 그룹/이미지/관계선/자료 카드/취소/다른 공간 거부/드래그 중 원본 삭제/창 닫힘/다중 모니터 배율. 복제 메뉴만 동작하면 요구사항 미충족이다.

## 6. 통합 범위와 품질 조건

- **백업/복원:** 새 문서·관계·자산은 동일 SQLite DB 안에 포함. 백업 이력 앱/DB 버전 정책 유지. 복원 후 노트·보드·이미지·참조·업무 연결을 검사한다.
- **검색:** Cabi.NET 내부 노트 본문 검색 필수, 전역 검색에서 새 노트/업무 보드 결과를 열 수 있게 통합. 원본 결과가 주간 메모인지 업무 보드인지 명시한다.
- **Universe·근거 묶음:** 기존 폴더/링크 노드 ID 유지. 새 노트/보드의 안정적인 식별자·열기 경로를 설계하고, 신규 노드 유형 반영 범위는 구현 세부안에서 확정한다. 이번 요구만으로 새로운 우주 레이아웃을 추가하지 않는다.
- **가이드/Feature List:** 구현 완료 시 고정 feature ID와 도입 버전을 등록, 기존 Cabinet 명칭/기능 근거 갱신, 가이드 화면/HTML/PDF 동반 갱신. 설계 단계에서 현재 1.19.0 기능표를 구현 완료로 바꾸지 않는다.
- **큰 데이터:** 업무 선택 때 모든 본문·이미지를 통째로 읽지 않는다. 허브 제목/요약/카운트 우선, 본문/썸네일 지연 로딩, 누적 메모 페이지 조회, 큰 이미지 캔버스 최적화 재사용. 초기 기준 fixture: 업무 100개·노트 1,000개·누적 메모 5,000개로 탐색 및 메모리 측정 후 허용치를 확정한다.
- **접근성/일관성:** 아이콘 버튼은 tooltip·aria-label·키보드 포커스, 본문/안내문 동일 gutter, 사각 색상 띠, 제목/본문 위계, 접이식/크기 조절 패널의 키보드 대체. 좁은 창에서는 미리보기/자료함을 닫고 본문 확보.

## 8. 승인 후 사용할 핵심 인수 시나리오

1. 기존 DB를 열어 폴더/링크·주간 업무 연결·메모·관계선·이미지가 이전과 같고 'Cabi.NET'으로 표시된다.
2. 한 업무에 노트 3개와 보드 1개 생성, 다른 날짜/주로 옮겨도 같은 자료가 유지된다. 같은 업무 보드 두 번 열기는 같은 창으로 이동한다.
3. 한글 블록 편집·순서 변경·Undo·Markdown 가져오기 후 재실행. 링크가 열리고 제외 자산이 안내되며 Markdown/PDF가 오프라인에서 정상 출력된다.
4. 폴더/링크/노트를 자료함에서 보드에 끌어 참조 카드를 만들고 연결한다. 카드 삭제가 원본을 삭제하지 않는다.
5. 같은 업무항목들과 연결된 주간 메모를 전체 기간에서 찾고 중복 없이 원본 연결한다. 원본 수정은 보이고 원본 삭제는 명시적인 끊긴 참조로 보인다.
6. 주간 보드의 이미지+글+관계선 그룹을 업무 창으로 드래그 복제, 역방향도 반복한다. 원본은 유지, 사본 수정은 독립, 원본 삭제 후 사본 이미지도 유지한다.
7. 복제·노트 입력·보드 이동 도중 공간을 3회 이상 바꿔도 다른 DB에 기록/이미지가 섞이거나 사라지지 않는다. 저장 실패·메인 종료·자식 창 종료를 각각 검사한다.
8. 전체 데이터 백업→다른 테스트 저장 위치로 복원→노트·업무 보드·이미지·원본 참조·검색 결과 비교. Windows/macOS에서 동일 기능 확인.

### 규모 측정 및 남은 검증

업무 100개·노트 1,000개(본문 약 1,000자)·주간 메모 5,000개(100주×50객체, 단일 업무에 연결)의 가상 SQLite 약 8.26MB로 저장소 조회를 1회 측정했다. 이 환경의 sql.js 결과는 노트 요약 1,000개 **14ms**, 누적 메모 첫 60개 **36ms**, 본문 검색(전체 100주를 읽는 조건) **52ms**였다. UI 전체 렌더링 시간·메모리 상한이나 실제 데스크톱 성능을 보증하는 수치가 아니다.

현재 브랜치 작업이며 main 병합·정식 버전·게시·배포는 수행하지 않았다.

## 11. 1.20.0 정식 main 반영 승인 — 2026-11-07

사용자가 main 반영 및 1.20.0 정식 버전을 승인했다. main 1.19.0(`8c2ce2e`)은 원격 `release/v1.19.0`에 보존했다. cabinet-v2 최종 CI와 직전 수정 CI 모두 성공 확인 후 로컬 main에 fast-forward 반영했다. 앱/잠금 파일·릴리스 노트·Feature List/Excel·가이드를 1.20.0으로 갱신한다. Windows 기본 설치판과 macOS 유니버설 DMG를 함께 빌드하며, 오프라인 설치판은 실행하지 않는다. 티저의 RC 배지·접미사·정식판 미포함 안내는 제거한다. 위 RC 검증 기록은 당시 수행 범위를 그대로 보존하며, OS 실기 확인을 새로 수행했다고 표시하지 않는다.
