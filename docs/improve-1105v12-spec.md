## 2. 현행 코드 확인

- 완료 정본: `domain/important.ts`의 `isDone` = flagged가 꺼져 있고 flagDoneAt이 있음. `repository.completeFlag`는 별을 끄고 완료 시각을 저장하며, `undoComplete`/기존 완료 취소는 별과 시각을 복원한다.
- `board/CellEditor.tsx`가 주간·데일리(`today/TodayView.tsx`) 공용이다. 현재 완료 배지는 있으나 본문에 완료 취소선 클래스가 없다. 본문은 textarea/링크 표시(`LinkedText`) 경로가 나뉘므로 양쪽을 함께 적용해야 한다.
- `repository.previousRecord` / `previousRecordsByCategory`는 depth/text만 읽고 완료 정보를 버린다. SQL의 trim(text) 조건도 구조 판정보다 먼저 적용된다.
- `boardStore.pullPrevious` / `pullPreviousDay`, 빈 칸 단추·데일리 미리보기/업무별 날짜 경로가 연결돼 있다. 조회→미리보기→실제 가져오기 전체에 같은 제외 규칙이 필요하다.
- `Board.module.css`: 기본 padding-left 14px, `.flagged` inset 3px 선. 별표 위치가 선에 가깝다. 오른쪽 곡률이 남은 강조 배경도 있다.
- `NoteColorPalette`: A 밑줄 + '색상' 형태 트리거, `.swatch`는 둥근 사각 버튼에 inset 하단 5px 색 띠. 버튼 모서리를 따라 색 띠가 휘는 것이 이번 개선 대상이다.

## 3. 완료 취소선의 의미와 범위

### 3-1. 표시 규칙

- `isDone(item)`만을 기준으로 CSS `text-decoration: line-through` 적용. 원문에 `~~`를 삽입하거나 문자열을 변환하지 않는다.
- 취소선은 **본문만**: 별/완료 배지·시작 시각·마감일 칩·연결/메뉴 아이콘에는 적용하지 않는다.
- 기본 글자 크기·줄 높이·줄바꿈 유지, 취소선 두께 1px 기준. 완료라는 이유로 본문을 과도하게 흐리게 하지 않는다. 세 테마 대비를 점검한다.
- 주간·데일리의 읽기/편집 상태, URL을 포함한 `LinkedText` 표시에서도 동일. 편집 중에도 취소선을 유지하며 커서·선택·IME 조합·링크 조작을 방해하지 않는다.
- 완료 취소 또는 다시 중요 표시하면 취소선 즉시 제거. 기존 완료 시각·완료 목록 정렬·완료 팝오버는 유지한다.
- 부모가 완료여도 **자식 상태를 자동 완료로 바꾸지 않는다**. 자식 본문은 자신이 완료일 때만 취소선. 가져오기에서는 부모 완료에 따라 함께 제외한다.

### 3-2. 주변 화면

- 중요 업무의 완료 목록은 완료 텍스트에 동일 규칙 적용을 추천한다. 메모의 업무 연결 제목 등 같은 항목을 직접 표시하는 곳은 완료 메타데이터를 추적할 수 있는지 점검해 통일한다. 단순 과거 발췌·수동 작성 메모·지식 카드 문장은 자동으로 고치지 않는다.
- 추가 승인에 따라 일반 항목에도 모노그램 완료/취소를 제공한다. 기존 완료 시각을 공통으로 사용하고, 완료 전 중요 여부를 구조 v14에 보관해 취소 시 복원한다. 중요 업무에서 처리한 상태도 같은 본문·아이콘에 반영한다.
- XLSX/Markdown/요약/검색/Universe의 필터·집계 방식은 변경하지 않는다. 외부 출력 취소선 표현은 별도 범위다. 저장된 원문과 기존 집계 결과는 보존한다.

## 4. 이전 기록 가져오기 규칙

### 4-1. 구조 단위 필터

| 원본 상태 | 가져오기 |
|---|---|
| 미완료 부모 + 미완료 자식 | 둘 다 포함 |
| 미완료 부모 + 완료 자식 | 부모와 나머지 미완료 자식만 포함 |
| 완료 부모 + 미완료/완료 자식 | **부모와 그 아래 자식 전부 제외** |
| 완료 독립 항목 | 제외 |
| 완료 취소한 항목 | 다시 대상에 포함(원래 날짜 선택 규칙 안에서) |

- 현재 depth는 0/1 구조. seq 순서대로 depth 0을 만날 때마다 부모 제외 상태를 갱신하고, 그다음 depth 0 직전까지의 depth 1에 적용한다. 업무/날짜/칸 경계에서 상태를 초기화한다.
- **빈 텍스트 정리 전에 완료 부모를 판정**한다. 완료 부모의 글을 지웠더라도 자식만 되살아나 복사되지 않도록 한다.
- 완료를 제외한 다음 기존 빈 항목 정리·중복 방지·깊이 정규화·덧붙이기·커서·실행 취소를 수행한다. 완료 속성은 새 항목으로 복사하지 않는다.
- 텍스트에 사용자가 `~~`를 적었거나 단어 '완료'가 있다는 이유로 제외하지 않는다.

### 4-2. 날짜 선택 (검토할 결정 D2)

**추천: 기존 '직전 기록일'을 먼저 고르고, 그날 자료에서 완료 묶음을 제외한다.** 전부 완료라면 '직전 기록은 모두 완료되어 가져올 항목이 없습니다' 안내를 표시한다. 더 오래된 날로 자동 거슬러 가지 않는다. 오래된 미완료 문장을 다시 가져와 혼란을 주는 것을 피하기 위한 선택이다.

- 4주 범위·종일 연차 제외·단일 업무/전체 업무의 기존 날짜 선택 의미는 그대로 둔다.
- 직전 날 A는 전부 완료, B는 미완료가 있으면 전체 가져오기는 B만 포함한다. A를 위해 더 오래된 날을 혼합하지 않는다.
- 데일리 업무별 직전 날짜도 같은 원칙. 가져올 수 있는 항목이 0이면 가져오기 단추를 비활성 상태+이유로 표시한다. 미리보기에는 제외 후 항목과 '완료/하위 포함 n개 제외' 안내를 제공한다.
- 하나라도 가져왔으면 'n개 가져옴 · 완료 묶음 m개 제외' 안내, 전부 완료/기존과 중복/원본 없음은 별도 메시지로 구분한다. 개수는 제외된 실제 행 수(부모+자식)를 센다.

### 4-3. 구현 경계

`domain/previousItems.ts` 등 순수 함수에 구조 필터를 둔다. 조회는 completion 메타데이터를 포함한 순서 있는 행을 가져오고, 이 함수 결과를 `PreviousRecord`의 가져오기 후보·제외 개수에 담는다. SQL에서 완료 행만 먼저 지우지 않는다. `previousRecordDates`·미리보기·`previousDayFor`·Alt+P·Alt+Shift+P·빈 칸 단추를 함께 점검한다.

완료 상태가 미리보기 이후 바뀔 수 있으므로 실행 시 원본을 다시 읽어 동일 규칙으로 계산한다. 공간 전환 시 repo/세대 검사를 거쳐 오래된 조회 결과를 폐기한다. 기존 저장소·실행 취소 경로를 재사용한다. 추가 승인된 일반 항목 완료의 원상태 복원을 위해 구조 v14 마이그레이션을 적용한다.

## 5. 별표·띠 여백 — 추천 배치

가로 시작을 `3px 띠 + 8px 여백 + 16px 표시 영역 + 6px 여백 + 본문`으로 구성한다(본문 시작 33px 기준). 구현 시 실제 글꼴/배지 폭을 확인해 조정한다.

- 별 없는 일반 항목도 같은 공간을 기본 예약한다. 별 표시/해제·완료 전환에도 글자와 줄바꿈 시작점이 움직이지 않는다.
- 하위 항목은 기존 들여쓰기를 이 기준 위에 더한다. 마우스 올림으로 나타나는 별표도 띠와 분리한다.
- 주간·데일리·중요 배지·드래그 손잡이·완료 팝오버를 함께 점검한다. 좁은 칸에서 입력 폭 감소와 기존 아이콘 겹침을 확인한다.
- 강조 **배경 띠도 네 모서리를 0**으로 한다. 일반 카드/대화상자 외곽은 별도 디자인 요소지만, 띠를 둥근 외곽으로 잘라 휘게 만들지 않는다.

## 6. 글자색 도구 시안 3개

### A — A 아이콘 + 사각 칩 (추천)

두꺼운 밑줄을 제거하고 `A  ■  ▾` 형태의 간결한 트리거. 글자 서식임을 A로, 현재색을 작은 직각 칩으로 표시한다. 혼합 선택은 분할 사각/‘혼합’ 접근성 이름, 기본색은 대각선이 있는 중립 칩으로 구분한다.

펼치면 기본색 복원 + 기존 5개 색을 직각 색상칩으로 표시한다. 선택은 색만이 아니라 바깥 테두리와 체크로 구분한다. 글자색 버튼 이름·색 이름 툴팁·radiogroup·키보드 이동·Esc·편집 선택 영역 보존을 유지한다.

### B — 문자 A가 들어간 색상 타일

현재색의 직각 타일 안에 A를 놓고 화살표를 분리한다. 색이 가장 잘 보이지만 어두운 색/테마에서 A의 대비를 별도로 검증해야 한다. 배경색 기능으로 혼동할 가능성이 있어 툴팁 '글자색'을 유지한다.

### C — '글자색' + 작은 사각 칩

텍스트 설명을 유지하고 옆에 현재색 칩을 둔다. 의미 전달은 가장 분명하지만 메모 도구 막대 폭을 더 쓴다. 좁은 메모에서는 A안을 추천한다.

세 안 모두 칩/색상 띠는 직각. 팔레트의 A 글자 반복·하단 굵은 띠를 제거하고 색 면·기본색 복원·선택 체크로 정리한다. 팝오버의 일반 테두리는 띠와 구분하되, 이번 시안에서는 외곽도 직각으로 맞춘다.

## 7. 전역 띠 규칙 (사용자 명시 요구)

- 이후 **모든 띠 디자인에 둥근 모서리 금지**. 세로 레일, 수평 색상 막대, 선택/중요/날짜 배경 띠, 색상칩 안 표시선, 의사 요소/box-shadow/clip-path 포함.
- 기존 v2의 '오른쪽 강조 면 곡률 유지' 예외는 강조 띠에 대해 폐지한다. 띠 자체와 강조 면 끝은 직각.
- 일반 입력칸·버튼·배지·점·팝오버 모서리를 전부 없애는 요구로 확대하지 않는다. 다만 그 외곽이 띠를 잘라 곡선으로 보이게 하면 띠를 독립 직각 요소로 분리한다.
- 전체 검색 대상: `border-left/right`, inset shadow, `::before/after`, `border-radius`, overflow hidden·clip. 주간/데일리·중요 업무·레일·색상 팔레트·Cabinet·Universe·설정·내보내기 화면을 점검한다. 차트 데이터 곡선·관계선은 띠가 아니다.
- 시그니처·라이트·다크에서 같은 기하 규칙. 이 문서의 규칙을 `CLAUDE.md`에 기록하고 향후 UI 리뷰 항목에 포함한다.

## 10. 승인 후 구현 기록

- 사용자 추가 승인: 일반 항목도 완료/취소를 모노그램 아이콘으로 제공한다. 중요 업무에서 처리한 상태는 같은 항목 본문/아이콘에 즉시 표시한다. 나머지는 추천안 적용.
- 완료 아이콘은 체크 사각형, 취소는 되돌림 화살표. 기존 완료 배지·완료 팝오버도 유지한다. 본문만 취소선이며 시각/마감 칩/메뉴에는 적용하지 않는다.
- 일반 항목 완료 취소가 새 별표를 만들지 않도록 `completion_was_flagged`를 구조 v14에 추가했다. 기존 완료는 중요 항목에서만 가능했으므로 기본값 1로 이관한다. 완료 시 원래 별표를 기록, 취소 시 복원. 편집·날짜/공간 이동·덮어쓰기 가져오기 되돌리기에 보존한다. 기존 백업/마이그레이션 트랜잭션 사용.
- 원문 글자를 고치지 않고 완료 메타데이터를 사용한다. 중요한 완료 목록은 중요 항목에서 완료한 것만 유지하며, 일반 완료가 그 목록에 섞이지 않는다. UI 완료 시각도 DB 저장값으로 맞춘다.
- 가져오기 제외는 완료 부모/하위 묶음 필터를 빈 텍스트 제거보다 먼저 수행한다. 업무별 미리보기와 실제 가져오기는 같은 함수를 사용하며, 직전 날짜는 유지하고 더 오래된 날로 거슬러 가지 않는다. 0건은 비활성/이유 안내, 일부 제외는 개수 안내.
- 새 완료 아이콘 공간을 더해 본문 예약 폭은 시안 33px에서 **54px**로 조정했다(띠/중요/완료/본문 순). 시작 시각 칩도 이 기준으로 이동해 겹침을 방지했다.
- 글자색 A안은 A+직각 칩, 팔레트는 기본 복원+기존 5색. 반복된 A와 두꺼운 하단 띠를 제거했다. 강조 면·정렬 드롭 선·Universe 버튼 선택 띠 등 실제 띠의 곡률도 함께 제거했다.
- 새 의존성·외부 통신 추가 없음. 버전은 현재 1.15.1에서 판올림 전이며 구현 브랜치의 작업 결과다.
