# 반응형 웹 UX/UI 구현 계획

2026-11-28 검토안 · `web-service-v1` · 데스크탑 기준 1.55.1 Open Beta

반응형 웹 개편은 **로그인한 온라인 공간에서 기록을 찾고, 추가하거나 고치고, 상태를 옮기는 흐름**부터 설계합니다. 데스크탑의 화면·조작·배포·동기화 방식을 유지하고, 웹의 탐색과 편집 화면은 가용 폭과 터치에 맞춥니다. 공개 웹 `a2bff01`과 현재 작업 브랜치의 로컬 첨부 구현을 출발점으로 사용합니다. [기능 ID별 범위](web-service-v1-feature-scope.md) · [웹 서비스 상세 설계](web-service-v1-spec.md) · [현행 웹 구현](../web/README.md)

## 1. 범위와 구현 기준

- 기능표에서 제안한 160개 제공 항목을 웹 v1 설계 대상으로 삼습니다. 첫 구현은 이미 웹에서 동작하는 흐름을 같은 데이터로 다시 구성하고, 기록 쓰기·섹션 관리·계정 설정 등 신규 동작은 기존 서버 계약과 왕복 검증 결과에 따라 단계적으로 엽니다.
- 웹에서 다루는 대상은 초대 계정의 온라인 공간입니다. 업무·기록·상태·공간 외형은 두 채널에서 동일하게 해석합니다. 브라우저의 화면 설정과 개인 표시 순서는 계정·공간별로 기억합니다. 웹의 테마나 표시 순서 변경으로 데스크탑 설정을 덮어쓰지 않습니다.
- 데스크탑의 브랜드, 사용 중인 업무 색, 아이콘 의미, 기본 글꼴을 계승합니다. 업무 색상띠는 4px 직선, 넓은 화면의 탐색 선택선은 3px 직선입니다. 띠의 끝과 카드 접점은 직각으로 처리합니다. 시그니처는 고운돋움, 라이트·다크는 기존 Pretendard 기준을 사용하고 웹에서 필요한 글꼴은 자체 배포합니다. [데스크탑 디자인 규칙](renewal/design-renewal-v2.md)
- 화면의 문구는 제목·조작·상태에 필요한 것만 둡니다. 업무·날짜·기록 제목이 이어지는 읽기 순서를 유지하고, 빈 화면과 오류에는 사용자가 바로 취할 수 있는 동작을 제공합니다.
- 공개 웹과 보호된 Preview는 현재 DEV 온라인 환경을 사용합니다. 웹과 데스크탑 간 데이터 왕복은 같은 DEV 공간에서 검증합니다. 정식 데스크탑의 운영 공간 연결은 UX/UI 개편의 배포와 별도 결정입니다. [공개 배포 구성](../web/production.md)

## 2. 정보 구조와 공통 화면

| 화면 | 주 진입과 동작 | 공통 탐색에서의 위치 |
| --- | --- | --- |
| 로그인·약관 | 티저에서 웹으로 열기 → 이메일·동의 → 인증번호 → 공간 목록. 액션은 한 열, 약관과 개인정보 처리방침은 입력을 유지한 채 열기 | 공개 헤더·푸터 |
| 공간 목록 | 아이콘·이름·접근 상태로 공간을 고릅니다. 0개 상태에는 사용 가능한 생성 또는 안내를 표시합니다. | 로그인 직후 또는 작업 화면의 공간 선택기 |
| 오늘 | 선택한 날의 업무와 기록, 빠른 추가, 중요·마감 확인 | 하단·사이드 탐색 |
| 주간 | 주 선택, 요일과 업무 비교, 주간 메모·요약·내보내기 | 하단·사이드 탐색 |
| 칸반 | 기간 필터, 상태별 카드, 상태 이동과 섹션 내 재정렬 | 하단·사이드 탐색 |
| 검색 | 현재 공간 검색, 결과 종류·일치 문맥, 원래 기록 열기 | 모바일 더 보기의 첫 항목, 넓은 화면 사이드 탐색 |
| 요약·자료·연결 | 주간 요약, 주간 메모, Cabi.NET, Universe 조회 및 원본 이동 | 주간에서 요약·메모로 바로 이동. 전체 목록은 더 보기나 사이드 탐색 |
| 설정·도움말 | 계정·사용량, 공간 외형, 웹 표시 설정, 가이드, 약관·정보, 로그아웃 | 더 보기 또는 사이드 탐색 하단 |

- **공통 헤더**에는 공간 선택기, 현재 화면 제목, 동기화 상태를 둡니다. 상호작용이 필요한 동기화 상태는 원인과 재시도 버튼을 열어 볼 수 있게 합니다. 화면별 날짜·필터는 본문 도구 모음에 배치합니다.
- **작은 화면 탐색**은 `오늘 · 주간 · 칸반 · 더 보기` 4개를 기본으로 합니다. 기록 편집이나 확인 화면이 열리면 저장·취소에 필요한 영역을 먼저 확보합니다. 큰 화면에서는 같은 경로를 사이드 탐색에 배치하고, 아이콘만 보이는 폭에도 접근성 이름과 선택 상태를 제공합니다.
- **주소와 돌아가기**는 기존 `/app/:spaceId/…` 경로와 `date` 링크를 살립니다. 날짜·선택한 기록처럼 다시 열 때 필요한 상태만 링크로 복원하고, 검색어·초안은 브라우저 주소에 담지 않습니다. 기록에서 뒤로 가면 같은 날짜·필터·스크롤과 원래 선택 위치로 돌아옵니다.
- **공간 및 계정 경계**에서는 이동 요청을 서로 구분합니다. 미저장 상태를 먼저 처리한 다음 대상 공간의 로딩을 표시합니다. 새 공간의 권한·데이터가 확인되면 본문을 표시하고, 앞선 요청이 늦게 와도 이전 공간의 내용을 표시하지 않습니다.

## 3. 화면 폭별 배치

| 가용 화면 폭 | 탐색 | 콘텐츠 | 상세·편집 |
| --- | --- | --- | --- |
| 320–599px · 바형 스마트폰과 접힌 폴드 | 하단 4개 메뉴. 상단에는 공간 선택과 필요한 상태만 표시 | 한 열. 주간은 요일 선택과 해당 날짜 기록. 칸반은 선택한 섹션 한 개 | 전체 화면 상세·편집. 저장 영역은 가상 키보드와 하단 안전 영역 위 |
| 600–1023px · 펼친 폴드·태블릿 | 폭이 충분하면 아이콘 레일. 본문 폭이 좁을 때 하단 탐색 사용 | 요일·섹션 선택과 목록을 유지. 본문 폭이 충분하면 목록 280px, 상세 320px, 간격 16px부터 검토 | 본문 616px부터 분할 후보. 필요한 폭이 줄면 상세를 단일 화면으로 전환 |
| 1024px 이상 · 넓은 브라우저 | 기본 레일을 사용하고 공간이 충분할 때 레이블 표시 | 주간 격자는 본문 880px부터, 칸반은 열당 최소 너비를 확보한 뒤 배치. 검색·자료는 목록과 상세 | 격자와 열 읽기가 어려워지면 상세를 겹침 패널로 전환 |

600px과 1024px은 시안에 쓰는 초기값입니다. 실제 배치는 메뉴·여백을 제외한 **본문 가용 폭**과 콘텐츠가 필요한 최소 폭으로 확정합니다. 예를 들어 펼친 폴드에서 두 패널이 들어가지 않으면 단일 화면을 사용합니다. 폴드 열기·닫기, 가로 회전, 브라우저 확대 중에도 선택한 기록과 현재 편집 입력은 유지합니다.

- 가로 스크롤은 칸반의 넓은 열 영역 같이 필요한 구성 요소 안에 한정합니다. 페이지 전체, 상단 헤더, 날짜 선택, 확인 화면은 320px에서도 잘림 없이 사용합니다.
- 주요 터치 대상과 손잡이는 44×44 CSS px을 기준으로 두고, 인접한 주요 버튼은 8px 이상에서 점검합니다. 마감·읽기 전용·오류는 색과 텍스트를 함께 사용합니다.
- 화면 키보드가 뜨면 입력칸과 저장 버튼을 계속 쓸 수 있게 합니다. 안전 영역, 접힘 경계 정보를 쓸 수 있는 브라우저에서 힌지 위치, 200% 확대, 저속 연결을 시안과 Preview에서 검사합니다.

## 4. 화면별 상호작용 명세

### 오늘·주간과 기록 편집

| 조작 | 좁은 화면 | 넓은 화면 | 저장·복귀 |
| --- | --- | --- | --- |
| 날짜 이동 | 짧은 날짜 표시와 이전·다음, 오늘 복귀. 주간에서 요일을 선택하면 선택한 날 목록을 갱신 | 주간 격자 날짜 머리와 기준일 선택. 업무/요일 머리는 본문을 읽는 동안 식별 가능 | 선택 날짜를 주소에 반영하고 주간 메모·요약에서도 같은 주를 엽니다 |
| 기록 열기 | 카드나 기록 줄을 누르면 상세. `편집`을 눌러 입력 시작 | 목록·격자는 유지하고 상세 패널에서 맥락과 기록 표시 | 상세 닫기나 뒤로 가기로 원래 기록 위치에 복귀 |
| 기록 추가 | 현재 날짜의 추가 버튼에서 업무 선택. 이미 업무가 정해진 곳에서 시작하면 그 업무를 기본값으로 사용 | 선택한 업무×요일 칸에서 바로 추가 | 저장 전 날짜·업무를 확인하고, 성공 후 추가한 기록을 보여 줌 |
| 기록 편집 | 본문을 먼저 배치하고 중요·마감·시작 시각·계층 변경은 필요한 조작을 꺼내서 사용 | 같은 입력과 명령을 상세 패널에서 제공 | 서버 확인 뒤 저장 표시. 한글 조합 중에는 저장 단축키가 입력을 끊지 않음 |
| 초안·동시 수정 | 닫기·화면 이동·공간 변경 시 저장 여부 확인. 네트워크 오류는 입력을 유지한 채 재시도 | 동일 동작. 두 버전을 나란히 비교할 폭이 충분하면 나란히, 좁으면 순서대로 표시 | 서버와 수정 번호가 달라지면 최신 기록과 내 입력을 표시하고 다시 저장하기 전에 재확인 |

첫 작업에서는 현재 본문 편집을 위 흐름에 연결합니다. 추가·삭제·계층과 날짜 이동·중요/완료·마감 등 신규 쓰기는 지원이 확인된 조작부터 같은 편집 화면에 연결합니다. 기존 자료나 연결을 보존하며, 실패한 저장을 성공으로 표시하지 않습니다.

### 칸반

- 좁은 화면에서는 섹션 이름·카드 수·선택 상태를 확인할 수 있는 상태 선택기를 사용합니다. 상태가 많으면 세로 선택 목록에서 전환합니다. 넓은 화면에서는 TODO·사용자 섹션·DONE을 칼럼으로 비교합니다.
- 첫 시안에서는 **카드를 연 뒤 상태 이동**, **같은 섹션에서 손잡이로 순서 변경**을 각각 검토합니다. 카드 본문을 눌러 읽거나 스크롤할 수 있게 하고, 외곽 손잡이에서만 끌기를 시작합니다. 같은 섹션의 순서 변경은 키보드에서도 가능하게 합니다. 필터로 숨긴 카드의 상대 순서는 유지하고, 현재 섹션의 기본 정렬로 되돌릴 수 있게 합니다.
- 다른 섹션으로 옮기는 조작은 카드 상세의 `상태 이동`으로도 가능합니다. 이동 전후의 상태를 알리고, DONE의 본·세부 완료와 다시 열기는 서버가 반환한 상태를 기준으로 표시합니다. 응답 중 새 상태 이동 입력은 해당 카드에서만 막습니다.
- 상단 기간·업무 필터와 사용자 섹션의 기간 고정을 구분합니다. TODO·DONE은 상단 기간을 따릅니다. 고정된 사용자 섹션은 현재 적용 기간을 섹션 제목 옆에 표시하고, 마감 표시는 D-2·D-1·당일·초과를 텍스트와 색으로 나타냅니다.
- 섹션 이름·아이콘·공용 순서는 기존 계약을 통해 공유합니다. 개인 카드 순서와 기간 고정은 범위표 기준으로 웹의 계정·공간·섹션별 표시 설정에 둡니다. 공용 상태 데이터의 순서와 섞지 않습니다.

### 검색·요약·자료·설정

| 화면 | 기본 흐름 | 상세 상태 |
| --- | --- | --- |
| 검색 | 검색어 → 유형·업무·기간 필터 → 결과 → 원본 열기. 현재 공간 범위 | 메모·노트·지식 카드의 원본 위치를 확인해 이동. 좁은 화면에서는 검색 목록으로 돌아가기 제공 |
| 주간 요약·내보내기 | 주 선택 → 수정본·저장된 AI본·자동 집계 중 표시할 내용 확인 → 복사 또는 다운로드 | Markdown은 현재 동작부터 유지. Excel은 시트·범위 선택, 진행·취소, 브라우저 다운로드로 제공. 내용이 바뀐 수정본은 비교 안내 |
| 주간 메모 | 선택한 주의 메모를 읽는 순서로 배치하고 링크·첨부·연결 열기 | 이미지는 비율을 유지하고 같은 출처에서 읽습니다. 실패한 첨부는 메모 설명과 다시 열기 상태를 제공합니다 |
| Cabi.NET | 업무 또는 유형으로 자료를 찾고 목록에서 상세 열기 | 등록한 폴더는 이름과 데스크탑 안내를 표시. 업무노트·메모보드 본문과 링크는 읽고 원본으로 이동 |
| Universe | 연결 목록 → 묶인 본 항목 → 날짜별 원본·세부 기록 | 동명 묶음은 같은 공간·업무 내에서 유지. 관계·출처를 펼쳐 원본을 확인 |
| 계정·워크스페이스 | 사용량, 공간 설정, 지원하는 계정·공간 관리 | 사용량은 항목당 한 행에 게이지와 사용량/한도 수치를 함께 표시. 삭제는 영향 범위와 대상 이름을 확인한 뒤 실행 |
| 둘러보기 | 공간 선택·빠른 기록·칸반 상태 이동의 짧은 안내 | 웹에서 지원하는 흐름을 먼저 보여 주며 가상 예시는 온라인 기록과 분리 |

## 5. 공통 상태와 웹 구현 경계

| 상태 | 화면 조작 |
| --- | --- |
| 첫 로딩 | 메뉴와 도구 모음의 자리를 유지하고 본문에 뼈대 화면을 표시합니다. 상태 문구는 `서버와 동기화 중`으로 통일합니다. |
| 다시 불러오기 | 같은 공간의 현재 목록을 유지합니다. 좁은 상태 영역에서만 동기화 진행을 표시합니다. |
| 공간 전환 | 작업 영역의 입력을 잠그고 대상 공간 이름과 진행을 표시합니다. 실패하면 목록으로 돌아가기와 재시도를 제공합니다. |
| 빈 화면 | 공간 0개, 기록 0개, 필터 결과 0개를 구분해 각각 공간 선택·기록 추가·필터 해제 등 가능한 다음 동작을 표시합니다. |
| 읽기 전용·한도 초과 | 서버가 허용한 조회를 계속 제공합니다. 쓰기 제한이 적용되는 조작에 현재 상태와 관련 설정으로 가는 경로를 표시합니다. |
| 연결 끊김·저장 미확인 | 열린 화면과 입력을 해당 탭에서 유지합니다. 동일한 저장의 재시도에는 같은 작업 ID를 사용합니다. |
| 충돌 | 서버의 최신 값과 내 입력을 비교합니다. 서버 값 사용 또는 내 입력을 검토한 뒤 최신 판에 다시 저장할 수 있게 합니다. |
| 세션 만료·권한 회수 | 화면의 해당 공간 데이터와 초안을 비우고 로그인 또는 공간 목록으로 이동합니다. 로그인한 계정이 달라져도 이전 기록이 화면에 나타나지 않게 합니다. |

- 기존 `web/pages.mjs`의 로그인·공간·작업 화면을 공통 골격으로 정리합니다. 웹 스타일에서 안전 영역·탐색·도구 모음·상태·편집 틀을 공유하고, 개별 화면은 해당 골격에 맞춰 배치합니다.
- `web/public/workspace.js`의 선택 날짜·선택 기록·카드 섹션·편집 상태를 렌더링과 구분합니다. 화면 폭이 달라져도 같은 선택과 초안을 렌더링하고, 화면별 코드는 기준 데이터를 같은 방식으로 읽습니다. 복잡한 전역 상태나 별도 프런트엔드 프레임워크 도입 없이 현재 HTML·CSS·ES 모듈 흐름을 사용합니다.
- `web/server.mjs`와 `web/workspace.mjs`의 로그인 검사·공간 권한·레코드 투영·수정 번호 경로를 유지합니다. 기능표 항목마다 `조회 가능 / 기존 쓰기 가능 / 서버 계약 확인 필요`를 구현 티켓에 기록합니다. 예를 들어 현재 본문 저장과 칸반 이동은 기존 API에 연결하고, 기록 추가·요약 쓰기·온라인 공간 생성·삭제는 해당 서버 명령과 이전 데스크탑 호환 여부를 확인한 뒤 연결합니다.
- 기록과 자료는 기존 서버 페이지 단위를 사용하고, 첨부는 보이는 시점에 엽니다. 날짜·필터 변경과 서버 갱신에서 변경된 화면 영역을 갱신해 스크롤 위치와 입력 초점을 유지합니다. 같은 데이터로 초기 표시와 날짜 전환에 걸리는 시간을 개편 전후 비교합니다.
- 본문과 초안의 기본 보존 범위는 현재 탭 메모리입니다. 브라우저에는 테마·보기 설정·개인 표시 순서 같은 설정값을 보관합니다. 폴더 경로·첨부 원본 주소·인증정보는 화면 응답이나 브라우저 저장소에 담지 않습니다.
- 데스크탑 공용 색상·글꼴·아이콘 자산은 기존 값과 라이선스를 사용합니다. 개편 변경 범위는 `web/`과 웹 설계·시안·테스트에 둡니다.

## 6. 단계별 작업과 완료 기준

| 단계 | 작업과 산출물 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 1. 반응형 시안 | 동일한 가상 업무 데이터로 오늘·주간·칸반, 공간 전환, 기록 상세·편집을 연결한 시안. 스마트폰·폴드 펼침·넓은 브라우저의 흐름을 비교. 모바일 메뉴의 `더 보기`와 검색 진입, 폴드 분할 기준을 포함 | 날짜 변경, 기록 열기·편집, 상태 이동, 목록 복귀를 입력 방식별로 검토하고 화면 구조를 확정 |
| 2. 공통 골격과 기존 흐름 | 로그인·공간 목록과 공통 작업 골격을 구현. 오늘·주간·칸반을 새 골격에 연결하고 기존 읽기·본문 저장·상태 이동을 유지. 크기 변경·초점 복귀·뒤로 가기·동기화 상태 검증 | 주요 화면의 레이아웃·색상띠 검증 통과. 기존 인증·저장·칸반·공간 분리 회귀 테스트 통과 |
| 3. 기존 보조 화면 반영 | 검색·요약·주간 메모·Cabi.NET을 공통 골격에 적용. 현재 검색·요약 Markdown·자료 읽기 연결. 로컬 첨부 구현은 보호된 Preview에서 실제 스트리밍 검증 | 기존 기능의 링크와 선택 상태가 유지되고, 비로그인·다른 계정 첨부 요청과 실제 이미지 크기 경계를 검증 |
| 4. v1 기능 확장 | 기록·업무·태그 관리 → 칸반 재정렬·필터 → 보고·내보내기 → 읽기 확장과 계정·공간 관리 순으로 묶어 반영. 기능표 ID를 작업과 검증에 연결 | 각 작업에 기존 서버 계약과 데스크탑 왕복 검증 기록이 있음. 파괴적 동작은 대상과 결과를 확인. 기능표에서 완료·보류·계약 확인 상태를 갱신 |
| 5. 통합 검증과 공개 | 가이드·웹 코칭 갱신, 보호된 Preview 실기, Production 후보 검증, 도메인 승격. 브라우저·데스크탑 조합과 확인한 커밋을 기록 | 인증·접근·저장·이동·동기화·다운로드 실기 통과. 배포 리비전과 이전 정상 배포의 복구 경로 확인 |

단계 1의 검토 화면에는 **주간→메모·요약**, **오늘→기록 상세→편집→복귀**, **칸반→상태 이동→다른 섹션에서 찾기**를 넣습니다. 시안과 기능 범위가 확정되면 설계안을 `web-service-v1`에 보존하는 커밋·푸시를 하고, 구현은 이후 변경으로 이어갑니다. 시안 검토 전에도 기존 빌드와 테스트로 기준 동작을 기록할 수 있습니다.

[반응형 대화형 시안](mockups/web-service-v1/responsive-review/index.html)에서 같은 가상 공간의 스마트폰·펼친 폴드·넓은 화면을 전환할 수 있습니다. 주간 보드에서 오늘 기록을 열고 편집한 뒤, 같은 기록을 칸반의 다른 섹션으로 옮겨 봅니다. 드래그 또는 손잡이의 위·아래 화살표로 순서를 바꾸고, 날짜 필터와 파킹랏의 독립 기간도 확인할 수 있습니다.

## 7. 검증 기준

| 검증 | 기준 |
| --- | --- |
| 화면 폭과 배율 | 자동 검증은 320·390·430·599·600·673·768·820·1023·1024·1280·1440 CSS px에서 화면별 핵심 조작과 잘림을 확인합니다. 실기는 iOS Safari, Android Chrome, 폴드 외부·내부·가로 전환, PC Chrome·Edge·macOS Safari를 대상으로 합니다. 폴드8에서 실기 가능한 폭과 확인 결과는 따로 기록합니다. |
| 터치·키보드 | 모바일 메뉴와 카드의 표시·조작 영역을 검사합니다. 스크롤 중 카드가 이동하지 않고, 상태 이동이 드래그 없이도 가능해야 합니다. 키보드 탐색, 화면 읽기 프로그램, 포커스 표시·복귀, 모션 감소, 한글 조합·200% 확대를 확인합니다. |
| 데이터·저장 | 가상 DEV 공간에서 데스크탑 작성→웹 읽기·편집→데스크탑 확인, 웹 작성→데스크탑 수정→웹 충돌 순으로 실행합니다. 저장 실패 재시도, 동일 요청 반복, 화면 폭 전환 중 편집, 늦은 이전 공간 응답을 재현합니다. |
| 인증·권한 | 비로그인 링크는 로그인으로 이동하고 보호 API는 거절합니다. A/B 계정, 공간 권한 회수, 읽기 전용, 다른 탭 로그아웃, 브라우저 뒤로 가기에서 계정과 공간 데이터가 섞이지 않아야 합니다. |
| 디자인 | 주요 화면과 라이트·다크·시그니처에서 스크린샷을 남깁니다. 업무 띠 4px, 선택선 3px과 직각 접점, 날짜·제목 기준선, 긴 업무명과 한글 줄바꿈을 확인합니다. 일반 텍스트는 4.5:1, 표시 요소의 상태 경계와 초점은 3:1 대비를 확인합니다. |
| 첨부·내보내기 | Preview에서 첨부 없음·정상·10 MiB 경계·초과·중간 끊김을 검사합니다. 실제 다운로드 파일의 이름·선택 범위·시트 값·한글·휴가와 완료 표시를 확인하고 취소 후에는 파일이 생성되지 않는지 확인합니다. |
| 빌드·배포 | `npm run build --prefix web`, 웹 린트, 임시 DB를 사용하는 `web/w1.test.mjs`, 필요한 Chromium 회귀 검증. Preview에서 승인한 커밋으로 Production 후보를 만든 뒤 로그인 리다이렉트와 `/healthz` 리비전 확인 후 승격합니다. |

검수 화면에는 커밋 ID, 배포 환경, 브라우저·화면 폭, 확인한 기능 ID를 남깁니다. 공개 배포 뒤 인증·공간 접근·저장 회귀가 확인되면 웹 도메인을 직전 정상 배포로 되돌리고 저장된 데이터는 기존 서버 계약으로 유지합니다. [로컬 통합 테스트](../web/README.md#로컬-통합-테스트) · [Vercel 공개 배포 절차](../web/production.md)
