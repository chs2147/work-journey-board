## 1. 설정 자리와 전체 설정 화면 (#1, 시안 ①②③)

### 1-1. 왜 레일 맨 아래인가 — 위계

| 자리 | 성격 | 들어가는 것 |
|---|---|---|
| 상단 바 | **지금 보고 있는 주**에 대한 동작 | 주 이동·오늘·연간 보기·보기 전환·태그 필터·주간 요약·내보내기·저장 표시 |
| 레일 위쪽 | 화면(보기) 바꾸기 | 주간 보드 · 인사이트 |
| 레일 구분선 아래 | 보드 옆 패널 | 중요 업무 ★ |
| **레일 맨 아래(새)** | **앱 전체 설정** — 자주 안 씀 | ⚙ 설정 |

- 지금 ⚙는 상단 바의 "이번 주" 동작들 사이에 섞여 있어 위계가 맞지 않는다. 앱 전체 설정은 보기 메뉴 줄의 **맨 아래 끝**에 따로 두는 것이 흔한 관례(윈도우 업무용 앱들의 왼쪽 막대 맨 아래 톱니)이고, 손이 자주 가는 위쪽 보기 단추와도 떨어진다.
- 레일: 보드 · 인사이트 · 구분선 · ★ · (빈 공간) · 구분선 · **⚙**. ⚙는 40×40 같은 단추, 설정 화면일 때 다른 보기 단추와 같은 "켜짐" 모양(옅은 파랑 바탕 + 왼쪽 막대, `aria-current="page"`).
- 새 판 파란 점(improve-1027v4-spec 1-2)은 레일 ⚙ 오른쪽 위로 옮긴다. 툴팁·aria-label: `설정 (Ctrl+,)` / 새 판이 있으면 `설정 (Ctrl+,) — 새 판이 있습니다`.
- 상단 바에서 ⚙ 단추는 없앤다. 그 자리는 저장 표시가 맨 오른쪽 끝을 차지한다(2절).

### 1-2. 설정 화면 = 보드 자리를 덮는 화면

- 인사이트와 같은 방식: 설정을 열면 **보드는 숨겨 둔 채 그대로**(보던 주·뷰·커서·메모 입력 상태 유지)이고 보드 자리에 설정 화면이 뜬다. 모달·뒤 배경 어둡게 하기 없음.
- 상단 바(시안 ②): 주 이동 자리에 **[← 주간 보드로]** + 제목 **"설정"**. [태그]·[주간 요약]·[내보내기]는 숨긴다(인사이트와 같은 규칙). 저장 표시는 그대로 보인다.
- 들어가기: 레일 ⚙ · `Ctrl+,`(새 단축키 — 지금 쓰지 않는 조합, 윈도우 앱의 흔한 설정 단축키).
- 나가기: `Esc` · [← 주간 보드로] · 레일 보드(`Alt+1`) · 레일 인사이트(`Alt+3`) · `Ctrl+,` 한 번 더. 레일 ★(`Alt+2`)를 누르면 보드로 돌아가며 중요 업무 패널이 열린다. 나갈 때 지금처럼 보드를 다시 읽는다(`reload`) — 종료된 업무 다시 시작·반복 수정이 보드에 바로 보이게.
- 인사이트에서 ⚙를 누르면 설정으로, 설정에서 나가면 **들어오기 전 화면**(보드 또는 인사이트)으로 돌아간다.
- 열 때 보이는 분류: **마지막에 본 분류**(설정 JSON `ui.settingsCategory`). 단 새 판 파란 점이 켜져 있으면 **업데이트·정보**로 연다(점을 보고 눌렀다는 뜻이므로).
- 보드에서 쓰던 칸으로 돌아가는 규칙은 인사이트와 같다(보던 칸에 커서, 없으면 보드 시작 칸).

### 1-3. 화면 구성 (시안 ②③)

- **왼쪽 분류 목록**(폭 248px, 카드 바탕 + 오른쪽 경계선): 분류마다 아이콘 + 이름(굵게) + 한 줄 설명(무엇이 들었는지). 고른 분류는 옅은 파랑 바탕 + 파랑 글자. 업데이트·정보는 새 판이 있으면 오른쪽에 파란 점. 목록 아래에 단축키 안내 한 줄(`↑ ↓ 분류 이동 · Esc 보드로`).
- **오른쪽 내용**(최대 폭 820px, 왼쪽 정렬, 위아래 스크롤): 분류 제목(22px) + 한 줄 설명 → **카드**들(바탕 = 카드, 테두리, 모서리 10px).
  - 카드 머리: 제목(16px 굵게) + 옆에 한 줄 설명(13px, 둘째 글자색).
  - 카드 몸통은 **설정 행**의 목록: 왼쪽 = 이름(14px 굵게) + 설명(12.5px) / 오른쪽 = 조작(단추·선택·입력). 행 사이는 가는 선.
  - 주된 동작 하나만 채운 파랑 단추(예: [지금 백업]), 나머지는 테두리 단추, 지우기·삭제는 빨간 글자 단추.
- **한 번에 한 분류만** 보여 준다(긴 한 장 스크롤이 아니라). 분류 5개라 목록 클릭 한 번이면 닿고, 화면이 복잡해 보이던 원인(9개 절이 한 줄로 이어짐)을 없앤다.
- 좁은 창(폭 1180px 미만): 분류 목록이 내용 위쪽 **가로 탭 줄**(아이콘 + 이름, 설명 숨김)로 바뀐다.

- 업무 관리 안의 순서는 자주 고치는 것부터: 매주 반복 → 태그 → 종료된 업무 → 무기록 종료 제안(뒤의 두 카드는 내용이 짧아 넓은 창에서 두 칸으로 나란히).

### 1-5. 키보드·접근성

- 분류 목록 = `role="tablist"`(세로), 분류 = `role="tab"` + 화살표 `↑`/`↓`로 이동하며 바로 바뀜, `Home`/`End`. 내용 = `role="tabpanel"`. `Tab`으로 목록 → 내용.
- 설정 화면을 열면 고른 분류 탭에 포커스. 화면 이름은 상단 바 "설정" 제목.
- `Esc`: 저장 위치 옮기기 확인처럼 펼친 흐름이 있으면 그것부터 닫고, 없으면 보드로. 글 입력칸(반복 문구·태그 이름)에서 `Esc`는 입력을 원래대로 되돌리고 칸을 벗어나며(새로 맞춤), 한 번 더 누르면 보드로.
- overview 10-3 단축키 표에 `Ctrl+,` 한 줄 추가, 화면 도움말도 함께.

## 2. 눈에 띄는 저장 표시 (#2, 시안 ①·⑤A)

| 상태 | 모양 | 글 |
|---|---|---|
| 저장됨 | **초록 테두리 알약**(높이 26px, 둥근 끝) + 옅은 초록 바탕 + **초록 굵은 글자** + 체크 원 아이콘 | 저장됨 |
| 저장 중 | 회색 테두리 알약 + 카드 바탕 + 둘째 글자색 + **도는 고리**(파랑 4분의 1) | 저장 중… |
| 실패 | 지금의 빨간 단추를 같은 높이로 맞추고 옅은 빨강 바탕 + 느낌표 원 아이콘 | 저장하지 못함 · 다시 시도 |

- 색(새 토큰): `--save-ok-bg` 라이트 `#eef7f2` / 다크 `#1a2c24`, `--save-ok-line` 라이트 `#8cc7b2` / 다크 `#2f7a60`, 글자 = 기존 `--ok`(라이트 `#0f6e56` / 다크 `#4fc29a`). 글자 대비 약 5.7:1(라이트) · 6.7:1(다크)로 작은 글자 기준 4.5:1을 넘는다. 색만으로 구분하지 않도록 아이콘(체크 / 고리 / 느낌표)과 글이 함께 바뀐다.
- **저장 중은 0.4초 넘게 걸릴 때만** 보인다. 보통 입력은 금방 저장되므로 글자 칠 때마다 알약이 회색↔초록으로 깜빡이지 않게 한다(초록은 "다 저장됨"이 기본 상태). 0.4초 안에 끝나면 계속 "저장됨".
- 툴팁: `모든 변경이 일지 파일에 저장되었습니다 · 마지막 저장 14:03`(저장됨일 때). 실패 단추 툴팁은 지금 그대로.
- 화면 읽기 프로그램: 저장됨/저장 중은 알리지 않는다(입력마다 읽어 주면 방해). 실패만 `role="alert"`로 한 번 알린다.
- 움직임 줄이기(`prefers-reduced-motion`)면 고리는 돌지 않는 반원.
- 자리: 상단 바 맨 오른쪽(⚙가 빠진 자리). 설정·인사이트 화면에서도 같은 자리.

## 3. 기존 일지 가져오기 화면 (#3, 시안 ④·⑤B·C)

### 3-1. 단계 표시(머리)

- 대화상자 폭 760 → **900px**(높이는 창에 맞춤, 지금처럼 몸통만 스크롤). 머리 = 제목 + 닫기(✕) 줄, 그 아래 **단계 표시 줄**.
- 단계 4개를 가로로: **원(28px) + 이름 + 한 줄 설명**, 단계 사이를 **선(2px)**으로 잇는다.

| 상태 | 원 | 이름 | 이어진 선 |
|---|---|---|---|

### 3-2. 진행 순서 상자(① 준비)

- 진행 순서 1~8 전체를 **다른 바탕의 상자**(바탕 `--surface-sub`, 테두리, 모서리 10px, 안쪽 여백 14·16px)에 넣는다. 상자 머리 = "진행 순서" + `8단계 · 한 번에 1~4주씩`.
- 8단계를 **3묶음**으로 나눠 위계를 준다 — **묶음 제목 = 상자 바탕과 다른 글상자**(카드 바탕 + 테두리, 모서리 6px, 상자 폭 가득, 굵은 13px) 안에 **정사각형 테두리(20px, 1.5px) 속 `A`·`B`·`C`** + 이름. 그 아래 단계 줄은 왼쪽으로 한 단 들여 쓴다(2026-10-27 사용자 지시 — 처음 시안의 작은 알약 + 회색 글자는 단계 번호 원과 위계가 어색했음):
  - **A 앱에서 준비** — 1, 2
  - **B 사내 AI로 옮기기** — 3, 4, 5
  - **C 앱으로 가져오기** — 6, 7, 8
- 단계 줄 = **번호 원(22px, 카드 바탕 + 테두리, 굵은 번호)** + 글. 문구는 지금 `STR.importer.procedure` 그대로(2단계 끝에 "아래 [AI 지시문 보기]로 내용을 볼 수 있습니다." 한 문장만 더함).
- **1단계 줄 끝에 [양식 엑셀 받기], 2단계 줄 끝에 [AI 지시문 복사]** 작은 단추(아이콘 + 글). 지금 절차 아래에 따로 있던 단추 줄은 없앤다 — 할 일과 단추가 같은 줄에 있어 "어느 단추를 언제" 헷갈리지 않는다.
- 상자 위에는 한 줄 소개만(`OneNote 등에 적어 온 업무 일지를 양식 엑셀로 옮겨 한 번에 가져옵니다. 아래 순서대로 진행하세요.`).

### 3-3. AI 지시문 코드 블록

- 기본은 지금처럼 **접힘**: `▸ AI 지시문 보기 — 사내 AI 도구에 그대로 붙여 넣는 글`(펼치면 `▾`, `aria-expanded`). 접혀 있어도 2단계 줄의 [AI 지시문 복사]로 바로 복사된다.
- 펼치면 **코드 블록**:
  - 머리 띠(높이 38px, 띠 바탕 `--code-head`): 코드 아이콘 `</>` + **AI 지시문** + `일반 텍스트 · N줄` + 오른쪽 **[복사]**(아이콘 + 글).
  - 본문(바탕 `--code-bg`): 고정폭 글꼴(`--font-mono` = Consolas, 한글은 맑은 고딕으로 대체), 12.5px, 줄 간격 1.65, 줄바꿈 유지(`pre-wrap`), **최대 높이 240px**(넘치면 블록 안 스크롤, `tabindex="0"`로 키보드 스크롤).
  - 맨 위 빈칸 `____-__-__`는 **노란 강조**(`--mark`, 굵게) — 사용자가 고쳐 적어야 하는 유일한 곳이 눈에 띄게.
- [복사]를 누르면 2초 동안 **초록 "✓ 복사됨"**(저장됨과 같은 초록 토큰)으로 바뀌고 지금처럼 토스트도 뜬다. 복사에 실패하면 본문 전체를 선택해 두고 `Ctrl+C로 복사하세요` 안내.
- 색(새 토큰): `--code-bg` 라이트 `#f7f6f2` / 다크 `#171716`, `--code-head` 라이트 `#eceae3` / 다크 `#1f1f1e`. 글자는 `--text-1`(대비 라이트 약 13:1, 다크 약 15:1). 테마를 따르는 밝은/어두운 블록으로 둔다(라이트 화면에 검은 블록을 띄우면 대화상자 안에서 너무 무겁다).

## 4. 테마 — 시스템 설정 / 라이트 / 다크 (#4, 시안 ②)

### 4-1. 화면

- 설정 › **화면** › 테마 카드: **미리보기 카드 3개**(라디오 묶음, `role="radiogroup"`).
  - **시스템 설정**(기본, `기본` 꼬리표) — 미리보기 반은 라이트·반은 다크. 설명 `윈도우 설정 › 개인 설정 › 색 › 앱 모드를 따릅니다 · 지금: 라이트`(지금 윈도우 값).
  - **라이트** — `밝은 바탕 — 윈도우가 다크여도 이 앱은 밝게`.
  - **다크** — `어두운 바탕 — 윈도우가 라이트여도 이 앱은 어둡게`.
- 고른 카드: 2px 파랑 테두리 + 옅은 파랑 빛. 방향키로 카드 이동하면 **바로 적용**(되돌리기 단추 없음 — 다시 고르면 됨).
- 카드 아래 안내 상자: `테마는 이 PC에 저장됩니다(일지 파일과 따로). 다른 PC에서 같은 일지를 열면 그 PC의 테마를 따릅니다. 시작 창도 같은 테마로 뜹니다.`

### 4-2. 값을 어디에 두나

- **이 PC 설정 = `config.json`**(`%LOCALAPPDATA%\WorkJourneyBoard\`, data-spec 3-4)에 `theme: "system" | "light" | "dark"`(없으면 system). 이유:
  - 시작 창(스플래시)·첫 실행·폴더 없음 화면은 **일지를 열기 전**이라 일지 안의 설정을 읽을 수 없다.
  - 화면 밝기는 PC(모니터·사무실 조명)에 딸린 취향이라, 일지를 다른 PC에서 열 때 따라가지 않는 편이 자연스럽다.
- 켤 때 깜빡임을 막는 **사본**: 같은 값을 웹 저장소(`localStorage` `wjb.theme`)에도 적는다. 메인 창·시작 창 스크립트가 **맨 먼저** 이 사본을 읽어 바로 적용하고, config.json 값과 다르면 config.json을 따른다(정본). 사본은 화면 취향 하나뿐이라 "데이터 = 파일 1개" 원칙과 부딪히지 않는다.
- `AppConfig`에 `theme?`가 생기므로 **config.json을 쓰는 곳은 모두 다른 값을 보존**해야 한다(지금 `saveConfig({ dataDir })`는 `dataDir`만 쓴다 → 저장 위치를 옮기면 테마가 지워지는 버그가 생길 수 있음). `loadConfig`·`saveConfig`가 전체 객체를 읽고 합쳐 쓰도록 바꾸고 단위 테스트로 막는다. Rust `config_read`/`config_write`는 글을 그대로 오가므로 바꿀 것 없음(`configured_data_dir`도 `dataDir`만 읽음).

### 4-3. 적용 방식

- 화면은 `<html data-theme="light|dark">` **하나로** 정한다. "시스템 설정"이면 스크립트가 `matchMedia("(prefers-color-scheme: dark)")`로 지금 값을 골라 넣고, 윈도우 앱 모드가 바뀌면 바로 따라간다.
- `tokens.css`: 라이트 값은 `:root`, 다크 값은 지금의 `@media (prefers-color-scheme: dark) { :root {…} }` 대신 **`:root[data-theme="dark"] {…}` 한 벌**(다크 값이 한 곳에만 있게 — 같은 값을 두 번 적지 않음). `color-scheme`도 따라가서 스크롤바·입력칸·선택 상자도 맞는다. 업무 색(`--cat-cN`)도 같은 선택자로.
- 시작 창 `splash.html`의 다크 미디어 쿼리도 같은 `data-theme` 방식으로 바꾼다(splash.test가 색 대조를 계속 지킴).
- **창 제목 표시줄**도 맞춘다: Tauri `getCurrentWindow().setTheme(null | "light" | "dark")`(시스템이면 null). 권한 `core:window:allow-set-theme`를 capabilities에 추가(네트워크와 무관).
- 바뀌지 않는 것: 메모 보드 스냅샷 PNG·엑셀은 지금처럼 **항상 밝은 색**(인쇄·공유용), 업무 색 팔레트 값 자체.

### 8-1. 설계와 달라진 점·구현에서 정한 것
- 테마 라디오의 접근성 이름은 테마 이름만(`시스템 설정`·`라이트`·`다크`), 설명은 `aria-describedby` — 설명 글에 "다크"가 섞여 이름이 겹치지 않게.
- 마지막 백업 행은 이름 "마지막 백업" + 설명 = 시각만(`2026-10-22 09:02`), 보관 규칙 문구를 행 설명에 맞게 줄임(`최근 14일 + 월 1개 × 12 보관 · 직접 만든 백업은 지우지 않음`).
- 반복 항목 카드 제목은 기존 문구 "반복 항목" 그대로(문서 1-4절의 "매주 반복"과 같은 것).
- 시작 창(스플래시)은 창 제목 표시줄이 없어 `setWindowTheme`은 메인 창만.
