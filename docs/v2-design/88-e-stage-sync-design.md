# 88. E단계 — 온라인 공간 편집·여러 기기 동기화 (설계 — 2026-11-15 E1~E4 추천안 승인)

2026-11-15 · `v2-design` · 앞 단계 D(온라인 공간 열기, Windows·macOS 상호 확인 — [87](87-d-stage-open-design.md)) · main 미반영

## 0. 이미 정해진 것 (다시 묻지 않음)

초기 설계([02](02-sync-data.md) · [06](06-sync-policy-flows.md) · [22](22-db-permission-sync-contract.md))에서 사용자 확정·추천으로 정해 둔 원칙:

| 원칙 | 내용 |
|---|---|
| 로컬 우선 | 고치면 **이 기기에 먼저 저장** + 보낼 목록(대기열)에 같은 묶음으로 기록 → 나중에 서버로. "저장됨"(이 기기)과 "동기화됨"(서버)을 따로 표시 |
| 서버 확정 | 서버가 권한·기대 판(revision)·참조를 확인하고 데이터 + 변경 기록을 한 트랜잭션으로. 같은 요청 번호는 같은 결과(재전송 안전) |
| 받기 | 공간별 변경 순번(cursor) 이후만 받기. 받은 것을 다시 보내지 않음 |
| 충돌 | **텍스트를 마지막 저장으로 덮어쓰지 않음.** 서로 다른 기록 = 각각 적용, 같은 기록의 겹치지 않는 칸 = 합침, 같은 칸 / 같은 문서(노트·보드·주간 메모) 동시 수정 = **양쪽 보존 + 충돌 목록에서 사용자가 선택** |
| 삭제 | 지움 표시(tombstone)로 전파. 지운 부모에 새 자식이 오면 충돌로 보존 |
| 그림 | 새 그림은 비공개 저장소에 먼저 올리고 확인된 뒤 문서 판 공개. 온라인 DB에 그림 본문 없음 |
| 범위 | 개인 여러 기기(같은 계정). 공유·팀 공동 편집은 후속 |
| 로컬판 | 로컬 전용 공간·정식판은 그대로(영구 유지). 온라인 공간만 해당 |

로컬 PoC로 이미 검증한 것: 대기열·충돌·셀 이동 원자성·재시작 복구(`poc/v2-sync`, 26~30문서).

## 1. 단계 제안

| 단계 | 내용 |
|---|---|
| **E-1 이 기기 저장** | 온라인 공간을 메모리가 아니라 **Preview 폴더의 SQLite 파일**로(지금 D단계 캐시에서 첫 생성). 편집 = 그 파일에 저장 + 대기열(`sync_outbox`) 같은 묶음. 읽기 전용 해제 |
| **E-2 서버 쓰기·받기** | 전진 SQL `019~`: 공간 기록별 서버 판(revision)·지움 표시·공간별 변경 순번(change log)·처리한 요청(멱등). `push`(묶음 단위, 기대 판 확인) / `pull`(순번 이후 페이지). gateway 경로 |
| **E-3 충돌** | 0절 규칙대로. 충돌은 이 기기에 양쪽 보존 + 상단 "충돌 N건" → 고르기 화면(내 기기 / 서버 / 둘 다) |
| **E-4 그림** | 노트·메모 보드에 새로 붙인 그림 = 기존 gateway 그림 경로로 올리고 확인 → 문서 판 공개 |
| **E-5 상태·실기** | 상단에 "이 기기에 저장됨 · 대기 N건 / 동기화 중 / 동기화됨 · 시각 / 오프라인 / 충돌 N건". 두 기기 동시 편집·오프라인 편집 후 합치기·충돌 고르기 실기 |

## 2. 결정이 필요한 것

| | 질문 | 추천 | 대안 |
|---|---|---|---|
| **E1** | 이 기기 저장 방식 | **Preview에서만 SQLite 플러그인을 켜되, Preview 폴더의 온라인 캐시 안 파일만 열 수 있게 Rust가 경로를 확인**(정식판과 같은 드라이버·같은 저장 안전성, 앱이 꺼져도 잃지 않음) | sql.js 메모리 일지를 몇 초마다 파일로 통째 저장(플러그인 없음, 단순하지만 그 사이 꺼지면 최근 편집 유실 가능) |
| **E2** | 1차 동기화 범위 | **전부 한 번에** — 업무·기록·태그·중요/완료/마감·칸반·주간 메모·노트·메모 보드·Universe. 기록 하나 = (표, 키) 단위 공통 처리라 표별로 나눌 이득이 작고, 일부만 동기화하면 참조가 어긋남 | 업무·기록만 먼저 → 문서(메모·노트·보드)는 다음 |
| **E3** | 보내고 받는 시점(개발 단계) | **고친 뒤 약 1초 묶어 보내기 + 창이 활성일 때 30초마다·창으로 돌아올 때·[지금 동기화] 받기** — 개발 검증용. 운영 기본값(06문서: 주기 5분 비용 우선)은 G단계에서 다시 | 처음부터 5분 주기(검증이 느림) / 서버 알림(실시간 소켓, 비용·복잡도 큼) |
| **E4** | 충돌 고르기 화면 위치 | **상단 상태 표시 → 충돌 목록 창**(항목마다 내 기기 / 서버 / 둘 다 보존, 문서는 나란히 보기). 고르기 전까지 다른 기록은 계속 동기화 | 충돌 시 즉시 모달로 막기(편집 흐름이 끊김) |

## 3. 바꾸는 것(승인 범위)

- 개발 서버만: 전진 SQL `019~`(동기화 표·push/pull 서버 함수, 서버 전용) · gateway 재배포. 운영 프로젝트·정식판·DEV 그대로.
- Preview 앱: (E1 추천 시) SQLite 플러그인을 Preview 빌드에 켜고 **열 수 있는 경로를 Preview 온라인 캐시로 제한**(Rust 가드 + 시험), 대기열·충돌 화면.
- 이미 만든 온라인 공간은 그대로 쓰되, E-1 첫 실행 때 그 공간의 이 기기 파일을 캐시에서 만든다(서버 자료는 바꾸지 않음).

## 4. 위험

| 위험 | 대응 |
|---|---|
| 같은 문서를 두 기기에서 고침 | 문서 단위 판 확인 → 양쪽 보존(조용히 덮어쓰지 않음) |
| 앱이 꺼지는 순간 | 데이터 + 대기열을 한 묶음으로 저장(SQLite 트랜잭션), 다음 실행에 이어 보내기 |
| 응답 유실 | 같은 요청 번호로 다시 보내면 같은 결과(서버 멱등) |
| 오래 오프라인 | 변경 순번 보관 한도를 넘으면 미전송 변경을 먼저 보존한 뒤 전체 다시 받기 |
| 정식판·로컬 일지 오염 | 온라인 공간 파일은 Preview 폴더에만, 정식판·DEV 설정·일지와 경로·앱 모두 분리(4-8 정책 그대로) |
| 일지 전환 무결성(4-7) | 온라인 공간 열기·닫기·전환은 `appController`의 한 길, 화면 저장소 `detach` |
