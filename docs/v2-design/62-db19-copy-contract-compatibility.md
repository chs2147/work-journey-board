# 62. DB18/19 사본 이관 계약·삭제 잠금 보존

2026-11-10 UTC · v2-design · 제품1.24.1/DB19 · 독립 PoC

## 완료한 1번 항목

기존 `create18`/`capture18`은18 전용 계약을 유지한다. 공통 `createWorkspaceDB`/`captureWorkspace`는18·19를 명시적으로 구분하고, 해당 버전까지의 실제 migration SQL로 만든 스키마와 일치하는지 검사한다. 알 수 없는 버전·스키마 변형·비정상 삭제 잠금 값은 거절한다. 읽기는 readOnly이며 사용자 DB를 업그레이드하거나 버전 번호를 바꾸지 않는다.

`createConnectedCopy`는 검증된 원본의 버전을 manifest에 기록하고 이미지 본문을 별도 파일로 분리한다. DB19도 기존 원본/사본 경로 분리·새UUID·원본 hash 검증·실패 시 자기 사본 정리 규칙을 그대로 사용한다. 원본 DB/이미지/백업은 유지한다.

매핑 계약을 `db18-contract.json`, `db19-contract.json`으로 분리했다. DB18 계약 파일은 바꾸지 않았으며 generator는 메모리 DB에서 두 계약을 생성한다. DB19 봉투는 `workspace-db19-map-poc-1` 프로필과19번 스키마 지문을 쓰고 `cabi_note.delete_locked`의0/1을 그대로 유지한다. DB18에 존재하지 않던 잠금 필드를 임의로 삽입하지 않는다. manifest와 원본 schema_version이 다르면 실패한다.

## 복원 시험의 의미

`restore-connected-copy.mjs`는 **합성 자료의 왕복 검증 도구**다. 제품의 온라인→로컬 전환 기능이 아니다. 검증된 사본과 분리 이미지로 새 DB18/19 파일을 만들고 전체 테이블/이미지 행의 일치·참조 무결성·스키마를 검증한다. 임시 파일 검증 뒤 hard link로 새 목적지만 공개하며 기존 파일을 덮어쓰지 않는다. 원본 경로가 목적지이면 이미 존재하므로 거절한다.

이 시험용 복원 DB는 기존 로컬 구조의 이미지 본문을 재구성한다. **온라인 metadata DB에 이미지를 다시 넣는 과정이 아니다.** 온라인 사본에는 본문 없이 참조만 유지한다. 원본 로컬 모델과 온라인 이미지 정책을 혼동하지 않는다.

복원 DB19에서 잠금만 변경하면 본문 revision이 유지되고, 잘못된 revision의 본문 수정은 CABI_CONFLICT로 거절된다. 삭제 잠금 CHECK도 유지된다. 제품 저장소의 실제 삭제 거절 기능은 main 구현을 그대로 사용하며 이번에 제품 코드를 수정하지 않았다.
