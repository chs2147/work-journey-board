# 89. E-1 — 온라인 공간 이 기기 일지·보낼 목록(구현 기록)

2026-11-15 · `v2-design` · 설계 [88](88-e-stage-sync-design.md) E1~E4 추천안 승인 · main 미반영 · 서버 쓰기는 E-2

## 1. 무엇이 바뀌었나

| | D단계(이전) | E-1(지금) |
|---|---|---|
| 온라인 공간 일지 | 열 때마다 캐시에서 **메모리**에 되살림 | 처음 열 때 한 번 캐시에서 만든 **이 기기 파일**(`online-cache/<계정>/<공간>/journal.db`) |
| 편집 | 읽기 전용(실제로 바뀌는 쓰기 거절) | **허용** — 이 기기 파일에 저장 + 보낼 목록(대기열)에 같은 트랜잭션으로 기록 |
| 닫기·앱 종료 | 저장 없이 바로 닫기 | 앱의 한 길(입력 중 저장 → 노트·메모보드 창 저장 후 닫기 → `closeCurrent`) 뒤 창 정리 |
| 서버 | 읽기만 | 그대로 읽기만(보내기·받기는 E-2·E-3) |

## 2. 이 기기 일지 — 경로는 Rust가 정함 (E1 추천안)

- Rust `space_db.rs`(Preview 빌드만): `space_db_exists·create·open·close·select·execute·batch·export`. 화면은 **공간 ID만** 넘기고 경로는 Rust가 `online-cache/<로그인 계정>/<공간>/journal.db`로 정한다(둘 다 UUID 검사). 정식판 SQLite 플러그인은 Preview에 여전히 없다(아무 경로나 여는 길 없음).
- 연결: 공간마다 1개(트랜잭션·저장점이 같은 연결), `journal_mode=DELETE`(파일 1개), 외래 키 켬, 대기 5초.
- 다른 파일에 쓰는 문 거절: `ATTACH`·`DETACH`·`VACUUM INTO`·`load_extension`·`writable_schema`(주석·대소문자 무시, 낱말 단위 — `cargo test`).
- 처음 만들기(`create`): 파일이 없을 때만, SQLite 파일 머리 확인, 임시 이름 → 이름 바꾸기.
- 앱 백업 사본: 앱은 가짜 폴더 경로로 `VACUUM INTO`를 보낸다 → 플랫폼이 가로채 `space_db_export`(같은 폴더 임시 파일 → 바이트 → 지움)로 받은 바이트를 **메모리 가짜 폴더**에만 둔다. 사용자 폴더·정식판 백업 폴더에는 쓰지 않는다.
- [목록에서 지우기](`space_remove`)는 열린 연결을 먼저 닫고 캐시·이 기기 일지를 함께 지운다.

## 3. 동기화 표(같은 일지 파일 안)

| 표 | 내용 |
|---|---|
| `wjb_sync_meta` | 공간 ID·기준 manifest·받은 순번(cursor, 지금 0)·만든 시각 |
| `wjb_sync_base` | 기록(표·키)별 마지막으로 서버와 맞춘 판(rev, 지금 0)·값 해시 — E-3 충돌 판정의 기준 |
| `wjb_sync_outbox` | **보낼 목록(대기열)** — 동기화 대상 표마다 `AFTER INSERT/UPDATE/DELETE` 트리거가 (표, 기본 키 JSON)을 적는다. 앱의 쓰기와 같은 트랜잭션이라 함께 저장·함께 되돌림 |
| `wjb_sync_flag` | `applying=1`인 동안(서버에서 받은 것을 적용할 때) 트리거가 적지 않는다 — 받은 것을 다시 보내지 않음 |

- 대상 표 = 일지의 모든 표 − `wjb_sync_*` − `kanban_ctx`(이 기기 쓰기 흐름용). 기본 키는 일지 구조에서 읽는다.
- 기록 키 = 서버 기록 키 규칙 `hash([표, 기본 키 값])`과 같게 계산할 수 있다(시험으로 고정). 실제 보낼 값(이미지 → 참조, 폴더 경로 제외 등)은 E-3에서 행 단위 사상으로 만든다.
- 외래 키 연쇄 삭제도 트리거가 잡는다(SQLite는 FK 동작에도 트리거 실행).
- 제품 열기 경로(호환 확인·연결 설정·무결성·구조 검사·마이그레이션)는 동기화 표가 있어도 그대로 통과(시험).

## 4. 시험

- Rust `space_db` 3개: 다른 파일 쓰기 거절, 만들기 검사(이미 있음·형식 아님), 조회 형식·묶음 되돌림·저장점·사본.
- 단위 `onlineWorkspace.test.ts`: 한 번만 만들기·기준 건수·제품 열기 경로 통과 / 쓰기 → 대기열, 묶음 실패 시 대기열도 되돌림, `applying` 동안 안 적음, 키 규칙 / 플랫폼: 백업 사본은 가짜 폴더에만·다른 경로 거절.
- E2E `online-spaces`: 열기 → 기록 고침 → 대기열 > 0(브라우저 모드 `__wjbApp.syncOutbox`, 읽기만).
- `appProfile`: Preview 명령 목록에 `space_db_*` 8개 추가 고정.

## 5. 남은 것

- E-2 서버: 기록별 판·지움 표시·변경 순번·멱등 처리, push/pull(전진 SQL 019~, 개발 서버만).
- E-3 보내기·받기 루프·충돌 보존, E-4 새 그림 올리기, E-5 상단 상태(이 기기에 저장됨·대기 N건·동기화됨·오프라인·충돌 N건)·실기.
- 이미 D단계에서 열어 본 공간은 다음 열기 때 이 기기 일지가 처음 만들어진다(서버 자료는 바뀌지 않음).
