## 구현한 처리

### 본문과 구조의 버전 분리

`cells.mjs`는 항목 내용 버전과 셀 membership/order 버전을 분리한다. 내용 수정 명령은 항목별 기대 내용 버전을 확인하고, 이동은 출발/도착 셀의 기대 구조 버전을 확인한다. 기존 모형 record revision은 수신 상태 비교용으로 별도 유지한다.

현재 내용 수정 필드는 text·flagged·flag_done_at이다. date/category/seq/depth는 이 경로로 바꿀 수 없다. 본문 수정은 셀 구조 버전을 증가시키지 않으며, 이동은 내용 버전을 바꾸지 않고 당시 최신 본문을 유지한다. 내용 수정과 이동이 어느 순서로 도착하든 둘 다 반영되는 것을 시험했다.

### 다중 셀 원자적 이동

`move-subtree` 명령은 depth0 상위 항목과 뒤따르는 depth1 하위 항목을 한 묶음으로 옮긴다. 원래 ID를 유지하고 메모·자료함 링크/자산 레코드는 변경하지 않는다. 출발/도착 셀의 순서를 다시 매기며 다른 부모의 하위 묶음 중간에 끼워 넣는 요청은 거절한다.

한 트랜잭션에 항목 위치/순서·셀 버전·명령 결과·change log·cursor를 기록한다. 같은 셀 재정렬은 구조 버전을 한 번만 올린다. 응답이 없어 같은 opId로 다시 요청하면 동일 결과를 반환하고 중복 이동하지 않는다. 같은 opId로 다른 내용을 보내면 거절한다.

변경 항목 전체를 **하나의 entry-batch 이벤트**로 전달한다. 수신 어댑터 `receiveBatches`도 모든 항목·내용/셀 버전·cursor를 한 트랜잭션으로 적용한다. 중복 이벤트는 건너뛰며 중간 순서가 빠지면 수신 페이지 전체를 취소한다.

### 우회 방지와 어댑터 경계

한 번 구조 버전 경로를 활성화한 workspace는 기존 범용 `accept`로 entry_item 전체 행을 덮어쓸 수 없다. 복원 후 새 generation에서도 이 제한을 유지하고 해당 generation의 버전은 새로 시작한다. 기존 `queue.applyPage`는 entry-batch를 실수로 한 행으로 처리하지 않고 `BATCH_ADAPTER_REQUIRED`로 거절한다.

**기존 tick과 새 명령 경로의 통합은 아직 남아 있다.** 현재 새 명령은 applyCommand/receiveBatches로 시험하며, 동일 workspace의 entry_item 쓰기에 이전 범용 경로를 섞지 않는다. 문서 등 다른 도메인 이벤트와 섞인 전체 스트림/영속 큐 dispatcher도 다음 연결 작업이다.

미전송 편집이 있는 항목으로 이동 이벤트를 수신하면 서버 위치는 갱신하되 기존 편집은 보존하고 충돌로 남긴다. 아직 필드 단위로 자동 재조정하는 UI/정책은 아니다.

## 발견한 실패와 수정

[수정 전 실패 기록](evidence/cells-lock-failure.txt)을 보존한다. 초기38개 시험 중 동시 접속2개가 실패했다. 원인 중 하나는 모형 DB의 연결 초기화가 잠금 대기 없이 실행돼 `database is locked`가 발생한 것이었다. 허용된 외부 실행기에서도 재현됐으므로 샌드박스 문제로 처리하지 않았다.

모형 DB 연결 생성에2초 제한의 잠금 대기를 적용했고, 경합 worker는 동기식 stdout으로 결과를 기록하도록 정리했다. 시험을 단일 프로세스로 축소하지 않고 같은 두 프로세스 시험을 재실행해 통과했다. 무한 재시도나 무제한 대기가 아니며, 잠금 시간이2초를 넘는 상황의 사용자 경험은 별도 검증 대상이다.

새 코드 ESLint·Prettier 및 diff 검사를 통과했다. 기존 migration·제품 코드/버전·루트 의존성·CI 설정은 유지했다.

3. 자산 포함 복원·generation 전환 통합, 만료 cursor·보존 하한·충돌 해결 흐름, 용량/디스크 부족·OS 실기·클라우드 시험은 후속이다.
