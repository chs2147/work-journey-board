# 1. 다국어 리소스·범위·배포 설계

1차 언어는 **한국어·영어로 사용자 확정(2026-11-08)**. 두 언어를 앱·사이트·현재 가이드·고객 접점의 동일 지원 범위로 설계한다.

## 1.1 현황과 사이징

기준: 1.23.0의 `src` TypeScript/TSX 217파일. TypeScript AST에서 한국어가 있는 문자열·템플릿 조각·JSX 텍스트를 추출했다. 사용자 파일은 열지 않았다.

| 구역 | 발견 건수 | 구역 내 중복 제외 문구 | 파일 | 원문 길이 합 |
|---|---:|---:|---:|---:|
| 중앙 문구 리소스 | 2,117 | 1,710 | 5 | 24,659 |
| 화면에 직접 적힌 문구 | 105 | 92 | 26 | 1,404 |
| 도메인·내보내기 | 294 | 184 | 20 | 1,789 |
| 플랫폼 | 60 | 55 | 6 | 1,061 |
| 기타(저장소·샘플 등) | 104 | 98 | 11 | 1,509 |
| **합계** | **2,680** | 구역 간 중복 별도 정제 | 구역별 집계 | **30,422** |

길이는 JavaScript 문자열 길이(UTF-16 코드 단위) 합으로, 단어 수·번역 견적이 아니다. 함수형 문구/템플릿은 여러 조각으로 계산되고, SQL·기본 샘플·휴일명이 포함된다. 한국어가 없는 접근성 라벨·영문 고정 문구와 Rust/HTML/설치 파일은 위 합계에 빠져 있다. 따라서 **2,680건을 번역 키 개수로 확정하지 않는다.** 같은 글자라도 문맥이 다르면 별도 키, 문맥과 치환 구조가 같으면 재사용한다.

추가 범위: 현재 가이드15장면, 스크린샷19개, 사이트 HTML2개(소개·생성 가이드), 릴리스 노트48개, docs Markdown140개. docs 수에는 과거 설계/배포 기록이 포함되어 있다. 완역 대상은 아래 범위 결정으로 나눈다. 실측 경로와 후보 문구는 CSV로 검토 가능하다.

## 1.2 적용 요소와 언어 배포 관문

| 요소 | 포함 내용 | 배포 정책 |
|---|---|---|
| 앱 전체 | 주간/데일리, 인사이트, Universe, Cabi.NET, 설정, 온보딩, 툴팁, 접근성, 단축키 안내, 빈 화면·오류·복원 | 선택 언어의 필수 키100%, 언어 혼합/넘침/키보드 검사 |
| 네이티브 | Rust 오류의 표시 변환, OS 메뉴, 파일 대화상자, NSIS, macOS 권한 안내·업데이트/실패 메시지 | OS/설치 언어와 앱 언어 차이를 명시. 설치기에서 앱 번들을 직접 읽지 않음 |
| 내보내기 | Excel 시트/머리글·요약 템플릿, PDF/Markdown 고정 표제·파일명 기본값 | 출력 언어를 명시 선택, 사용자 내용은 그대로, 호환 포맷 버전 유지 |
| 사이트 | 소개, SEO title/description, FAQ, 다운로드, 언어 선택, 모션 대체 설명 | `/ko/`, `/en/` 등 언어별 URL, canonical/hreflang·링크 검사 |
| 가이드 | 15장면 원문, HTML/PDF, 이미지19개, alt/caption·메뉴 명칭 | 제품 버전+locale 기준 생성. 메뉴 용어는 앱과 같은 용어집 |
| 공개 문서 | README 핵심 소개, 현재 릴리스 노트/변경 이력·설치/복원 주의 | 현재 지원 언어 제공. 과거48개 기록은 원문 보존+명시된 언어 안내/연결을 우선 제안 |
| 기능 목록 | 공개 Feature List의 명칭·설명·Excel·미제공 표기 | 고정 Feature ID 공통. 번역을 신규 기능/도입 버전으로 오인하지 않음 |
| 지원·메일 | 가입/OTP, 기기 연결, 복원·정리·연결 해제, 개인정보·약관, 서버 오류 | 온라인 서비스 출시 관문에 포함. 발송 언어와 고객 언어 설정 기록 |
| 기술·과거 설계 문서 | 설계·ADR·과거 이력·개발 가이드 | 기본 원문 정본+필요 문서 번역 제안. **140개 문서/과거 이력까지 전부 번역할지는 별도 범위 결정** |

사용자가 원하는 ‘모든 요소’는 고객이 보는 동작 경로 전체로 취급한다. 라이선스 원문·사용자 작성 데이터·외부 사이트/OS 고유 메시지는 앱 번역 대상이 아니다. 지역 정책 문서의 법적 번역 검토도 일반 UI 번역과 별도 비용이다.

## 1.3 제안 리소스 구조 (미생성)

```text
packages/i18n/
  contract/keys.ts                 안정된 키·타입·치환 인자 계약
  locales/ko/{common,board,insights,note,cabi,universe,settings,errors,export}.json
  locales/en/{같은 namespace}.json
  glossary/{ko,en}.json            용어집·금지 번역·브랜드명
  metadata/{ko,en}.json            locale·방향·지원 상태·리소스 revision
content/{ko,en}/site/              언어별 소개/SEO 원문
content/{ko,en}/guide/             현재 가이드 정본
content/{ko,en}/release-notes/      현재 이후 릴리스
native-locales/{ko,en}/            설치/권한/메일용 빌드 산출물 계약
```

- 같은 repo와 키 계약을 쓰고 언어별 앱 브랜치/언어별 DB를 만들지 않는다. i18next/FormatJS 등 엔진은 키 추출·ICU 지원·번들 크기 PoC 후 결정한다.
- `cabi.export.pdf`, `sync.error.offline`처럼 의미 기반 키. 원문 문장을 키로 쓰거나 문장 조각을 순서대로 연결하지 않는다.
- 예: `sync.pending = "{count, plural, one {# change waiting} other {# changes waiting}}"`. ICU 치환값은 일반 텍스트로 이스케이프하고 임의 HTML/코드/동적 함수를 번들에 넣지 않는다.
- `Error {code, args}`를 저장/전송하고 화면에서 번역한다. 기존 SQL 마이그레이션의 한국어 RAISE 문구는 파일을 고쳐 없애지 않고 오류 매핑 경계에서 처리한다. 매칭이 불명확한 구 오류는 원문과 진단 코드를 보존한다.
- 언어 계약과 제품 버전을 분리한다. 한 앱 버전에서 지원 locale·리소스 revision·콘텐츠 revision을 manifest로 고정한다. 번역 수정은 별도 revision이나 패치 릴리스로 반영한다.

## 1.4 언어·지역·날짜·데이터

- 최초 실행: 명시 선택 > 장치의 지원 언어 > 기본 한국어(영어 기본 여부 미정). 이후 설정을 PC/기기에 저장한다. 앱 계정의 기본 선호는 새 기기의 제안값이고 다른 기기의 언어를 강제로 바꾸지 않는다.
- 언어 전환은 미저장 편집을 먼저 정리하고 자식 창에도 전달한다. 에디터 문서·커서·작업 공간을 새 언어로 다시 생성하지 않는다. 네이티브 메뉴/권한 문구는 재시작이 필요하면 명시 안내한다.
- fallback은 기본 언어로 제공하되 개발/CI에서 누락 키를 실패시킨다. 공개 지원 언어는 필수 경로가100%여야 한다. 부분 번역은 정식 언어 선택 목록에 넣지 않는다.
- 언어(locale), 타임존, 달력/공휴일 지역, 주차 정책은 별도다. 영어 UI를 고른다고 한국 휴일/ISO 주차를 미국 규칙으로 바꾸지 않는다. 국외 휴일 지원은 데이터 소스/정책 확정 후 별도 기능이다.
- 날짜 업무 항목은 기존 date-only를 유지하고 전송 중 UTC로 변환해 날짜가 바뀌지 않게 한다. 실제 사건 시각만 UTC timestamp로 전달한다. 기존 로컬 시각 필드의 변환 규칙을 테이블별로 정하고 임의로 `Z`를 붙이지 않는다.
- 업무명·태그·노트·사용자가 입력한 휴일 이름은 번역하지 않는다. 공용 기본 샘플은 locale별 seed, 이미 생성된 사용자 데이터에는 언어 전환을 소급 적용하지 않는다.
- `Intl` 날짜/수/복수형·목록·통화와 OS별 Ctrl/⌘ 표기를 공통 formatter에서 처리한다. URL/기계 식별자·파일 확장자·Markdown 구조는 locale 불변이다.

## 1.5 배포·번들·품질

- Desktop은 지원 언어 전체를 포함한 단일 설치 파일을 기본으로 한다. 완전 오프라인 설치에서도 번역/폰트가 동작해야 한다. Web은 namespace/locale별 지연 로드와 콘텐츠 캐시, 모바일은 지원 언어 번들 우선. 번역을 임의 외부 CDN에서 즉시 가져오지 않는다.
- 언어 추가: 용어집 → 키/치환 검증 → 번역/검수 → 의사 번역(문자열35~50% 확장) → 화면/키보드/접근성 → 출력/PDF 폰트 → 사이트/가이드 링크 → locale 릴리스 승인.
- 캡처는 실제 번역 앱+가상 데이터에서 생성한다. 언어2개 가정이면 가이드19개×2=38개가 기본 목표이고, OS별 단축키·고해상도/작은 창 변형은 추가다. 한국어의 기존 이미지를 영어 페이지에 그대로 두지 않는다.
- 한글·라틴·향후 일본어 폰트는 glyph coverage와 PDF 실제 렌더링으로 검사한다. 기존 v19의 빈 PDF 회귀를 유지하고 언어별 제목/본문 검사를 확장한다.
- 스크린샷에 글자를 합성하지 않고 동작 화면을 원본으로 한다. 별도 locale별 사이트/가이드 생성 결과는 `/guide/<locale>/<version>/`에 고정하고 과거 링크를 보존한다.

## 1.6 초기 공수 범위 (추정, 확정 견적 아님)

확정된 한국어/영어·기존 desktop+사이트+현재 가이드 기준. 1인일은 숙련 작업자의 집중1일이며 병렬 인력/번역 대기와 달력 기간은 다르다.

| 작업 | 설계·구현 인일 범위 | 검수 조건 |
|---|---:|---|
| 목록 정제·용어집·키/인자 계약 | 4~7 | CSV 후보를 실제 문맥별 번역 단위로 승인 |
| 번역 엔진·앱 문구 이전·설정·자식 창 | 10~18 | 직접 문구·오류·동적 서식 포함 |
| 네이티브·출력·폰트/날짜 | 5~9 | Windows/macOS·Excel/PDF/Markdown |
| 사이트·가이드·공개 문서 생성 파이프라인 | 6~12 | 15장면·19캡처·다운로드/SEO·버전 링크 |
| 통합 QA·언어 완성도 관문 | 7~12 | 의사 번역·접근성·실제 출력 |
| **기술 작업 합계** | **32~58** | 번역/법률 검수·전체 과거 문서 완역·온라인 메일/계정 화면·모바일 신규 UI 제외 |

번역/언어 검수 인일은 정제된 단위와 사이트/매뉴얼 원문을 받은 뒤 따로 산정한다. 추가 언어는 기술 골격을 재사용하지만 번역·폰트·캡처·QA는 언어별로 증가한다. 위 범위에는 여유 예산을 포함하지 않았으며 초기 PoC 후 재산정한다.
