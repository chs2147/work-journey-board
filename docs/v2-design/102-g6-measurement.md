- `wjb_ops.metric_day`: DB 크기, 그림 사용량 합, 저장소 객체 수·크기, 계정·공간·동기화 공간 수, 지금 기록·지움 표시 행, 그날 기록 변경·보내기 요청·보낸 기기·새 그림 신고, 안 쓰는 그림으로 넘긴 누적.
- **합계만** — 기록 내용·이메일·계정별 줄 없음(시험이 칸 이름까지 확인). API 역할은 읽을 수 없다.
- `wjb_ops.snapshot_metrics()` — 같은 날 다시 부르면 그 줄을 새 값으로. `pg_cron` `wjb-ops-metrics` 매일 23:50 KST.

## 4. 판단 기준(측정 뒤)

- Edge 호출이 무료 한도(월 50만)의 50%를 넘거나 하루 받기 대부분이 "변경 없음"이면 → 조용할 때 주기를 더 길게(최대 10분) 또는 실시간 알림 검토.
- 안전선까지 남은 날이 90일 미만이면 → 기본 한도 낮추기 또는 안 쓰는 그림 보관 7일 → 3일.
- 지움 표시가 기록 행의 20%를 넘으면 → ③ 정리(예: 90일 지난 지움 표시 삭제 + 오래 오프라인 기기 전체 다시 받기) 설계.

## 5. 측정 중 발견

- **처음 동기화 경합(019, 기존)**: 한 번도 동기화하지 않은 공간에 여러 기기가 같은 순간 처음 보내면 `wjb_sync.ensure_space`의 게시본 복사가 겹쳐 그중 하나가 실패할 수 있다(로컬 시험 `concurrent_push` 1회 흔들림, 다시 돌리면 통과). 앱은 실패하면 다시 보내므로 자료는 잃지 않는다. G-2 전에 전진 SQL로 `ensure_space`를 공간 행 잠금(`FOR UPDATE`) 뒤 복사하도록 고친다(로컬 시험에 동시 처음 동기화 반복 추가).
