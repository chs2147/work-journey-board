C단계로 서버에 올라간 온라인 공간은 지금 **볼 방법이 없다**(올리고 확인만 함). D단계는 Preview에서 내 온라인 공간 목록을 보고, 열어서 **지금 앱과 같은 화면**(주간 보드·칸반·인사이트·메모 보드·Cabi.NET…)으로 보는 것이다.

## 1. 단계 제안

| 단계 | 내용 | 확인 |
|---|---|---|
| **D-1 서버 읽기 경로** | ① 내 온라인 공간 목록(공간 ID·만든 시각·원본 판·기록/그림 수, 게시된 것만) ② 공간 기록 **나눠 읽기**(지금 `workspace` 명령은 봉투 전체를 한 번에 — 2만 행이면 수 MB라 앱 응답 한도 1MB를 넘음 → 페이지로) ③ 그림 내려받기는 기존 gateway 경로. 전진 SQL `016`(서버 전용 함수 2개) + gateway 경로 | 로컬 PostgreSQL·실서버 |
| **D-2 이 기기 캐시** | Preview 폴더 `online-cache/<계정>/<공간>/`에 **기록 캐시 DB(이미지 본문 없음, 참조만)** + 그림 파일(`assets/<해시>.bin`). 72문서 캐시 v1 형식(application_id로 로컬 일지와 구분, 덮어쓰기 없이 게시). 서버와 해시가 맞을 때만 연다 | Rust·단위 시험 |
| **D-3 되살리기** | 캐시 → 메모리 안 제품 일지(구조 v20)로 되살림: 온라인 형식 → 로컬 행(이관 매핑의 역방향, `restore-connected-copy`의 순수 핵심화), 그림은 열 때 파일에서 읽어 메모리에만. **원본 로컬 일지·정식판·DEV 설정과 완전 분리** | PoC 왕복(원본 → 온라인 → 되살림 = 같은 행) |
| **D-4 화면** | Preview 첫 화면에 **내 온라인 공간** 목록 → [열기] → 지금 앱 화면 그대로 + 상단 "온라인 공간 · 읽기 전용" 띠. 쓰기는 저장소 단계에서 막고 안내(편집은 E단계) | E2E(가짜 서버), 실기 |

## 2. 결정이 필요한 것

| | 질문 | 추천 | 대안 |
|---|---|---|---|
| **D4** | D단계 범위 | **읽기 전용으로 먼저 연다** — 화면·되살리기·캐시를 검증한 뒤 E단계에서 편집·동기화 | 처음부터 편집까지(충돌·여러 기기 동기화 설계가 같이 필요해 길어짐) |
| **D5** | 이 기기 캐시 | **캐시 보관**(다시 열 때 빠름, 서버가 안 될 때도 마지막 내용 보기, E단계 동기화의 바탕) | 열 때마다 서버에서 다시 받기(단순하지만 매번 수 MB·그림 전부) |
| **D6** | 보류한 D-b(게시 직전 60초 확인) | **이번에 함께 고침** — 그림이 많은 실제 일지는 게시 직전 재확인을 60초 안에 못 끝내 게시가 막힌다(D단계에서 실제 일지를 열려면 먼저 올라가야 함). 판정을 "확인한 입출력 판 = 지금 판 + 진행 중 입출력 없음"으로(이미 같이 검사 중), SQL `017` | 계속 보류(그림 적은 일지만) |

D-c(취소 때 지운 그림 캐시 약 60초)는 기능 문제가 없어 계속 보류를 추천.

## 3. 바꾸는 것(승인 범위)

- 개발 서버만: 전진 SQL `016`(읽기 함수, 서버 전용) · D6 승인 시 `017` · gateway 재배포. 운영 프로젝트·정식판·DEV는 그대로.
- Preview 앱: 새 Rust 명령(목록·페이지 읽기·그림 받기·캐시 파일 쓰기 — 모두 Preview 폴더 안), 화면.
- 이미지 본문은 온라인 DB·캐시 DB에 넣지 않는다(파일로만, CLAUDE.md 이중 저장 금지). 로컬 원본 일지는 읽지도 않는다(D단계는 서버 → 캐시 방향만).

## 4. 위험

| 위험 | 대응 |
|---|---|
| 제품 화면이 열 때 쓰기를 시도(설정 저장·백업·마이그레이션) | 온라인 공간 전용 열기 경로 — 마이그레이션·백업·주기 저장을 부르지 않고, 드라이버가 쓰기를 거절 → 화면에 "읽기 전용" |
| 되살린 일지가 원본과 다름 | 원본 → 온라인 → 되살림 왕복 시험(DB18·19·20, 가상 1년치·그림) + 실제 일지 실기 |
| 기록이 큰 공간 | 페이지 읽기(1,000행), 캐시에 이어 받기 |
| 4-7 일지 전환 무결성 | 온라인 공간 열기·닫기도 `appController`의 한 길(`detachAll`)로 — 화면 저장소가 이전 공간 상태를 들고 가지 않게 |
