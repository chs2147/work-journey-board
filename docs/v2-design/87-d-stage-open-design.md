## 1. 단계 제안

| 단계 | 내용 | 확인 |
|---|---|---|
| **D-1 서버 읽기 경로** | ① 내 온라인 공간 목록(공간 ID·만든 시각·원본 판·기록/그림 수, 게시된 것만) ② 공간 기록 **나눠 읽기**(지금 `workspace` 명령은 봉투 전체를 한 번에 — 2만 행이면 수 MB라 앱 응답 한도 1MB를 넘음 → 페이지로) ③ 그림 내려받기는 기존 gateway 경로. 전진 SQL `016`(서버 전용 함수 2개) + gateway 경로 | 로컬 PostgreSQL·실서버 |
| **D-2 이 기기 캐시** | Preview 폴더 `online-cache/<계정>/<공간>/`에 **기록 캐시 DB(이미지 본문 없음, 참조만)** + 그림 파일(`assets/<해시>.bin`). 72문서 캐시 v1 형식(application_id로 로컬 일지와 구분, 덮어쓰기 없이 게시). 서버와 해시가 맞을 때만 연다 | Rust·단위 시험 |
| **D-3 되살리기** | 캐시 → 메모리 안 제품 일지(구조 v20)로 되살림: 온라인 형식 → 로컬 행(이관 매핑의 역방향, `restore-connected-copy`의 순수 핵심화), 그림은 열 때 파일에서 읽어 메모리에만. **원본 로컬 일지·정식판·DEV 설정과 완전 분리** | PoC 왕복(원본 → 온라인 → 되살림 = 같은 행) |
| **D-4 화면** | Preview 첫 화면에 **내 온라인 공간** 목록 → [열기] → 지금 앱 화면 그대로 + 상단 "온라인 공간 · 읽기 전용" 띠. 쓰기는 저장소 단계에서 막고 안내(편집은 E단계) | E2E(가짜 서버), 실기 |

## 2. 결정이 필요한 것

| | 질문 | 추천 | 대안 |
|---|---|---|---|
| **D4** | D단계 범위 | **읽기 전용으로 먼저 연다** — 화면·되살리기·캐시를 검증한 뒤 E단계에서 편집·동기화 | 처음부터 편집까지(충돌·여러 기기 동기화 설계가 같이 필요해 길어짐) |

## 3. 바꾸는 것(승인 범위)

- 개발 서버만: 전진 SQL `016`(읽기 함수, 서버 전용) · D6 승인 시 `017` · gateway 재배포. 운영 프로젝트·정식판·DEV는 그대로.
- Preview 앱: 새 Rust 명령(목록·페이지 읽기·그림 받기·캐시 파일 쓰기 — 모두 Preview 폴더 안), 화면.
- 이미지 본문은 온라인 DB·캐시 DB에 넣지 않는다(파일로만, CLAUDE.md 이중 저장 금지). 로컬 원본 일지는 읽지도 않는다(D단계는 서버 → 캐시 방향만).

## 4. 위험

| 위험 | 대응 |
|---|---|
| 제품 화면이 열 때 쓰기를 시도(설정 저장·백업·마이그레이션) | 온라인 공간 전용 열기 경로 — 마이그레이션·백업·주기 저장을 부르지 않고, 드라이버가 쓰기를 거절 → 화면에 "읽기 전용" |
| 되살린 일지가 원본과 다름 | 원본 → 온라인 → 되살림 왕복 시험(DB18·19·20, 가상 1년치·그림) + 실제 일지 실기 |
| 기록이 큰 공간 | 페이지 읽기(1,000행), 캐시에 이어 받기 |
| 4-7 일지 전환 무결성 | 온라인 공간 열기·닫기도 `appController`의 한 길(`detachAll`)로 — 화면 저장소가 이전 공간 상태를 들고 가지 않게 |

## 5. 결정·구현 결과 (2026-11-15)

사용자 결정: **D4 읽기 전용 먼저 · D5 캐시 보관 · D6 게시 판정 함께 고침**(추천안).

| 단계 | 결과 |
|---|---|
| D-1 서버 | 전진 SQL `016`(+`017` 점검·`018` 되돌리기, 001~015 그대로): `wjb_v2_workspace_read` — 목록(게시된 공간)·머리(+그림 목록)·기록 **키셋 페이지**(manifest 순서, ≤1,000행·약 900KB). 서버 전용·주인/기기/세션 확인·게시 전/취소 작업은 안 보임. **D6**: 게시 판정을 "확인한 입출력 판 = 지금 판 + 진행 중 입출력 없음"으로(60초 창 제거) → 실행기의 게시 직전 그림 재확인 제거. gateway `POST /v2/read/{list,header,records}`(v10). 로컬 PostgreSQL 126(새 5). 개발 DB 적용·점검([증거](evidence/migration-dev-workspace-read-install.json)) |
| D-2 캐시 | Rust `online_space.rs`(Preview만): 서버 → `online-cache/<계정>/<공간>/` `header.json`·`records.json`(그림 본문 없음)·`assets/<sha256>.bin`(해시·크기 확인 후)·`complete.json`(마지막 = 완성 표시). 같은 manifest면 다시 받지 않음, 서버에 닿지 못하면 완성 캐시로(`stale`), 목록도 캐시로. 72문서 캐시 v1(SQLite)은 Preview에 SQLite 플러그인이 없어 **파일 형식으로 바꿈**(같은 원칙: 이미지 본문 분리·완성 확인 후 열기) |

| D-4 화면 | Preview 계정 카드 아래 **내 온라인 공간**(복제 완료 시 자동 새로 고침) → [열기] → 캐시 채우기 → 메모리 일지 → **지금 앱 화면 그대로** + 위 띠 "온라인 공간 · 읽기 전용 · 언제 복제본" [목록으로](창을 새로 불러 화면 저장소 상태를 남기지 않음 — 4-7). 앱이 공간을 다 띄운 뒤부터 쓰기 거절(드라이버 문지기, 조회·백업 사본은 됨) + "읽기 전용" 알림. 일지는 메모리 위 가짜 폴더에만(사용자 폴더·원본·정식판 설정 무관), 내보내기·폴더 고르기·Cabinet 폴더 열기·새 판 확인 없음 |

### 남은 것

- **실기**(Preview 설치 파일): 실제 정식 일지 복제본을 Windows·macOS에서 열어 화면 확인, 다른 기기에서 열기(맥에서 올린 공간을 윈도우에서), 오프라인 열기.
- 읽기 전용 중 고치기를 시도하면 저장 실패 알림이 날 수 있다(편집 막기는 저장소 단계) — 편집·동기화는 **E단계** 설계에서.

### 실기 중 고친 것 (2026-11-15)

- **업무노트를 열면 "별도 창이 차단되었습니다. 팝업을 허용해 주세요"**(사용자 실기): 온라인 공간 화면이 브라우저식 팝업(`window.open`)으로 열려 했고 데스크톱 앱 창이 막았다. 사용자 요청대로 **정식판과 같은 별도 OS 창**으로 — 업무노트·업무 메모보드(`cabi-*`)·Cabi.NET 파일 목록(`cabinet`)·폴더 창(`folder-*`).
  - 온라인 공간 플랫폼이 실앱에서 Tauri 창 다리(정식판 `tauriCabiBridge`·Cabinet·폴더 창)를 쓴다. 자식 창은 DB를 열지 않고 메인 창(메모리 일지)이 읽어 준다 — 정식판과 같은 구조.
  - Preview 권한: 메인 창에 창 만들기·닫기·앞으로·클립보드 글, 별도 창 권한 `preview-cabi`·`preview-cabinet`·`preview-folder` = 정식판 창 권한의 부분 집합(저장 대화상자·SQLite 없음, 시험이 고정).
  - Preview 화면 입구: 별도 창 주소(`win=cabi|folder|cabinet`)는 그 창 화면만, 그 밖은 Preview 시작 화면(기존 앱 메인 화면으로 빠지지 않음).
  - [목록으로]는 열린 별도 창을 모두 닫고 돌아간다.
  - 같은 창 안에 겹쳐 띄우는 방식(iframe)은 사용자 판단으로 쓰지 않는다.
- **메모보드 열기가 읽기 전용 문지기에 막힘**: 열 때 "없으면 만들기"(`INSERT OR IGNORE`)를 실행하는데 문장 종류로 막았다 → **실제로 내용이 바뀌는 쓰기만** 거절(저장점으로 감싸 바뀌면 되돌리고 오류, 구조 변경 문은 늘 거절).
- **메인 창을 닫아도 노트·메모보드 창이 남음**(사용자 실기): 온라인 공간 플랫폼의 닫기 처리가 비어 있었다 → 메인 창 닫기 요청 때 별도 창을 모두 없애고 닫는다(읽기 전용이라 저장 확인 없이). [목록으로]도 같은 방식.
- 읽기 전용 중 노트·메모보드에서 쓰면 "읽기 전용" 알림이 나는 것은 의도(E단계 편집에서 해소).
- 남은 제약: 폴더 창의 파일 목록은 이 기기 폴더를 읽는 기능이라(온라인으로 보내지 않은 경로) 온라인 공간에서는 비어 있다.
