# 16. 개인 소규모·저비용 원칙에 따른 전체 설계 재검토

**후속 전제 갱신:** 사용자가 Supabase 신규 계정을 생성해 신규 계정 기준의 여유/비용 검토가 다시 가능해졌다. 실제 프로젝트/한도는 미확인이다. Supabase 선택 시 Keep Alive를 기본 포함한다([20문서](20-supabase-keepalive.md)). 아래 기존 계정 소진 기록은 당시 조건이다.

2026-11-08 (KST) · 사용자 지시를 반영한 최신 설계 기준

**후속 사용자 환경:** Supabase 무료 프로젝트2개가 모두 사용 중이다. 신규 무료 프로젝트 가정을 제거하고 [17문서](17-neon-option.md)의 Neon 조합을 우선 비교한다.

## 16.1 확정 원칙과 적용 경계

**AWS 직접 구성/운영안은 현재 후보와 후속 자동 대안에서 제외한다. 무료 티어 또는 개인 요금제 수준에서 개인 소규모로 운영할 수 있어야 한다.** 아시아·개인 다기기·ko/en·설계 전용 범위는 유지한다.

이는 특정 사업자의 무료 플랜으로 모든 기능이 가능하다고 확인한 뜻이 아니다. 관리형 사업자가 내부적으로 어떤 인프라를 사용하는지까지 금지한다는 의미로 확대하지 않는다. 실제 법인/하위 처리자 제한이 필요하면 별도 검토한다. ‘개인 요금제’의 월 지출 상한은 아직 숫자로 정해지지 않았다.

이 문서는 기존의100명 기준 비용 모델·상시 실시간·30일 백업·PITR 필수화보다 우선한다. 아래 조정은 비용 원칙을 충족하기 위한 **추천 범위**이고 사용자에게 기능 축소를 승인받은 것으로 기록하지 않는다.

## 16.2 후보 재정리

| 후보 | 현재 판단 | 검증 조건 |
|---|---|---|
| Supabase 단일 프로젝트 / 현재 무료 여유 없음 | 기존 구성 수를 줄일 수 있으나 신규 프로젝트의 비용 확인 필요 | 실제 무료/개인 플랜의 DB/파일/전송/함수/인증·메일·프로젝트 제한·일시정지·백업·아시아 리전 확인 필요 |
| Firebase | 비교 후보 유지, 비용 적합성 미검증 | Storage/서버 기능의 결제 연결 조건·읽기/쓰기/리스너 과금·SQL 모델 전환 비용을 함께 확인. ‘무료 대안’으로 확정하지 않음 |
| AWS 직접 구성 | **현재 범위 제외** | Supabase 조건 미충족 시 자동으로 AWS로 전환하지 않음 |
| 별도 상시 서버·여러 관리형 조합 | 초기 필수 구성에서 제외 제안 | 공급자 내 검증 가능한 서버 함수/트랜잭션으로 해결 가능한지 우선 검증. 불가능하면 범위/예산 재검토 |

공급자의 DB CRUD만으로 동기화가 완성되는 것은 아니다. 권한·revision·멱등성·문서/참조의 원자성은 서버에서 검증해야 한다. 비용 절감을 이유로 관리자 키를 클라이언트에 넣거나 서버 검증을 빼지 않는다.

## 16.3 과도했던 기존 가정과 수정 추천

| 기존 초안 | 비용 관점 문제 | 조정 추천 |
|---|---|---|
|100명×공간2×100MiB를 첫 모델로 사용 | live 원본만 약19.53GiB여서 무료 가능성 검증의 출발점으로 큼 | 우선 본인 기기2대·가상 사용자5명·공간1개·25MiB를 시험 가정으로 사용 |
| 즉시 기본·상시 소켓·60초 보완 pull | 사용하지 않는 공간도 연결하면 메시지·요청 비용 증가 | 주기5분/수동을 기본 검증, 즉시는 활성 공간·한도 확인 후 제공하는 후보 |
| 하루1회·30일·수동10개 백업 | 이미지 중복과 이력까지 합치면 무료 저장 한도를 쉽게 넘을 수 있음 | 초기 원격 보존본 총3개(최신 자동1+사용자 지정 최대2) 제안, 중요한 로컬 사본은 별도 유지 |
| PITR·객체 버전 보관을 운영 필수처럼 기술 | 유료 기능일 수 있고 자체 보존본과 비용 중복 | PoC는 논리 snapshot+manifest·실제 복원부터. PITR은 선택 플랜에서 확인 후 후속 결정 |
| 전용 worker·다중 프로젝트·전문 모니터링 | 소규모에서도 고정 비용 발생 | 단일 배포 단위·기본 로그/대시보드·수동 점검 우선. 운영 자료와 시험 자료는 논리/권한으로 반드시 격리 |
| 이메일 OTP만으로 무료 운영 기대 | 기본 메일러는 시험용/제한적일 수 있음 | 전용 SMTP 필요 여부·전달/횟수 확인. 메일 비용도 총예산에 포함 |
| 대용량 이미지·장기 이력을 무제한 동기화 | 저장/egress/복원 비용이 지배적 | 문서/이미지 한도·장치 캐시·변경 이력 기간을 실제 플랜에 맞춰 결정 |

원격3개는 검토값이며 기존 로컬 백업 정책을 임의로 줄이지 않는다. 보호 중인/복원 중인/현재 generation 참조 자산은 자동 삭제하지 않는다. 수동 보존본이 한도를 채우면 자동 백업을 무조건 실패시키지 않도록 자동1개 슬롯을 예약하는 방향이다. 이전 정상 자동본은 신규 보존본 검증 완료 후에만 교체한다.

## 16.4 작은 규모부터 측정

| 가정 | live 원본 | 3개를 전체 단순복제한 보존본 | 주의 |
|---|---:|---:|---|
|5명×공간1×25MiB |125MiB |375MiB | live+보존본 합500MiB. DB·로그·썸네일·staging은 별도 |
|10명×공간1×50MiB |500MiB |1,500MiB | live+보존본 합2,000MiB. 무료 가능성을 가정하지 않음 |

값은 사업자 한도나 가입 제한이 아닌 시험 가정이다. 불변 blob 재사용 시 절약될 수 있으나 복구본 참조를 계산하기 전에는 절감률을 약속하지 않는다.100/1,000/10,000명 모델은 확장 민감도 자료로만 남긴다.

8시간/일·22일/월·기기2개가 모두 활성이라는 가정에서60초 확인은 사용자당 월21,120회,5분 확인은4,224회다. 사용자5명이면 각각105,600회와21,120회다. 요청당 DB/인증 연산·재시도는 추가다. 즉시 소켓과 polling 중 어느 쪽이 싼지는 실제 플랜/활성 패턴으로 측정한다.

## 16.5 비용 통제와 무료 운영의 판정

플랜 확인표에는 다음을 모두 채운다. 확인일/리전/통화, 무료와 유료의 포함량, 결제수단 필수 여부, 초과 시 차단 또는 자동 과금, 프로젝트 휴면/중지, DB/스토리지/다운로드/실시간/함수/인증·SMTP/백업 제한, 월 고정비·최악의 초과 비용, 보존/복구 가능성.

- 공개 무료 기준은 후속 [23문서](23-supabase-free-tier-readiness.md)의 고정 공식 소스로 확인했다. 실제 계정의 잔여량·계약·초과 처리와 총비용은 별도 확인하며 무과금을 보장하지 않는다.
- 무료 티어로 가능한 범위 → 개인이 승인한 월 상한 내 최소 유료 플랜 → 기능/용량 조정 순으로 비교한다. 조건 미충족 시 실행을 중단하고 재검토한다.
- 예산 알림은 하드 지출 차단과 다르다. 공급자가 실제 hard cap을 지원하는지 확인하고, 미지원이면 API/업로드·로그인 발송·동시 연결의 서비스 한도로 위험을 줄인다. 그래도 상한을 보장할 수 없다면 그 사실을 명시한다.
- 한도 도달 시 로컬 편집 유지, 신규 업로드 보류·분명한 대기 표시. 사용자 업무를 자동 삭제하거나 유료 플랜으로 자동 올리지 않는다.
- 메일·도메인·외부 로그·백업 저장소 같은 부대 비용도 포함한다. 공급자 무료 DB만 보고 월0원이라고 하지 않는다.

## 16.6 유지할 품질과 조정할 서비스 수준

유지: 원본 보존·로컬 저장/outbox 원자성·충돌 사본 보존·계정/공간 격리·복원 검증·모든 한국어/영어 오류·원문/자산 무단 삭제0.

조정 후보: 즉시 반영을 기본 필수에서 조건부로, 장기 백업/PITR·상시 운영·다중 리전·Web/Mobile 동시 출시·별도 worker를 후속으로. 제한이 있어도 ‘24시간 무중단’·‘임의 시점 복구’ 같은 약속을 하지 않는다.

공급자 무료 플랜이 휴면 중지를 허용한다면 앱에 재연결/재개 상태를 표시하고 로컬 사용을 계속 지원해야 한다. 무료 휴면 환경을 운영 복구본의 유일한 사본으로 삼지 않는 방향으로 로컬 검증 사본을 유지한다.

## 16.7 영향과 다음 결정

기존 문서의 AWS 비교는 제외 기록으로 바꾸고, 즉시/보관/PITR·MVP·PoC의 추천 수치를 맞춘다. 과거 진행 기록은 당시 사실로 남긴다. 암호화는 TLS+서버 저장 암호화, 첫 플랫폼은 Windows·macOS로 사용자 확정됐다. 인증/계정 복구와 실제 비용/조건은 추가 검토한다.

다음 검토는 **Neon을 포함한 DB/Auth/API/blob 합산 운영 조건의 확인표**와 **월 예산 상한**이다. 특정 사업자 가입·유료 자원 생성·앱 구현·PoC 실행은 현재 범위가 아니다.
