# 97. G 운영 준비 — 상세 계획(결정 대기)

2026-11-17 · `v2-design` · 로드맵: E 실기 → E+ → 1.40.1 → 온라인 UX 통합(95) → **G 운영 준비** → F 다국어(보류)

## 0. 목표와 원칙

**목표**: 지금 개발 서버·Preview 검증판으로만 돌던 온라인 워크스페이스를, 사용자 본인이 **개인용으로 실제로 쓰고 초대한 몇 명이 함께 쓸 수 있는** 운영 상태로 만든다(무료 플랜 안).

**지키는 것**
- 로컬 전용 모델은 그대로(CLAUDE.md 4절 — 폐기·로그인 강제·자동 온라인 전환 없음). 정식판(로컬) 화면·설정·업데이트 피드는 바뀌지 않는다.
- 온라인 설치물은 기존 로컬판 업데이트 피드에 올리지 않는다(4절). 별도 앱 식별자·설정 폴더·피드를 실제로 검증한다.
- 이미지 본문은 온라인 DB에 넣지 않는다(Blob 참조만). 원본 로컬 일지는 복제 후에도 그대로.
- 운영 프로젝트(`hutqsfftioxtredcjhsy`)는 **G-2 승인 전까지 접속·쓰기 없음**. 관리 토큰·서비스 키·관리자 이메일은 저장소·앱·증거 파일에 두지 않는다.
- 운영에 적용하는 모든 SQL은 개발에서 같은 파일로 먼저 적용·검증한 것만.

## 3. 순서

```
1단계(개발 서버만, 운영 접촉 없음)
  G-3 환경 설정 ─┬─ G-4 새 키
                 └─ G-5 데이터 수명 ── G-7 백업·복구 도구
  G-6 측정(실사용 2주, 병행)

2단계(승인 후 운영 프로젝트)
  G-2 개발에서 처음부터 리허설 → 운영 적용 → 관리자 지정 → KeepAlive → 복구 리허설

3단계(출시)
  G-1 배포 형태 구현 + G-8 개인정보·약관 → G-9 출시
```

- 1단계 끝 관문: 개발 서버에서 G-3~G-5·G-7 시험·실기 통과, 7-49~7-52 실기 완료.
- 2단계 관문: 리허설 기록 + 사용자 승인. 운영 적용 뒤 복구 리허설까지 통과해야 3단계.
- 3단계 관문: 로컬판과 나란히 설치·업데이트·제거 실기 통과, 개인정보 문서 확정.

## 6. 첫 묶음 제안

결정을 받으면 **G-3 → G-4 → G-5(①②④) → G-7** 순서로 개발 서버에서 진행하고, 묶음마다 시험·커밋·Preview 빌드 후 실기 항목을 드린다. 운영 프로젝트는 2단계에서 절차서와 리허설 기록을 보고 승인해 주실 때만 접속한다.
