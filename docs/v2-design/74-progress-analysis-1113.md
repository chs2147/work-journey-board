## 4. 이번 동기화로 생긴 차이·위험

1. **일지 구조 v20 미지원 (가장 큼).** main 1.30.0부터 `0020_kanban.sql`이 `kanban_section`·`item_status_log`·`kanban_ctx`·`kanban_bulk` 4테이블과 `entry_item.kanban_section_id` 열을 더했고, 1.35·1.40은 일지 설정(`ui.kanbanLayout`·`ui.kanbanColumns` — 섹션 순서·아이콘)을 더했다. V2 `captureWorkspace`·`workspace-map`·fixture는 v18·v19만 받아 **v20 일지는 원본을 건드리지 않고 `SCHEMA_VERSION`으로 거절**한다(안전). 실제 사용자는 이미 v20이므로 이관 경로는 지금 쓸 수 없다. 62문서(DB19 보완)와 같은 방식의 "DB20 사본 계약·왕복 검증"이 먼저 필요하다. 상태 이력 로그의 서버 보관 범위·칸반 설정 JSON의 통째 교체 규칙도 함께 정해야 한다.
2. **V2 시험이 CI에 없다.** `ci.yml`은 `poc/`를 돌리지 않고, V2 커밋은 모두 `[skip ci]`다. 앞으로 main을 다시 병합할 때마다 로컬에서 Node 311개(+Rust 31개)를 직접 돌려야 한다 — 이번 세션은 Node만 재실행.
3. **47문서 표가 오래됨.** U01~U08·A01~A11 표의 "미구현/대기"는 당시 상태이고 뒤 절들이 완료를 기록한다. 재개 정본은 RESUME → 73 → 이 문서 순으로 읽는다.
4. **업데이트 주소·비공개 전환과 맞물림.** Classic의 새 판 확인이 이 저장소 Releases에 고정돼 있다는 점(73문서 표)은 main `docs/private-repo-plan.md`의 공개 배포 저장소 분리안과 같은 부분을 건드린다. Preview는 업데이트가 꺼져 있어 직접 영향은 없지만, 정식 V2 배포 채널을 정할 때 두 계획을 같이 결정해야 한다(CLAUDE.md: 온라인 설치물은 기존 로컬판 피드에 게시하지 않음).
5. **비용·한도 관찰.** DEV/운영 모두 Free. 운영 Usage 0.026GB(11/09 사용자 제공) 이후 재확인 없음. KeepAlive는 DEV에만 있다.
