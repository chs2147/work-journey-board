# 10. 한국어·영어 키·용어집·번역 계약

2026-11-08 (KST) · 설계용. 실제 앱 번역 엔진·리소스를 교체하지 않는다.

## 10.1 계약 단위

| 구분 | 계약 |
|---|---|
| locale | `ko`, `en`. `en-US` 같은 지역 선택은 별도 formatter 설정이며 번역 키를 복제하는 이유가 아님 |
| namespace | `common/board/insights/note/cabi/universe/settings/errors/export/auth/sync` |
| key | 의미와 위치 기준. 예: `sync.status.pending`, `cabi.export.pdf`. v19 같은 릴리스 이름을 키에 넣지 않음 |
| value | ICU MessageFormat 문자열. 함수/임의 HTML/코드 실행을 포함하지 않음 |
| args | 키별 이름·타입·표시 규칙. locale별 동일. `{count}`에 문자열 날짜를 넘기지 않음 |
| version | 앱 버전·키 계약 revision·번역 revision·가이드 revision을 분리 |
| fallback | 개발/CI의 필수 키 누락은 실패. 런타임은 기본 언어로 복구하며 원문 업무 데이터는 건드리지 않음 |

단일 JSON의 평면 dotted key를 기준으로 타입을 생성하는 안을 추천한다. 실제 폴더는 namespace별로 나눌 수 있지만 key alias/중첩 해석의 모호함은 허용하지 않는다. i18next+ICU/FormatJS 선택은 앱·네이티브·정적 문서 생성의 호환 PoC 후 결정한다. 이번 문서는 특정 패키지 설치 승인이 아니다.

```text
키 계약 → locale별 번역 → 치환/문법 검증 → typed t(key,args)
                              ├ 앱/접근성/메일
                              ├ 설치/네이티브 빌드용 변환
                              └ 사이트·가이드 생성 계약
```

## 10.2 인자·날짜·오류

예시 사전과 용어집은 `i18n-contract-samples.json`, `glossary-ko-en.csv`에 둔다. 예시는 번역 완료 번들이 아니며 기존2,680건 후보 전체를 대체하지 않는다.

- `count:number`는0/1/2/큰 수·영문 복수형까지 검사한다. `{workspaceName}` 등 사용자 입력은 번역값에 끼워 넣는 일반 텍스트이며 이스케이프한다.
- timestamp는 UTC instant+사용자 표시 time zone으로 포맷한다. 업무 날짜(date-only)·ISO 주차는 언어 변경과 무관하게 보존한다. `YYYY-MM-DD`를 현지 자정 timestamp로 변환하지 않는다.
- 경로/링크/파일명은 별도 타입으로 취급하고 번역문을 경로 조각이나 HTML로 실행하지 않는다. 영문 문장 순서에 맞추려고 사용자 텍스트를 분리/번역하지 않는다.
- 오류는 `code + params`를 반환한다. 네트워크 응답/DB에 완성된 한국어 문장을 새로 영속화하지 않는다. 기존 immutable SQL migration의 한국어 오류는 호환 매핑한다.
- native 코드가 TS 번들을 읽을 수 없으므로 빌드 단계에서 검증된 표시 문자열/오류 매핑을 생성한다. API 서버는 locale 문구 대신 안정된 코드를 반환하고 메일 템플릿만 명시한 locale로 생성한다.

## 10.3 용어와 브랜드

- Work Journey Board / Universe / Cabi.NET은 브랜드 표기를 유지한다. `Cabinet` 신규 번역 키를 만들지 않고 현재 명칭과 기존 코드 경로를 분리한다.
- 업무=Task, 날짜별 기록=Entry, 업무항목=Entry item, 워크스페이스=Workspace를 초기 구분으로 제안한다. 실제 UI 문맥 검수 전에는 `Task`를 모든 항목에 기계 치환하지 않는다.
- `Saved`는 로컬 저장, `Synced`는 서버 수신/확인, `Backed up`은 복구본 보관이라는 의미를 분리한다. 모두 ‘저장됨’ 하나로 번역하지 않는다.
- 같은 ‘복원’이라도 공간 복원·계정 복구·기기 재연결은 다른 키와 설명을 쓴다.
- 접근성 라벨/툴팁/메뉴 문구는 목적별 키를 두고 필요하면 공통 원문을 공유한다. 아이콘만 보이는 버튼도 양 언어 라벨을 가진다.

## 10.4 현재 소스에서의 이전 순서

1. CSV2,680건을 문맥별 분류: 고객 문구/샘플/휴일 데이터/오류/내부 텍스트. 중복 텍스트를 곧바로 같은 키로 합치지 않는다.
2. 기존 `STR_BASE` 및 CABI/V17/V18/V19 리소스에 대해 `oldPath → newKey → args → 화면/근거` 매핑을 만든다. 함수형 문구는 인자 계약으로 변환한다.
3. 공통 버튼·저장/오류·설정부터, 주간/데일리·메모·Cabi.NET·Universe·인사이트, 출력/네이티브, 사이트/가이드 순으로 이전한다.
4. 모듈 import 때 번역문을 고정하지 않고 화면/반응형 selector에서 locale 변경을 구독한다. 에디터 schema/문서 JSON은 locale 전환 때문에 재생성하지 않는다.
5. 자식 창에 locale revision을 전달하되 연결된 업무/메모·커서·미저장 작업을 보존한다. 번역 변경 때문에 저장소 detach/새 문서 생성이 일어나지 않게 한다.
6. 옛 키 alias는 이전 기간과 제거 조건을 기록한다. DB의 내부 enum·휴일 종류·문서 node type을 번역 문자열로 바꾸지 않는다.

## 10.5 배포 관문

- 키 집합/인자 이름·타입/ICU 문법을 양 언어에서 검사하고 빈 번역·중복 키를 거부한다.
-0/1/2개·긴 업무명·한국어/영어 혼합 사용자 텍스트·날짜/시간대·Ctrl/⌘·작은 창·스크린리더 라벨 검증.
- 영문35~50% 확장 의사 번역을 적용하고 본문 overflow/버튼 줄바꿈을 확인한다. 고정 폭을 늘리는 것만으로 모든 화면을 해결하지 않는다.
- PDF는 glyph coverage와 실제 렌더링, Excel은 시트명 제한/표제, Markdown은 구조/링크 불변을 확인한다.
- 지원 locale별 현재 릴리스 안내·사이트 링크·가이드15장면/이미지19개를 대응시킨다. 내부/과거 기술 문서의 완역 범위는 아직 별도 결정이다.

이번 단계의 검증은 예시 키/인자·용어집 형식의 정합성 확인이다. 앱 번역 동작/전체 번역 완료 검증은 구현 이후 수행한다.
