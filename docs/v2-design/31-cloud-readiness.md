Supabase를 이번 실제 검증 대상으로 사용한다. 프로젝트 제공은 기존 데이터 변경·유료 서비스 가입이나 공개 출시의 승인이 아니다. 과거 문서의 ‘월 금액 상한 미정’은 이 문서의 0원 기준으로 대체한다. [공식 공개 무료 한도](23-supabase-free-tier-readiness.md)와 계정의 현재 조건은 구분한다.

## 접속 준비

현재 실행 환경에는 Supabase 자격 증명과 목적지 허용이 없다. 환경 설정 초안에 다음 항목을 저장했다. **초안 저장은 실행 환경 적용/게시가 아니다.** 기존 GitHub 도메인·패키지 프리셋·저장소·설치/시작 지침은 보존했다.

| 항목 | 설정 |
|---|---|
| Management API 목적지 | `api.supabase.com` |
| 프로젝트 목적지 | `hutqsfftioxtredcjhsy.supabase.co` |
| 비밀이 아닌 환경 변수 | `WJB_SUPABASE_PROJECT_REF=hutqsfftioxtredcjhsy` |
| 개인 비밀 입력 항목 | `WJB_SUPABASE_MANAGEMENT_TOKEN` → `api.supabase.com`만 대상으로 지정 |

토큰은 채팅·문서·Git에 넣지 않고 환경 설정의 비밀 입력으로 제공한다. Supabase Management API용 access token을 사용하며 DB 비밀번호나 service-role key를 대신 넣지 않는다. 사용 가능한 범위 제한/만료 설정을 확인해 최소 권한으로 발급한다. **일반 access token이 읽기 전용이라고 가정하지 않는다.** 도메인 허용도 HTTP 메서드를 제한하지 않으므로, 이번 작업에서는 검증된 메타데이터 GET만 실행한다. 접근 권한이 과도하거나 발급이 어려우면 비밀이 없는 대시보드 항목을 사용자에게 확인받는 방식으로 대체할 수 있다.

환경 설정에서 검토·비밀 입력·저장 후 환경을 게시해야 적용된다. 적용 후에는 실행 상태 관측을 새로 조회하고 새 HTTPS 연결을 확인한다. 이 단계에는 인증 메일 발송·회원 생성·SQL 실행·데이터 업로드·유료 설정 변경을 포함하지 않는다.

## 월 0원 검증 순서와 통과 기준

| 순서 | 확인 내용 | 통과 기준 / 멈추는 조건 |
|---|---|---|
| 1. 대상·플랜 | 정확한 ref·상태·조직 플랜·기존 유료 항목 | 대상 일치, Free 검증 가능. 유료 조직/항목이면 변경하지 않고 보고 |
| 2. 리전 | 실제 primary region | 아시아. 다른 리전이면 기존 프로젝트를 이동/삭제하지 않고 대안 검토 |
| 3. 용량·사용량 | DB·Storage·egress·Auth·Functions의 현재 및 조직 합산 사용량 | 한도와 잔여량을 항목별 기록. API로 안 나오는 항목은 미확인 유지 |
| 4. 메일 | 기본 SMTP 제한·실제 custom SMTP 유무·무료 발송 조건 | 팀 테스트와 외부 사용자 발송을 분리. 외부 발송은 무료 SMTP/도메인 조건 확인 전 보류 |
| 5. 권한 | Auth 설정·테넌트 경계·private bucket·RLS 적용 계획 | 현재 설정의 비밀 없는 요약만 기록. 이번 점검에서 자동 수정하지 않음 |
| 6. 휴면 | 기존 스케줄·프로젝트 pause 상태 | Keep Alive 설치 전후 별도 검증 계획. 내부 cron의 휴면 방지 효과는 보장하지 않음 |
| 7. 복구 | 계정 접근 복구·무료 한도 초과/휴면 시 운영 절차 | 로컬 원본/수동 내보내기 보존. 유료 백업·PITR를 무료 기능으로 간주하지 않음 |

초기에는 단일 기존 프로젝트와 가상 자료만 대상으로 한다. 유료 branching·추가 compute·PITR·유료 SMTP·도메인 구매는 포함하지 않는다. API에서 확인할 수 없는 과금/잔여량은 대시보드 확인이 필요하다. 무료 사용량 초과 시 유료 전환으로 처리하지 않고 클라우드 검증/신규 전송을 멈추고 로컬 운영을 유지한다. 서비스 제공자의 차단 동작을 앱의 비용 제한 기능으로 간주하지 않는다.

기존 ‘5명 × 25MiB’ 표본은 검토용 상한 후보이며 즉시 업로드할 양이 아니다. 첫 네트워크 시험은 훨씬 작은 가상 표본부터 시작하고, 보관 사본·교체 중 피크·다운로드 트래픽까지 함께 측정한다. F2의 약1.2GB 메모리 로컬 Node 모형을 Edge Function에 그대로 올리지 않는다.

## 다음 구현 단위

접속이 적용되면 위 표의 조회 결과와 누락 항목을 기록한다. 무료/리전/메일 조건이 충족된 후 **최소 서버 스키마·권한·API 적용안을 먼저 구체화**하고, 가상 두 계정의 접근 차단과 소형 자산 저장/복원 시험으로 이어간다. 실제 SQL·Auth·Storage 쓰기 범위는 그 적용안에서 분명히 한다.

현재 결과는 **프로젝트·예산 확정 및 접속 초안 준비 완료 / 실제 클라우드 검증 대기**다. P01~P22 전체 환경 판정은 NOT_RUN을 유지한다. 제품 소스·DB18·앱 버전·배포는 변경하지 않는다.
