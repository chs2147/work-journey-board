# 26. DB18 가상 원본 전환·왕복 복원 결과

**후속 계약:** 이 문서의 v2-poc-staging-1은 binary를 내부 blobs 테이블에 보관하는 역사적 왕복 시험 포맷이다. 온라인 DB에는 사용/업로드하지 않는다. 원본 영구 유지와 metadata-only 새 사본은 [56문서](56-local-permanence-copy-migration.md)를 따른다.

2026-11-08 · `v2-design` · 독립 로컬 PoC 두 번째 구현 증분.

## 결과

기존 migration 0001~0018을 수정 없이 실행해 **실제 DB18 스키마의 가상 원본**을 생성했다. 이 원본을 읽기 전용으로 검사해 실험용 보존 포맷으로 전환하고, 별도 새 DB18 파일로 다시 복원했다.

- 신규 시험19개 PASS / 실패0 / 생략0. 기존 모형 회귀시험30개 PASS. 서로 다른 두 명령의 세부 시험 합계49개다.
- 실행 환경: Linux / Node24.22.1 / 파일 SQLite. 새 모듈 ESLint·Prettier 검사 통과.
- 모든26개 테이블의 열·행을 보존하고, 표본17/41/73의 원문·문서 JSON·이미지 bytes·링크·반복 정보를 왕복 비교했다. 일부 테이블은 빈 상태이며 모든 도메인 기능을 시험한 것은 아니다.
- 정상 표본은 업무2·태그2·주차2·항목8·업무노트2·주간 보드2·업무 보드2·이미지2·반복규칙/발생1개 및 세 종류 링크를 포함한다.
- 동일 이미지2개는 각각 소유자 정보를 보존하며 해시 기반 blob1개로 저장했다. 두 workspace scope를 따로 전환하고 잘못된 scope의 열기는 거절했다.
- 원본 byte hash 불변, 전환 전후 테이블별 내용 hash·개수 일치, 복원 파일 FK/무결성 검사를 확인했다.

**전환 대상은 `v2-poc-staging-1`이다.** 최종 V2 로컬/서버 도메인 스키마나 제품 migration이 아니다. SQLite 행의 손실 없는 보존과 자산 분리·검증 경계를 먼저 시험했다. 이 파일을 클라우드에 업로드하지 않는다.

## 구현한 처리

1. 직접 생성한 시험 디렉터리만 사용하며, 원본을 읽기 전용으로 연다. DB 버전18·기존 스키마 fingerprint·FK·무결성·동결 journal 상태를 검사한다. 알 수 없는 테이블/열은 제외하지 않고 거절한다.
2. 모든 테이블의 행과 열을 전환본에 보존한다. 메모 이미지/썸네일은 base64와 길이를 확인한 뒤 blob으로 분리하고 문서·자산 소유자·링크/관계선의 참조를 검사한다.
3. manifest에 scope·포맷·원본 앱/DB 버전·원본 hash·테이블별 개수/hash·blob hash/bytes를 남긴다.
4. 임시 파일을 검증한 후 배타적으로 게시한다. 목적 파일이 이미 있으면 덮어쓰지 않으며, 실패한 임시 전환본은 정리한다.
5. 검증된 전환본을 새 DB18 파일로 복원한다. 시험용 복원 중 trigger를 잠시 제거한 뒤 같은 정의로 재생성하고, FK·schema fingerprint·전체 내용 hash를 다시 확인한다. 원본/기존 목적 파일은 변경하지 않는다.

## 실패 주입 범위

새 버전·새 테이블·새 열, 없는 연결 항목/메모 상자, 잘못된 이미지 소유자·base64·byte 길이, 잘못된 JSON·이미지 참조·관계선을 거절했다. 또한 원본을 목적 파일로 지정하거나 기존 목적 파일을 덮어쓰는 요청을 거절했다. 전환본의 blob·행·테이블·scope 변조도 검출했다.

각 거절 시험은 원본 hash 유지·정상 목적 파일 미게시·실패 임시 파일 미잔류를 확인한다. 해시는 사고/변조 검출용이며, 신뢰되지 않는 발신자를 인증하는 전자서명은 아니다.

## 증거와 재현

- [성공 실행 증거 JSON](evidence/db18-staging-pass.json): 런타임·표본별 source/fixture/manifest hash·코드 및 migration18개 hash.
- [수집기 실행 제한 기록](evidence/db18-launcher-failure.json): 샌드박스 `spawnSync EPERM`으로 수집하지 못한 실행. 시험 건수는 null이며 실패를 삭제하지 않았다. 이 실행을 DB 검증 실패나 PASS로 세지 않는다.
- 허용된 외부 실행기에서 동일 수집기를 다시 실행해19개 성공을 수집했다. 이는 로컬 프로세스 권한 차이이며 클라우드 시험이 아니다.

```sh
node poc/v2-sync/model.test.mjs  # 기존 모형30개
node poc/v2-sync/db18.test.mjs   # DB18 전환/왕복/거절19개
node poc/v2-sync/run-db18.mjs    # 새 임시 폴더에 tests.log와 evidence.json 저장
```

수집기가 자식 프로세스 실행을 허용하지 않는 환경에서는 FAIL로 종료하고 실행 오류를 기록한다. 출력 경로는 매 실행마다 달라진다. 원본/전환본/이미지는 시험 후 생성한 임시 폴더 안에서만 정리하며 실제 업무 파일은 읽지 않는다.

## 남은 범위

- 전환본에서 최종 V2 도메인/서버 명령으로의 매핑과 모형 연결.
- 영속 전송 스케줄러·응답 유실 뒤 후속 편집 재조정, 항목 수정과 셀 구조 버전 분리·다중 셀 이동.
- 전체 문서 포맷 파서·자료 카드/Live Widget·Universe의 의미 검증. 현재 업무노트는 텍스트 표본이며 이미지 노드는 미지원으로 거절한다. 보드 JSON은 이 표본의 구조/참조 검사이며 제품 파서 전체와 같지 않다.
- 썸네일·여러 MIME·대형 자료·변환 도중 강제 종료·디스크 부족 시험, 복원과 generation 프로토콜 통합.
- Windows/macOS·실제 Auth/Postgres/Storage·암호화 설정 검증.

이번 결과는 L01의 DB18 표본 보존·왕복 검증을 보완했다. L01~L08의 모든 세부 경로나 첫 구현 묶음 전체 완료는 아니며, P01~P22의 전체 환경 상태는 NOT_RUN으로 유지한다. 앱/제품 버전·기존 migration·루트 의존성·CI 설정은 변경하지 않았다.
