## 4.2 우선 논의 순서

1. **완료:** 한국어·영어, 개인 여러 기기 동기화 우선으로 확정했다. 팀 협업은 후속 확장으로 두며 개인 다기기 간 충돌 처리는 1차에 포함한다.
2. 온라인 기능의 목적을 ‘재난 복구용 백업’과 ‘여러 기기의 동일 업무 상태’ 중 어디에 두는지 정한다. 둘 다 필요하면 별도 상태/정책으로 제공한다.
3. 서비스 저장소/사내 저장소, 데이터 리전·외부 저장 허용 범위·E2EE 여부를 정한다. 이것이 검색·복구·메일·운영 구조를 바꾼다.
4. 로컬 전환·새 기기 연결·충돌·복원·연결 해제 화면의 시안을 작성한다. 자동 전환/묵시적 업로드는 하지 않는다.
5. 포맷/API/권한·자산 정책과 지원 범위를 잠근 뒤 PoC/구현 계획을 승인한다.

## 4.3 개발 단계 제안 (아직 착수하지 않음)

| 단계 | 결과물 | 종료 관문 |
|---|---|---|
| S0 범위·계약 | 언어·용어, 데이터 경계, 개인/팀, 식별·포맷, 통신·보관/복구 정책 | 미확정 핵심 결정과 사용자 흐름 합의 |
| S1 다국어 골격 | 앱/네이티브/출력/사이트/가이드의 언어별 생성·검사 | 현재 기능의 한국어 회귀 없음, 영어 고객 경로 완료 |
| S2 저장·전환 PoC | V1 사본→V2, outbox 원자성, 첨부 분리, 공통 명령 | count·참조·자산 checksum·이전 파일 보존, 장애 주입 통과 |
| S3 온라인 백업 | 계정/기기·불변 snapshot·업로드 재개·보관·복원 | 다른 새 공간에 실제 복원, 버전/자산·원본 보존 |
| S4 수동/주기 증분 | push/pull·충돌·삭제·재접속·기기 회수 | 두 기기의 오프라인 수정 수렴, 손실/중복/다른 공간 혼입 없음 |
| S5 즉시 반영 | 이벤트 채널·debounce·관측·성능 | 이벤트 유실/재정렬에도 pull로 회복, 연결/서버 비용 검증 |
| S6 Web | 브라우저 어댑터·권한/캐시·지원 기능별 UI | 저장 eviction/여러 탭/오프라인·언어 QA |
| S7 Mobile | 스택 결정·작은 화면·기기 저장/보안·백그라운드 | 실제 iOS/Android 편집·재개·동기화 검증 |

S1과 S2의 일부는 병렬 진행할 수 있지만 포맷/에러 코드·날짜/언어 계약은 공통으로 먼저 정해야 한다. S3만 제공하는 시점은 ‘온라인 백업 지원’으로 출시하고 실시간 동기화라고 표기하지 않는다.

## 4.4 규모 추정의 기준

- 다국어 기술 작업은 01문서의 **32~58인일** 초안. 번역/언어·법률 검수와 모든 과거 문서 완역 비용은 별도다.
- 개인 다기기 동기화는 저장/전환·인증·자산·outbox/충돌·백업/복원·운영/장애 검증이 필요한 별도 대형 작업이다. 설계 승인 전 ‘몇 주면 완료’로 확약하지 않는다. S2 PoC 후 화면/명령별 작업 분해로 산정한다.
- 팀 공동 편집, E2EE, 여러 클라우드 제공자 선택, 모든 V1 기능의 웹/모바일 동등 제공은 기본 동기화와 별도 범위다. 원소스가 플랫폼별 구현/검수 비용을 없애지는 않는다.
- 다음 견적에 필요한 입력: 사용자/기기/공간 수, 공간별 텍스트·이미지 용량과 증가량, 업무당 노트·객체 수, 하루 변경량, 최대 오프라인 기간, 백업 보관 기간, 동시 활성 비율, 웹/모바일 첫 제공 기능.

## 4.5 운영 비용 모델 (사업자 가격 미조회)

월 비용 = Auth 사용자/메일·SMS + DB 용량/연산/PITR + API/worker + 실시간 연결/메시지 + 객체 live/backup 저장량 + 다운로드 egress + 로그/관측 + 지원/복원 운영.

- live blob ≈ 사용자 수 × 사용자당 공간 수 × 공간당 평균 원본 자산 bytes.
- 월 변경량 ≈ 사용자 수 × 활성 일수 × 일평균 op 수. 실제 HTTP 요청 수는 묶음 크기와 재시도로 다르다.
- 새 기기/전체 재동기화 비용은 공간 전체 다운로드 횟수로 따로 산정한다. 실시간 알림 메시지에는 원문/이미지를 넣지 않는다.
- 매일 전체 snapshot을 복제하면 용량이 급증한다. 예: **가정** 1,000명×공간1개×250MB이면 live 약250GB, 같은 크기30개 전체 백업은 약7.5TB다(압축·중복 제거 전). 불변 blob 재사용/증분 manifest를 검토하되 실제 절감률을 미리 보장하지 않는다.
- 무료 티어를 운영 보장으로 사용하지 않는다. 사업자·리전·트래픽이 정해지면 실제 가격표와 쿼터/요금 경고를 붙인다.

## 4.6 정합성·복구 검증 체크리스트

- 같은 항목/노트의 동시 수정, 서로 다른 객체 수정, 부모 삭제와 자식 수정, 업무 완료/취소, 링크·자료·이미지 포함.
- 로컬 저장 직후 종료, push 커밋 후 ack 유실, 같은 op 재전송, pull 적용 중 종료, 역순/중복 이벤트, 시간대·장치 시계 오차.
- 첫 업로드 중 편집/취소/실패·다른 공간 전환, staging 미노출, 새 기기에 내려받기 전후 count·관계·checksum 비교.
- 오래된 기기 cursor 만료/권한 박탈·세션 만료·generation 복원, 미전송 outbox를 버리지 않는 재조정.
- 이미지 업로드 실패·비정상 형식·공간 용량 초과, 백업 참조가 있는 자산의 GC 금지, 실제 복원 훈련.
- 기존 공간 전환의 flush→detach→activate 경계를 유지하고 수신도 해당 workspace/binding에만 적용. 전환 후 늦게 도착한 응답이 새 공간에 쓰이지 않음.
- 로컬 전용 프로필 외부 요청0, 온라인 프로필 미연결 공간의 업로드0, 토큰/원문 비기록, 테넌트 간 접근 거부.
- 언어 변경/국외 타임존이 기존 업무 날짜·주차·데이터를 바꾸지 않음. 모든 지원 언어의 오류·복원·메일·내보내기 실제 출력 확인.

## 4.7 현재 산출물 확인

현재 브랜치는 문서와 번역 후보 조사 파일만 포함한다. 앱·DB·백엔드 코드는 변경하지 않았고, 실제 업무 파일을 읽거나 업로드하지 않았다. 코드 테스트/빌드로 구현을 검증했다고 주장하지 않는다. 문서의 상대 링크·CSV 집계·git 변경 범위를 확인한다.

## 4.8 범위 확정 기록 — 2026-11-08
