## 1. 확정된 운영 원칙

**기존 로컬 원본은 기존 워크스페이스 그대로 유지한다. 신규 온라인 워크스페이스를 별도로 생성하고, 이후 온라인 기능은 그 신규 공간 기준으로 운영한다.** 기존 공간을 폴더 참조/백업본으로 격하하거나 동일 공간의 유형을 제자리에서 바꾸지 않는다.

| 대상 | 생성 후 상태 | 식별/저장 | 이후 운영 |
|---|---|---|---|
| 기존 회사일지 | 오프라인 전용 워크스페이스 유지 | 기존 식별 정보·이름·폴더·DB·이미지·백업 유지 | 기존 기능으로 계속 사용 |
| 신규 회사일지 · 온라인 | 별개의 온라인 워크스페이스 | 새 workspaceId·온라인 metadata/Blob·별도 기기 캐시 | 온라인 작업/기기 간 동기화의 기준 |
| 두 번째 기기의 온라인 캐시 | 같은 온라인 워크스페이스의 기기 데이터 | 동일 cloudWorkspaceId·새 deviceId·별도 캐시 위치 | 같은 온라인 공간과 동기화 |

복제는 ‘오프라인 기록으로 시작’할 때 내부적으로 원본을 보존하는 처리 방식이다. 사용자 기능의 최상위 명칭은 **‘온라인 워크스페이스 만들기’**다.

- **새로 시작하기:** 빈 온라인 워크스페이스 생성. 기존 오프라인 공간을 선택/변경하지 않는다.
- **오프라인 기록으로 시작:** 기존 공간의 기록을 가져와 새 온라인 워크스페이스 생성. 기존 공간의 ID/유형/구조는 그대로 유지한다.
- **기존 온라인 워크스페이스 연결/이 기기에 받기:** 이미 있는 온라인 공간에 연결한다. 신규 공간 생성으로 취급하지 않는다.

생성 완료 후 기본 CTA는 **‘온라인 워크스페이스 열기’**다. 선택하면 신규 온라인 공간을 활성화하며 원본 목록 항목을 교체·삭제하지 않는다. 이후 원본에 별도로 추가한 기록은 온라인 공간으로 자동 합쳐지지 않는다. 향후 추가 가져오기는 별도 충돌/중복 검토 절차가 필요하다.

## 2. 유형과 상태를 독립적으로 표시

workspace.kind는 **offline_only 또는 online**이다. 인터넷 연결, 로그인, 전송 성공 여부로 이 값을 변경하지 않는다. 앱의 빌드/실행 프로필과도 다른 개념이다. 별도 Preview 앱 운영 여부는67문서의 미확정 구현 제안이며 이번 워크스페이스 운영 원칙의 필수 전제가 아니다.

| 유형 | 상시 배지 | 보조 상태 | 네트워크 사용 |
|---|---|---|---|
| offline_only | 디스크 모노그램 + **오프라인 전용** | 이 PC에 저장됨 / 이 기기에서만 저장 | 워크스페이스의 클라우드 동기화 없음 |
| online·정상 | 구름 모노그램 + **온라인** | 이 PC에 저장됨 / 온라인 반영됨 | 같은 온라인 공간으로 전송 |
| online·연결 끊김 | 동일한 구름 + **온라인** 유지 | 연결 끊김 / N건 전송 대기 | 로컬 캐시에 보관하고 재연결 후 전송 |
| online·로그인 만료 | **온라인** 유지 | 다시 로그인 필요 / 대기 기록 보존 | 같은 owner 인증 전 전송 중단 |
| online·용량/충돌/서버 장애 | **온라인** 유지 | 해당 오류와 다음 행동 | 원본 오프라인 공간으로 fallback하지 않음 |

기존 DB19에 kind 컬럼을 추가하거나 온라인용 migration을 적용하지 않는다. 유형 필드가 없는 기존 항목은 읽기/표시 시 offline_only로 해석한다. 온라인 항목과 원본 참조에 필요한 추가 식별 정보는 신규 registry/journal에만 보관한다.

색만으로 구분하지 않는다. 모든 배지에 아이콘과 한글 유형명을 함께 제공하고 테마/접근성 이름에서도 유지한다. ‘오프라인’ 단독 문구를 연결 끊김과 공간 유형에 중복 사용하지 않는다. 유형은 **오프라인 전용**, 일시 상태는 **연결 끊김/전송 대기**로 표기한다.

### 적용 위치

1. 메인 상단: 현재 워크스페이스 이름 바로 옆에 유형 배지를 상시 표시한다.
2. 워크스페이스 전환 메뉴: 모든 항목에 유형을 표시한다. 이름만 같아도 유형/ID로 구분한다.
3. 설정 목록: 기존 오프라인 전용과 온라인 공간을 구분하며 원본/신규 항목을 동시에 유지한다.
4. 생성 검토·완료: ‘기존 워크스페이스 · 그대로 유지’와 ‘신규 워크스페이스 · 이후 온라인 운영’을 병기한다.
5. 보조 창(Cabi.NET 노트·업무 메모보드·Universe 등): 해당 창이 연결된 공간의 이름/유형을 표시한다. 메인 공간을 바꿔도 이전 창이 다른 공간에 쓰지 않게 epoch/저장소 소유권을 유지한다.
6. 상태 패널: 고정 유형과 가변 연결/저장 상태를 분리한다. ‘이 PC에 저장됨’을 서버 반영 성공으로 표시하지 않는다.

## 3. 기존 설계에서 수정한 부분

| 종전 표현/동작 | 수정 내용 |
|---|---|
| 온라인 사본 만들기 | 온라인 워크스페이스 만들기 |
| 폴더 참조가 주된 사용자 개념 | 기존 오프라인 전용 워크스페이스가 유지되는 것이 주된 개념. 참조 경로는 구현 정보 |
| 로그인/연결 상태만으로 온라인 여부 표현 | 공간 이름 옆 고정 유형 배지 추가 |
| 원본과 온라인 생성 대상의 모호한 관계 | 기존 공간 유지 + 신규 ID의 온라인 공간 + 완료 후 신규 공간 열기 |
| 온라인 연결 끊김이 ‘오프라인’처럼 보일 가능성 | 온라인 배지 유지 + ‘연결 끊김 · 전송 대기’ 별도 표시 |

UI에 유형 전환 스위치를 제공해 기존 공간을 제자리에서 온라인화하지 않는다. HTML 상단의 유형/인터넷 선택기는 **검토용 시안 도구**이며 제품 기능이 아니다. 명칭을 바꿔도 원본 보존/새ID/별도 경로/이미지 본문 분리/서버 완료 검증 계약은 유지한다.
