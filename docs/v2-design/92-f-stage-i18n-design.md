언어 범위는 이미 사용자 확정(2026-11-08, 한국어·영어). 범위·리소스 구조·용어 원칙은 [01](01-localization.md)·[10](10-i18n-contract.md)에 설계해 두었다(엔진·순서는 미정이었음).

## 1. 지금 코드에서 알게 된 것

- 화면 문구는 이미 거의 한곳에 모여 있다: `src/shared/strings.ts`의 `STR_BASE`(약 2,400줄, 104개 파일이 사용) + 기능별 묶음 5개(`cabiStrings`·`v17~v20Strings`, 29개 파일). 숫자가 들어가는 문구는 함수(`(n) => \`대기 ${n}건\``)다.
- **맥 표기 변환이 이미 "문구 묶음 전체를 시작할 때 한 번 바꾸는" 구조**다(`localizeTree(STR_BASE)` — 윈도우 표기 → ⌘·⌥·Finder). 언어도 같은 자리에서 바꿀 수 있다: 시작할 때 고른 언어의 묶음을 고르고 → 맥 표기 변환.
- 따라서 **2,680곳의 호출(`STR.x.y`)을 고치지 않고**, 영어 묶음을 **한국어 묶음과 같은 모양**(TypeScript가 빠진 칸·모양 차이를 컴파일 오류로 막음)으로 더하는 방식이 가장 작고 안전하다. 01문서의 "의미 기반 키·ICU" 원칙은 키 이름 = 지금 경로(`STR.onlineSpaces.sync.pending`), 복수형 = 함수(영어는 `Intl.PluralRules`)로 지킨다.
- 묶음 밖 문구: 화면에 직접 적힌 약 100건, 도메인·내보내기(엑셀 머리글·요약 형식) 약 300건, 플랫폼·Rust 오류 문구, 휴일 이름·샘플(번역하지 않음 — 데이터), 이용 가이드·사이트.

## 2. 단계 제안

| 단계 | 내용 | 확인 |
|---|---|---|
| **F-1 기반** | 언어 묶음 고르기(시작할 때, 맥 표기와 같은 자리) · 설정 › 일반에 [언어] · 첫 실행 기본값 · 바꾸면 저장 후 창 다시 불러오기(자식 창 포함) · `Intl` 날짜·숫자 형식 한곳 · 시험(모양 일치·빠진 칸 0·영어 의사 번역으로 넘침 검사) | 단위·E2E(두 언어) |
| **F-2 문구 모으기** | 묶음 밖에 직접 적힌 문구·도메인 문구를 묶음으로(동작 변화 없음), Rust 오류는 코드로 받아 화면에서 번역(이미 대부분 코드) | 기존 시험 그대로 통과 + 직접 한국어 문구 검사(CI) |
| **F-3 영어 묶음** | 용어집 먼저(업무 = Task, 기록 = Entry, 저장됨 / 동기화됨 / 백업됨 구분 — 10문서) → 영어 묶음 전체 → 화면 넘침·줄바꿈 점검(넓은/좁은 창·3테마) | 영어 화면 스크린샷 검토 |
| **F-4 출력·네이티브** | 엑셀 시트·머리글·자동 집계 형식(언어 선택), PDF·Markdown 고정 표제, 맥 메뉴·설치 프로그램 문구, Preview 온라인 문구 | 골든 시험(한국어 출력은 지금과 한 글자도 같게) |
| **F-5 가이드·사이트** | 이용 가이드 15장면 영어판·영어 스크린샷·소개 사이트 `/en/` | `guide.mjs check` 두 언어 |

- 자동 집계(output-spec 2-2절) 한국어 출력은 **문자 단위 골든 시험 그대로** — 영어 출력은 새 골든 시험.
- 업무 이름·태그·노트·사용자가 적은 휴일 이름 등 **사용자 데이터는 번역하지 않는다**. 언어를 바꿔도 주차(ISO)·한국 공휴일 규칙은 그대로(01문서 1.4).
- 영어는 **필수 경로 100% + 넘침 점검을 통과하기 전까지 언어 목록에 내놓지 않는다**(부분 번역 노출 금지, 01문서 1.5).

## 3. 결정이 필요한 것

| | 질문 | 추천 | 대안 |
|---|---|---|---|
| **F1** | 번역 방식 | **지금 문구 묶음 모양 그대로 영어 묶음을 더하기**(새 의존성 없음, 호출 2,680곳 그대로, 빠진 칸은 컴파일 오류, 복수형은 `Intl.PluralRules`) | i18next·FormatJS 등 라이브러리 + 모든 호출을 `t("key")`로 바꾸기(표준적이지만 코드 전체 변경·의존성·번들 증가) |
| **F2** | 언어를 바꾸는 시점 | **설정에서 바꾸면 입력 저장 → 창 다시 불러오기**(노트·메모보드 창 포함, 일지 전환과 같은 한 길) | 다시 불러오지 않고 즉시 반영(모든 화면이 언어 바뀜을 구독해야 해 범위·위험 큼) |
| **F3** | 첫 실행 기본 언어 | **OS 언어가 영어면 영어, 그 밖은 한국어**(이미 쓰던 사용자는 한국어 그대로). 영어 묶음이 완성 전이면 늘 한국어 | 늘 한국어로 시작(설정에서만 영어) |
| **F4** | 영어 문안 작성 | **제가 용어집 → 영어 묶음 초안 작성, 사용자 검수**(용어집을 먼저 확인받고 그 뒤 전체) | 외부 번역 의뢰(비용·대기) |
| **F5** | 적용 범위·순서 | **정식판·DEV·Preview 공통으로 `v2-design`에서 개발**, 영어는 완성 관문 통과 뒤 목록에 노출. main 반영(판올림)은 관문 통과 후 사용자 결정 | Preview만 먼저(정식판은 나중) — 같은 화면 코드라 나눌 이득이 작음 |
| **F6** | 문서 범위 | **앱·이용 가이드·소개 사이트·현재 판 릴리스 노트까지 영어**. 설계·과거 기록(docs 140개+)은 한국어 원문 유지 | 공개 문서 전체 번역 |

## 4. 바꾸는 것(승인 범위)

- 앱(정식판·DEV·Preview 공통 화면 코드): 언어 고르기·설정 항목·영어 묶음. 한국어 화면·출력은 지금과 같아야 한다(시험으로 고정).
- 설정 파일(`config.json`)에 `language` 한 칸(없으면 지금처럼 한국어). 일지 구조·서버는 바꾸지 않는다.
- 새 런타임 의존성·외부 통신 없음(F1 추천 시). 글꼴: 영어는 지금 번들된 Pretendard로 충분(라틴 포함).

## 5. 위험

| 위험 | 대응 |

| 한국어 화면·출력이 바뀜 | 한국어 묶음은 그대로 두고 고르는 길만 더함. 기존 E2E·골든 시험 전부 통과가 조건 |
