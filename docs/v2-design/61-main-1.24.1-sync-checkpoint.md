## 보존과 반영

V2 구현 결과194c172와60문서/검증176개를 보존하고, main 동기화 전 중단 기록을e908afb로 커밋·푸시했다. origin/main ae97c10까지12개 커밋을 충돌 없이 병합한다. main 자체는 수정하지 않는다.

반영 범위는 업무노트 삭제 잠금·삭제 최종 확인·복제·표/블록 이끌이 개선, 새 판 확인403/429 대응·ETag/대체 경로, 데일리 기록 있는 업무만 보기, 가이드/릴리스 노트/Feature List다. package.json 기준 앱은 **1.24.1**, 현재 제품 DB는 **19**다. 새 배포/판올림은 하지 않는다.

## 이관 호환성: 반드시 다음에 처리

DB19는 cabi_note에 `delete_locked`를 추가하고 revision 트리거 적용 범위를 조정한다. `ui.todayHideEmpty`는 기기 UI 설정이므로 기존 V2 설정 제외 정책에 들어간다.

기존 독립 이관/매핑 모형은 여전히 **DB18 전용**이다. create18은18번까지의 SQL만 적용하고 capture18은 버전과 스키마를 엄격히 검사한다. 실제19번 SQL로 만든 합성 표본이 SCHEMA_VERSION으로 거절되며 원본 hash가 변하지 않는 것을 확인했다. 따라서 DB19 노트의 삭제 잠금을 누락한 채 온라인 전환되는 경로는 열지 않는다. 기존 DB18 계약과 검증 증거는 역사적 호환 기준으로 유지한다.

다음 구현은 DB18/19 명시적 계약 분기 및 DB19 사본 추출/삭제 잠금 보존·복원 시험을 먼저 진행한다. 이후 전체 봉투 서버 프로필/저장 검증 → journal source/target 해시 영속 바인딩 → 실제 Storage readback/취소 부재 확인 → DEV 통합 순이다. 단순히 버전 숫자를18에서19로 교체하거나 DB19를18로 낮춰 읽지 않는다.

## 병합 검증

- 앱 단위59파일/532개 통과.
- 기존 V2 JavaScript136개 통과. PG SQL/RPC 소스는 이번 병합에서 변경하지 않아60문서의40개 결과를 다시 실행한 것으로 표시하지 않는다.
- npm run build 통과(타입 검사 포함). 기존 큰 번들/동적 import 경고는 남아 있다.
- 릴리스 노트1.24.1·가이드15장면·Feature List255개 정합성 통과. 기능표의 정식판 생성물은 main 것을 그대로 유지한다.
- 실제 DB19 SQL 합성 표본의 안전한 거절/원본 hash 유지 확인.

- Chromium 화면 테스트11개 통과(v20·1.24.1 핫픽스). 기본 Playwright 번들 브라우저가 없어 첫 시도는 실행 전 실패했고, 설치된 `/usr/bin/chromium`을 PW_CHROMIUM_PATH로 지정한 재실행이 통과했다. WebKit/Windows/macOS 실기는 이번에 실행하지 않았다.
