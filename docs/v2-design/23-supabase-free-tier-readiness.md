## 23.2 무료 기준과 설계 영향

단위 MB/GB와 MiB/GiB를 혼용하지 않는다. 아래 공급자 표기는 원문 MB/GB이며, 시험 모델은 MiB로 계산한다.

| 항목 | 공개 Free 기준 | V2 반영 |
|---|---|---|
| DB | 프로젝트당500MB | 업무/관계·change log·멱등 기록·index·인증/스토리지 메타데이터까지 실측. base64 원본 중복 저장 제외 |
| 파일 저장 |1GB | live·보존본·임시 업로드·썸네일 모두 합산. 다른 프로젝트와 조직 quota 공유 여부 확인 |
| 일반 egress | 월5GB | DB/API·파일 다운로드·복원 등 실제 집계 항목 확인 |
| cached egress | 별도 월5GB 표기 | private 다운로드의 cache hit를 보장하지 않음. 일반 전송량과 합쳐 ‘아무 전송10GB’로 산정하지 않음 |
| MAU |50,000 | 메일 발송 한도와 별개. 무료 SMTP가 외부 사용자 가입을 지원한다는 뜻 아님 |
| Edge Functions | 월500,000회 | polling·push·업로드 예약/확정·재시도·관리 요청 포함 |
| Realtime | 월2,000,000 messages·동시200 connections | 즉시 모드는 후속 실측. 메시지 fan-out을 사용자 작업 수와 동일시하지 않음 |
| 단일 파일 업로드 |50MB | 실제 bucket/프로젝트 설정은 더 작을 수 있음. 대형 백업 분할 필요 |
| 자동 DB 백업/PITR | Free 미제공 표기 | 앱의 원격 snapshot+로컬 사본·실제 복원 검증 유지 |
| 관리형 branching | Free 미제공 표기 | 기본 개발 환경은 로컬. 클라우드 dev branch를 무료 구성에 포함하지 않음 |
| 휴면 | 비활성1주 후 pause |20문서 Keep Alive 기본 요구 유지, 내부 cron의 휴면 판정 효과는 미검증 |

API 요청 무제한 표기는 CPU·전송량·함수·인증·동시성까지 무제한이라는 의미가 아니다. 최신 Free 초과 시 제한/복구 절차와 결제 조건은 아직 계정에서 확인하지 않았다. 자동 유료 전환을 설계하지 않는다.

## 23.3 작은 모델을 실제 기준에 대입

16문서의 가상 모델을 그대로 사용한다. 원본25MiB 전체가 파일 저장소를 사용한다고 보수적으로 계산하고, 중복 제거/압축 절감은 미리 차감하지 않는다. 별도 DB 크기는 이 계산에 포함하지 않는다.

| 모델 | steady 파일 사용 | 백업 교체 중 추가 공간 | 판정 |
|---|---:|---:|---|
|5명×공간1×원본25MiB, live+보존3개 |500MiB =524,288,000bytes | 새 자동본을 모든 사용자에 대해 동시에 준비하면125MiB 추가 →625MiB =655,360,000bytes | 공개1GB 기준 안에 들어갈 가능성. 썸네일·충돌 사본·고아/실패 업로드·다른 프로젝트 사용량은 추가 |
|10명×공간1×원본50MiB, live+보존3개 |2,000MiB =2,097,152,000bytes |500MiB 추가 | 무료1GB를 초과. 가입/용량 조정 또는 별도 비용 검토 필요 |

원격3개 정책은 **교체 도중 이전 정상본+새 후보본을 일시 공존**시켜야 한다. 자리 확보를 위해 정상본부터 지우지 않는다. 앱 한도는 공급자1GB 전체를 소진하게 설정하지 않고, 조직 사용량과 예약 중 bytes를 포함한 여유 공간을 확인한다. 새 보존본을 만들 공간이 없으면 기존 정상본을 유지하며 백업 대기를 알린다.

5명·기기2대·8시간/일·22일/월·5분 polling은 월21,120회다. 매 확인당 Edge 호출1회라면 공개500,000회의 약4.2%지만 push/인증/업로드 등은 별도다. 기기2대가24시간 켜져 있고30일 모두 확인하면86,400회로 늘어난다. 비활성/백그라운드 중지 정책이 필요하다. 호출 수가 작다는 사실로 DB 부하·응답시간 합격을 대신하지 않는다.

5명×25MiB를 기기2대가 각1회 전체 다운로드하면250MiB다. 반복 복원·기기 재연결 때 매번 전체 다운로드하는 설계는 전송 예산을 빨리 소모한다. manifest/hash·로컬 자산 cache·변경분 pull을 유지하고 실제 bytes를 측정한다.

## 23.4 업로드/백업 보완 계약

- 일반 이미지와 backup chunk를 모두 private 객체로 취급한다. 앱의 대용량 데이터를 Edge 함수의 요청/응답 본문으로 중계하지 않고, 검증된 권한으로 제한된 직접 Storage 전송을 사용한다. 함수 한도는 별도 검증한다.
- 큰 백업은 **chunk 최대10MiB 추천**으로 분할한다. 최종 값은 실제 bucket·클라이언트 메모리·암호화 overhead·전송 시험 후 고정한다. 압축 전/후, 암호화 후의 bytes를 구분한다.
- manifest는 backupId·순서·chunk hash/bytes·총길이·전체 hash·포맷 버전을 기록한다. 일부 chunk만 올라간 백업은 목록에 ‘복원 가능’으로 공개하지 않는다. 재개 업로드는 같은 식별자/검증 결과를 사용한다.
- 다운로드 후 모든 chunk와 전체 무결성 검증·복원 검증까지 마쳐야 완료다.1차 암호화는 사용자 확정인 TLS+서버 저장 암호화다. 향후 E2EE 도입 시 복호화/인증 실패도 완료 관문에 포함하도록 별도 설계한다.
- 동시 예약이 저장 한도를 넘지 않도록 서버에서 bytes 예약·만료·확정 상태를 관리한다. 실패 chunk는 참조/유예기간을 확인한 후 정리하며 이전 정상 백업은 유지한다.
- chunk 크기10MiB는 업무노트/이미지·전체 공간 용량의 최종 서비스 한도가 아니다. 실제 자료를 임의로 손실 압축하거나 큰 로컬 원본을 삭제하지 않는다.

## 23.5 아시아 리전·메일·예산 추천

**리전:** 한국 사용자 중심이면 서울 `ap-northeast-2`를 우선 검토하고, 선택 불가/요건 미충족 시 도쿄 `ap-northeast-1`, 싱가포르 `ap-southeast-1`를 비교한다. 공개 목록에 있다는 사실은 해당 계정 Free 프로젝트 생성 시 선택 가능함을 보장하지 않는다. 일반 `APAC` 선택을 서울 지정과 동일시하지 않는다. Auth·메일·운영 로그·지원 처리 경로까지 모두 한국에만 머문다는 보장도 아니다.

**메일:** 로컬 모형은 테스트 메일 수신함을 사용한다. 외부 사용자 대상 시험은 custom SMTP·발신 도메인 인증·외부 수신 성공·재발송/abuse 제한을 확인한 뒤 진행한다. 기본 SMTP는 공개 기준 시간당2통이면서 팀 주소 제한이 있으므로 외부 가입용으로 채택하지 않는다. SMTP 업체/무료량·도메인 소유/비용은 미확인이다.

**예산:** 월 고정비0원을 우선 목표로 유지하되 SMTP/도메인 등 합산 확인 전 총비용0원으로 확정하지 않는다. 공개 Pro 시작 가격은 $25/월이며 환율·세금·추가 사용량 별도다. 이는 승인된 지출 상한이 아니다. 초과 시 로컬 편집과 미전송 내용을 보존하고 업로드를 대기시키며, 유료화는 비용표 검토 후 결정한다.

**판정:** Supabase 무료 구성은 작은 시험 모델에서 용량상 후보가 된다. 실제 무료 운영 확정이나 클라우드 PoC 준비 완료는 아니다. 다음 검토는14문서의 미정 선택과 위 계정/메일 조건을 한 번에 마무리하고,15문서의 로컬 가상 fixture 기반 W01~W05 범위를 먼저 확정하는 것이다. 클라우드 W06 이후는 실제 설정 확인 후 분리한다. 실제 자료 업로드·프로젝트 생성·SQL/cron 적용은 수행하지 않았다.
