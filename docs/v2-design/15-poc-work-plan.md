# 15. PoC 작업 분해·산출물·검증 추적표

2026-11-08 (KST) · 작업 계획만 작성 · 코드/시험 미실행

**최신 비용 원칙:** [16문서](16-low-cost-review.md). W06은 무료/개인 요금·초과 과금·휴면·백업 제한 확인을 포함한다. 상시 서버/PITR/즉시 모드가 무료로 가능하다고 가정하지 않는다.

## 15.1 목적

13문서의 P01~P22를 실제 작업 단위와 연결해 ‘무엇을 만들고 어떤 증거로 완료를 판단할지’를 정의한다. 전체 MVP 구현 계획을 단순 PoC로 축소하지 않으며, 시뮬레이터 통과와 실제 클라우드/실기 통과도 구분한다.

## 15.3 모형과 실제 환경의 증거 분리

- `LOCAL_MODEL`: 가상 서버/네트워크·로컬 DB로 명령과 장애를 재현. 제공자 인증/권한·실제 스토리지/비용의 증거로 쓰지 않는다.
- `CLOUD_TEST`: 승인된 테스트 계정·리전에서 실제 Auth/API/DB/blob/알림을 확인한다. 계정 소유자/토큰/원문이 증거에 노출되지 않게 한다.
- `NATIVE_WIN_MAC`: 실제 desktop 설치/OS 저장·창/종료·기기 재개·내보내기 검증. 브라우저 개발 모드 성공을 실기 성공으로 대신하지 않는다.
- Web 동시 출시를 선택하면 `WEB_BROWSER` 대상과 탭/eviction·cookie/CSRF·브라우저별 명세를 추가한다. Mobile 출시는 별도 범위다.

## 15.4 결과 레지스터

[PoC 시나리오 레지스터](poc-scenario-register.csv)는22개 시나리오 ID·기대 결과·선행 작업·필수 환경을 연결한다. 현재 모든 상태는 NOT_RUN이다. 단일 행을 PASS로 바꾸기 전 모든 필수 환경 결과를 확인한다.

실제 실행 결과는 `scenarioId + target + runId`별로 별도 기록한다. commit/버전·fixture hash·환경·시각·기대/실제 결과·증거 경로·실패/복구·재실행 사유가 필요하다. 동일 시험의 성공 실행 하나로 이전 실패를 삭제하지 않는다.

소스/문서의 ID 매핑·링크 검사는 수행할 수 있지만 PoC 실행과는 다르다. 이번 작업에서 ‘문서 검증 통과’를 P01~P22 PASS로 기록하지 않는다.

## 15.5 끝났다고 판단할 수 없는 사례

- 로그인·파일 업로드·다운로드만 되는 데모.
- 서버에서 보이지만 이전 기기의 미전송 내용을 잃는 재동기화.
- 레코드 총 개수는 같으나 문서·이미지 hash/참조가 다른 복원.
- 이벤트 소켓이 정상일 때만 기기가 수렴하는 동기화.
- 실제 요금/리전/세션 회수 제약을 확인하지 않은 제공자 선택.

다음 산출물은 G0 선택을 반영한 계약 수정본과 승인 가능한 PoC 구현 범위다. 사용자의 설계 결정 응답 전에는 백엔드/암호화/첫 플랫폼을 승인 상태로 바꾸지 않는다.
