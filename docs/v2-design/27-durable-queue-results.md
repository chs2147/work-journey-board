# 27. 전환본 연결·영속 전송 대기·후속 편집 재조정

2026-11-08 · 독립 로컬 PoC 세 번째 증분 · 제품 1.23.0 / DB18 유지.

## 결과

DB18 전환 표본을 두 기기와 서버 모형에 연결하고 파일 DB에 남는 전송 대기를 구현했다. **신규28개 + 기존30개 + DB18 시험19개 = 총77개 세부 시험이 통과**했다. 실제 클라우드가 아닌 Linux / Node24.22.1 / SQLite 모형의 결과다.

- [전체 실행 증거](evidence/local-queue-pass.json): 세부 시험 이름·로그 hash·런타임·코드/migration hash 및 DB18 표본 hash.
- 원시 실행 로그: `/tmp/wjb-v2-local-evidence-2P1UIO/` (이 실행 환경의 임시 산출물).
- [재현 코드/명령](../../poc/v2-sync/README.md): `node poc/v2-sync/run-local.mjs`가 매 실행 새 임시 폴더에 로그와 JSON 증거를 만든다.

초기 개발 시험에서는 이미지 캐시의 `Uint8Array`를 일반 객체 hash로 비교한 검증문 때문에21개 중3개가 실패했다. 검증문이 실제 byte hash를 비교하도록 Buffer 변환을 적용했고, 데이터 변환 엔진의 이미지 저장 방식은 바꾸지 않았다. 위 증거는 수정 후 전체 재실행 결과다.

## 구현한 내용

### 1. 전환본 → 모형의 최초 데이터

`stage-import.mjs`는 검증된 staging 파일의 PK/복합키를 사용해 안정적인 `table + key values` 식별자를 만든다. 업무항목·노트·보드·링크 등은 scope 안에 저장한다. 같은 주차/로컬 ID가 다른 공간에서 충돌하지 않는다.

이미지는 bytes를 scope별 로컬 자산 캐시에 두고 레코드에는 hash/길이 참조를 남긴다. 로컬 DB의 `app_meta`는 동기화 콘텐츠에서 제외하고 원본 manifest를 별도 보존한다. 대상이 비어 있지 않으면 기존 내용을 덮어쓰지 않고 거절하며, 레코드·자산·import manifest는 같은 트랜잭션으로 기록한다.

이 매핑은 **PoC용 SQL 행 wrapper**다. 최종 제품의 도메인 명령·서버 정규화 스키마나 모든 관계의 의미 검증을 완성한 것은 아니다. 자산 캐시도 기기에 미리 넣은 것이며 원격 업로드/다운로드 성공 증거가 아니다.

### 2. 미전송 초안과 불변 전송 명령

`queue.mjs`는 아직 보내지 않은 초안과 전송할 명령을 분리한다. 초안의 서버 기준 revision/hash를 유지하며 연속 편집은 초안만 합친다. 명령을 고정하면 opId·내용·기대 revision을 재시작 후에도 바꾸지 않는다. aggregate 하나에 고정 명령은1개다.

명령 고정 후의 추가 편집은 별도 초안에 남는다. 자기 명령의 수신 결과가 돌아오면 해당 명령만 완료하고 후속 초안은 보존한다. 서버가 자기 수락 결과와 같을 때만 다음 명령을 만들며, 다른 기기의 변경이 끼면 충돌로 남긴다.

### 3. 수신·재개·충돌

수신은 서버 기준 사본·명령 완료·cursor를 같은 트랜잭션으로 기록한다. 두 건씩 페이지를 읽으며 중복은 건너뛰고 순서가 비면 전체 페이지를 취소한다. 재시작 후 저장된 명령을 읽거나 이미 서버가 수락한 결과를 다시 수신해 이어간다.

동시에 수정된 노트/보드는 기준·내 수정·서버 사본을 보존한다. 서버의 제3수정이 와도 최초 비교 기준을 지우지 않는다. 충돌한 aggregate의 자동 전송은 멈추고 관련 없는 항목의 전송은 계속한다. generation 변경·잘못된 계정은 대기 중인 편집을 지우지 않고 거절한다.

## 신규28개 시험의 범위

| 구성 | 검증 |
|---|---|
| 표본17/41/73별6개 =18개 | DB18 레코드/이미지 분리·scope, 명령 불변/초안 합치기/응답 유실 뒤 재시작, 서로 다른 항목 수렴, 충돌 기준/독립 항목 진행, generation/계정 거절, 페이지 중복/빈 순서 rollback |

| 경계5개 | tick 응답 유실, 자기 명령 수락 뒤 원격 변경, 명령 수락 전 원격 변경, 고정 전 초안 합치기, scope가 다른 import 거절 |

## 남은 범위와 다음 구현

1. **항목 수정과 셀 구조 버전 분리, 여러 셀 이동의 원자성**을 다음 구현 단위로 진행한다. 현재는 하나의 행 wrapper/aggregate 단위 CAS다.
2. 문서 본문과 링크를 함께 바꾸는 복합 명령 및 전체 참조 검증은 아직 없다. 노트/보드 시험은 문서 JSON 변경이며 링크 변경을 함께 수락한 시험이 아니다.
3. 복원 manifest/자산과 generation 전환 통합, cursor 만료/재조정·멱등 키 보존 하한, 충돌 해결 명령/UI가 남아 있다.
4. 현재 스케줄러는 사용자가 호출하는 결정적 `tick`이다. 실제 네트워크·타이머/백오프·sleep/resume·기기 세션·클라우드 권한은 아직 제공하지 않는다. importer/queue는 가상 시험용 신뢰된 입력을 사용한다.
5. 실제 두 프로세스의 병렬 제출·서버 종료/디스크 부족·Windows/macOS와 클라우드 검증은 별도다. 이번 SIGKILL은 클라이언트 파일 대기의 내구성 시험이다.

전체 PoC 첫 묶음은 진행 중이다. P01~P22의 전체 환경 상태는 계속 NOT_RUN이며 로컬 모형 결과를 실제 Auth/Postgres/Storage·실기 통과로 올리지 않는다.
