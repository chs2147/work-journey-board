# 96. G 운영 준비 — 계정별 용량 한도·관리자·개인 운영 방안(2026-11-17 추천안 확정)

2026-11-17 · `v2-design` · 로드맵: 온라인 UX 통합(95) 완료 → **G 운영 준비** → F 다국어(보류)

사용자 요구(2026-11-17): Supabase 무료 한도와 이미지 저장 제한을 고려한 **계정별 용량 한도(제한·해제) 정책**, **관리자 = 사용자 본인 이메일 고정**, 개인용으로 운영할 수 있는 현실적인 운영 방안 — 설계와 구현.

## 1. 기준 — Supabase 무료 플랜(2026-11 공식 문서)

| 항목 | 무료 한도 | 이 앱에서 쓰는 곳 |
|---|---|---|
| DB 크기 | 프로젝트당 500MB(요금 기준, 디스크 2GB — 95%면 읽기 전용) · 무료 프로젝트 2개 | 기록(업무·메모 문서 JSON)·동기화 기록·게시본 |
| 파일 저장 | 1GB | 메모 그림(Storage, 비공개) |
| 내보내기(egress) | 월 5GB(+캐시 5GB), DB·Auth·Storage 합산 | 그림 받기(이 기기 캐시라 기기마다 한 번), 동기화 |
| 일시 정지 | 1주일 활동이 적으면 정지(데이터는 남음) | 개발 프로젝트는 KeepAlive 적용(RESUME) |

**지금 서버 제한(개발 프로젝트)**: 공간마다 그림 합계 200MB(`wjb_gateway.workspace.quota_bytes`)·그림 2,000개·개당 10MB, 복제 기록 2만 행. **계정 단위 한도는 없다** — 한 계정이 공간을 여러 개 만들면 무료 1GB를 혼자 다 쓸 수 있다.

## 2. 정책(추천안)

### 2-1. 두 겹 한도

1. **프로젝트 안전선(모두에게, 관리자 포함)** — 무료 한도를 넘기지 않게: 그림 합계 **800MB**(1GB의 80%) · DB **400MB**(500MB의 80%). 넘으면 **새 그림·새 공간·복제를 모두 거절**(지우기·읽기·글 고치기는 그대로). 관리자에게만 경고.
2. **계정 한도(계정마다)** — 기본값(초대한 계정):

| 한도 | 기본 | 관리자 |
|---|---|---|
| 그림 합계 | **100MB** | 무제한(안전선만) |
| 온라인 공간 수 | **3개** | 무제한 |
| 기록 데이터(DB) | **30MB** | 무제한 |

- 관리자는 계정마다 **값 바꾸기 / 무제한 / 정지(읽기만)** 를 정한다. "해제" = 무제한(안전선은 남음).
- 기록 30MB ≈ 텍스트 업무 기록 수만 건(실측 가상 1년치 일지 기록 약 2MB) — 그림이 주로 한도를 쓴다.

### 2-2. 넘었을 때

| 동작 | 계정 한도 넘음 | 안전선 넘음 |
|---|---|---|
| 새 그림 올리기 | 거절 — "그림 용량 한도(100MB)를 넘었습니다" | 거절 |
| 새 온라인 공간·복제 | 거절(공간 수·예상 용량 미리 계산) | 거절 |
| 글 고치기·동기화 | **이 기기에는 저장**, 서버 보내기는 기록 한도 안에서만 — 넘으면 대기열에 남고 알약 "용량 한도 · 대기 N건" | 같음 |
| 읽기·받기·지우기 | 그대로(지우면 한도가 다시 생김) | 그대로 |

### 2-3. 관리자

- **관리자 = 사용자 본인 이메일 하나로 고정.** 이메일은 공개 저장소 코드에 넣지 않고 **서버 설정에만** 둔다(적용 도구가 `WJB_ADMIN_EMAIL` 환경변수로 받아 서버 표에 그 계정 ID를 기록). 앱은 서버가 "이 계정은 관리자"라고 답할 때만 관리 화면을 보인다 — 화면이 아니라 **서버 함수가 매번 확인**.
- 관리 기능(서버 함수 하나, 앱 화면과 명령 도구가 같은 것을 부름):
  - 전체 사용량(안전선 대비 그림·DB), 계정 목록(가린 이메일·공간 수·그림·기록·한도·마지막 활동)
  - 계정 한도 바꾸기 / 무제한 / 정지 / 정지 풀기
  - 초대(지금 `dev-signup-admin.mjs --invite`와 같은 일)
- 화면: **설정 › 계정** 아래 **관리** 카드(관리자만). 공용 Card·Row(95 계정 화면과 같은 모양).

### 2-4. 사용자에게 보이는 것

- 설정 › 계정 **사용량** 행: `그림 12MB / 100MB · 공간 1 / 3 · 기록 0.4MB / 30MB` — 80% 넘으면 배지 **한도 임박**, 넘으면 **한도 초과**(설명 글 없이 배지, 95 규칙).
- 거절될 때만 알림 문구(무엇을 넘었는지 + 지우면 다시 쓸 수 있음).

## 3. 개인 운영 방안(현실적인 최소 루틴)

| 무엇 | 방법 | 주기 |
|---|---|---|
| 프로젝트 | **개발**(시험·Preview) / **운영**(실제 사용) 2개 — 무료 2개 안. 운영에는 시험 데이터 없음 | 고정 |
| 일시 정지 방지 | KeepAlive(가벼운 요청, 개발과 같은 방식)를 운영에도 | 매일 |
| 사용량 확인 | 앱 관리 카드(안전선 대비) + Supabase 대시보드 Usage(egress) | 월 1회·경고 뜰 때 |
| 백업 | 무료 플랜은 자동 백업 내려받기가 없음 → **관리자 내보내기 도구**(기록 = 공간별 게시본·동기화 기록 JSON, 그림 = 원본 바이트) — 각 기기 이 기기 일지도 사본 역할 | 월 1회 |
| 가입 | 초대 전용(94), 필요할 때만 대시보드 스위치 | 필요 시 |
| 키·비밀 | 관리 토큰·서비스 키는 이 저장소·앱에 두지 않음, 새 키 형식(`sb_secret_`)으로 옮기기(G3) | 2027 초 전 |
| 장애 | 앱 알약이 "연결 끊김"이면 대시보드 Status·일시 정지 여부 확인 → 이 기기 일지로 계속 쓰고 복구 후 자동 보내기 | 생길 때 |
