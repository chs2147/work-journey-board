# 81. C단계 — 앱에서 온라인 사본 만들기 (설계, 승인 대기)

2026-11-15 · `v2-design` · 사용자 결정 D3 = 용량 확장(추천안) · 앞 단계 [79](79-preview-dev-connection.md)(B단계 실기 완료)

## 1. 왜 설계부터인가 — 지금 한도로는 실제 일지가 안 올라간다

| 한도(현재 서버·gateway) | 값 | 실제 일지 |
|---|---|---|
| 공간 1개 = 요청 1번 | 최대 1MiB, 기록 행 2,048개 | 가상 1년치 일지(`?sample=year`)만 해도 업무 항목 **4,406개**(+주간 메모 52·업무 6) |
| 이미지 | 8개, 개당 64KiB(gateway가 메모리에 받아 확인) | 이미지 수십 장·수백 MB |
| 위치 | 001·004·007 SQL 함수·테이블 제약(`bytes BETWEEN 1 AND 65536`), gateway 본문 한도, 이관 저널 | 이미지 한도만 고치면 끝나지 않음 |

→ 서버 이관 계약을 **v2(나눠 보내기)** 로 바꾸고, 앱(Preview)에 원본 읽기·이관 엔진·화면을 붙인다.

## 2. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| **C-1 서버 계약 v2** | 전진 SQL `010`(기존 001·004·007은 고치지 않음, 함수 교체 + 자산 크기 제약 확장 + 페이지 보관 테이블): ① 기록을 **페이지**로 — 작업 시작 → 페이지 올리기(페이지당 ≤1,000행·≤900KiB, 순번·페이지 해시) → 받은 페이지 목록 조회(재개) → 전체 확인(원본/온라인 manifest 해시·총 행·페이지 수) → 게시 ② 이미지 = gateway 예약(해시·크기) → **Storage 서명 업로드 주소**(같은 개발 프로젝트, 2분) → 앱이 Storage에 직접 올림 → gateway가 받아 SHA-256·크기 재확인 → 정산. 취소 울타리·삭제/부재 확인·할당량 반환은 지금 규칙 그대로 | 로컬 PostgreSQL + 로컬 Storage 대체 서버 시험, 기존 회귀 유지 |
| **C-2 원본 읽기(6-C)** | Preview Rust: 사용자가 고른 로컬 일지 폴더의 일지를 **읽기만** 해서 Preview 자기 폴더에 임시 사본(정식판이 쓰는 중이면 거절, 원본 폴더에 아무것도 만들지 않음 — DEV 복제와 같은 규칙). 이후 그 사본만 읽음 | Rust 시험(원본 파일·목록 불변) |
| **C-3 이관 엔진(앱)** | `poc/v2-migration`의 DB18/19/20 매핑·manifest를 `src/`(Preview 전용)로 옮김 → 사본을 sql.js로 열어 행·이미지 추출 → 페이지 생성. 이관 저널(재개·취소, ID·해시·크기·상태만, 이미지 본문 없음)은 Rust가 Preview 프로젝트 폴더에 원자적 파일로 | 단위·통합 시험(응답 유실·중단·재시작) |
| **C-4 화면(A안 일부)** | Preview 계정 카드 아래 [로컬 일지에서 온라인 공간 만들기] → 원본 폴더 고르기 → 검토(업무·기록·이미지 수·용량, 전송 동의 기본 해제) → 진행(단계·바이트) → 잠시 중단·이어서·취소(확인 → 정리 대기) → 완료(서버 확인). 공간 **열기는 D단계** | 브라우저 모드 E2E(가짜 서버) |
| **C-5 실서버 검증** | 가상 1년치 일지(+가상 이미지)로 개발 서버 이관·중단 후 재개·취소·잔여 0, 원본 해시 불변 | 증거 JSON |

## 3. 개발 단계 한도(제안)

공간당 기록 200,000행 · 페이지 1,000행 · 이미지 2,000개 · 이미지당 10MB · 공간 합계 200MB(Supabase Free 저장 1GB 안). 운영 한도는 운영 준비 때 다시 정한다.

D3 “분할 전송”의 구현 방식: **기록은 페이지로 나눠 보내고, 이미지는 gateway를 거치지 않고 Storage에 직접**(개당 10MB 이하라 이미지를 다시 조각낼 필요 없음, gateway 메모리 한도 회피). 확인은 서버가 한다는 점은 같다.

## 4. 개발 서버에 바꾸는 것(승인 필요)

1. 전진 SQL `010` 개발 DB 적용(검토 manifest·해시 고정, 001·004·007 다시 적용 안 함, 빈 상태 되돌리기 SQL `011` 함께)
2. 개발용 영구 private bucket 1개(`wjb-v2-dev-assets`, 파일 10MB 한도, 이미지 형식만) — 지금은 시험마다 만들고 지움
3. gateway Edge Function 재배포(페이지·서명 업로드 경로)

운영 프로젝트·정식판·DEV·원본 로컬 일지는 바꾸지 않는다. 이미지 본문은 온라인 DB·저널에 넣지 않는다(CLAUDE.md 로컬 영구 유지·이중 저장 금지).

## 5. 진행 방식

C-1 → C-2·C-3 → C-4 → C-5 순서, 단계마다 커밋. 개발 서버 적용(4절)은 C-1 로컬 시험이 끝난 뒤 한 번에 진행하고 결과를 보고한다. 여러 세션에 걸친다.
