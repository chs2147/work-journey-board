# 14. G0 설계 결정표 — PoC 계획 잠금용

2026-11-08 (KST) · 설계 선택과 구현/자원 생성 승인을 구분한다.

**변경:** 사용자 지시로 AWS 선택지를 제외했다. 무료/개인 요금 원칙은 [16문서](16-low-cost-review.md)가 우선한다. 이전 AWS 선택 질문은 철회하며 서비스 후보의 비용 적합성을 먼저 확인한다.

## 14.1 이미 확정된 기준

- 한국어·영어부터 시작한다.
- 개인의 여러 기기 사용을 우선하고 팀 공동 편집은 후속이다.
- 개인용/외부 서비스용 퍼블릭 클라우드가 가능한 모델이다.
- 소규모·아시아 범위로 출발한다. 특정 도시·제공자·실제 사용자 수는 아직 확정되지 않았다.
- 현재 브랜치의 범위는 상세 설계다. 코드 구현/서비스 생성/결제/실제 자료 전송은 수행하지 않는다.

## 14.2 핵심 선택과 현재 상태

| ID | 선택/검토안 | 현재 상태 | 선택이 바꾸는 설계 |
|---|---|---|---|
| G0-ENC | TLS+서버 저장 암호화로 시작 | 사용자 확정(2026-11-08) | 허가된 서버 본문 처리 가능, 1차 E2EE/기기 복호 키 전달 제외. 실제 저장 암호화 범위 검증 별도 |
| G0-PLATFORM | Desktop Win/macOS 먼저 | 사용자 확정(2026-11-08) | Web/Mobile 후속, 브라우저/모바일 전용 검증은 해당 출시 관문으로 분리 |
| G0-BACKEND | 신규 계정의 Supabase 통합 구성·Neon 합산 비용 비교 | 최종 미확정, Supabase 상세 설계 작업 기준 | 인증 어댑터·세션 회수·Sync API·스토리지/알림 운영 구성 |

신규 Supabase 계정 기준의 통합 구성을 상세 설계 작업 기준으로 두고 Neon 대안을 유지한다. Supabase 채택 시 Keep Alive 기본 요구가 추가됐다(20문서). 암호화/첫 플랫폼은 사용자 답변으로 확정됐으며, 백엔드 최종 선정·계정 복구안·실제 리전/플랜·예산은 계속 별도 확인이다. 이 선택은 사업자 설정 검증이나 PoC 구현/자원 생성 승인이 아니다.

## 14.3 이번 선택으로 자동 확정되지 않는 항목

| 항목 | 추천/다음 확인 |
|---|---|
| 실제 리전 | 후보의 아시아 내 실제 DB/Auth/blob/API/백업/로그·메일 경로 확인 후 선택 |
| 계정 복구 | OTP 기본 제안과 별개로 이메일 상실 시 복구·MFA/대체 수단 확정 |
| 보관/용량 | 16문서 기준 원격 총3개를 저비용 검토값으로 제안. tombstone/cursor·멱등 키 보존 하한을 연동해 결정 |
| 운영 규모·예산 |5명 시험 가정은 계산 기준이며 사용자 수/월 지출 상한이 아님 |
| 앱/DB/protocol 버전 | 구현 시 마이그레이션·호환성 계약에 따라 발급. 현재1.23.0/DB18은 유지 |
| 정식 출시·플랫폼 일정 | 검증 결과·지원 기능·운영 준비를 확인한 뒤 별도 결정 |

확정된 암호화/플랫폼을 계약에 반영하고, 실제 서비스 자원이 필요한 검증은 후보 조건과 비용 상한을 확인한 후 진행한다. 미정값을0원·무제한·영구 보존으로 처리하지 않는다.

## 14.4 설계 선택 이후의 작업 경계

1. 선택한 안으로 인증/동기화/복원 계약의 모순을 정리한다. 수정된 문서는 현재 설계 브랜치에서 검토한다.
2. 로컬 가상 데이터 PoC와 실제 클라우드 검증의 범위를 나눈다. 처음부터 현재 앱 전체를 V2로 바꾸지 않는다.
3. 구현할 작업·시험 데이터·환경·유료 자원/메일 발송·정리 책임을 구체화한다.
4. 해당 범위를 승인받은 뒤 PoC 구현을 시작한다. 설계 질문에 대한 답변만으로 실행 승인 상태를 변경하지 않는다.

현재 상태는 **설계 검토 중**이다. 선택 전제별 세부 공수와 실제 제공자 견적은 아직 산정/검증 전이다.

## 14.5 공개 조건 조사 이후의 검토 묶음

[23문서](23-supabase-free-tier-readiness.md)에서 공식 공개 기준의 무료 한도/리전/SMTP를 확인했다. [24문서](24-local-poc-review-package.md)는 사용자 확정인 TLS+서버 암호화·Desktop 우선과 추천인 제한적 계정 복구안, 실제 클라우드 없이 먼저 검증할 로컬 구현 단위를 묶는다. 두 설계 선택을 반영했으며 실제 계정/메일 조건·로컬 PoC 구현 범위 확정은 별도다.

## 14.6 로컬 묶음과 클라우드 관문 분리

24.9~24.10에 첫 로컬 구현의 코드 경계·가상 데이터 크기·명령/장애·반복·증거·완료 기준을 정리했다. 검토 대상은 이 묶음의 구현 착수이며, 공급자 최종 선정·실제 계정 복구 정책·SMTP/리전/예산은 클라우드 단계 전에 확정한다. 가상 주체/세션으로 로컬 권한 경계를 시험하는 것은 실제 인증/계정 복구 구현이나 채택 승인이 아니다. 구현 결과를 확인한 후 W06 이후의 클라우드 시험 범위를 따로 검토한다.
