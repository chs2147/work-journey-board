# 9. 기존 공간 전환·충돌·복원 화면 흐름 초안

2026-11-08 (KST) · 소규모·아시아 단일 리전 출발 · 개인 다기기 · 설계 검토용

앱 구현/실제 업로드가 아닌 화면·동작 설계다. 아래 화면은 배치 와이어프레임이며 최종 그래픽 디자인은 아니다. 새 계정 생성/백엔드 선정·암호화 정책과 독립적으로 원본 보존과 공간 격리를 먼저 정의한다.

## 9.1 온라인 사본 만들기 — 원본을 유지하는 온보딩

설정 > 공간 관리 > 해당 공간의 **‘온라인 사본 만들기’**에서 시작한다. 원본 로컬 공간은 영구 유지하며 새 ID/위치의 별도 공간을 만든다. [56 철칙](56-local-permanence-copy-migration.md)을 따른다. 계정 로그인 상태와 로컬 저장 상태를 별도로 표시한다. 공간 이름이 같은 다른 공간을 자동 연결하지 않는다.

```text
온라인 사본 만들기                               [닫기]
공간: 개인 업무                 계정: user@example.com

사용 방식
( ) 온라인 백업    복구본을 보관합니다. 자동 병합하지 않습니다.
(●) 기기 간 동기화 다른 기기에서도 같은 업무를 이어 씁니다.

저장 위치: 아시아 · [확정된 리전명]        [처리 정책]
업무·노트·메모·등록 이미지: 업로드
기기 폴더의 실제 파일·로그인 정보: 제외
예상 전송량: [사전 검사 결과]

원본 로컬 공간은 그대로 유지합니다.
별도의 온라인 공간을 복제 생성하고, 사본의 이미지는 Blob으로 옮깁니다.
                                  [취소] [사본 생성 내용 확인]
```

이메일은 설명용 가상값이다. 실제 화면에서는 현재 인증 계정만 표시하고 진단/로그에 그대로 기록하지 않는다. 리전명이 미정이거나 업로드 추정이 아직 끝나지 않았다면 실제 연결 버튼을 활성화하지 않는다. 자료 카드의 기기 경로와 사내 URL 등 메타데이터 처리 범위는 최종 계약과 동일하게 설명한다.

다음 확인 화면은 원본 파일 위치, 새 사본 위치, 업무/노트/보드/이미지 개수, 업로드 제외 항목, 연결 방식을 요약한다. ‘사본 생성하고 연결’이 실제 업로드 시작점이다. 원본 로컬 공간의 이미지/구조는 변경하지 않고 새 온라인 DB에는 이미지 참조만 둔다. 신규 설치나 로그인 완료만으로 이 단계를 자동 실행하지 않는다.

## 9.2 전환 상태와 실패 복구

| 단계 | 처리 | 사용자에게 보이는 상태 |
|---|---|---|
| 사전 검사 | 앱/스키마/문서 버전·쓰기 가능·자산/참조·현재 계정 검사 | 준비 중. 불가 항목은 이유와 복구 안내 |
| 편집 경계 정리 | 자식 창 flush·진행 작업 완료, 일관된 원본 사본 생성 | 저장 마무리 중. 실패하면 업로드 전 중단 |
| 온라인 사본 준비 | 새 ID/위치, 원본 보존, 이미지 추출/metadata 참조·manifest 생성 | 온라인 사본 준비 중 |
| 초기 전송 | 비공개 staging에 분할 업로드·재개 | 문서/이미지 진행량, 남은 대기량 |
| 검증 | 개수·정합성·hash·버전 확인 | 검증 중. 아직 다른 기기에 공개되지 않음 |
| 연결 확정 | generation 공개·binding/cursor 확정 | 연결됨. 이후 편집분 전송 |

V2 사본 준비가 끝나기 전에는 편집을 잠깐 정리하고, 준비 후에는 그 사본의 편집을 snapshot 이후 outbox에 남긴다. V1 원본에서 계속 수정한 내용은 독립 자료다. 이를 자동으로 탐지/병합한다고 안내하지 않는다.

- 연결 중 닫기: 현재 작업 중단 여부와 로컬 보존 상태를 안내한다. 앱 종료가 staging 성공으로 오인되지 않도록 한다.
- 전송 중 네트워크 끊김: 검증된 청크만 재사용하고, 이전 토큰/계정으로 재개하지 않는다.
- 다른 계정/공간으로 전환: 전송 작업의 account/workspace/generation을 확인하고 늦은 응답을 버린다. 새 공간에 적용하지 않는다.
- 취소: 원본과 V2 로컬 사본 보존, 원격 미완료 staging 정리. 현재 온라인 공간이 이미 있으면 그것을 삭제하지 않는다.
- 서버 검증 실패: 연결 완료 표시 금지. 실패한 문서/자산을 상세 목록으로 보여주고 재검증한다.

## 9.3 기존 온라인 공간과 내용 있는 로컬 공간

1차에는 자동 합치기를 제공하지 않는 방향을 추천한다.

```text
이 온라인 공간을 가져올까요?
온라인 공간: 개인 업무            현재 기기: 노트북

(●) 새 로컬 공간으로 내려받기
( ) 현재 로컬 공간과 합치기        [후속 지원 예정]

현재 로컬 공간의 파일을 덮어쓰지 않습니다.
                                      [취소] [가져오기]
```

지원 예정 선택지는 실제 제품에서는 비활성 라디오보다 안내/도움말로 표현하는 편이 낫다. 위 그림은 설계 차이를 설명하기 위한 것이다. 공간 복제 시에는 새 공간 정체성과 참조 ID 매핑을 처리하고 기존 sync binding/opId를 복제하지 않는다.

## 9.4 충돌 화면

```text
충돌 검토                                         [닫기]
공간: 개인 업무             문서: 정산 배치 검토 노트
이 기기: 노트북             서버 수정: 데스크톱

[이 기기 내용]              [서버에 저장된 내용]
제목·본문·수정 시각         제목·본문·수정 시각
이미지/연결 차이            이미지/연결 차이

[둘 다 보존]      [이 기기 내용 사용]      [서버 내용 사용]
```

**기본 추천 액션은 ‘둘 다 보존’.** 충돌 보류 중에도 해당 사본을 읽고 복사/내보낼 수 있다. 서버 수정 시각은 클라이언트 시계보다 우선순위를 정하는 기준이 아니라 비교 정보다.

- 선택 직전 base/server revision을 다시 확인한다. 새 수정이 들어왔으면 재비교하며 이전에 본 내용으로 덮어쓰지 않는다.
- 이 기기/서버 내용 선택 시에도 선택되지 않은 사본을 복구 가능한 충돌 보존본으로 남긴다. 보관 기한은 정책 확정 후 표시한다.
- ‘둘 다 보존’은 원래 문서와 새 문서로 구분한다. 새 문서 ID·제목 접미사·원본 자산 참조/복제·링크 정책을 함께 처리한다. 캔버스 내용만 복사하고 연결 테이블을 잃지 않는다.
- 삭제와 수정의 충돌은 ‘삭제 요청’과 ‘수정된 사본’을 비교하고, 기본 추천은 수정 사본 복구 보존이다. 삭제를 취소해 다른 기기의 명시적 삭제 의도를 조용히 무시하지 않는다.
- 보드 충돌은 객체 수·내용/이미지·연결 차이를 보여준다. 노드 순서만 비교해 문서가 동일하다고 판단하지 않는다.
- 같은 이름의 업무/태그, 반복 항목·부모 삭제 등의 구조 충돌은 문서 UI로 해결하지 않는다. 도메인 검증 결과에 따른 별도 액션을 제공한다.

## 9.5 복원 화면과 영향 범위

```text
백업에서 복원                                     [닫기]
공간: 개인 업무
백업: [시각]    앱/문서 버전: [정보]    이미지: [개수/크기]

(●) 새 로컬 공간으로 복원           권장
( ) 현재 온라인 공간 전체를 이 시점으로 복원

현재 온라인 상태와 이 기기의 미전송 자료를 먼저 보존합니다.
[영향 상세: 연결 기기 · 미전송 변경 · 변경될 자료]
                                     [취소] [복원 계획 확인]
```

새 로컬 공간 복원은 기존 온라인 공간을 바꾸지 않는다. 내려받기·hash·참조·호환성 검증 후에만 활성화하고, 새 공간이 자동으로 원래 cloudWorkspaceId를 이어받지 않게 한다.

전체 온라인 복원은 별도 최종 확인을 요구한다. 서버 현재 상태의 보존본을 만들고 새 generation을 공개한다. 다른 기기가 새 generation을 받기 전 미전송한 자료는 별도 재조정 대상으로 남긴다. 다른 기기의 대기량을 서버가 모두 알 수 없으면 ‘대기 없음’으로 단정하지 않고 최근 접속/미확인 기기를 표시한다.

실패 시: 원래 온라인 generation 유지 또는 커밋 결과 조회로 완료 여부 확인. 네트워크 timeout만으로 복원 요청을 다시 실행하지 않고 operation ID로 같은 결과를 확인한다.

## 9.6 V1로 돌아가기와 서비스 연결 해제

V1 원본 복귀는 V2의 새 기능/서버 변경을 자동 역변환하는 기능이 아니다. 마지막 V2 사본·표준 내보내기와 미전송 변경을 보존하고 V1 원본은 별개로 열도록 안내한다.

이 기기 연결 해제 시 [마지막 동기화 후 해제] 또는 [미전송 내용이 포함된 독립 사본 보존 후 해제]를 제공한다. 서버·다른 기기 자료는 유지한다. 모든 기기의 원격 공간 삭제는 다른 메뉴/확인 절차로 둔다.

## 9.7 화면 검토·검증 관문

- 기존 V1 fixture의 업무/항목/노트/보드/참조/이미지 개수와 hash를 전환 전후 비교.
- 문서 하나/이미지 하나가 빠진 staging은 공개되지 않음. 재개·취소·앱 종료·로그아웃 후 계정 격리 유지.
- 충돌 선택 중 제3의 수정, 삭제/부모 삭제·자산 GC와 복원본 참조, 구 generation 요청의 격리.
- 데이터가 많을 때 진행 UI가 멈추지 않음. 오류 후 원본/미전송 사본으로 복구 가능.
- 한국어·영어 긴 문구, 키보드 포커스·닫기·최종 확인, 시간대별 동일 백업 시각 표현.

실행 테스트는 아직 하지 않았다. 위 내용은 검증 요구와 화면 동작 계약 초안이다.
