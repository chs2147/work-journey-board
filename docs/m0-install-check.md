## 0. 준비물 (어디서 받나)
- 다운로드 위치: **GitHub 저장소 → Releases → `M0 설치 검증 m0-v0.0.1`(사전 릴리스)**
  `https://github.com/chs2147/work-journey-board/releases`
- 받을 파일: `WJB-M0-Probe_setup.exe` (막히면 `WJB-M0-Probe_setup.zip`)
- 저장소가 **공개**라 로그인 없이 받을 수 있습니다. github.com 접속 자체가 막혀 있으면 1-3의 대체 경로를 쓰세요.

## 1. 설치 파일 받기 — 체크: "설치 파일 전달 경로"
1. 회사 PC 브라우저(Chrome)로 위 Releases 페이지 열기 → `WJB-M0-Probe_setup.exe` 다운로드.
2. 다운로드가 막히면 `.zip`을 받아 압축 해제.
3. 둘 다 막히면 기록만 하고, 회사 보안 정책이 허용하는 경로로 옮깁니다(예: 개인 PC에서 받아 사내 승인 저장 매체·사내 파일 공유). **정책상 허용되지 않는 경로는 쓰지 마세요** — "전달 경로 없음"도 중요한 판정 결과입니다.
4. (선택) 파일이 변조되지 않았는지 확인: 명령 프롬프트에서
   ```
   certutil -hashfile WJB-M0-Probe_setup.exe SHA256
   ```
   → Releases의 `SHA256SUMS.txt` 값과 같으면 정상.

## 2. (선택) 설치 전 WebView2 확인
명령 프롬프트에서 아래 중 하나라도 `pv` 값(버전)이 나오면 WebView2가 있는 것입니다.
```
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}" /v pv
reg query "HKCU\Software\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}" /v pv
```
(건너뛰어도 됩니다. 앱이 실행되면 자동 점검에서 버전이 표시됩니다.)

## 3. 설치 — 체크: "관리자 권한", "SmartScreen", "사내 백신"
1. `WJB-M0-Probe_setup.exe` 더블클릭.
2. 화면을 보며 기록:
   - **SmartScreen**("Windows의 PC 보호") 창이 뜨면 → `추가 정보` → `실행` 버튼이 있는지. 있으면 눌러 진행, 없으면 "차단".
   - **관리자 암호/UAC(예/아니오) 창**이 뜨는지. 뜨면 "아니오"로 취소하고 기록(이 설치 파일은 관리자 권한이 필요 없게 만들어졌습니다).
   - **사내 백신** 알림·격리 여부.
3. 설치 마법사를 끝까지 진행 → 마지막에 "실행" 체크 후 마침.

> 설치 위치는 `C:\Users\<사용자>\AppData\Local\WJB M0 Probe\`(현재 사용자 전용)입니다.

## 4. 앱 화면에서 점검
### 4-1. 자동 점검 (열자마자)
| 항목 | 기대 결과 |
|---|---|
| 앱 실행 | ✅ `WJB M0 Probe v0.0.1 · windows/x86_64` |
| 설치 위치(현재 사용자 전용) | ✅ 경로에 `\AppData\Local\` 포함 |
| WebView2 런타임 | ✅ 버전 숫자(예 `141.0.xxxx`) |
| OneDrive 환경 변수 | 없으면 ✅ / 있으면 ⚠️ (회사 PC는 대개 ⚠️ — 정상, 기록용) |
| "문서" 폴더 OneDrive 리디렉션 | ✅ 아님 / ⚠️ OneDrive로 동기화됨 → **실제 앱에서 문서 폴더를 쓰면 안 된다는 근거** |
| 실행 기록 | ✅ `이번이 1번째 실행` |

> 앱 창이 아예 안 뜨거나 WebView2 오류 창이 뜨면 → 그 화면을 사진으로 남기고 5절 판정 "대안 전환" 후보.

### 4-2. 저장 폴더 테스트 — [폴더 선택 후 테스트]를 **2~3번**
1. **새 폴더** `C:\Users\<사용자>\WorkJourney` (탐색기에서 만든 뒤 선택) — 실제 앱 추천 위치.
2. **한글·공백 폴더** 예: `C:\Users\<사용자>\업무 일지`.
3. (가능하면) **문서 폴더** — OneDrive 경고가 제대로 뜨는지 확인용.

각 테스트에서 아래가 모두 ✅이면 통과:
| 항목 | 의미 |
|---|---|
| 파일 쓰기·읽기 | 고른 폴더에 파일 저장 가능 |
| backups 하위 폴더 생성 | 자동 백업 폴더 생성 가능 |
| SQLite 열기(절대 경로) | **tauri-plugin-sql로 사용자가 고른 폴더의 DB를 열 수 있음**(overview 12-4 #2) |
| journal_mode 유지 | `delete` — 데이터 파일 1개 원칙 유지 가능(data-spec 3-1) |
| SQLite 쓰기·읽기(한글) | 한글 저장 정상 |
| VACUUM INTO 백업 | 열린 상태에서 백업 사본 생성 가능(data-spec 7-2) |

> 결과 보고서에는 앱이 마지막으로 테스트한 폴더 결과만 담깁니다. **추천 위치(1번) 테스트를 마지막에** 한 번 더 해 두세요.

### 4-3. 수동 확인 입력 → [결과 복사]
- 화면 3번 칸에 1~3절에서 본 내용을 고르고, 막힌 점은 메모에 적습니다.
- [결과 복사] → 메모장에 붙여넣어 `M0결과.txt`로 저장(클립보드 정상 여부도 같이 확인됨).

## 5. 재부팅 후 재실행 — 체크: "재부팅 후 재실행"
1. PC 재부팅(또는 다음 출근 시) → 시작 메뉴에서 **WJB M0 Probe** 실행.
2. 자동 점검의 "실행 기록"이 `이번이 2번째 실행 · 직전 실행 …`이면 정상 → 화면의 재부팅 체크박스 체크.
3. 저장 폴더 테스트(추천 위치) 한 번 더 → [결과 복사] → `M0결과.txt`를 갱신.

## 6. 결과 전달
- `M0결과.txt` 내용을 Claude 세션에 붙여넣어 주세요. 회사에서 붙여넣기가 어렵다면 집에서 옮겨 적거나 화면 사진으로도 충분합니다.
- 보고서에는 업무 내용이 없고 **경로(윈도우 사용자 이름 포함)·버전·판정**만 있습니다. 사용자 이름을 가리고 싶으면 `<사용자>`로 바꿔 붙여도 됩니다.
- 붙여주시면: ◆G1 판정 → overview.md 12-4의 1~3 확정 → `tauri.conf.json` WebView2 설치 모드·저장 방식 확정 → I-M1 착수 순서로 진행합니다.

- 실행 기록 폴더: `%LOCALAPPDATA%\com.chs2147.workjourneyboard.m0` 삭제(선택)

## 8. ◆G1 판정 기준
| 결과 | 판정 | 다음 |
|---|---|---|
| 관리자 권한 없이 설치 + 실행 + WebView2 있음 + 폴더 테스트 전부 ✅ (SmartScreen은 "추가 정보 → 실행"으로 통과해도 됨) | **GO (Tauri 확정)** | data-spec 그대로(SQLite 파일), WebView2 설치 모드 `skip` 확정 |
| SmartScreen 차단·백신 격리 등으로 실행 불가, 단 IT 허용 목록 등록 가능 | **조건부 GO** | 9절 문구로 IT 요청, 등록 전에도 개발은 진행 |
| 설치·실행 불가 + 허용 목록 등록도 불가 | **대안 전환** | Chrome 전용(sql.js + File System Access, data-spec 8-3) 구조로 스택 갱신 |
| SQLite 열기(절대 경로)만 실패, 나머지 정상 | GO + 저장 계층 변경 | tauri-plugin-sql 대신 얇은 rusqlite 커맨드로 교체(overview 12-4 #2) |
| journal_mode가 `delete`로 유지 안 됨 | GO + 연결 옵션 보완 | 연결 시마다 `PRAGMA journal_mode=DELETE` 적용하도록 드라이버에 반영 |

