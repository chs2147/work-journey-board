# 백업과 복원

**언제 쓰나요** — 기록을 안전하게 보관하고, 앱·DB 버전을 확인해 복원하거나 오래된 자동 백업을 정리할 때.

1. 앱이 시작·종료 시와 내용이 바뀐 2시간 간격으로 **일일 백업**, 그 달 첫 백업 때 **월간 백업**을 만듭니다. 업데이트·구조 변경·가져오기 전에도 별도 사본을 남깁니다.
2. 설정 › **데이터·백업**에서 [지금 백업], 마지막 백업의 **생성 앱 버전·DB 구조 번호**, 폴더 사용량을 확인합니다. 새 파일명에도 두 버전이 들어 있어 파일 하나만 옮겨도 식별할 수 있습니다.
3. [**백업 이력·복원**]에서 날짜·종류·앱·DB 구조·크기를 확인하고 사본을 선택합니다. 선택하면 실제 DB를 검사합니다. 더 최신 구조·손상·파일명/실제 구조 불일치는 복원을 막고, 구형 구조는 복원 후 갱신할 번호를 알려 줍니다. 과거 백업의 앱 버전은 **기록 없음**으로 표시합니다.
4. [**정책 변경**]에서 일일 보관을 **최근 N일 또는 최신 N개**, 월간 보관 개수, 선택적인 **폴더 용량 목표**로 정합니다. 신규 공간 추천은 최근 30일·월간 12개·용량 목표 끔입니다. 기존 공간의 개수 정책은 그대로 유지합니다.
5. [**정리 미리보기**]로 후보·이유·확보 예상 용량을 확인한 뒤 적용합니다. 용량 기준은 기간 안의 자동 사본도 정리할 수 있습니다. 삭제한 파일은 되돌릴 수 없고, 확인 중 목록이 바뀌면 다시 확인합니다.

**보호되는 사본**
- 수동·구조 변경 전·업데이트 전·가져오기 전·복원 전 사본과 최신 정상 일일 사본은 자동 정리하지 않습니다. 보호/기타 파일 때문에 용량 목표를 초과할 수 있습니다. 보호 사본은 [백업 폴더 열기]로 확인해 직접 관리합니다.
- 복원 전에 현재 일지를 별도 사본으로 보존하고, 정상 복원에서는 현재 보관 정책을 유지합니다. 파손 복원으로 정책을 읽을 수 없으면 정책 검토 전까지 자동 삭제를 보류합니다. 새 백업 생성은 계속됩니다.
- 보조 백업 위치는 공간별 별도 폴더에 최근 3개를 유지합니다. 주 폴더 용량 목표에 합산하지 않습니다.

**팁**
- 일지 파일이 깨졌다고 나오면 시작 화면의 같은 백업 목록에서 복원할 수 있습니다.
- 다른 PC로 옮길 때는 저장 폴더째(`work-journey.db` + `backups`) 복사하면 됩니다. 앱 버전 차이만으로 복원 가능 여부를 판단하지 말고 실제 DB 구조 검사 결과를 확인하세요.
