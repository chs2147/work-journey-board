### 0-2. 왜 가져오기를 먼저 하나
- 시각화의 완료 기준이 "4주 이상 실데이터에서 의미 있게 읽힘"(project-plan I-M3)인데, ◆G2를 막 시작한 일지에는 기록이 몇 주뿐이다. **기존 일지를 가져오면 첫날부터 몇 달치 흐름**을 볼 수 있고, 타임라인·히트맵을 실제 분량으로 검증할 수 있다.
- 가져오기는 저장소 쓰기(스키마·백업·덮어쓰기)를 건드리는 일이라, 화면만 그리는 시각화보다 먼저 안정화해 두는 편이 안전하다.

### 0-3. 제외
- 앱이 **AI를 직접 부르는 일** — 사내 AI 도구에는 사용자가 직접 캡처와 양식을 넣는다(앱은 양식·지시문·절차만 제공, 외부 통신 0 — CLAUDE.md 4-1). OneNote와의 자동 연동도 하지 않는다.
- 캡처 이미지를 앱이 읽는 기능(OCR) — 사내 AI 도구가 맡는다.
- 주간 요약 수정본·AI본, 중요 표시·매주 반복 규칙의 가져오기.

### 0-4. 완료 기준
- [ ] 가상 기존 일지(가상 OneNote 캡처 대신 **AI가 채운 모양의 가상 양식 엑셀** 6개월치 + 표 붙여넣기 글) 가져오기 → 보드·자동 집계·엑셀 내보내기·무기록 판정이 손으로 쓴 기록과 똑같이 동작(단위·E2E)
- [ ] 같은 파일을 두 번 가져와도(병합) 기록이 늘지 않는다 / 덮어쓰기·건너뛰기가 주 단위로 정확하다
- [ ] 가져오기 직전 자동 백업 + [이 가져오기 되돌리기]로 가져온 행이 빠지고 **덮어쓰기로 지운 기존 행이 되살아난다**
- [ ] viz-spec 체크 항목 전부 ✅, 클라우드 Playwright 스크린샷(라이트·다크)으로 차트 확인
- [ ] **회사 PC**: 실제 OneNote 주간 페이지 몇 주를 절차대로 가져와 4주 이상 흐름이 타임라인·히트맵에서 의미 있게 읽힘(캡처·파일·화면은 저장소·세션에 올리지 않고 결과·증상만 알림)
- [ ] 매일 기록 흐름(앱 열기 → 바로 타이핑, 2분 시나리오 E2E)이 그대로

## 2. M3-S1~S3 시각화 — 요점

스펙은 viz-spec이 정본이고, 구현하며 정할 점만 적는다.
- 데이터 계산(주 묶음·일수 집계·접기·"기타" 묶기)은 `src/domain/insights.ts` 순수 함수 + 단위 테스트. 차트는 `(data, size) → SVG` 컴포넌트(직접 SVG + d3-scale/d3-array, 차트 라이브러리 없음).
- 인사이트 진입은 **왼쪽 레일 아이콘**(important-repeat-spec M1 레일)과 `Alt+3`. 보드 상태(편집 중 칸·스크롤)는 그대로 두고 숨긴다(메모 [크게 보기]와 같은 방식).
- 실앱 CSP: SVG 속성으로만 그린다(인라인 `style` 문자열 금지 — 메모 편집기와 같은 이유). CSP E2E에 인사이트 화면을 더한다.
- 가져온 기록(M3-S0)도 손으로 쓴 기록과 구분 없이 그린다(6절 #9).

## 3. M3-S0 기존 일지 가져오기 — 상세

### 3-1. 기존 일지 상황 (2026-10-25 사용자 설명)
- OneNote **자유 양식**, **한 주 = 한 페이지**.
- 페이지 안 **표**에 요일별 진행 업무가 **여러 업무가 섞인 채** 정리되어 있다. 날짜·요일이 없는 칸(주간 요약 등)도 있다.
- → 앱이 OneNote를 직접 읽을 수 없고(외부 통신 0, 형식 자유), 표 구조도 주마다 조금씩 다르다. 그래서 **사내 AI 도구가 캡처 이미지를 읽어 앱의 양식 엑셀에 옮겨 적고**, 앱은 그 엑셀을 정확하게 받는 데 집중한다.

### 3-2. 전체 절차 (앱 안 가져오기 마법사 ① 단계에 그대로 보여 줌)
| 단계 | 누가·어디서 | 할 일 |
|---|---|---|
| 1 | 앱 | 설정 → [기존 일지 가져오기…] → **[양식 엑셀 받기]** — 이번 주 진행 중 업무가 미리 채워진 `WorkJourney_가져오기양식_<날짜>.xlsx` 저장(저장 대화상자) |
| 2 | 앱 | **[AI 지시문 복사]** — 사내 AI에 붙일 지시문(3-4절)이 클립보드로 |
| 3 | OneNote | 가져올 주간 페이지를 **한 주씩 캡처**(`Win+Shift+S`, 표 전체가 보이게. 길면 2장으로 나눠도 됨) |
| 4 | 사내 AI 도구 | 새 대화 → 양식 엑셀 + 캡처 이미지(1~4주 분량) 첨부 → 지시문 붙여넣기 → **그 주의 월요일 날짜**를 지시문 맨 위 빈칸에 적기(페이지에 날짜가 보이면 생략 가능) → 실행 |
| 5 | 사내 AI 도구 | 작성된 엑셀 파일 받기. **파일을 줄 수 없는 도구면** AI가 출력한 표(탭 구분)를 복사 |
| 6 | 앱 | 마법사 ② → 작성된 엑셀 고르기(또는 **[표 붙여넣기]**에 복사한 표 붙여넣기) |
| 7 | 앱 | ③ 미리보기 — 주별 처리(빈 주: 가져오기 / 기록이 있는 주: 병합·덮어쓰기·건너뛰기), 새 업무, 건너뛸 행·경고 확인 → ④ [가져오기] |
| 8 | 반복 | 다음 몇 주 분량으로 4~7 반복. 같은 양식 파일을 계속 써도 되고(이미 가져온 주는 병합 = 중복 없음), 양식을 새로 받아도 된다(새로 생긴 업무까지 미리 채워짐) |

- 1~4주씩 나눠 하는 이유: 한 번에 캡처가 많으면 AI가 요일·업무를 섞기 쉽다. 주마다 확인하며 가져오는 편이 정확하다.

### 3-3. 가져오기 양식 엑셀 (`export/importTemplate.ts`, ExcelJS — 받을 때마다 새로 만듦)
**시트 ① `안내`** — 절차(3-2절 4~5단계 요약), 열 규칙, 지시문 전문(AI가 파일 안에서도 읽도록), 양식 버전 `WJB-IMPORT-1`, 만든 날짜.

**시트 ② `업무`** — 업무 목록. **이번 주 진행 중 업무를 보드 순서로 미리 채움**.
| A `업무` | B `구분` | C `설명`(선택) |
|---|---|---|
| 차세대 정산 시스템 구축 | 기존 | |
| 협력사 보안 점검 | 기존 | |
| *(AI가 추가)* 레거시 데이터 이관 | 신규 | 2025년 상반기 진행 |
| 메모 | 예약 | 업무에 속하지 않는 그날의 일 → 주간 메모로 |

**시트 ③ `기록`** — 한 행 = 항목 하나. 머리줄만 있고 비어 있음(예시 행은 `안내` 시트에만 — 예시가 가져오기에 섞이지 않게).
| A `주 시작일` | B `날짜` | C `요일` | D `업무` | E `세부` | F `내용` |
|---|---|---|---|---|---|
| 2025-03-03 | | 화 | 차세대 정산 시스템 구축 | | 현행 분석 자료 정리 |
| 2025-03-03 | | 화 | 차세대 정산 시스템 구축 | 세부 | 배치 목록 30개 확인 |
| 2025-03-03 | 2025-03-06 | 목 | 메모 | | 부서 회의 참석 |

- 엑셀 편의: `업무` 열은 `업무` 시트 목록 드롭다운(데이터 유효성 — 목록 밖 이름도 허용), `요일`은 월~일 드롭다운, `세부`는 빈칸/`세부`, 날짜 열은 `yyyy-mm-dd`, 첫 행 고정·열 너비. 저장소에는 가상 업무만 채운 샘플 `docs/samples/import-template.xlsx`.
- 저장: 엑셀 내보내기와 같은 저장 대화상자·규칙(`.xlsx`만, backups 거부 — CLAUDE.md 4-3), 기본 위치 = 마지막 내보내기 폴더.

### 3-4. 사내 AI 지시문 (마법사 [AI 지시문 복사] · 양식 `안내` 시트 · 이 절이 정본)
```
[이 캡처의 주 시작일(월요일)]: ____-__-__   ← 캡처에 날짜가 보이면 비워 두어도 됩니다. 여러 주를 함께 넣으면 "캡처1: 2025-03-03, 캡처2: 2025-03-10"처럼 적습니다.

당신은 업무 일지 정리 도우미입니다. 첨부한 캡처 이미지는 OneNote에 한 주 = 한 페이지로 적은 업무 일지이고,
첨부한 엑셀 파일은 이 일지를 옮겨 적을 양식입니다. 캡처의 표에서 요일(또는 날짜)에 속한 업무 기록만 읽어
엑셀의 '기록' 시트에 한 행에 항목 하나씩 적고, 작성한 엑셀 파일을 돌려주세요.

[규칙]
1. 시트 이름·머리줄·열 순서를 바꾸지 않습니다. '기록' 시트 열: 주 시작일 | 날짜 | 요일 | 업무 | 세부 | 내용
2. 요일이나 날짜에 속하지 않는 칸(주간 요약, 다음 주 계획, 이슈 정리 등)은 옮기지 않습니다.
3. 주 시작일: 위에 적은 그 주의 월요일(YYYY-MM-DD). 날짜: 캡처에 그날의 날짜가 보이면 YYYY-MM-DD, 없으면 비웁니다.
   요일: 월·화·수·목·금·토·일 중 한 글자.
4. 업무: '업무' 시트 목록에 있는 업무면 그 이름을 글자 하나 바꾸지 않고 그대로 씁니다.
   목록에 없는 업무면 '업무' 시트 맨 아래에 새 행을 추가하고(구분 = 신규) 그 이름을 씁니다.
   비슷한 이름을 새로 만들지 말고, 같은 일이면 기존 업무에 맞춥니다.
5. 어느 업무에도 속하지 않는 그날의 일(회의 참석, 교육, 개인 일정 등)은 업무 = 메모.
6. 한 칸에 여러 업무가 섞여 있으면 업무별로 나눠 각각의 행으로 적습니다.
7. 내용: 캡처의 한 줄(글머리 하나) = 한 행. 들여쓴 하위 줄은 세부 = 세부로, 바로 위 항목 다음 행에 적습니다.
   캡처에 적힌 순서를 지키고, 요약·수정·추측하지 말고 글자 그대로 옮깁니다. 읽을 수 없는 글자는 [?]로 적습니다.
8. 엑셀 파일을 만들 수 없으면 '기록' 시트 내용을 머리줄 포함 탭으로 구분한 표로만 출력하고,
   새로 추가한 업무가 있으면 표 아래에 "신규 업무: 이름1, 이름2"로 적습니다.
```
- 지시문 안의 업무 목록은 양식 파일이 담고 있으므로 지시문에는 넣지 않는다(지시문은 늘 같은 글 — 클립보드 다리, output-spec 5절과 같은 성격).
- 실제 사내 AI로 회사 PC에서 시험해 보고 문구를 고친다(확인표 7-4절). 고친 문구는 이 절과 앱 문자열(`strings.ts`)을 함께 바꾼다.

### 3-5. 가져오기 마법사 (설정 → [기존 일지 가져오기…], 4단계)
```
① 준비                  ② 파일                   ③ 미리보기·주별 처리                                    ④ 결과
절차 8단계(3-2)         [작성된 엑셀 고르기…]     2025-03-03 ~ 2025-06-29 · 17주 · 항목 412(세부 61)       기록 386개를 가져왔습니다
[양식 엑셀 받기]        또는 [표 붙여넣기]        ┌ 주차        항목  지금 기록   처리 ─────────────┐     새 업무 4개(이번 주까지 진행 중)
[AI 지시문 복사]        (양식이 아니면 열 맞추기)  │ 2025-W10     24    —          가져오기          │     [가져온 첫 주로] [되돌리기]
                                                 │ 2026-W42     18    15         [병합 ▾]          │
                                                 │                               병합/덮어쓰기/건너뛰기│
                                                 └ [기록이 있는 주 모두: 병합 ▾] ─────────────────┘
                                                 업무: 기존 9 · 새로 만듦 4 [목록] · 종료된 업무에 연결 1
                                                 건너뜀 7 [목록] · 확인 필요 3 [목록]
```
- **② 받는 것**: 이 양식(머리줄로 알아봄 — AI가 숨은 정보를 지워도 머리줄 6개 이름만 맞으면 됨) / **표 붙여넣기**(AI가 파일을 못 줄 때, 탭·쉼표 구분, 머리줄 포함) / 그 밖의 엑셀·CSV(이 앱의 원장 시트는 자동, 나머지는 열 맞추기 — 날짜·업무·내용·세부 열 고르기). 파일은 **읽기만**(웹 표준 파일 선택, 새 Rust 명령 없음). CSV·붙여넣기 글은 UTF-8/CP949 자동 판별.
- **③ 주별 처리**(사용자 요구):
  | 그 주 상태(이 앱 일지) | 처리 | 기본값 |
  |---|---|---|
  | 기록 없음(항목·주간 메모 모두 없음) | **가져오기**(파일의 그 주 내용을 모두) | 고정 |
  | 기록 있음 | **병합** — 기존 기록을 두고 파일 항목을 각 칸 끝에 더함, 같은 날·업무·내용·깊이는 건너뜀 | ✅ 기본 |
  | | **덮어쓰기** — 그 주의 기존 업무 기록(모든 업무)을 지우고 파일 내용으로 바꿈. 지울 개수를 표에 보여 주고 [가져오기] 때 한 번 더 확인 | |
  | | **건너뛰기** — 그 주는 가져오지 않음 | |
  - "지금 기록" 열 = 그 주 이 앱의 항목 수(주간 메모가 있으면 `+메모`). 행을 펼치면 업무별 개수 비교.
  - 주간 메모(`메모` 업무 행): 병합 = 그 주 메모에 상자 하나 **추가**, 덮어쓰기 = 그 주 메모를 그 상자 하나로 **교체**(이미지 상자 포함 — 지울 상자 수 표시), 건너뛰기 = 그대로.
- **④ 결과**: 토스트 + 마법사 마지막 화면. 설정의 **가져오기 기록** 목록(언제·파일 이름·주 수·항목 수·[되돌리기])에 남는다.

### 3-6. 해석 규칙 (`domain/importer.ts`, 순수 함수 — 단위 테스트)
| 항목 | 규칙 |
|---|---|
| 날짜 | ① `날짜` 칸이 있으면 그것(엑셀 날짜 값, `2025-03-04`·`2025.03.04`·`2025/3/4`·`25.03.04`). ② 없으면 `주 시작일` + `요일`로 계산. ③ 둘 다 없으면 바로 위 행의 날짜(같은 주 시작일·요일일 때만)를 이어 씀 — 그래도 없으면 **건너뜀(날짜 없음)** |
| 주 시작일 | 월요일이 아니면 그 날짜가 속한 ISO 주의 월요일로 보정하고 **확인 필요**에 표시(AI가 일요일·날짜를 잘못 적은 경우). 주차 계산은 `domain/week.ts`만(CLAUDE.md 4-4) |
| 요일 ↔ 날짜 | `날짜`와 `요일`이 함께 있는데 맞지 않으면 날짜를 따르고 **확인 필요**에 표시. `날짜`가 `주 시작일`의 주 밖이면 확인 필요 |
| 업무 | 이름 정규화(앞뒤·연속 공백, 전각/반각, 대소문자) 후 **이 앱의 모든 업무**(진행 중·종료)와 비교 — 같으면 그 업무, 없으면 **새 업무**. `업무` 시트의 `구분`은 참고만(신규라고 적혀 있어도 이미 있는 이름이면 기존으로). `기록`에 나온 적 없는 `업무` 시트 행은 만들지 않는다 |
| `메모` | 예약 업무 이름 — 업무로 만들지 않고 그 주 **주간 메모의 텍스트 상자**로: `- (요일) 내용` 글머리 목록(예전 요일 메모 옮기기와 같은 모양, weekly-note-spec 5-1) |
| 내용 | 한 행 = 항목 1개(칸 안 줄바꿈은 그 항목 안 줄바꿈으로 둠 — 보드 `Shift+Enter`와 같음). 앞머리 글머리 기호(`-`·`•`·`·`·`○`·`▪`·숫자.)는 뗀다. 2000자 넘으면 건너뜀. 빈 칸·`[?]`만 있는 행은 건너뜀 |
| 세부 | `세부` 칸에 값(`세부`·`Y`·`1`·`○`·`√` 등)이 있으면 세부 항목. 그 칸의 첫 항목이 세부면 본 항목으로 올림(data-spec 2절) |
| 순서 | 같은 날·같은 업무 안에서는 파일 순서대로 `seq` — 병합이면 그 칸 기존 항목 뒤에 |
| 중복 | 병합에서 같은 날·업무·내용(정규화)·깊이가 이미 있으면 건너뜀(같은 파일을 두 번 가져와도 그대로) |
| 미래 날짜 | 오늘 이후는 **건너뜀**에 표시(목록에서 "그래도 가져오기" 선택 가능) |

### 3-7. 업무 만들기·활성 구간 (사용자 요구: 새 업무는 이번 주까지 이어지게)
- **새 업무**: 가져온 첫 기록이 있는 주의 월요일부터 시작, **끝 없음(진행 중)** → 그 주부터 이번 주까지 보드에 계속 보인다. 색은 팔레트 다음 순서, 보드 순서는 기존 업무 아래에 파일에 처음 나온 순서대로.
- **기존 업무**(진행 중): 시작일이 가져온 첫 기록보다 늦으면 시작을 앞당긴다(기록이 활성 구간 밖에 남지 않게, data-spec 4절).
- **종료된 업무**와 이름이 같으면 그 업무에 기록만 붙인다(다시 시작하지 않음 — 미리보기 "종료된 업무에 연결 n"에서 개별로 [다시 시작] 선택 가능). 가져온 기록이 그 업무의 첫 구간보다 앞이면 첫 구간 시작을 앞당긴다.
- 결과: 오래전에 끝난 일도 새 업무로 들어오면 이번 주까지 진행 중으로 보이므로, 최근 3주 기록이 없는 업무에는 보드의 **무기록 종료 제안**(data-spec 5절)이 뜬다 → 사용자가 [종료]/[유지]로 정리. 결과 화면에 "최근 3주 기록이 없는 새 업무 n개 — 보드에서 종료 제안이 뜹니다"를 알린다.
- ※ 6절 #6(마지막 기록 후 4주 지난 업무 자동 종료)은 이 요구로 **대체**한다(새 업무는 이번 주까지 이어 둠).

### 3-8. 새로 정한 점 (사용자 설명 + 확정 결정을 합치며 — 확인 요청)
| # | 내용 | 이유 |
|---|---|---|
| A | 기록이 있는 주의 기본 처리 = **병합**, 덮어쓰기는 지울 개수를 보여 주고 한 번 더 확인 | 덮어쓰기는 손으로 쓴 기록을 지움 — 실수 방지 |
| B | 덮어쓰기 범위 = **그 주 전체**(모든 업무의 항목 + 주간 메모) | "주간 단위" 요구. 업무별 덮어쓰기는 미리보기가 복잡해짐 |
| C | **[표 붙여넣기]** 추가 — 사내 AI가 엑셀 파일을 돌려주지 못해도 표 글로 가져오기 | 사내 AI 도구의 파일 출력 지원 여부를 모름 |
| D | 날짜 = `날짜` 칸, 없으면 `주 시작일 + 요일` | OneNote 페이지에는 요일만 있는 경우가 많음 — 사용자가 지시문 맨 위에 그 주 월요일만 적으면 됨 |
| E | 예약 업무 `메모` → 주간 메모 상자 | 업무에 속하지 않는 그날 일을 잃지 않게(#7 "메모 열 → 주간 메모"와 같은 생각) |
| F | 종료된 업무와 이름이 같으면 기록만 연결(다시 시작은 선택) | "새 업무만 이번 주까지 이어짐" 요구와 구분 |
| G | 6절 #6 자동 종료는 3-7절로 대체 | 사용자 요구 우선 |

### 3-9. 쓰기 순서와 안전 (CLAUDE.md 4-3)
1. **가져오기 직전 자동 백업** `work-journey_<날짜시각>_pre-import.db`(마이그레이션 직전 백업과 같은 위치·규칙, 자동 삭제 안 함).
2. 업무 만들기·구간 조정·덮어쓰기 삭제·항목 넣기·메모 상자를 **`SqlDriver.batch`**(전부 성공 또는 전부 취소). 행이 많으면(5,000개 넘음) 주 단위 묶음으로 나누되 같은 가져오기 id를 쓰고, 중간 실패 시 이미 들어간 묶음을 같은 id로 되돌린다.
3. **되돌리기**: 가져오기 id가 달린 행 삭제 + 덮어쓰기로 지운 행·메모 문서를 **되살림** + 그 가져오기로 만든 업무는 남은 기록이 없으면 삭제, 앞당긴 시작일은 원래대로. 그 사이 사용자가 고친 가져온 항목은 "고친 항목 n개는 남김" 선택.
4. 스키마 `0004_import.sql`(전진 전용, 직전 자동 백업 `_pre-migration-v4`):
   ```sql
   CREATE TABLE import_batch (
     id           TEXT PRIMARY KEY,   -- UUIDv7
     file_name    TEXT NOT NULL,      -- 파일 이름만(경로 저장 안 함). 표 붙여넣기는 '(붙여넣기)'
     week_count   INTEGER NOT NULL,
     item_count   INTEGER NOT NULL,
     undo_json    TEXT NOT NULL,      -- 되돌리기 자료: 덮어쓰기로 지운 항목·메모 문서, 만든 업무 id, 앞당기기 전 시작일
     created_at   TEXT NOT NULL,
     undone_at    TEXT
   );
   ALTER TABLE entry_item ADD COLUMN import_id TEXT REFERENCES import_batch(id);
   CREATE INDEX ix_item_import ON entry_item(import_id);
   ```
5. 파일·붙여넣기 글은 읽기만 → 사용자 폴더에 새로 생기는 파일은 1번 백업과 사용자가 저장 대화상자로 받은 양식 엑셀뿐.

### 3-10. 테스트
- **단위**: 양식 머리줄 인식(시트·열 순서 바뀜, AI가 숨은 정보 지움), 날짜 3단계·주 시작일 보정·요일 불일치·주 밖 날짜, 업무 정규화·기존/신규/종료 매칭·`메모` 예약어, 세부 표기들, 글머리 기호 떼기, 중복, 주별 처리 계획(가져오기·병합·덮어쓰기·건너뛰기), 활성 구간(새 업무 열린 끝·시작 앞당기기), 표 붙여넣기(탭·쉼표·CP949), 되돌리기(덮어쓴 행 되살림·고친 항목 남김), 양식 엑셀 생성(업무 시트 = 이번 주 진행 중 업무·드롭다운), 마이그레이션 0004(fixture 왕복·직전 백업).
- **E2E**(Chromium·WebKit·실앱 CSP): 양식 받기 → 가상 작성본 가져오기 → 미리보기 숫자 → 기록 있는 주 병합/덮어쓰기/건너뛰기 → 보드·자동 집계·엑셀·무기록 제안 → 되돌리기, 표 붙여넣기, 지시문 복사, 5,000행 진행 표시·응답성.
- **회사 PC**(확인표 7-4절): 양식 엑셀이 사내 AI 도구에 첨부되는지, AI가 지시문대로 채우는지(엑셀 파일 / 표 출력), 실제 OneNote 2~4주로 가져오기 → 미리보기 숫자·업무 매칭이 맞는지, 한글 깨짐, 끝난 뒤 속도. **캡처·파일·화면은 보내지 않고** 증상과 "AI가 틀린 곳의 유형"(예: 요일 밀림, 업무 섞임)만 알려 주면 지시문을 고친다.
