### 0-2. 왜 가져오기를 먼저 하나
- 시각화의 완료 기준이 "4주 이상 실데이터에서 의미 있게 읽힘"(project-plan I-M3)인데, ◆G2를 막 시작한 일지에는 기록이 몇 주뿐이다. **기존 일지를 가져오면 첫날부터 몇 달치 흐름**을 볼 수 있고, 타임라인·히트맵을 실제 분량으로 검증할 수 있다.
- 가져오기는 저장소 쓰기(스키마·백업·중복)를 건드리는 일이라, 화면만 그리는 시각화보다 먼저 안정화해 두는 편이 안전하다.

### 0-3. 제외 (뒤 마일스톤)
- 다른 앱(노션·원노트 등)과의 **자동 연동·실시간 동기화** — 외부 통신 0 원칙(CLAUDE.md 4-1)상 하지 않는다. 파일로 내보낸 것을 가져오는 방식만.
- 가져온 기록을 **AI로 정리**(I-M4), 백업에서 통째로 복원하는 화면(I-M5).
- 주간 요약 수정본·AI본, 중요 표시·매주 반복 규칙의 가져오기(원장에 없는 정보).

### 0-4. 완료 기준
- [ ] 가상 기존 일지(엑셀·CSV, 각 6개월치) 가져오기 → 보드·자동 집계·엑셀 내보내기·무기록 판정이 손으로 쓴 기록과 똑같이 동작(단위·E2E)
- [ ] 이 앱이 내보낸 엑셀 **원장 시트를 그대로 다시 가져오면** 같은 기록이 된다(왕복 테스트, 중복은 0건 추가)
- [ ] 가져오기 직전 자동 백업 + [이 가져오기 되돌리기]로 가져온 행만 정확히 빠진다(손으로 쓴 기록 보존)
- [ ] viz-spec 체크 항목 전부 ✅, 클라우드 Playwright 스크린샷(라이트·다크)으로 차트 확인
- [ ] **회사 PC**: 사용자의 실제 기존 일지를 가져와 4주 이상 흐름이 타임라인·히트맵에서 의미 있게 읽힘(파일·화면은 저장소·세션에 올리지 않고 결과만 알림)
- [ ] 매일 기록 흐름(앱 열기 → 바로 타이핑, 2분 시나리오 E2E)이 그대로

## 2. M3-S1~S3 시각화 — 요점

스펙은 viz-spec이 정본이고, 구현하며 정할 점만 적는다.
- 데이터 계산(주 묶음·일수 집계·접기·"기타" 묶기)은 `src/domain/insights.ts` 순수 함수 + 단위 테스트. 차트는 `(data, size) → SVG` 컴포넌트(직접 SVG + d3-scale/d3-array, 차트 라이브러리 없음).
- 인사이트 진입은 **왼쪽 레일 아이콘**(important-repeat-spec M1 레일)과 `Alt+3`. 보드 상태(편집 중 칸·스크롤)는 그대로 두고 숨긴다(메모 [크게 보기]와 같은 방식).
- 실앱 CSP: SVG 속성으로만 그린다(인라인 `style` 문자열 금지 — 메모 편집기와 같은 이유). CSP E2E에 인사이트 화면을 더한다.
- 가져온 기록(M3-S0)도 손으로 쓴 기록과 구분 없이 그린다. 가져온 묶음 표시는 하지 않는다(6절 #9).

## 3. M3-S0 기존 일지 가져오기 — 상세

### 3-1. 사용자 흐름 (설정 → [기존 일지 가져오기…], 3단계 마법사)
```
① 파일 고르기         ② 열 맞추기                          ③ 미리보기·가져오기
[파일 선택…]          시트 [업무일지 ▾]  머리줄 [1행 ▾]       2025-03-04 ~ 2026-10-17 · 31주
.xlsx · .csv          날짜 열   [A 날짜 ▾]   2025-03-04 …     항목 1,284개 (세부 212)
(이 앱의 엑셀 원장은   업무 열   [D 업무 ▾]   정산 시스템 …     업무 9개: 기존과 같은 이름 3 · 새로 만듦 6
 자동으로 알아봄)      내용 열   [G 내용 ▾]   현행 분석 …       건너뜀: 같은 기록 이미 있음 41 · 날짜 없음 3 [목록]
                      세부 열   [F 세부 ▾ / 없음 / 앞머리 기호]   ☑ 마지막 기록 후 4주 넘게 지난 업무는 종료로
                      메모 열   [없음 ▾]                          [가져오기] — 직전에 자동 백업
```
- **① 파일**: 웹 표준 파일 선택(`<input type="file">`) — 새 Rust 명령 없음, 파일은 **읽기만** 한다(사용자 폴더에 쓰지 않음). 엑셀은 ExcelJS(이미 있는 의존성, 지연 로딩), CSV는 직접 해석(UTF-8 / 윈도우 엑셀 기본 저장 CP949 자동 판별).
- **② 열 맞추기**: 머리글 이름으로 추측(`날짜·일자·Date` / `업무·프로젝트·분류·Category` / `내용·업무내용·한 일` / `세부` / `메모·비고`) → 사용자가 고친다. 각 열 옆에 첫 값 3개 미리보기. **이 앱의 원장 시트**(output-spec 3-2: `날짜|주차|요일|업무|순번|세부|내용|중요`)면 열 맞추기 없이 바로 ③으로.
- **③ 미리보기**: 기간·주 수·항목 수·업무별 개수, 업무 이름 매칭(기존 업무와 같은 이름 → 그 업무에, 처음 보는 이름 → 새 업무, 색은 팔레트 순서), 건너뛸 행 목록(이유별). [가져오기]를 누르면 3-3 순서로 쓴다.
- 끝나면 토스트 `기록 1,284개를 가져왔습니다 [가져온 첫 주로] [되돌리기]` + 설정의 "가져오기 기록" 목록에 남는다(언제·파일 이름·개수·[되돌리기]).

### 3-2. 해석 규칙 (`domain/importer.ts`, 순수 함수 — 단위 테스트)
| 항목 | 규칙 |
|---|---|
| 날짜 | 엑셀 날짜 값, `2026-10-17`·`2026.10.17`·`2026/10/17`·`26.10.17`, `10/17(금)`처럼 **연도 없는 날짜는 ② 단계에서 고른 연도**. 날짜 칸이 비어 있으면 **바로 위 행의 날짜를 이어 씀**(날짜를 묶음 머리에만 적은 일지) — 선택, 기본 켬 |
| 업무 | 앞뒤 공백·연속 공백 정리 후 이름이 같으면 같은 업무(대소문자·전각/반각 구분 안 함). 비어 있으면 위 행 업무 이어 쓰기(날짜와 같은 선택) 또는 `(분류 없음)` 업무 |
| 내용 | 한 칸 = 항목 1개. 칸 안 줄바꿈은 **줄마다 항목**으로 나눔(보드 붙여넣기와 같은 규칙: 앞머리 `-`·`•`·`*`·`·`·`○`·`1.` 떼고, 들여쓴 줄은 세부). 2000자 넘는 항목은 건너뛴 행 목록에 |
| 세부 | 세부 열(원장의 `세부`에 숫자가 있으면 세부) / 앞머리 기호·들여쓰기로 판별 / 없음(모두 본 항목) 중 선택. 첫 항목이 세부면 본 항목으로 올림(data-spec 2절) |
| 순서 | 같은 날·같은 업무 안에서는 파일 순서대로 `seq` — 그 칸에 이미 기록이 있으면 **그 뒤에** 붙인다 |
| 중복 | 같은 날·같은 업무·같은 내용(정규화 후)·같은 깊이가 이미 있으면 건너뜀 → 같은 파일을 두 번 가져와도 두 배가 되지 않는다(원장 왕복 테스트) |
| 메모 열 | 주마다 묶어 그 주 **주간 메모의 텍스트 상자 1개**(`- (요일) 내용` 목록 — 예전 요일 메모 옮기기와 같은 모양, weekly-note-spec 5-1). 그 주에 메모가 이미 있으면 상자를 하나 **더** 둔다(덮어쓰지 않음) |
| 업무 활성 구간 | 새 업무 = 가져온 첫 기록 주부터 시작. 기존 업무의 시작이 가져온 기록보다 늦으면 시작을 앞당긴다(data-spec 4절 — 기록이 구간 밖에 남지 않게). 선택 시 마지막 기록 후 4주 넘게 지난 업무는 그 주로 **종료**(무기록 제안이 한꺼번에 뜨지 않게, 6절 #6) |
| 미래 날짜 | 오늘 이후 날짜는 건너뜀 목록에 표시하되 선택으로 가져올 수 있음(일정 메모 등, data-spec 4-3) |

### 3-3. 쓰기 순서와 안전 (CLAUDE.md 4-3)
1. **가져오기 직전 자동 백업** `work-journey_<날짜시각>_pre-import.db`(마이그레이션 직전 백업과 같은 경로·보존 규칙 — 자동 삭제하지 않음).
2. 업무 만들기·구간 조정·항목 넣기·메모 상자를 **`SqlDriver.batch` 한 번**(전부 성공 또는 전부 취소). 행이 많으면(예: 5,000개 넘음) 묶음을 나누되 각 묶음이 하나의 가져오기 id를 공유하고, 실패하면 이미 들어간 묶음을 같은 id로 지운다.
3. 가져온 행에는 **가져오기 id**를 단다 → [되돌리기]는 그 id의 행만 지운다(그 사이 사용자가 고친 항목은 "고친 항목 n개는 남김" 선택). 새로 만든 업무는 남은 기록이 없으면 함께 지운다(기록 0건 업무 삭제 규칙과 같음).
4. 스키마: `0004_import.sql`(전진 전용, 직전 자동 백업 `_pre-migration-v4`)
   ```sql
   CREATE TABLE import_batch (
     id          TEXT PRIMARY KEY,      -- UUIDv7
     file_name   TEXT NOT NULL,         -- 파일 이름만(경로 저장 안 함)
     item_count  INTEGER NOT NULL,
     created_at  TEXT NOT NULL,
     undone_at   TEXT                   -- 되돌린 시각(목록에서 흐리게)
   );
   ALTER TABLE entry_item ADD COLUMN import_id TEXT REFERENCES import_batch(id);
   CREATE INDEX ix_item_import ON entry_item(import_id);
   ```
   손으로 쓴 행은 `import_id`가 NULL. 보드에서 가져온 항목을 고치면 `import_id`는 그대로 두고 `updated_at`이 바뀐다(되돌리기에서 "고친 항목" 판별).
5. 가져오기는 **읽기만** 하는 파일 선택 → 사용자 폴더에 새 파일을 만드는 것은 1번 백업뿐.

### 3-4. 가져오기 양식(템플릿)
- 설정 > [기존 일지 가져오기…] ① 단계에 **[양식 엑셀 받기]**: 원장 시트와 같은 열(`날짜|업무|세부|내용|메모`)과 가상 예시 3행이 든 `.xlsx` — 다른 형식의 기존 일지를 이 양식에 옮겨 붙이면 열 맞추기 없이 들어간다. 저장은 엑셀 내보내기와 같은 저장 대화상자·규칙(`.xlsx`만).
- 저장소에는 가상 양식 샘플 `docs/samples/import-template.xlsx`와 가상 기존 일지 `fixtures/legacy-*.xlsx|csv`(6개월치, 여러 형식)만 둔다(CLAUDE.md 4-2).
