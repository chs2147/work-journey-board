> - 지금은 직장용 보드 하나뿐 → **개인용 등 새 작업 공간을 용도에 따라 더 만들어 운영**
> - 설계 때 정할 것: DB 파일을 **분리**할지 **통합**할지, 새 공간을 만든 뒤 **온보딩**, 명칭을 **보드**로 할지 **워크스페이스**로 할지

이 문서에서는 이름이 정해지기 전까지 이 개념을 **"작업 공간"** 이라고 부른다.

## 0. 지금 구조(조사 결과)

| 항목 | 지금 | 멀티로 갈 때 의미 |
|---|---|---|
| 데이터 | 저장 폴더 1개 = 일지 `work-journey.db` 1개 + `backups\` | 폴더 단위로 이미 완결 — 폴더를 여러 개 두면 공간이 여러 개 |
| 이 PC 설정 | `config.json` `{ dataDir, theme, backupMirror, cabinet }` | `dataDir`가 하나뿐 → 목록이 필요 |
| 전환 | 설정 > 저장 위치 > **다른 폴더의 기존 일지 열기**(`switchTo`) — 지금 일지를 닫고 새 일지를 열어 보드를 다시 띄움 | 전환 동작은 **이미 있다**. 목록·빠른 전환·새로 만들기가 없을 뿐 |
| 백업·복원 | 폴더마다 `backups\`, 이름 규칙·지우기 가드(TS + Rust) | 폴더별로 그대로 동작 |
| Rust 검사 | `export_write`가 "저장 폴더의 `backups\`에는 쓰지 않기"를 `config.json`의 `dataDir` **하나**로 검사 | 등록된 **모든** 폴더로 넓혀야 함(8절) |
| 일지 안 설정 | `app_meta`(키·값) — 휴일·태그·무기록 알림 등 | 공간마다 따로(자연스럽게 분리) |
| 항목 ID | UUIDv7(시각 + 난수) | 공간끼리 겹치지 않음 → 나중에 공간 사이 연결(Universe)·옮기기 가능 |
| 화면 용어 | "주간 보드", "메모 보드" — **"보드"는 이미 화면 이름** | 공간 이름을 "보드"로 하면 겹침(1절) |

## 1. 명칭 — 후보 5개

| 후보 | 화면 문구 예 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **보드** | 새 보드 · 보드 전환 · "개인 보드" | 앱 이름(Work Journey **Board**)과 이어짐 | **"주간 보드"·"메모 보드"와 겹침** — "개인 보드의 메모 보드" 같은 문장이 생김. 가이드·도움말 전체에서 뜻이 둘이 됨 |
| **워크스페이스** | 새 워크스페이스 · 워크스페이스 전환 | 노션·슬랙·VS Code에서 익숙, 뜻이 분명("데이터가 따로인 큰 단위") | 6글자로 김 · "Work"라 개인용에 어색할 수 있음 · 앱의 순한 한국어 문구 결에서 튐 |
| **공간** | 새 공간 · 공간 전환 · "개인 공간" | 짧고 한국어 · 회사/개인 어느 쪽에도 자연스러움 · 겹치는 화면 이름 없음 | 단독으로는 뜻이 조금 넓음("공간 = 저장 공간?") — 처음 한 번 설명 필요 |
| **일지** | 새 일지 · 일지 전환 · "개인 일지" | 실제 구조(일지 파일 1개)와 1:1 · 이미 설정·백업 문구에 "일지"가 씀 | 기록 하나하나도 "일지"라 부를 수 있어 헷갈림 · "개인 일지"는 일기처럼 들림 |
| **스페이스**(Space) | 새 스페이스 · Space 전환 | Cabinet·Universe처럼 영문 고유 기능명 계열 · 컨플루언스·클릭업 용어 | 외래어 · Universe(우주)와 함께 쓰면 "Space ⊂ Universe"로 그럴듯하지만 말장난처럼 보일 수 있음 |

**추천: "워크스페이스"** — 사용자가 처음 말한 후보이고, 노션 등에서 이미 "데이터가 완전히 따로인 단위"로 익숙해 설명 없이 통한다. 화면에서는 대부분 **공간 이름**("회사", "개인")이 보이고 일반 명사는 메뉴 몇 곳에만 나오므로 길이 부담이 작다. 대안: 짧고 한국어인 **"공간"**.
"보드"는 비추천(화면 이름과 겹침).

> 앱 이름 **Work Journey Board**는 그대로 둔다(이름 바꾸기는 별도 논의).

## 2. 저장 구조 — 분리 vs 통합

| | **가. 분리**(공간마다 폴더·일지 파일 1개) — 추천 | 나. 통합(일지 파일 1개에 모든 공간) |
|---|---|---|
| 구조 변경 | **없음**(마이그레이션 없음) — 지금 폴더가 곧 첫 공간 | 표 대부분(업무·메모·휴일·태그·반복·Cabinet·가져오기 기록…)에 `workspace_id` 추가 — 큰 마이그레이션 |
| 섞일 위험 | 파일이 다르므로 **구조적으로 0** | 모든 조회에 공간 조건을 빠뜨리지 않아야 함 — 하나라도 빠지면 회사 화면에 개인 기록이 보임 |
| 회사 PC / 개인 기록 | 개인 공간을 **다른 폴더**(OneDrive 회사 폴더 밖, 또는 맥에만)에 둘 수 있음 | 한 파일이라 회사 동기화 폴더에 개인 기록이 함께 올라감 |
| 백업·복원 | 공간별 `backups\` 그대로 · 한 공간을 복원해도 다른 공간 영향 없음 | 복원하면 모든 공간이 함께 되돌아감 |
| 다른 PC로 옮기기 | 폴더째 복사 = 그 공간만 | 전부 아니면 전무 |
| 원칙과의 관계 | "데이터 = 일지 파일 1개"를 **공간마다** 유지 | 원칙은 그대로지만 한 파일이 커짐 |
| 공간을 넘는 기능 | 여러 파일을 함께 열어 읽어야 함(Universe·전체 검색) — 읽기 전용으로 열면 됨(9절) | SQL 하나로 쉬움 |
| 구현량·위험 | 작음(목록·전환·만들기 화면 + 설정 형식) | 큼(전 표·전 조회·엑셀·가져오기·테스트) |

**추천: 가. 분리.** 섞일 위험이 구조적으로 없고, 지금 데이터를 전혀 건드리지 않으며(마이그레이션 0), 회사 PC에서 개인 기록을 회사 동기화 폴더 밖에 둘 수 있다. 공간을 넘는 조회는 Universe 단계에서 "다른 공간 일지를 읽기 전용으로 여는" 방식으로 푼다.

| | **A안 · 레일 맨 위 공간 단추(추천)** | B안 · 상단 타이틀 옆 드롭다운 | C안 · 레일에 공간 아이콘 나열 |
|---|---|---|---|

| 전환 | 2번(누르고 고르기) · 단축키 1번 | 2번 · 단축키 1번 | **1번** |

| 지금 어느 공간인지 | 레일 색 + 상단 공간 이름 | 상단 알약(가장 잘 보임) | 강조된 아이콘 |
| 공통 | 단축키 `Ctrl+Alt+1`~`9`(맥 `⌘⌥1`~`9`) = n번째 공간, `Ctrl+Alt+0` = 목록 열기 · 공간 색을 레일 왼쪽 띠와 창 제목(`Work Journey Board — 개인`)에 표시 · 전환하면 지금 공간 저장·백업 확인 → 다른 공간을 열어 **같은 화면(주간/오늘)과 오늘 날짜**로 |

**추천: A안** — 공간이 2~3개인 개인 사용에서 레일 자리를 하나만 쓰고, 지금 레일(보기·중요·Cabinet·설정)의 문법을 그대로 따른다. 상단에는 공간 이름을 작게 함께 보여 "어느 공간인지" 헷갈리지 않게 한다(B안의 장점 흡수).

### 3-1. 지금 공간 구분 표시
- 공간마다 **색 1개**(업무 색 팔레트 c1~c8 재사용) — 레일 왼쪽 3px 띠 + 공간 단추 + 상단 이름 앞 점.
- 창 제목: `Work Journey Board — <공간 이름>`(작업 표시줄·Dock에서 구분). 공간이 하나뿐이면 지금처럼 이름 없이.
- 스플래시: "개인 워크스페이스 여는 중…".
- 테마(라이트·다크·시그니처)는 **이 PC 하나로 공통**(D6에서 공간별로 할지 결정).

## 4. 새 공간 만들기(온보딩) — 4단계 (`onboarding.png`)

공간 목록의 [+ 새 워크스페이스]에서 시작. 지금 첫 실행 화면(첫 업무 2개·추천 폴더)을 재사용해 같은 모양으로.

1. **이름·색·용도** — 이름(필수, 예: 개인), 색 8개 중 하나, 용도 고르기(회사 업무 · 개인 생활 · 공부 · 사이드 프로젝트 · 직접) — 용도는 3단계 추천 업무에만 쓰인다.
2. **저장 위치** — 추천: 지금 공간 폴더 옆 `WorkJourney-<이름>`(예: `문서\WorkJourney-개인`). [다른 폴더…]. 기존 일지가 있는 폴더를 고르면 "이 폴더의 일지를 공간으로 추가"로 바뀜. 회사 OneDrive 폴더 안을 고르면 안내: "회사 계정 OneDrive와 함께 동기화됩니다".
3. **첫 업무** — 용도별 추천 3~4개를 미리 채움(지우고 고칠 수 있음, 0개도 가능). 예: 개인 생활 = 건강·운동 · 공부 · 집안일 · 재테크 / 공부 = 강의 · 과제 · 독서 / 사이드 프로젝트 = 기획 · 개발 · 홍보.
4. **가져올 설정**(선택, 지금 공간에서 복사) — ☑ 휴일 설정(공휴일 자동·기타 휴가 이름) ☐ 태그 목록 ☐ 무기록 알림 설정. 기록·메모·Cabinet은 복사하지 않는다.

→ [만들고 열기] = 새 폴더에 일지 생성 → 목록에 추가 → 그 공간으로 전환. 첫 실행(앱을 처음 설치)은 지금 흐름 그대로이며, 그 공간이 첫 번째 공간이 된다(이름 기본값 "회사"·고칠 수 있음).

## 5. 관리 — 설정 > 워크스페이스 (`manage.png`)

설정 분류(화면 · 데이터·백업 · 가져오기 · 업무 관리 · 달력·휴일 · 업데이트·정보) 맨 앞에 **워크스페이스**를 더한다(지금 데이터·백업의 "저장 위치"는 이 분류 안 공간마다의 [위치 옮기기…]로 옮김).

| 동작 | 내용 |
|---|---|
| 목록 | 이름 · 색 · 폴더 경로 · 마지막으로 연 날 · 단축키 번호 — 끌어서 순서(= `Ctrl+Alt+숫자` 순서) |
| 이름·색 바꾸기 | 그 공간 일지 안(`app_meta`)에 저장 — 폴더를 다른 PC로 옮겨도 이름·색이 따라감. 목록 표시용으로 이 PC 설정에도 사본 |
| 위치 옮기기 | 지금 "저장 위치 변경…"(옮기기)·"다른 폴더의 기존 일지 열기"를 공간마다 |
| 기존 폴더 추가 | 다른 PC에서 가져온 폴더·예전 백업 폴더를 공간으로 등록 |
| **목록에서 빼기** | 이 PC 목록에서만 뺀다. **파일은 지우지 않는다**(CLAUDE.md 4-3 — 앱이 사용자 파일을 지우는 곳은 백업 가드뿐). 안내: "폴더는 그대로 남습니다: <경로>". 지금 연 공간·마지막 하나는 뺄 수 없음 |
| 폴더 열기 | 탐색기/Finder에서 보기 |

## 6. 기능별 영향

| 기능 | 정할 내용(추천) |
|---|---|
| 자동 백업(그날 첫 실행·종료·2시간 주기) | **연 공간만**(지금과 같음). 전환할 때 떠나는 공간은 "종료 백업"을 한다 |
| 업데이트 전 백업(`_pre-update`) | 연 공간 + **이 PC에 등록된 모든 공간**(닫힌 파일은 그대로 복사·검증) — 새 판이 다른 공간을 처음 열 때 마이그레이션 직전 백업도 따로 한 번 더 함 |
| 보조 백업 위치(`backupMirror`) | 이 PC 설정 하나 → 그 아래 공간별 하위 폴더(`<보조 위치>\<공간 이름>`)에 최근 3개씩 |
| 복원 | 공간별(설정 > 백업은 연 공간 대상) — 지금과 같음 |
| Cabinet | 공간별(등록 폴더·링크는 일지 안). 전환하면 열린 Cabinet 창·폴더 창을 닫고, 다음에 그 공간을 열면 그 공간의 창 상태를 다시 연다(`config.cabinet`을 공간별로) |
| 검색 | **연 공간만**(1단계). 모든 공간 검색은 Universe 단계에서 |
| 주간 요약·엑셀·마크다운·스냅샷 | 연 공간만. 파일 이름에 공간 이름을 붙임(예: `업무일지_개인_2026-W45.xlsx`) — D8 |
| 인사이트 | 연 공간만 |
| 휴일·공휴일·태그·무기록 알림 | 공간별(일지 안) — 개인 공간은 무기록 알림 기본 끔(용도 = 개인 생활·공부일 때) — D9 |
| 새 판 확인 | 앱 하나 — 변화 없음 |

## 7. 데이터·설정 형식

- **일지(공간마다)**: 표 구조 변경 없음(구조 v10 그대로). `app_meta`에 키 2개 — `workspace.name`, `workspace.color`(없으면 폴더 이름·c1).
- **이 PC 설정 `config.json`**:
  ```json
  {
    "dataDir": "C:\\Users\\me\\Documents\\WorkJourney",          // 지금 연 공간(예전 판과 호환되는 자리)
    "workspaces": [
      { "dir": "C:\\Users\\me\\Documents\\WorkJourney",        "name": "회사", "color": "c1", "lastOpened": "2026-11-03" },
      { "dir": "C:\\Users\\me\\Documents\\WorkJourney-개인",   "name": "개인", "color": "c5", "lastOpened": "2026-11-02" }
    ],
    "cabinetBy": { "<dir>": { "open": true, "windows": [] } }
  }
  ```
  - `name`·`color`는 목록을 빨리 그리기 위한 사본(정본은 각 일지 `app_meta`) — 공간을 열 때 맞춰 고친다.
  - `workspaces`가 없으면(지금 사용자) `dataDir` 하나로 목록 1개를 만든다 → **업데이트해도 아무것도 바뀌지 않은 것처럼 보이고**, [+ 새 워크스페이스]만 생긴다.
- **되돌려 설치(1.7.x 이하)**: 설정 쓰기는 이미 "있던 키는 두고 합치기"라 `workspaces`는 남는다. 예전 판은 `dataDir`(마지막으로 연 공간)만 연다 — 다른 공간 파일은 그대로 있으니 다시 새 판을 깔면 목록이 돌아온다.

## 8. Rust 변경(최소)

- `export_write`의 "백업 폴더에는 내보내지 않기" 검사를 `dataDir` 하나 → `dataDir` + `workspaces[].dir` **모두**로. `cargo test`에 두 공간 경우 추가.
- 그 밖의 명령(백업 지우기·이름 바꾸기·복원·Cabinet)은 이미 경로를 인자로 받고 이름 규칙으로 검사하므로 변경 없음.
- 새 Rust 명령 없음 · 권한(capabilities) 변경 없음 · 외부 통신 변화 없음.

## 9. Universe 대비(다음 문서의 전제)

- 공간마다 파일이 따로이므로 Universe는 **여러 일지를 읽기 전용으로 함께 열어** 그린다(실앱 `tauri-plugin-sql` 연결 여러 개 · 브라우저 모드 sql.js 여러 개). 쓰기는 연 공간에만.
- ID가 UUIDv7이라 공간이 달라도 겹치지 않음 → 노드 ID = `<공간>:<종류>:<ID>`로 그대로 쓸 수 있음.
- 공간 사이 연결(예: 개인 공부 항목 ↔ 회사 업무)은 Universe 문서에서 따로 결정(지금 단계에서는 만들지 않음).
- 이 문서에서 정하는 공간 이름·색이 Universe의 묶음(성단) 색·이름이 된다.

### rc.1 실기 확인에서 나온 심각한 버그와 수정(rc.2, 2026-11-03)
- **증상**(사용자 확인): 새 워크스페이스를 만들어 연 채 앱을 닫고 다시 켜면, 이전 워크스페이스가 목록에서 사라지고 마지막 공간만 남음.
- **원인**: 실앱이 `config.json`을 읽는 `parseConfig`가 알던 키(dataDir·theme·backupMirror·cabinet)만 골라 읽어 **`workspaces`·`cabinetBy`를 버렸다** → 다시 켜면 목록 = 지금 연 공간 하나 → 그 목록을 다시 저장해 이전 공간 줄이 지워짐. 브라우저 모드는 이 함수를 거치지 않아 e2e가 잡지 못했다.
- **데이터**: 일지 파일은 공간마다 다른 폴더에 있고 앱은 일지를 지우거나 덮어쓰지 않으므로 **이전 공간의 `work-journey.db`는 그 폴더에 그대로** 있다 — 설정 › 워크스페이스 › [기존 폴더를 워크스페이스로 추가…]로 다시 넣으면 이름·색·아이콘까지 돌아온다(일지 안 `settings.workspace`).
- **수정**
  1. `parseConfig`가 `workspaces`·`cabinetBy`를 그대로 읽음 + 브라우저 모드도 같은 길(글 → `parseConfig`)로 읽어 e2e가 이런 누락을 잡게.
  2. 설정 저장을 하나씩 차례로(`serialize`) — 목록 저장과 Cabinet 창 저장이 겹쳐 먼저 쓴 값이 지워지지 않게.
  3. **새 워크스페이스 = 무조건 새 일지 파일**(사용자 지시): 고른 폴더에 이미 일지가 있거나 다른 공간 폴더면 그 안에 `WorkJourney-<이름>` 새 폴더를 만들어 새 일지를 둔다(추천 폴더가 겹치면 `-2`…). 2단계에 "만들 일지 파일: …\work-journey.db"를 보여 준다. 만들기 경로는 기존 일지를 열지 않는다(일지가 있는 폴더면 거부) — 기존 일지 추가는 설정의 [기존 폴더를 워크스페이스로 추가…]만.
- 테스트: 단위 `parseConfig`가 목록을 지키는지·동시 저장, e2e "지금 공간 폴더를 골라도 새 폴더·새 일지, 기존 일지 그대로".
