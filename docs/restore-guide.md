# 백업에서 일지 복원하기 (수동 절차)

> 앱 안의 [백업에서 복원] 기능은 I-M5에서 만든다(data-spec 7-3). 그 전까지는 이 문서의 절차로 복원한다.
> 원칙: **지금 파일을 지우지 않는다.** 이름을 바꿔 보존해 두고, 백업 파일은 옮기지 않고 **복사**한다.

## 1. 언제 쓰나
| 상황 | 방법 |
|---|---|
| 앱을 켜면 **"데이터 파일에 문제가 있습니다"** 화면이 뜬다 | **A. 제자리 복원** |
| 앱은 잘 열리는데 **예전 상태로 되돌리고 싶다**(실수로 많이 지움 등) | **B. 복원본으로 전환**(지금 일지는 손대지 않음) |

복원하면 **백업 시각 이후에 쓴 기록은 복원본에 없다.** 지금 파일을 보존해 두므로 나중에 필요한 내용을 다시 옮겨 적을 수 있다.

## 2. 파일 위치
- **저장 폴더**: 앱의 설정 > 저장 위치에 나오는 폴더다. 기본값은 `C:\Users\<사용자>\WorkJourney`.
  - 앱이 열리지 않으면 `%LOCALAPPDATA%\WorkJourneyBoard\config.json`을 메모장으로 열어 `dataDir` 값을 본다.
  - "데이터 파일에 문제" 화면의 [백업 폴더 열기] 버튼을 눌러도 된다.
- 저장 폴더 안의 파일:

```
<저장 폴더>\
├─ work-journey.db                    ← 지금 일지(앱이 쓰는 유일한 원본)
├─ work-journey.db-journal            ← (있을 때만) 쓰다가 멈춘 흔적. 복원할 때 함께 치운다
└─ backups\
   ├─ work-journey_2026-10-22.db                  ← 일일 자동(그날 첫 실행 + 종료 시, 최근 14일)
   ├─ work-journey_2026-10_monthly.db             ← 월간 자동(그 달 첫 백업, 최근 12개월)
   ├─ work-journey_2026-10-22_1430_manual.db      ← 설정 > [지금 백업]
   └─ work-journey_2026-10-22_1431_pre-migration-v2.db  ← 앱 업데이트로 구조가 바뀌기 직전
```

- 파일명의 날짜·시각은 PC의 현지 시각이다. 일일 백업은 **그날 앱을 마지막으로 닫은 상태**를 담고 있다.
- 어느 백업을 쓸지: 문제가 생기기 직전 날짜의 일일 백업이 보통 가장 좋다. 그보다 오래됐으면 월간 백업을 쓴다.

## 3. A. 제자리 복원 — "데이터 파일에 문제가 있습니다" 화면이 뜰 때
1. **앱을 완전히 닫는다.** 창을 닫은 뒤 작업 표시줄에 앱이 남아 있지 않은지 본다.
2. 저장 폴더를 탐색기로 연다.
3. **지금 파일 보존**: `work-journey.db`의 이름을 `work-journey_<날짜>_<시각>_before-restore.db`로 바꾸고 `backups\` 폴더로 옮긴다(예: `work-journey_2026-10-23_0915_before-restore.db`).
   - `work-journey.db-journal`이 있으면 이것도 같은 이름 + `-journal`(예: `work-journey_2026-10-23_0915_before-restore.db-journal`)로 바꿔 함께 옮긴다. **남겨 두면 복원한 파일이 다시 망가질 수 있다.**
   - 이 이름은 자동 삭제 대상이 아니므로 앱이 지우지 않는다.
4. **백업 복사**: `backups\`에서 고른 백업 파일을 **복사**해 저장 폴더에 붙여 넣는다. 붙여 넣은 사본의 이름을 `work-journey.db`로 바꾼다.
5. 앱을 켠다. 보드가 열리면 복원된 마지막 날짜의 기록을 확인한다.
6. 그래도 같은 화면이 뜨면 1단계부터 다시 한다. 이번에는 4단계에서 **더 이전 백업**을 고른다. 3단계는 다시 하지 않고, 실패한 사본만 지우거나 다른 이름으로 바꾼다.

> 파일 확장자가 보이지 않으면 탐색기 [보기] > [표시] > **파일 확장명**을 켠다. `work-journey.db.db`처럼 이름이 이중으로 붙는 실수를 막는다.

## 4. B. 복원본으로 전환 — 앱은 열리지만 예전 상태로 돌아가고 싶을 때
지금 일지 폴더는 그대로 두고, 백업으로 만든 새 일지로 앱을 옮겨 탄다.

1. 새 폴더를 만든다. 예: `C:\Users\<사용자>\WorkJourney-복원-1023`. OneDrive 아래는 피한다.
2. 저장 폴더의 `backups\`에서 고른 백업 파일을 새 폴더로 **복사**하고 이름을 `work-journey.db`로 바꾼다.
3. 앱에서 **설정 > 저장 위치 > [저장 위치 변경…]** → 1번 폴더를 고른다.
4. "이 폴더에 다른 일지가 있습니다" → **[그 일지로 전환]**. 지금 일지는 원래 폴더에 그대로 남는다.
5. 이후 기록과 백업은 새 폴더(`…\WorkJourney-복원-1023\backups\`)에 쌓인다. 원래 일지로 돌아가려면 같은 방법으로 원래 폴더를 고른다.

## 5. 하지 말 것
- 앱이 켜져 있는 상태에서 `work-journey.db`를 바꾸거나 덮어쓰지 않는다.
- `backups\` 안의 파일을 옮기지 않는다(항상 복사). 원본 백업이 남아 있어야 다시 시도할 수 있다.
- 일지 파일이나 백업을 메일·메신저·클라우드로 보내지 않는다. 실제 업무 기록이다. 문제를 알릴 때는 증상만 적는다.
