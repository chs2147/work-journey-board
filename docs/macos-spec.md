## 2. 현재 구조 점검 — 무엇이 윈도우에 묶여 있나

### 2-1. 그대로 쓰는 부분 (변경 없음)

| 영역 | 이유 |
|---|---|
| 화면·도메인·저장소(`src/ui`·`src/domain`·`src/data`) | 순수 TS. 주차·집계·마이그레이션·백업 규칙도 플랫폼과 무관하다. |
| SQLite 일지 파일 | 같은 스키마. **윈도우에서 쓰던 `.db` 파일을 맥에서 그대로 열 수 있다**(파일 형식 동일). |
| 글꼴 | Pretendard·고운돋움을 번들한다(OS 글꼴에 기대지 않음) → 화면 글자가 같다. |
| CSP | `default-src 'self'; connect-src ipc: http://ipc.localhost; …`. 맥 WKWebView의 IPC는 `ipc://localhost`인데, 이미 `ipc:`가 허용되어 있다 → **CSP 변경 없음.** |
| Tauri 플러그인 | sql·dialog·clipboard-manager·opener·single-instance·window-state 모두 맥을 지원한다. |
| 엑셀·마크다운·PNG 내보내기 | 저장 대화상자(NSSavePanel)에서 고른 경로에 쓴다. Rust 검사 `export_path_allowed`는 `\`·`/`를 모두 구분자로 본다 → 맥 경로도 통과한다(테스트 추가). |
| 설정 파일 | `local_data_dir()/WorkJourneyBoard/config.json` → 맥 `~/Library/Application Support/WorkJourneyBoard/config.json`. 코드 변경 없음. |
| 기본 저장 폴더 | `homeDir()/WorkJourney` → 맥 `~/WorkJourney`. 홈 바로 아래라 맥 개인정보 보호(TCC) 권한 묻기 대상이 아니다. 좋은 기본값이므로 유지한다. |
| 단축키 판정 | 이미 대부분 `e.ctrlKey || e.metaKey`라 맥 `⌘`에서도 동작한다(12개 파일 확인). |
| 한글 조합 판정 | `isComposingKey` = `isComposing || keyCode === 229`. WebKit 대응까지 이미 들어 있다(그래도 실기 확인 필요, 5절 R1). |
| WebKit 호환 | E2E가 이미 **Chromium + WebKit** 두 엔진으로 돈다(CLAUDE.md 5절). 맥 WKWebView와 같은 엔진 계열이라 큰 화면 깨짐 위험은 낮다. |

## 3. 상세 설계

### 3-1. 앱 메뉴·종료 (맥 전용, Rust `menu.rs` 새 모듈 `#[cfg(target_os = "macos")]`)

맥 메뉴 막대를 한국어로 만든다. 윈도우에는 메뉴를 달지 않는다(지금과 같음).

| 메뉴 | 항목 |
|---|---|
| **Work Journey Board** | Work Journey Board 정보 · ─ · 설정… `⌘,` · ─ · 서비스 · ─ · Work Journey Board 가리기 `⌘H` · 기타 가리기 `⌥⌘H` · 모두 보기 · ─ · **종료 `⌘Q`** |
| **편집** | 실행 취소 `⌘Z` · 실행 복귀 `⇧⌘Z` · ─ · 오려두기 `⌘X` · 복사 `⌘C` · 붙여넣기 `⌘V` · 모두 선택 `⌘A` |
| **보기** | 주간 보드 `⌥1` · 주간 요약 `⌥2` · 인사이트 `⌥3` · Cabinet `⌥4` · ─ · 전체 화면 `⌃⌘F` |
| **윈도우** | 최소화 `⌘M` · 확대/축소 · ─ · 모두 앞으로 가져오기 |
| **도움말** | 빠른 이용 가이드 ↗ |

- **편집** 메뉴는 Tauri 기본 제공 항목(`PredefinedMenuItem`)을 써서, WKWebView 입력란의 복사·붙여넣기·실행 취소가 OS 표준대로 동작하게 한다.
- **설정…**·**보기** 항목은 웹 화면에 이벤트(`menu-action`)를 보내고, 웹 화면이 지금 단축키 처리기와 같은 함수(`setSettingsOpen` 등)를 부른다. 업무 로직은 Rust에 두지 않는다(4-5).
- **종료 `⌘Q`**: 기본 "종료"(바로 끝냄) 대신 직접 만든 항목을 쓴다. 이 항목은 메인 창에 **닫기 요청**을 보내 지금의 `onExit` 경로(저장 마무리 → 종료 백업 → 창 닫기)를 그대로 거친다. Dock 아이콘 우클릭 "종료"·로그아웃 때 오는 앱 종료 요청(`RunEvent::ExitRequested`)도 한 번 막고 같은 경로로 돌린다. 안전 시간 5초가 지나면 그냥 끝낸다(멈춤 방지).
- **빨간 닫기 단추**는 메인 창을 닫고 앱도 끝낸다. 맥 관례(창을 닫아도 앱은 Dock에 남음)와 다르지만, 윈도우와 같게 둬야 단일 인스턴스·백업 시점이 흔들리지 않는다(8절 D6).

### 3-2. 문구·단축키 표시 — `platformText` 도우미

- `Platform.os: "windows" | "macos" | "browser"`를 추가한다(Rust 명령 `app_os` = `std::env::consts::OS`, 시작 때 1번). 브라우저 모드는 `?os=mac` 쿼리로 맥 문구를 흉내 낸다(E2E용).
- **단축키 표시**: 문구 원본(`strings.ts`)은 계속 한 벌만 둔다. 단축키는 `Mod+Shift+F`처럼 **중립 표기**로 적고, 표시 직전에 `keyLabel()`이 바꾼다.

  | 중립 표기 | 윈도우 | 맥 |
  |---|---|---|
  | `Mod` | `Ctrl` | `⌘` |
  | `Alt` | `Alt` | `⌥` |
  | `Shift` | `Shift` | `⇧` |
  | 이어 붙이기 | `Ctrl+Shift+F` | `⇧⌘F`(맥 표준 순서 ⌃⌥⇧⌘) |
  | `Delete` | `Delete` | `⌦`(fn+delete) |
  | `Backspace` | `Backspace` | `⌫` |
  | `F2`·`F5` | 그대로 | 그대로(맥 키보드는 fn과 함께) |
  | `Shift+F10`(메뉴) | 그대로 | 표시하지 않음(맥은 ⌃클릭·우클릭) |

- **낱말 바꾸기**(같은 키 2벌): `탐색기` ↔ `Finder`, `윈도우 설정 › 개인 설정 › 색 › 앱 모드` ↔ `시스템 설정 › 화면 모드`, `바로 가기(.lnk)` ↔ `가상본`, `탐색기에서 열기` ↔ `Finder에서 보기`. `strings.ts`에 `os({ windows: "…", macos: "…" })` 형태로 적고, 나머지 문구는 그대로 한 벌이다.
- 검사: 단위 테스트가 `strings.ts` 안의 `Ctrl+`·`탐색기` 같은 날 글자를 찾아 **실패**시킨다(새 문구가 윈도우 표기로 들어오는 것을 막음). 화면 도움말 단축키 표(`overview.md` 10-3)는 "윈도우 / 맥" 두 칸으로 바꾼다.

#### 단축키 동작 — 맥에서 키가 겹치는 것

| 지금 단축키 | 맥에서 | 대응 |
|---|---|---|
| `Ctrl+←/→`(다른 요일 포커스) | `⌃←/→`는 맥 "Mission Control: 데스크톱 이동"이 먼저 가져간다 | 판정이 이미 `ctrl||meta`라 **`⌘←/→`로 동작**한다. 표시도 `⌘←/→`로 한다(편집 중이 아닐 때만이라 줄 처음·끝 이동과 겹치지 않음). |
| `Alt+문자`(`Alt+I`·`Alt+M`·`Alt+V` 등) | `⌥`+문자는 특수 글자(µ·√…)를 만들고, `⌥E`·`⌥I`·`⌥U`·`⌥N`·`` ⌥` ``는 **조합 대기 글쇠**라 `keyCode 229`로 와서 지금 코드가 무시할 수 있다 | `Alt` 단축키 판정을 조합 검사(`isComposingKey`)보다 **앞에** 두고 `e.code`로 본다(윈도우에서도 같은 동작). 실기 확인 R2. |
| `Alt+Delete`(행 삭제) | 맥 키보드의 "delete"는 `Backspace`다 | 맥은 `⌥⌫`도 받는다. |
| `Ctrl+휠`(메모 확대) | 맥 트랙패드는 두 손가락 벌리기가 `ctrlKey` 휠로 온다 | 지금 코드 그대로 동작(확인만). `⌘+휠`도 받는다. |
| `F5`(폴더 창 새로 고침) | 맥은 `fn+F5` | `⌘R`도 받는다. |

### 3-3. 저장 폴더·동기화 폴더 감지

- OneDrive 판정을 **"동기화 폴더" 판정**으로 넓힌다(경고 문구 이유는 같음: 동기화가 SQLite 파일을 반쯤 쓴 채 올리거나 충돌 사본을 만든다).
  - 맥: `~/Library/CloudStorage/`(OneDrive·Google Drive·Dropbox·Box의 새 위치), `~/Library/Mobile Documents/`(iCloud Drive), `~/Dropbox`.
  - 윈도우: 지금 규칙 그대로.
  - 순수 함수 `isSyncedFolderLike(path, roots, os)` + 단위 테스트.
- **맥 개인정보 보호 권한(TCC)**: `~/Documents`·`~/Desktop`·`~/Downloads`·iCloud는 처음 접근할 때 "…폴더에 접근하려고 합니다" 확인 창이 뜬다.
  - 기본 저장 폴더 `~/WorkJourney`는 대상이 아니다.
  - 사용자가 저장 폴더나 Cabinet 폴더를 `~/Documents` 아래로 고르면 확인 창이 한 번 뜬다(허용하면 끝).
  - **애드혹 서명(D1-A)이면 판이 바뀔 때마다 서명이 달라져 이 확인을 다시 물을 수 있다** → 첫 실행 안내에 적고, 기본 폴더 유지를 권한다. 정식 서명(D1-B)이면 한 번만 묻는다.
- 윈도우에서 쓰던 일지를 맥으로 옮기는 경우:
  - 파일만 복사하면 된다(형식 동일).
  - Cabinet에 등록한 폴더 경로(`C:\…`)는 맥에 없으므로 이미 있는 **"폴더 없음" 표시 + [경로 다시 지정]**(v1.5.0 K3)으로 처리한다. 새 코드는 없다.
  - 이 내용은 가이드 부록에 적는다.

### 3-4. Cabinet — 끌어 놓기·숨김·가상본 (맥)

| 기능 | 윈도우(지금) | 맥(설계) |
|---|---|---|
| Finder에서 폴더 끌어 놓기 | WebView2 다리로 경로 받기(A안) | **Cabinet 창만** `dragDropEnabled: true`로 만들어 Tauri 기본 끌어 놓기 이벤트(`onDragDropEvent` → `paths`)로 경로를 받는다. 받은 경로는 지금 `handleDrop`(폴더인지 확인·이유 안내)으로 넘긴다. |
| 메인 창 끌어 놓기 | 다리 있음 | 메인 창은 `dragDropEnabled: false` 유지. 메모 보드 이미지 끌어 놓기(HTML 파일 끌어 놓기)를 지키려는 것이다. 메인 창에서 폴더 등록은 Cabinet 창으로 안내한다. |
| 크롬 주소·파비콘 끌어 놓기(링크 등록) | HTML 끌어 놓기 | 같은 HTML 끌어 놓기. **단, Cabinet 창의 기본 끌어 놓기를 켜면 주소 끌어 놓기도 가로챌 수 있다**(파일이 아닌 끌기를 Tauri가 막는지는 확인 필요) → M0 시험에서 확인. 막히면 끌어 놓기 이벤트를 Rust에서 걸러 파일이 아닌 끌기는 웹에 넘기는 맥 전용 다리를 만든다(R3). |
| 줄 끌어 순서·업무 연결 | HTML 끌어 놓기 | 맥 WKWebView는 기본 끌어 놓기를 켜도 화면 안 HTML 끌기가 동작한다(윈도우와 다름) → 확인만. |
| 숨김 파일 | 숨김·시스템 속성 + 점 이름 | 점 이름 + `UF_HIDDEN` 플래그(`std::os::macos::fs::MetadataExt::st_flags`). |
| 바로 가기 해석 | `.lnk`(IShellLinkW) | 심볼릭 링크는 이미 `canonicalize`가 따라간다. Finder **가상본**(alias)은 CoreFoundation 북마크 API로 대상 경로만 읽는다(`cabinet_resolve_shortcut`의 맥 분기 — 파일 내용은 읽지 않음, 4-3 규칙 그대로). 우선순위가 낮아 M2 끝에 한다. |
| 등록 폴더 밖 차단 | `within_roots` | 같은 함수(경로 정규화·접두어 비교). 맥 APFS도 기본은 대소문자를 구분하지 않으며, `canonicalize`가 실제 표기로 맞춰 준다. `cargo test`에 맥 경로 사례를 추가한다. |

### 3-5. 새 판 확인·설치 (맥) — `update.rs`

통신 범위는 그대로다: GitHub Releases(이 저장소)의 판 목록·설치 파일·`SHA256SUMS.txt`, 켤 때 1번 + [업데이트 확인]. **새 주소·시점은 없다**(4-1 예외 범위 안).

```
[새 판 있음] → 내려받기(WorkJourneyBoard_<v>_mac.dmg, 앱 자료 폴더/updates)
  → SHA256 확인 → 일지 자동 백업(_pre-update)      ← 여기까지 윈도우와 같음
  → hdiutil attach -nobrowse -readonly (임시 마운트)
  → 디스크 이미지 안 "Work Journey Board.app"의 서명·판 번호 확인(Info.plist 판 = 받은 판)
  → 지금 앱 옆에 "Work Journey Board.app.new"로 복사(ditto, 서명 유지)
  → 지금 앱을 ".old"로 이름 바꾸기 → ".new"를 원래 이름으로 → ".old" 지우기
  → hdiutil detach → 새 앱 실행(open -n) → 지금 앱 종료
  (중간에 실패하면 .old를 원래 이름으로 되돌린다)
```

- 앱이 직접 받은 파일에는 맥 "격리(quarantine)" 표시가 붙지 않는다 → **업데이트 뒤에는 Gatekeeper 경고가 다시 뜨지 않는다**(애드혹 서명이어도).
- **앱 위치 검사**: 디스크 이미지 안에서 바로 실행했거나, 맥이 "앱 이동 보호(App Translocation)"로 임시 위치에서 실행 중이면 교체할 수 없다. 이때 설치하지 않고 "앱을 응용 프로그램 폴더로 옮긴 뒤 다시 실행하세요"라고 안내한다(`current_exe()` 경로에 `/AppTranslocation/` 또는 `/Volumes/`가 있으면).
- 응용 프로그램 폴더에 쓸 권한이 없으면(관리자가 아닌 계정) 받은 DMG를 Finder로 열어 주고 "끌어서 바꿔 주세요"라고 안내하는 길로 넘어간다(설치 실패 아님).
- **4-3 규칙 확장(사용자 승인 필요, 8절 D7)**: 사용자 폴더가 아닌 **앱 자신의 번들**(`…/Work Journey Board.app`)을 바꾸고 옛 판(`.old`)을 지운다. 윈도우는 NSIS 설치 프로그램이 같은 일을 하므로 실질은 같다. Rust 검사는 이렇다.
  - 지울 수 있는 것은 지금 실행 중인 번들 옆의 `Work Journey Board.app.old` 하나뿐이다.
  - 경로가 `.app`으로 끝나고, 실행 파일이 그 안에 있어야 한다.
  - 이 규칙을 `cargo test`로 고정한다.
- 윈도우 1.5.0 이하 클라이언트는 영향이 없다. 판 목록에서 `…_setup.exe`만 찾고, `SHA256SUMS.txt`에 맥 줄이 더해져도 이름으로 찾기 때문이다(`parse_sums`).

## 4. 빌드·릴리스 — 하나의 판, 두 설치 파일

### 4-1. 워크플로 재구성 — `build-windows.yml` → `build-desktop.yml`

```
plan (ubuntu)            판 종류(formal)·만들 설치판 목록
 ├─ windows (windows-latest)   NSIS → WorkJourneyBoard_<v>_setup.exe          · cargo test
 ├─ macos   (macos-latest)     유니버설 DMG → WorkJourneyBoard_<v>_mac.dmg   · cargo test(맥)
 └─ release (ubuntu, main만, needs: windows + macos)
       두 산출물 모으기 → SHA256SUMS.txt 하나로 합치기 → 릴리스 본문(release-notes.mjs body)
       → v<v> 릴리스 1회 생성(정식 판 = Latest)
```

- **둘 다 성공해야 릴리스한다** → 두 플랫폼의 판 번호가 항상 같다(D3).
- 작업 브랜치(`claude/**`) 푸시 때는 두 빌드만 돌고, 산출물은 Actions에 14일 보관한다(지금과 같음).
- **오프라인 설치판**(`webview=offline` 수동 실행)은 윈도우 전용이다. 맥은 WebView2가 필요 없어 해당이 없다. 수동 실행 때는 windows 작업만 돌고 기존 릴리스에 파일을 더한다(지금 규칙, 2026-11-01 사용자 지시 유지).
- 맥 빌드 방법: `rustup target add aarch64-apple-darwin x86_64-apple-darwin` → `npx tauri build --target universal-apple-darwin`. 걸리는 시간은 약 15~25분(두 아키텍처를 컴파일)으로 본다.
- 비용: 공개 저장소라 GitHub 호스팅 macOS 러너도 **무료**다(비공개라면 분당 10배로 계산되니 주의).
- 경로 필터는 지금 목록을 그대로 쓰고, `src-tauri/tauri.macos.conf.json`·DMG 배경은 `src-tauri/**`에 포함된다.
- CI(`ci.yml`)에 **맥 Rust 검사 작업**을 하나 더한다(`cargo test --lib`, macos-latest) — 맥 분기 코드(`#[cfg(target_os = "macos")]`)가 PR 단계에서 컴파일되는지 본다. 웹 E2E는 지금처럼 ubuntu에서 Chromium + WebKit으로 돈다.

## 7. 이 설계가 지키는 프로젝트 규칙

- **4-1 외부 통신**: 새 호스트·시점 없음. 업데이트는 같은 GitHub Releases 주소만 쓴다. 소개 사이트의 OS 판정은 방문자 브라우저 안에서만 한다.
- **4-2 실제 업무 기록 금지**: 맥 시험도 가상 샘플만 쓴다.
- **4-3 데이터 파일 안전**: 사용자 폴더 규칙은 그대로다. 앱 번들 교체만 새 예외다(D7 승인 후, Rust 가드 + `cargo test`).
- **4-5 얇은 껍데기**: 맥 기능도 Rust는 메뉴·끌어 놓기 경로·업데이트 교체뿐이다. 업무 로직은 웹 앱에 둔다.
- **6절 판·Git**: 판 정본 하나, 릴리스 노트 하나, 가이드 동반 갱신 규칙을 그대로 따른다.
