## 1. 연차 사용일 표시 (#1)

### 1-1. 화면·조작 (시안 ③ 왼쪽 위)
- 요일 머리에 마우스를 올리면 **⋯**. 누르면 메뉴:
  - `이 날 근무 상태`: ◉ 근무(기본) / ○ 연차(종일) / ○ 오전 반차 / ○ 오후 반차
  - 구분선 아래 `<직전 기록일> 업무 전체 가져오기 Alt+Shift+P`(3절), `이 열을 넓게 보기 Ctrl+←/→`
- 표시:
  - **연차**: 머리 배경 옅은 주황 + `연차` 배지(진한 주황 글자), 그 열 칸 배경도 옅은 주황.
  - **반차**: 머리에 테두리만 있는 `오전 반차`/`오후 반차` 배지, 열 음영 없음.
- 기록 칸은 **막지 않는다**(연차 날 급한 일 기록 가능). 오늘 뷰(8절)에서는 날짜 옆 [근무 ▾] 단추로 같은 메뉴.
- 미래 날짜에도 미리 표시할 수 있다(연차 계획).
- 색은 업무 색(c1~c8)·중요 표시 형광펜과 겹치지 않는 주황 계열 토큰(`--leave-*`, 라이트/다크).

### 1-2. 데이터
```sql
CREATE TABLE day_mark (
  date       TEXT PRIMARY KEY CHECK (date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'),
  kind       TEXT NOT NULL CHECK (kind IN ('leave', 'half_am', 'half_pm')),
  updated_at TEXT NOT NULL
);
```
- `근무`로 돌리면 행 삭제. 보드 실행 취소(`Ctrl+Z`) 대상.

### 1-3. 다른 기능과의 관계
| 기능 | 처리(추천) |
|---|---|
| 자동 집계(output-spec 2-1) | 맨 끝(무기록 줄 앞)에 `※ 연차: 화(10/27) · 오전 반차: 수(10/28)` 한 줄 |
| 엑셀 주간보고 | 요일 머리를 `화 10/27 (연차)`로. 원장에는 넣지 않음 |
| 무기록 판정(data-spec 5-1) | **그 주 근무일(월~금)이 모두 연차**면 판정 대상 주에서 뺀다(휴가 주에 종료 제안이 몰리지 않게) |
| 전날 가져오기(3절) | 직전 기록일을 찾을 때 연차일(종일)은 건너뛴다 |
| 인사이트(I-M3) | 히트맵·비중 차트에서 연차일은 빗금(나중 세션에서) |
| 가져오기(M3-S0) | 변화 없음 |

### 1-4. 테스트
단위: 표시 저장·해제·실행 취소, 자동 집계 연차 줄(골든 테스트에 영향 없게 — 연차가 없으면 줄 없음), 무기록 판정 예외. E2E: 메뉴로 연차 → 머리·열 표시 → 다시 근무.

## 2. 메모 빈 텍스트 상자 안 만듦 (#2)

### 2-1. 지금의 문제
v0.2.1부터 빈 곳을 클릭하면 **상자부터 만들고**, 편집을 끝낼 때 비어 있으면 지운다. 그래서 (1) 클릭만 해도 상자 테두리·서식 막대가 생겨 보이고, (2) 편집 중에 주 이동·앱 종료·`Alt+T`처럼 **편집 끝(blur)을 거치지 않는 길**로 나가면 빈 상자가 저장될 수 있다.

### 2-2. 설계 (시안 ④ 가운데 아래)
- 빈 곳 클릭 = 그 자리에 **깜빡이는 커서와 옅은 점선 자리**만 보인다(`여기에 입력 — 글자를 치면 상자가 생깁니다`). 문서·실행 취소 기록에는 아무것도 없다.
- **첫 글자(한글 조합 시작 포함)를 칠 때** 그 자리에 상자가 생기고 편집이 이어진다. 붙여넣기도 같다(그림이면 이미지 상자).
- 다른 곳을 누르거나 `Esc`면 커서 자리는 그냥 사라진다.
- **저장할 때도** 글·이미지가 없는 텍스트 상자는 버린다(`saveWeekNote`·`parseNoteDoc`) → 어떤 길로 나가도 빈 상자가 남지 않고, 이미 저장된 빈 상자도 다음 저장 때 정리된다.
- `Alt+M`·마지막 업무 칸 `↓`로 메모에 들어왔는데 상자가 없을 때도 같은 커서 자리(맨 위 왼쪽 빈 자리).

### 2-3. 테스트
E2E: 빈 곳 클릭 → 상자 0개 확인 → 글자 입력 → 상자 1개, 클릭만 하고 주 이동 → 다시 와도 0개, 한글 조합 첫 글자.

## 3. 전날 업무 내역 복제 (#3)

### 3-1. "전날"의 뜻 (추천)
- **업무별**: 그 업무에 기록이 있는 **가장 가까운 이전 날**(직전 기록일). 월요일이면 보통 금요일, 연차·빈 날은 건너뛴다. 최대 4주 전까지 찾는다.
- **전체**: 어느 업무든 기록이 있는 **가장 가까운 이전 근무일**의 모든 업무 내역.
- 화면에는 늘 날짜를 함께 보인다(`10/28(수) 내역 가져오기`) — 무엇을 가져오는지 헷갈리지 않게.

### 3-2. 조작
| 어디서 | 동작 |
|---|---|
| 칸 안(편집 중) `Alt+P` | 그 업무의 직전 기록일 내역을 이 칸 **끝에 덧붙임** |
| 빈 칸(포커스 열) | `+ 기록 추가` 아래 **[10/28(수) 내역 가져오기 Alt+P]** 점선 단추(시안 ①) |
| 요일 머리 ⋯ 메뉴 / `Alt+Shift+P` | 직전 기록일 **전체 업무** 내역을 이 날 각 업무 칸 끝에 |
| 오늘 뷰 카드 | 카드 아래 `10/28(수): …` 한 줄 미리보기 + [가져오기](8절) |

- 가져오는 것: 본 항목·세부 항목과 순서. **같은 날·업무·내용이 이미 있으면 건너뜀**.
- 가져오지 않는 것: 중요 표시(★), 매주 반복 연결(↻) — 새 기록으로 시작.
- 가져온 뒤 토스트 `10/28(수) 항목 3개를 가져왔습니다 [되돌리기]`, 보드 `Ctrl+Z`로도 되돌림.
- 직전 기록이 없으면 `가져올 이전 기록이 없습니다(4주 안)`.

### 3-3. 테스트
단위: 직전 기록일 찾기(주말·연차·4주 한도), 중복 건너뛰기, 세부 항목 소속 유지. E2E: `Alt+P`·빈 칸 단추·전체 가져오기·되돌리기.

## 4·5. 업무 태그 (#4·#5)

### 4-1. 화면·조작 (시안 ③ 오른쪽 위)
- 업무 행 머리 이름 아래 **회색 칩** `#프로젝트A` `#개발`. 3개를 넘으면 `+2`.
- 업무 ⋯ 메뉴 → **태그…** → 팝오버:
  - 맨 위 입력칸: 글자를 치면 목록을 거르고, 없는 이름이면 `+ '#회의' 새 태그 만들기(Enter)`.
  - 체크 목록: 모든 태그(그 태그가 붙은 업무 수 표시), 체크 = 붙이기/떼기, 바로 저장.
  - 키보드: `↑/↓` 이동, `Space` 체크, `Enter` 새로 만들기, `Esc` 닫기.
- 칩의 `+ 태그`(마우스를 올렸을 때)로도 같은 팝오버.
- **설정 › 태그**: 이름 바꾸기·순서·지우기(지우면 모든 업무에서 떨어짐, 확인 후).
- 태그 이름: 1~20자, 앞뒤 공백 정리, 대소문자 무시 중복 금지. `#`은 화면 표시용이라 저장하지 않는다.
- **색 없음(회색 칩)** 추천 — 업무 색 8개와 섞이면 보드가 시끄럽고 색만으로 구분하게 됨(viz-spec 6절 원칙).

### 4-2. 데이터
```sql
CREATE TABLE tag (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 20),
  sort_order INTEGER NOT NULL,
  created_at TEXT NOT NULL
);
CREATE UNIQUE INDEX ux_tag_name ON tag(lower(name));
CREATE TABLE category_tag (
  category_id TEXT NOT NULL REFERENCES category(id) ON DELETE CASCADE,
  tag_id      TEXT NOT NULL REFERENCES tag(id) ON DELETE CASCADE,
  PRIMARY KEY (category_id, tag_id)
);
```
- 태그는 **업무에** 붙는다(항목·날짜에는 없음). 종료된 업무도 태그를 유지.

## 6. 태그 기준 필터 보기 (#6)

### 6-1. 화면·조작 (시안 ③ 왼쪽 가운데)
- 상단 2줄의 **[태그: 전체 ▾]** → 체크 목록(태그 + `태그 없음`, 각 업무 수) + `필터 해제`.
- 고르면 단추가 파랗게 `태그: #프로젝트A`(여럿이면 `#프로젝트A 외 1`), 보드 위에 안내 띠 `태그 #프로젝트A로 거른 보기 · 업무 2개 숨김 [필터 해제]`.
- 규칙: 고른 태그가 **하나라도** 붙은 업무만 보인다(OR, 추천).
- 키보드 이동(`↑/↓`·마지막 업무 아래 `↓`)은 보이는 업무만 지난다. 오늘 뷰(8절)도 같은 필터.

### 6-2. 범위 (추천)
| 대상 | 필터 적용 |
|---|---|
| 주간 보드·오늘 뷰 | ✅ |
| 주간 요약·엑셀 내보내기 | ❌ 그대로 전체(보고서가 필터에 따라 바뀌면 혼란). 요약 패널에 `보드는 태그로 거른 보기 중 — 요약은 전체` 한 줄 |
| 무기록 판정 | ❌ |
| 인사이트(I-M3) | 인사이트 필터의 "업무" 항목 옆에 태그 고르기를 더함(그 세션에서) |

- 필터는 앱을 다시 켜도 **유지**(설정 `ui.tagFilter`) — 대신 안내 띠가 늘 보여 "업무가 사라졌다"는 착각을 막는다.

## 7. 오늘 날짜 머리 강조 (#7)

- 지금: 포커스 열(기본 오늘)에만 옅은 파랑 배경·파란 글자·아래 선. 다른 요일을 누르면 포커스가 옮겨 가 **오늘이 눈에 띄지 않는다**.
- 바꾼 뒤(시안 ③ 아래):
  - **오늘 머리 = 늘 채운 파랑(`--accent`) + 흰 글자 + 흰 [오늘] 배지** — 포커스와 무관.
  - **포커스 열 = 위쪽 3px 진회색 선 + 굵은 글자**(폭은 지금처럼 넓게).
  - 오늘 열 칸의 옅은 파랑 배경은 포커스와 무관하게 유지.
- 대비: 흰 글자/`#1d5fb4` 6.6:1, 다크 테마는 `--accent` 다크 값으로(4.5:1 이상 확인).
- 이번 주가 아니면 강조 없음(지금과 같음). 오늘 뷰는 날짜 옆 [오늘] 배지.

## 8. 뷰 모드: 주간 뷰 / 오늘 뷰 (#8)

### 8-1. 전환
- 상단 2줄 **[주간 | 오늘]** 단추 묶음, 단축키 **`Alt+V`**(두 뷰 오가기). 마지막 뷰를 기억(`ui.viewMode`) — 다시 켜면 그 뷰로, 커서는 그 뷰의 오늘 첫 업무 칸.
- 오늘 뷰의 날짜 이동: `◀ ▶`·`Alt+←/→` = **하루씩**, `Alt+T` = 오늘. 주간 뷰로 돌아가면 그 날이 든 주.

### 8-2. 오늘 뷰 화면 (시안 ②)
```
┌ 레일 ┬ 이번 주 메모(왼쪽, 폭 조절·기본 42%) ┬ 오늘 기록(오른쪽) ──────────────────────────┐
│      │ [− 90% +] [+ 상자]                   │ 10/29(목) [오늘]  [근무 ▾]  [10/28(수) 전체 가져오기] │
│      │ 점 격자 판(줌·패닝 그대로)             │ ┌ 차세대 정산 시스템 구축 #프로젝트A #개발 ┐  │
│      │                                     │ │ • 개발계 1차 배포 리허설              │  │
│      │                                     │ │   ◦ 로그 점검 결과 공유|              │  │
│      │                                     │ │ 10/28(수): 배포 절차 정리 …  [가져오기] │  │
```

- 오른쪽 = 그날 보이는 업무를 **카드**로(보드 순서·태그 필터 적용). 카드 안 기록 편집은 보드 칸과 **같은 편집기**(개조식 규칙·단축키·자동 저장 그대로).
- 카드 아래 회색 한 줄 = 그 업무의 **직전 기록일 내역 미리보기**(첫 1~2항목) + [가져오기 Alt+P](3절).
- 왼쪽 = 그 날이 속한 주의 **주간 메모**(아래 도크와 같은 판). 경계선으로 폭 조절, 기억(`ui.todaySplit`). 오늘 뷰에서는 아래 메모 도크를 두지 않는다.
- 키보드: 카드 사이 `↑/↓`는 보드의 위/아래 업무 칸과 같고, 마지막 카드 아래 `↓`·`Alt+M` = 왼쪽 메모.
- 창 폭이 1100px보다 좁으면 메모가 위로 접힌 띠가 된다(펼치기 단추).

### 8-3. 테스트
E2E: 전환·기억, 하루 이동·주 경계, 카드 편집 2분 시나리오(오늘 뷰 버전), 가져오기, 메모 왼쪽 편집.

## 9. 업무 기록 속 링크 (#9)

### 9-1. 화면·조작 (시안 ③ 오른쪽 가운데)
- 지금 보드 칸은 늘 입력칸(textarea)이라 링크를 그릴 수 없다. **칸에 포커스가 없을 때는 "보기"로 그리고, 누르면 그 자리에 커서를 둔 편집으로** 바꾼다.
  - 보기: `http://`·`https://`로 시작하는 주소를 **밑줄 링크 + ↗**로(긴 주소는 가운데를 줄여 보임, 마우스를 올리면 전체 주소).
  - **`Ctrl+클릭` 또는 ↗ 클릭 = 기본 브라우저로 열기**, 그냥 클릭 = 지금처럼 그 자리 편집(클릭 위치에 커서).
  - 편집: 그냥 글자(지금과 같음). 붙여넣기·개조식 규칙 그대로.
- 자동 집계·엑셀·가져오기에는 **글자 그대로**(링크 표시 없음).
- 메모 텍스트 상자 안 글에도 같은 링크 표시(`Ctrl+클릭` 열기) — TipTap 링크 표시를 켜되 자동 열기는 끔.

### 9-2. 안전
- 여는 주소는 **http/https만**(파일·스크립트 주소 거부). 실앱은 Rust 명령 `open_url`이 한 번 더 검사하고 OS 기본 브라우저에 넘긴다(앱이 그 주소에 직접 접속하지 않음 — 13절).
- **weekly-note-spec 4-3 "링크는 만들지 않는다"(누르면 바깥 브라우저가 열리는 경로를 두지 않음) 결정을 바꾸는 일**이라 15절 #9에서 확인.

### 9-3. 입력 UX 위험과 대응
보기/편집 전환이 매일 기록(2분)에 끼어들지 않게: (1) 키보드로 칸에 들어오면 바로 편집, (2) 클릭 위치 그대로 커서(브라우저 `caretPositionFromPoint`), (3) 2분 시나리오 E2E·한글 조합 E2E를 그대로 통과해야 함. 위험이 크다고 판단되면 대안 B(입력칸은 그대로, 링크가 든 항목 끝에 작은 ↗ 단추만)로 줄인다.

## 10. 메모 보드 링크 카드 (#10)

### 10-1. A 오프라인 링크 카드 (추천, 시안 ④ 가운데)
- 넣는 방법: 메모 판에 **주소를 붙여 넣기**(빈 곳·선택 상태에서) / 도크 머리 **[링크 넣기]**(주소·제목 입력 창) / 탐색기·브라우저에서 주소 끌어다 놓기. 글 상자 **안**에 붙이면 글 속 링크(9절)로 남는다.
- 카드: 왼쪽 44px 정사각 = **도메인 첫 글자**(도메인별 고정 색조) 또는 **내가 붙인 캡처 썸네일**(선택, 이미지 상자와 같은 저장), 오른쪽 = 제목(굵게) · 도메인 ↗ · 메모 한 줄, 아래 작은 글씨 전체 주소.
- 제목은 비우면 주소에서 만든다(`wiki.example.local/deploy/checklist` → `deploy/checklist`). 카드를 두 번 누르면 제목·메모 편집, `Ctrl+클릭`·↗ = 열기.
- 옮기기·폭·삭제·되돌리기·복제·앞/뒤는 다른 상자와 같다(줌에서도).
- 문서 JSON: `{ "kind": "link", "x","y","w","z", "url", "title", "note", "asset"?: "<note_asset.id>" }`
- 자동 집계·엑셀: `- (링크) 제목 — 주소`.

### 10-2. B 사이트 미리보기 (노션식 — 비추천)
노션처럼 대표 이미지·설명을 자동으로 채우려면 **앱이 그 주소에 직접 접속해 페이지를 받아 와야 한다.** 이는:
- CLAUDE.md 4-1 **외부 통신 0**(제품의 존재 이유)과 CSP(`connect-src`)를 바꾸는 일이고(사용자 승인 필수 항목),
- 사내망 주소는 프록시·로그인 때문에 대부분 실패하며, 외부 주소는 회사 보안 정책상 막히거나 기록될 수 있다.
→ **A로 진행하고, B는 하지 않는 것을 추천**한다. 필요하면 썸네일은 사용자가 캡처를 붙이는 방식(A의 선택 기능)으로 대신한다.

## 11. 메모 보드 줌인·줌아웃·패닝 (#11)

### 11-1. 조작 (시안 ④)
| 동작 | 마우스 | 키보드 |
|---|---|---|
| 확대·축소 | 도크 머리 `−` `+`, `80% ▾`(목록: 25·50·67·80·90·100·125·150·200%), **`Ctrl+휠`(커서 위치 중심)**, 터치패드 두 손가락 벌리기 | 메모 안에서 `Ctrl+=` / `Ctrl+-` |
| 100%로 | `80% ▾` → 100% | `Ctrl+0` |
| 화면에 맞춤 | [화면에 맞춤] — 모든 상자가 보이게 | `Ctrl+1` |
| 이동(패닝) | 휠 = 위아래, `Shift+휠` = 좌우, **`Space`+끌기** 또는 **가운데 버튼 끌기**(빈 곳 끌기는 지금처럼 아무 일 없음) | — |
| 미니맵 | 오른쪽 아래 작은 지도(상자 배치 + 보이는 범위 틀) — 끌거나 눌러 이동, 접기 가능 | — |

### 11-2. 설계
- 판 전체를 CSS `transform: scale()`로 그린다(실앱 CSP: CSSOM으로 넣는 값이라 허용, style 속성 아님). 끌기·크기·클릭 위치는 배율로 나눠 계산, 8px 눈금도 배율 무관하게 문서 좌표 기준.
- 편집 중 글자는 배율대로 커지고 작아진다(서식 막대는 늘 100% 크기로 상자 위).
- 배율은 **앱 전체 하나**로 기억(`ui.noteZoom`) — 주마다 다르면 헷갈림. 오늘 뷰 왼쪽 메모도 같은 값.
- 판의 범위: 지금처럼 오른쪽·아래로 늘어남(음수 좌표 없음). 축소하면 넓은 판을 한눈에.
