## 0. 목표와 원칙

**목표**: 그 주에 확인한 것을 **메모지 붙이듯** 한곳에 모은다. 업무 칸(개조식 기록)과 달리 형식에 얽매이지 않고, 캡처 이미지도 함께 둔다.

**원칙**
1. **매일 기록(2분)에 부담을 더하지 않는다.** 메모는 쓰고 싶을 때만 쓰는 곳이다. 앱을 열면 커서는 지금처럼 보드 오늘 칸에 있다.
2. **외부 통신 0 그대로.** 편집기·이미지 처리 모두 앱 안에서 한다. 인터넷 주소의 이미지는 불러오지 않는다.
3. **데이터는 일지 파일 1개.** 이미지도 일지 파일(SQLite) 안에 넣는다. 그래서 백업·옮기기·복원도 지금 그대로다.
4. **기존 요일 메모를 잃지 않는다.** 업데이트할 때 주마다 메모 1개로 옮기고, 원래 표는 지우지 않는다.

## 1. 요구사항 (2026-10-25 사용자 요청)

| # | 요구 | 설계 반영 |
|---|---|---|
| R1 | 주간별 메모란은 **1개** | 주 1개 메모(`week_note`, 주차 = 기본 키). 보드에서 보고 있는 주를 따라간다 |
| R2 | 고정 행 개조식이 아니라 **자유 서술식** | 상자 안은 자유 서술(문단·목록·제목). 개조식 규칙(Enter=새 항목, Tab=들여쓰기)을 쓰지 않는다 |
| R3 | **OneNote처럼** 아무 곳에나 쓰고, 글이 들어가면 **오브젝트**로 인식, 자유로운 배치 | 시안 A: 빈 곳을 클릭한 자리에 **텍스트 상자**가 생기고, 상자는 끌어서 옮기고 폭을 바꾼다 |
| R4 | **캡처 이미지·외부 이미지 파일** 넣기 | 이미지 상자: 캡처 붙여넣기(Ctrl+V)·파일에서·끌어다 놓기. 일지 파일 안에 줄여서 저장 |
| R5 | **리치 에디터**: 제목/본문, 글자 크기, 굵기, 선 등 | 서식 막대: 제목 1·2·본문, 크기 4단계, 굵게·기울임·밑줄·취소선, 글자색·형광펜, 목록·체크 목록·구분선 |
| R6 | 해당 주 업무 진행에 대해 **확인한 사항을 메모지 붙이듯** | 보드 바로 아래에 붙은 메모 영역(도크) — 기록을 보면서 정리 |

## 2. 시안 비교

| 안 | 구성 | 장점 | 약점 | 판단 |
|---|---|---|---|---|
| **A 자유 캔버스(OneNote형)** ✅ 추천 | 점 격자 바탕의 넓은 판. 빈 곳 클릭 → 그 자리에 텍스트 상자, 이미지도 상자. 끌어서 이동·폭 조절·겹침 허용 | 요구 R3에 가장 가깝다. 고객 미팅 정리 옆에 캡처를 붙이는 식의 "메모지 붙이기"가 그대로 된다 | 구현이 가장 크다(상자 이동·크기·겹침·실행 취소). 좁은 창에서 가로 스크롤이 생길 수 있다 | **추천** — 요구의 핵심이 "자유로운 폼" |
| B 메모지 보드 | 색 메모지(카드)가 왼쪽 위부터 4열로 자동 정렬. 끌어서 순서만 바꿈 | 늘 깔끔하다. 창 폭이 바뀌어도 자동 배치 | 원하는 자리에 둘 수 없다(R3 일부만) | 대안 |
| C 한 장 문서 | 위에서 아래로 이어지는 리치 문서 하나 + 이미지 | 구현이 가장 작고 키보드만으로 편하다 | 배치 자유가 없다(R3 미충족) | 대안(가장 보수적) |

> A를 고르더라도 상자 안 편집기·서식·이미지 처리·데이터 구조는 B·C와 같다. 다른 것은 "상자를 어디에 두느냐"뿐이라, 실사용 후 B로 단순화하는 길도 열려 있다.

```
├ ◀ 2026-W43 ▶ [오늘] [연간 보기] … [주간 요약] [내보내기] 저장됨 ✓ ⚙ ┤
│ 레일 │ 주간 보드(업무 × 월~일)                                  │
│      │ …                                                        │

│      │ 이번 주 메모  상자 4 · 이미지 1   [+ 텍스트 상자] [이미지 넣기] [크게 보기] [▾] │
│      │ · · · · · · · · · · · · · · · · · · · · · · · · · · · ·  │
│      │ ┌고객 미팅 정리┐  ┌[캡처 이미지]┐   ┌다음 주 확인┐        │
│      │ └─────────────┘  └─────────────┘   └───────────┘        │
└──────┴──────────────────────────────────────────────────────────┘
```
- 지금 보드 맨 아래의 **메모 행(요일 7칸)을 없애고**, 그 자리에 보드와 경계선으로 나뉜 **메모 도크**를 둔다.
- **높이**: 기본은 **보드 우선 자동 높이**(2026-10-25 확정, 14절 F1) — 보드는 필요한 만큼(업무 행 + `+ 업무 추가`), 메모는 남는 공간(최소 160px). 경계선을 끌면 그 높이로 고정(설정 `ui.noteDockAuto=false`·`ui.noteDockHeight`에 기억, 최소 120px), 도크 머리 빈 곳이나 경계선을 **두 번 누르면** 다시 자동. (v0.2.1~0.2.2는 고정 280px 기본) **[▾] 접기**: 머리줄만 남기고 접는다(`상자 4 · 이미지 1` 요약은 보인다).
- **[크게 보기]**: 메모가 보드 영역 전체를 덮는다(보드 머리줄·레일·상단 2줄은 그대로). `Esc` 또는 같은 버튼으로 돌아온다. 큰 캡처를 정리할 때 쓴다.
- 오른쪽 주간 요약 패널·왼쪽 중요 업무 패널과 함께 열려도 도크는 보드 폭을 따라간다.
- **대안(결정 2)**: 왼쪽 레일에 "메모" 보기를 두고 보드와 번갈아 본다. 넓게 쓸 수 있지만 기록을 보면서 정리하기 어렵다.

## 4. 시안 A 상세

### 4-1. 판(캔버스)
- 바탕은 16px 점 격자. 상자 위치는 **8px 단위로 맞춘다**(가지런함).
- 판의 높이는 `max(도크 높이, 가장 아래 상자 끝 + 160px)` — 아래에 늘 빈 공간이 있어 이어서 붙일 수 있다. 세로 스크롤.
- 판의 폭은 도크 폭. 상자가 오른쪽으로 넘으면 가로 스크롤(창을 줄였을 때). 새 상자는 보이는 폭 안에 만든다.
- 빈 메모: 가운데 안내 "이번 주에 확인한 것을 자유롭게 붙여 두세요 · 빈 곳을 클릭해 쓰기 · 캡처는 Ctrl+V · 이미지 파일은 끌어다 놓기".

### 4-2. 텍스트 상자
| 동작 | 마우스 | 키보드 |
|---|---|---|
| 새 상자 | 빈 곳 클릭 → 그 자리(8px 맞춤)에 폭 320px 상자, 바로 입력 | `Alt+M`로 메모에 들어간 뒤 `Ctrl+Enter` → 마지막 상자 아래에 새 상자 / [+ 텍스트 상자] |
| 편집 | 상자 안 클릭 | `Enter`(선택 상태에서) |
| 편집 끝 | 바깥 클릭 | `Esc` → 상자 **선택** 상태 |
| 옮기기 | 마우스를 올리면 위에 나타나는 막대를 끌기 | 선택 상태에서 방향키(8px), `Shift`+방향키(32px) |
| 폭 | 오른쪽 손잡이 끌기(160~960px). 높이는 글에 맞춰 자동 | — |
| 지우기 | 상자 ⋯ 메뉴 → 삭제 | 선택 상태에서 `Delete` — 토스트 [되돌리기] |
| 그 밖 | ⋯ 메뉴: 복제 · 맨 앞으로/맨 뒤로 · 상자 배경색(흰색·노랑·파랑·초록·분홍) · 글만 복사 | — |
- 빈 채로 편집을 끝낸 상자는 저절로 없어진다(빈 상자가 쌓이지 않게).
- **v0.2.7(improve-1026-spec 11절)**: 판 줌(25~200%)·패닝(`Space`/가운데 단추 끌기)·미니맵. 상자 좌표·8px 눈금은 늘 문서 px이고 판만 CSS scale로 그린다(끌기·클릭 위치는 배율로 나눔). 도크 머리 단추는 아이콘.
- **v0.2.5 변경(improve-1026-spec 2절)**: 빈 곳 클릭은 상자를 만들지 않고 **커서 자리(점선 + `여기에 입력 — 글자를 치면 상자가 생깁니다`)** 만 연다. 첫 글자(한글 조합 시작 포함)·붙여넣기에서 상자가 되어 메모 기록에 들어간다(`Ctrl+Z` = 상자째 지움). 아무것도 치지 않고 떠나면 흔적이 없다. 저장할 때도 글이 없는 텍스트 상자는 버린다(`parseNoteDoc`) — 주 이동·앱 종료처럼 편집 끝을 거치지 않는 길로 나가도 빈 상자가 남지 않는다.
- 상자는 겹칠 수 있다(OneNote처럼). 나중에 만든 상자가 위에 온다.

### 4-3. 글 서식(리치 편집)
편집 중인 상자 위에 **서식 막대**가 뜬다(상자 바로 위, 화면 밖이면 아래).

| 묶음 | 항목 | 단축키 |
|---|---|---|
| 문단 | 제목 1(20px 굵게) · 제목 2(17px 굵게) · 본문 | `Ctrl+Alt+1` · `Ctrl+Alt+2` · `Ctrl+Alt+0` |
| 크기 | 작게(12) · 보통(14) · 크게(17) · 아주 크게(21) | — |
| 모양 | 굵게 · 기울임 · 밑줄 · 취소선 | `Ctrl+B` · `Ctrl+I` · `Ctrl+U` · `Ctrl+Shift+X`(편집기 기본 `Ctrl+Shift+S`도 동작) |
| 색 | 글자색 6가지(기본·회색·주황·파랑·초록·빨강) · 형광펜(노랑) | — |
| 목록 | 글머리 · 번호 · 체크 목록(☐ 누르면 ☑) | `Ctrl+Shift+8` · `Ctrl+Shift+7` · `Ctrl+Shift+9` |
| 기타 | 구분선 | — |
- 색은 라이트/다크 테마 토큰으로 바뀐다(다크에서도 읽히게).
- ~~링크는 만들지 않는다~~ → **v0.2.8 변경(2026-10-26 사용자 확정, improve-1026-spec 15절 #9)**: 글 상자 안 `http://`·`https://` 주소는 **글 속 링크**(밑줄, 클래스로만 그림 — `target`·`rel` 없음). 그냥 클릭은 편집, `Ctrl+클릭` = OS 기본 브라우저(Rust `open_url`이 http/https만 한 번 더 검사). 앱은 주소에 접속하지 않는다. 판(빈 곳·선택 상태)에 주소를 붙이면 **링크 카드**(10절 #10, 문서 JSON `kind: "link"`).
- **붙여넣기**: 다른 곳에서 복사한 서식 있는 글은 위 서식 범위만 남기고 정리한다(표·글꼴 이름·인터넷 이미지 주소는 버림). 붙여넣은 내용에 이미지 데이터가 있으면 이미지 상자로 바꾼다.

### 4-4. 이미지 상자
| 넣는 방법 | 동작 |
|---|---|
| 캡처 붙여넣기 | 윈도우 캡처 도구(`Win+Shift+S`) 후 메모에서 `Ctrl+V` → **마지막으로 클릭한 자리**(없으면 보이는 곳 왼쪽 위 빈 자리)에 이미지 상자 |
| 파일에서 | [이미지 넣기] → 파일 고르기(PNG·JPG·GIF·WEBP·BMP) |
| 끌어다 놓기 | 탐색기에서 메모 위로 끌어 놓은 자리에 |
- **줄여서 저장**: 긴 변 **1600px**을 넘으면 줄이고 **WebP(품질 0.82)**로 바꿔 저장한다(캡처 1장 보통 100~250KB). 투명한 PNG도 WebP가 투명을 지킨다. 10MB가 넘는 원본은 받지 않는다(안내 토스트).
- 크기: 모서리 손잡이로 줄이고 늘린다(비율 유지, 폭 80~1600px). 처음 넣을 때는 폭 최대 480px로 보인다.
- 아래에 한 줄 설명(선택)을 달 수 있다. 설명은 자동 집계·엑셀에 글로 들어간다.
- 이미지를 누르면 [크게 보기] 미리보기(원본 크기, `Esc` 닫기). ⋯ 메뉴에 **[이미지로 저장…]**(내보내기와 같은 저장 대화상자, `.png`/`.webp`)을 둔다 — 결정 3과 함께 확인.

### 4-5. 저장·실행 취소
- **자동 저장**: 글·배치가 바뀌면 0.5초 뒤 저장(보드와 같은 "저장 중… / 저장됨 ✓"). 주를 옮기거나 창을 닫을 때 대기 중인 저장을 먼저 끝낸다.
- **실행 취소**: 상자 안 글은 그 상자의 편집 기록(`Ctrl+Z`/`Ctrl+Y`), 상자 만들기·옮기기·크기·삭제·이미지 넣기는 **메모 전체 기록**(편집 중이 아닐 때 `Ctrl+Z`). 보드의 실행 취소와는 따로다(포커스가 있는 곳 기준).

### 4-6. 키보드 흐름(매일 기록과의 연결)
- `Alt+M`: 메모로 가기(마지막으로 편집한 상자 끝, 없으면 새 상자) / 메모에서 누르면 보드로.
- 보드 **마지막 업무 칸에서 `↓`** → 지금은 메모 행으로 갔다. 바꾼 뒤에는 **메모로** 간다(위와 같음). 2분 시나리오의 "메모 1줄"은 그대로 키보드만으로 된다.
- 메모 첫 상자에서 `Ctrl+↑`… 같은 복잡한 이동은 두지 않는다. 보드로 돌아갈 때는 `Alt+M` 또는 `Esc` 두 번.

## 5. 데이터

### 5-1. 마이그레이션 `0003_week_note.sql` (전진 전용, 직전 자동 백업 `_pre-migration-v3`)
```sql
CREATE TABLE week_note (
  week_id    TEXT PRIMARY KEY CHECK (week_id GLOB '[0-9][0-9][0-9][0-9]-W[0-9][0-9]'),
  doc        TEXT NOT NULL,            -- 메모 문서 JSON(5-2)
  updated_at TEXT NOT NULL
);

CREATE TABLE note_asset (
  id         TEXT PRIMARY KEY,         -- UUIDv7
  week_id    TEXT NOT NULL,
  mime       TEXT NOT NULL CHECK (mime IN ('image/webp','image/png','image/jpeg','image/gif')),
  data       TEXT NOT NULL,            -- base64(줄인 이미지)
  width      INTEGER NOT NULL,
  height     INTEGER NOT NULL,
  bytes      INTEGER NOT NULL,         -- 원래 바이트 수(용량 표시용)
  created_at TEXT NOT NULL
);
CREATE INDEX note_asset_week ON note_asset(week_id);
```
- 이미지를 BLOB이 아니라 **base64 TEXT**로 둔다: 실앱(tauri-plugin-sql, JSON으로 값 전달)과 브라우저 모드(sql.js)에서 같은 방식으로 확실히 오가게 하려는 것(용량 약 1.33배).
- **기존 요일 메모 이관**: `day_memo`를 주별로 묶어 주마다 텍스트 상자 1개 — 줄마다 `- (목) 부서 월례 회의 참석` 형식(지금 자동 집계의 `[메모]`와 같은 모양). `day_memo` 표는 **지우지 않고 남겨 둔다**(I-M5에서 정리 여부 결정).
  - **구현(N1)**: SQL 안에서 옮기지 않고 **읽을 때 바꾼다** — 그 주에 `week_note` 행이 없으면 요일 메모로 상자를 만들어 보여 주고(도크에 "예전 요일 메모를 옮겨 보여 주는 중" 안내), 처음 저장할 때 `week_note`에 쓴다. 저장은 비어도 행을 남겨 요일 메모가 다시 나오지 않는다. 이유: 요일 이름·주차 계산은 `domain/week.ts` 한 곳(CLAUDE.md 4-4, SQL `strftime` 금지)이고, 편집기 JSON을 SQL로 만들면 깨지기 쉽다. 사용자에게 보이는 결과(상자 1개·자동 집계 같음·원래 표 보존)는 결정 5와 같다.

### 5-2. 메모 문서 JSON
```json
{
  "v": 1,
  "boxes": [
    { "id": "…", "kind": "text", "x": 24, "y": 24, "w": 360, "z": 1, "bg": null,
      "content": { "type": "doc", "content": [ { "type": "heading", "attrs": { "level": 2 }, "content": [ { "type": "text", "text": "고객 미팅 정리" } ] } ] } },
    { "id": "…", "kind": "image", "x": 408, "y": 24, "w": 330, "z": 2, "asset": "<note_asset.id>", "caption": "응답 시간 전후 비교" }
  ]
}
```
- `content`는 편집기(ProseMirror 계열)의 문서 JSON. 허용하는 노드·서식은 4-3 표뿐(스키마로 강제).
- 저장 단위는 **문서 통째**(작아서 한 번에 쓴다, 수 KB). 이미지는 넣을 때 `note_asset`에 먼저 쓰고 문서가 그 id를 가리킨다 — 한 batch.
- 문서에서 빠진 이미지(삭제 후 되돌리기 시간이 지남)는 그 주를 저장할 때 `note_asset`에서 지운다(DB 안의 행 — 사용자 폴더 파일이 아님).

### 5-3. 용량
- 캡처 1장 ≈ 100~250KB(base64 포함). 주에 이미지 2장 × 50주 ≈ **연 10~25MB**가 일지 파일에 더해진다.
- 백업은 일일 14 + 월간 12개라 백업 폴더는 그만큼 곱해진다(연 25MB면 최대 약 0.6GB). 설정 > 백업에 **일지 파일 크기·이미지 용량**을 보여 주고, 이미지가 많은 사용자는 보관 개수를 줄일 수 있게 안내한다.

## 6. 다른 기능과의 관계

| 기능 | 지금(요일 메모) | 바꾼 뒤(주간 메모) |
|---|---|---|
| **자동 집계 `[메모]`**(output-spec 2-1 규칙 7) | `- (요일) 내용` 줄 | 메모의 **글만** 읽는 순서(위→아래, 같은 높이면 왼쪽→오른쪽)로 이어 붙인다. 제목은 그대로 한 줄, 글머리 `- `, 번호 `1. `, 체크 목록 `- `·완료는 `- (완료) `, 상자 사이 빈 줄, 이미지는 설명이 있으면 `- (이미지) 설명`, 없으면 생략. **골든 샘플(2-2) 갱신**: 이관된 주는 지금과 같은 결과가 나온다 |
| **메모 포함 설정** | 켜고 끔 | 그대로 |
| **엑셀 주간보고** | 메모 행(요일 칸마다) | 메모 행 1개: A=`메모`, **B~마지막 열 병합** 한 칸에 위 글(요약 행과 같은 방식, 행 높이 계산) |
| **엑셀 원장** | `(메모)` 행이 날짜마다 | 주마다 1행: 날짜 = 그 주 월요일, 요일 빈칸, 업무 `(주간 메모)`, 내용 = 위 글 |
| **무기록 판정**(data-spec 5-1 "뭐라도 기록한 주") | 메모 있는 날이 있으면 기록한 주 | 메모에 글·이미지가 있으면 기록한 주 |
| **연간 미니맵**(기록한 날 수) | 메모 있는 날도 셈 | 업무 기록 날만 센다(메모는 날짜가 없음). 메모만 있는 주는 연한 1단계로 표시 |

## 7. 기술 선택

- **편집기: TipTap(ProseMirror 기반, MIT)** — 오프라인·번들 포함, 서식 범위를 스키마로 정확히 제한할 수 있고, 문서를 JSON으로 저장한다. **처음 메모를 열 때만 불러오는 별도 조각**(ExcelJS와 같은 방식, 앱 시작에 영향 없음). 런타임 네트워크 호출 없음을 확인하고 커밋 설명에 적는다(CLAUDE.md 4-1).
  - **CSP 주의**: 실앱은 HTML 속 `style="…"` 속성이 막힌다(스플래시 v1에서 확인한 문제). 그래서 글자 크기·색·형광펜은 **클래스로만** 표현한다(`note-fs-l`, `note-c-blue` …). 인라인 style을 쓰는 확장은 쓰지 않는다. 엑셀과 같은 방식으로 **실앱 CSP 아래 E2E**를 둔다.
  - 대안: Lexical(Meta, MIT). 서식을 `style` 속성으로 넣는 기본 동작이 많아 CSP 대응이 더 번거롭다.
- **이미지 처리**: 화면의 `<canvas>`로 줄이고 WebP로 바꾼다(라이브러리 없음). 표시는 `data:` 주소(지금 CSP `img-src 'self' data:` 안에서 동작 — CSP 변경 없음).
- **이미지 파일 고르기**: 웹 표준 파일 선택(`<input type="file">`)과 끌어다 놓기 — 새 Rust 명령 없음. [이미지로 저장…]만 내보내기의 `export_write` 규칙을 넓혀야 하므로 결정 3에서 함께 정한다.

## 8. 보안·안전
- 인터넷 주소 이미지는 넣지 않는다(붙여넣기에서도 버림). CSP도 외부 이미지를 막는다(이중). 링크(v0.2.8)는 http/https 주소 글자만 저장하고(`sanitizeContent`가 `href` 하나만 남김) 앱이 접속하지 않는다.
- 링크 카드 상자(v0.2.8): `{ "kind": "link", "x","y","w","z", "url", "title", "note", "asset"? }` — 제목·메모 200자, 폭 200~640, 썸네일(선택)은 이미지 상자와 같은 `note_asset`.
- 메모 데이터는 일지 파일 안 — 백업·옮기기·복원 경로 그대로. 사용자 폴더에 새 파일을 만들지 않는다(결정 3의 [이미지로 저장…] 제외).
- 스키마 변경 = 새 마이그레이션 + 직전 자동 백업 + fixture 왕복 테스트(CLAUDE.md 4-3). 기존 `day_memo`는 남긴다.
- 테스트·스크린샷은 가상 메모·가상 이미지(그림 대신 단색 도형)만.

## 9. 테스트
- **단위**: 메모 → 글 추출(읽는 순서·목록·체크·제목·이미지 설명), 자동 집계 골든(이관된 주는 지금 결과와 같음), 이미지 줄이기 크기 계산, 문서 JSON 검증(허용 노드 밖은 버림), 마이그레이션 0003(요일 메모 이관·`day_memo` 보존·직전 백업·fixture 왕복).
- **E2E**(Chromium·WebKit): 빈 곳 클릭 → 상자 → 글·서식 → 옮기기·폭 → 삭제·되돌리기, 캡처 붙여넣기(가상 이미지 클립보드) → 이미지 상자 → 다른 주로 갔다 와도 그대로, `Alt+M`·마지막 업무 `↓`, 2분 시나리오 갱신, 실앱 CSP 아래 편집기 동작, 외부 요청 0.
- **회사 PC 확인표**: 윈도우 캡처 도구 → `Ctrl+V`, 탐색기 끌어다 놓기, 한글 입력기로 상자 안 입력, 큰 이미지 10장 넣은 뒤 속도·일지 파일 크기.

| 4 | 붙여넣기 자리: 편집 중인 **빈** 글 상자가 있으면 그 자리(빈 곳 클릭 → `Ctrl+V`, 빈 글 상자는 사라짐), 글이 있는 상자를 편집·선택 중이면 그 아래, 아니면 가장 아래 상자 아래. 클립보드에 글도 있으면 글로 붙인다(워드 등에서 복사한 글이 그림으로 바뀌지 않게) | "마지막으로 클릭한 자리"(4-4)를 빈 곳 클릭 흐름으로 구현 |
| 5 | 그림을 끌면 이동(위 막대도 됨), **선택된 그림을 한 번 더 누르면** 크게 보기(⋯ 메뉴에도). 선택 상태 `Enter` = 설명 입력, 설명 칸에서 `Enter`/`Esc` = 다시 선택. 크기는 오른쪽 아래 손잡이(폭 80~1600, 비율 유지, 1px 단위) | 첫 클릭은 선택(옮기기·Delete), 끌기와 크게 보기가 섞이지 않게(3px 넘게 움직이면 끌기) |
| 6 | 화면 표시는 `data:` 주소만(`blob:` 주소는 실앱 CSP `img-src 'self' data:`에서 막힘), 그림 읽기는 `createImageBitmap`. 실앱 CSP E2E에 이미지 넣기를 더함 | CSP 변경 없음 |

## 14. 실사용 전 점검에서 찾은 마찰 후보 (N3, 2026-10-25 — **모두 추천안으로 확정·구현, v0.2.3**)

클라우드 브라우저 모드에서 가상 샘플로 화면 크기를 바꿔 가며 확인했다. 회사 PC 확인(m1-check 7-3)·◆G2 기록에서 나온 항목은 이 표에 이어 적는다.

| # | 마찰 | 근거 | 추천 | 대안 |
|---|---|---|---|---|
| F1 | **작은 화면에서 보드가 잘린다** — 1366×768에서 메모 도크(기본 280px)가 본문의 약 37%를 차지해 업무 4번째 행이 반쯤 가려진다. 매일 쓰는 곳은 보드다 | 원칙 1(매일 기록에 부담을 더하지 않는다)·CLAUDE.md 4-6 | **보드 우선 자동 높이**: 보드는 필요한 만큼(업무 행 + `+ 업무 추가`), 메모는 남는 공간(최소 160px). 경계선을 끌면 그 높이로 고정(지금처럼 기억), 도크 머리를 두 번 누르면 자동으로 돌아감 | 기본 높이만 화면에 맞춰 줄임(창 높이의 30%, 최대 280px) / 지금 그대로 |

**구현(v0.2.3)**
- F1·F2: 자동 높이일 때 보드 영역은 `flex: 0 1 auto`(내용만큼, 모자라면 줄며 스크롤), 메모 도크는 `flex: 1 1 0; min-height: 160px`. 접으면 보드가 다 쓴다. 끌기는 2px 넘게 움직였을 때만 고정으로 바꾼다(두 번 누르기와 섞이지 않게). v0.2.2 이전 저장값은 높이가 기본 280이면 자동, 아니면(사용자가 끌어서 정함) 고정으로 읽는다.
- F3: 보드 칸에 글 없이 그림만 붙이면 칸에는 아무것도 넣지 않고 토스트 "그림은 보드 칸에 넣을 수 없습니다 — 메모에 붙일 수 있습니다 [메모에 붙이기]" → 누르면 메모(접혀 있으면 펼침)의 가장 아래 상자 아래에 이미지 상자.
